## 二、骨架：一个字都不能少的四样

```csharp
// 第 NN 课：<主题> —— <一句话说明这一课要教什么>
//
// ══ 这一课要教什么 ══
// <两三句。说清"为什么需要这个知识"，而不是复述语法>
//
// ══ 检查设计说明（给维护者）══
// <核心检查点是哪一条？学生能用什么偷懒办法蒙过去？那条检查怎么防住的？>

using System;
using System.Collections.Generic;
using System.Linq;
using HybridEngineLight;
using HybridEngineLight.CsLessons;

[课程("NN", "第 NN 课：<标题>",
    """
1. <要求一>
2. <要求二>
3. <要求三>
""")]
public static class 第NN课
{
    public static string 模板 => """
// …（见第四节的分节要求）
""";

    public static string 参考答案 => """
// 参考答案 —— 必须**真的能通过所有检查**（自己跑一遍）
""";

    [检查说明("<一句给学生看的话，说明这条检查查什么>")]
    public static CheckResult 检查_xxxx(string 代码)
    {
        // …
    }
}
```

硬性规则：

1. **文件名**：`第NN课_<主题>.cs`（课号两位，`17`、`23`、`40`）。
2. **必须有 `[课程(...)]` 特性**，否则运行器发现不了你这一课。
3. **检查方法名必须以 `检查_` 开头**，签名固定
   `public static CheckResult 检查_xxx(string 代码)` —— 运行器靠反射收集。
4. **每条检查都要加 `[检查说明("…")]`** —— 那是给学生看的，函数名不是。
5. **每课至少一条「核心检查点」** —— 防住"能输出对但没学到东西"的偷懒解法。
   检查说明里用 `★` 开头标出来（照第 17 课）。
6. **`参考答案` 必须真的能通过你写的所有检查**（自己跑，见第五节）。
7. **检查数 4~7 条**。第 17 课是 6 条。
8. **课与课之间不许重名**：每个文件的类名是 `第NN课`（在 `HybridEngineLight.CsLessons` 命名空间下），
   私有辅助函数写成 `private static`，不会互相撞。

## 三、学生代码跑在什么环境里（**先读这一节，能省你一小时**）

学生的答案被塞进一个自动生成的类里，结构等价于：

```csharp
using System;                       // 已给
using System.Collections.Generic;   // 已给
using System.Linq;                  // 已给
using System.Text;                  // 已给
using System.IO;                    // 已给

public static class 学生代码        // ← 学生写的东西全在这里面
{
    // 学生写的方法 / 类 / record
}

public static class 入口            // 运行器自己的
{
    public static void Main() { /* 课程给的「调用点」在这里 */ }
}
```

由此推出**五条**必须记住的约束：

1. **学生写不了顶层语句、写不了 `using` 指令** —— 他只能在类里写
   `static` 方法 / `class` / `record` / `struct` / `enum`。
   ⇒ 你的题目**只能是"写几个 static 方法"**（像第 17 课那样），
   不要让学生自己写 `Main`。
2. **类里不能有实例字段**（`static class` 的限制）。
   要是题目需要一份"外部数据"，让**调用点**去准备（第 17 课的 `表甲`、`表乙` 就是这么来的）。
3. **学生的方法默认是 private，课程库会替他补 `public`**（`补公开`）。
   他写了 `public` 也不会重复。**你在题目里只写 `static` 就行**
   （和参考答案保持一致）。
4. **调用点是与 `学生代码` 平级的另一个类**，所以调用点里提到学生的方法/类型时
   必须限定成 `学生代码.xxx` —— 这件事由 `CppLesson.限定(代码, 调用点)` 自动做。
   ⇒ 你写调用点时**写裸名字**（`冒泡排序(甲)`），让 `限定` 去加前缀。
   ⚠ 前提是你的调用点里不要有和学生方法同名的**局部变量**。
5. **`InvariantGlobalization=true`**：运行时报错是**英文**的
   （`NullReferenceException: Object reference not set to an instance of an object.`），
   而**编译报错是中文**的（`error CS0022: [] 内的索引数错误，应为 2`）。
   模板里"配真实报错"那一节照这个来引（自己跑一遍拿到原话再写，别编）。

## 四、模板（`模板 => """…"""`）的分节 —— 顺序不能变

照第 17 课，**一节都不能少、顺序不能变**：

```
// 第 NN 课：<标题>
// ─────────────────────────────────────────────────────
//  怎么读这一课
// ─────────────────────────────────────────────────────
//
//   先从头读一遍讲解，再照着最后的「轮到你了」写。
//   卡住了看答案（先自己写一遍）—— 命令在「怎么自己测」那一节。
//
// <一两句：这一课讲的是哪一件事>
// ─────────────────────────────────────────────────────
//  这一课你会学到
// ─────────────────────────────────────────────────────
//    <一行>
//
//  需要先会
//    第 MM 课：<哪一课，为什么>
//
// ─────────────────────────────────────────────────────
//  先介绍：<为什么需要这个东西>
// ─────────────────────────────────────────────────────
//  （具体到数字的例子，别写空话）
//
// ─────────────────────────────────────────────────────
//  一、<速查表式的小节>
// ─────────────────────────────────────────────────────
//  二、…
//  三、…
//
// ─────────────────────────────────────────────────────
//  ⚠ 这一课唯一要记住的坑：<一句话>
// ─────────────────────────────────────────────────────
//  （写出**错的代码** + **真实的报错原文**或**具体的错误结果**，再写怎么改）
//
// ─────────────────────────────────────────────────────
//  这一课不碰什么
// ─────────────────────────────────────────────────────
//   （写明这一课**不**碰什么 + 那是第几课的事）
//
// ─────────────────────────────────────────────────────
//  ══ 轮到你了 ══
// ─────────────────────────────────────────────────────
//
//   在下面写几个方法：
//
//    1. static ……
//    2. static ……
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────
//     点界面上的「检查」。卡住了看答案（先自己写一遍）。
//
// ── 在下面写 ──
```

**要求**：

- **第 1 节必须叫「怎么读这一课」**，第 2 节是「这一课你会学到」+「需要先会」。
- 「轮到你了」用 `//    1. ` 这种**编号**格式（4 个空格 + 数字 + 点 + 空格）。
- 「⚠ 这一课唯一要记住的坑」里**必须有一条真实报错或真实错误结果**
  （csc 的编译错、运行时的异常名、或者"编译通过结果全错"的具体数字）。
- **正文（散文）里不许出现英文双引号 `"`** —— 一律用 `「」`。
  代码示例行里有 `"` 是允许的（那是代码），但能不用就不用。
- 讲解必须落到**具体数字**，不许写空话（❌「筛法比试除法快」；
  ✅「n=1000000 时试除法要做约 5 亿次除法，埃氏筛只要约 300 万次标记」）。
  **你写进课里的每个数字都要自己算过**，不许估。
- 变量名 / 方法名**一律中文**（`左边界`、`试除数`、`拿着`）。
- 结尾就是 `// ── 在下面写 ──`（第 17 课没有再放空函数壳，你也不用放）。

## 五、检查怎么写（照第 17 课抄这套工具）

### 5.1 调用点：一次编译，所有检查共用

第 17 课的做法是一个 `private const string 调用点`（或 `调用点()` 方法）+ `跑一次(代码)` 缓存。
**每次检查都会重新编译一遍学生代码（一次一两秒）** ⇒ 一份代码只编译一次，检查之间共用结果。

```csharp
    private static string 上次代码;
    private static CppRun 上次运行;

    private static CppRun 跑一次(string 代码)
    {
        if (上次运行 != null && 上次代码 == 代码) return 上次运行;
        上次代码 = 代码;
        上次运行 = CppCheck.编译并运行(代码, null, CppLesson.限定(代码, 调用点()));
        return 上次运行;
    }
```

### 5.2 输出对齐用「标记|值」，不要用"第几行"

学生自己多打一行调试输出，按行号对答案就全错位了。所以：
调用点里每问一个值就打一行 `标记|值`，检查里按**标记**去找那一行。

```csharp
    private static string 造调用点(string 准备, params (string 标记, string 表达式)[] 用例们)
    {
        var sb = new System.Text.StringBuilder();
        sb.Append(准备).Append('\n');
        foreach (var (标记, 表达式) in 用例们)
        {
            // ⚠ 每组各自 try/catch：学生代码抛异常时只影响那一组，
            //   不然整次检查会变成"程序崩了"，学生看不出是哪一组出的问题。
            sb.Append("try { Console.WriteLine(\"").Append(标记).Append("|\" + (")
              .Append(表达式)
              .Append(")); } catch (Exception __e) { Console.WriteLine(\"")
              .Append(标记).Append("|崩溃:\" + __e.GetType().Name); }\n");
        }
        return sb.ToString();
    }
```

`比一比` 里遇到 `崩溃:XXX` 要单独说一句（第 17 课有范例）。
**void 方法（就地改数组那种）不能直接当表达式** ⇒ 那种调用点手写原始字符串，
每组照样 `标记|` 输出（第 17 课的思路一样，只是准备语句里先调用、再打印结果）。

### 5.3 检查里能用的库

```csharp
CppCheck.编译并运行(学生代码, null, 调用点)   // → CppRun
CppCheck.编译失败说明(run)                     // 编译失败时的标准提示（含报错翻译）
CppLesson.限定(代码, 调用点)                   // 给调用点里学生的方法/类型加 学生代码. 前缀
CheckResult.过("给学生看的说明")
CheckResult.不过("给学生看的说明")
```

`CppRun` 上有什么：`run.编译通过`、`run.行`（输出行列表）、`run.全部输出`、
`run.编译信息`、`run.Raw.CompileFailed`、`run.Raw.Error`。

### 5.4 三条经验（违反了就会被学生骂）

1. **失败的提示必须说清"下一步做什么"**：
   ❌「结果不对」 ✅「得到 6，应该是 2。⚠ 表.Length 是总格数，行数要问 GetLength(0)」。
2. **判据要宽，别把等价写法判死**：要求"有循环"就 `for`/`while`/`foreach` 都算；
   第 17 课就栽过一次 —— 只认 `.Length`，把正确的 `foreach` 解法判错了。
   **文本检查只判"有没有这个关键写法"，不判"必须怎么写"。**
3. **别测时间**（除了规格里明确写了计时的那两课）：机器忙的时候正确代码也会被判慢。

### 5.5 反面测试（硬性）

每课至少写一个"**偷懒但输出对**"的答案（把答案写死、用现成库函数绕过要考的知识点、
少写一层循环……），确认**被你自己的检查抓住**，并把结论写进报告。
做法：把错答案写进沙箱的答题文件 → 跑检查 → 看它确实报了 ✗ 且提示说到点子上。

## 八、常见的坑（都是踩过的）

| 现象 | 原因 / 怎么改 |
|---|---|
| `error CS0103: 当前上下文中不存在名称"xxx"` 出现在**你的检查**里 | 调用点里的学生方法名没被限定 ⇒ 一定要走 `CppLesson.限定(代码, 调用点)` |
| `error CS0117: "学生代码"不包含"Main"的定义` | 你让学生写完整程序了。学生**只写 static 方法** |
| 学生写 `record 成绩(...)`，调用点里 `new 成绩(...)` 报 CS0246 | 调用点里写 `new 学生代码.成绩(...)`（或让学生定义的名字和规格里一致，并靠 `限定`） |
| 检查永远"通过"，但错答案也通过 | 你的检查没喂**多组数据**。至少要含边界：空、1 个、重复、全相同、负数、大数 |
| 检查把正确解法判错 | 文本判据太窄（只认一种写法）。见 5.4 |
| 检查跑得特别慢（每课 >30 秒） | 每个检查方法各编译了一次。用 `跑一次(代码)` 缓存 |
| 沙箱里 `✓0 ✗0`（一条检查都没输出） | 答题文件被清了（你删过 cs-answers？）—— 重跑 ⑤ 生成，再写答案 |
| `dotnet build` 报文件被占用 | 你在真工程上构建，或者和别人共用 TEMP。回到沙箱 + 自己的 TEMP |
| 中文乱码 / ps1 报语法错 | PowerShell 5.1 读**无 BOM** 的 .ps1 按 ANSI ⇒ 别自己写含中文的 ps1 |
