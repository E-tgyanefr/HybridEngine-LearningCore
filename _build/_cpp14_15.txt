标题|第 14 课：动态内存 —— 什么时候该 new，什么时候不该
要求|1. 写一个函数 造数组(int n)，用 new int[n] 造一个长度为 n 的数组，把每个元素填成 i*i，返回它
要求|2. main 里用 造数组(4) 得到数组，打印 4 个元素（0 1 4 9），然后 delete[]
要求|3. 写一个函数 求和(int* 数们, int n)，返回前 n 个元素的和；用 1 2 3 4 调用并打印
模板|// 第 14 课：动态内存 —— 什么时候该 new，什么时候不该
模板|//
模板|// 先介绍：这一课先讲**不该用**的时候
模板|//
模板|// 大多数教材把 new / delete 讲得很靠前。我把它排在 14 课，是有意的：
模板|//
模板|//   ⚠⚠ **现代 C++ 里，绝大多数场合你不该手写 new / delete。**
模板|//
模板|//   需要"长度运行时才知道的数组"？ → `std::vector`（上一课）
模板|//   需要"字符串"？                → `std::string`（第 07 课）
模板|//   需要"一个能指向任何东西的东西"？ → 智能指针（以后会碰到）
模板|//
模板|//   这三个东西**自己管好内存** —— 你不需要记住"在哪一行释放"。
模板|//   而手写 new / delete 意味着你**必须**记住 —— 忘一次就是内存泄漏，
模板|//   释错一次就是崩溃，而且这两种错**都不会当场告诉你**。
模板|//
模板|// 那为什么还要学？因为你要**看懂别人的代码**：
模板|//   · 老代码、C 风格的库、操作系统接口里到处是 new/delete
模板|//   · 报错信息里会出现 "heap-use-after-free"、"memory leak" 这些词
模板|//   · 你自己写容器/工具的时候（少数场合）真的需要它
模板|//
模板|// 所以这一课的目标是：**知道它是什么、知道它危险在哪、知道什么时候不用它。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：栈 vs 堆
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 先分清内存里的两个地方：
模板|//
模板|//     栈（stack）      函数里 `int a;` 这种，**函数一返回自动消失**
模板|//                      快、自动、但**大小必须在编译时知道**
模板|//
模板|//     堆（heap）       `new` 出来的，**一直活着直到你 delete**
模板|//                      可以运行时决定大小，但**必须自己记得释放**
模板|//
模板|//     int  a[10];              ← 栈上，长度必须写死
模板|//     int* p = new int[n];     ← 堆上，n 可以是运行时算出来的
模板|//
模板|//   ⚠ `int* p = new int[n]` 读作"我要 n 个 int 的地方，把首地址给我"。
模板|//     p 本身是个**指针**（在栈上，8 字节），它指向的那块内存在**堆**上。
模板|//
模板|// 用完要还：
模板|//
模板|//     delete[] p;               ← ⚠ 数组要用 **delete[]**，不是 delete
模板|//     p = nullptr;              ← 好习惯：还完之后把指针清掉
模板|//
模板|//   ⚠ `delete` 和 `delete[]` 写错是**未定义行为** —— 可能没事，
模板|//     可能崩，可能悄悄破坏内存。编译器**不会**提醒你。
模板|//
模板|// ⚠ 指针怎么传给函数：数组参数会"退化"成指针
模板|//
模板|//     int 求和(int* 数们, int n)      ← 注意：**必须另外告诉它有几个**
模板|//
模板|//   为什么：`int* 数们` 只是一个地址，**它自己不知道那块地方有多长**。
模板|//     所以数组当参数时，长度得单独传。
模板|//     （这也是 vector 的好处：`数们.size()` 随时问得到。）
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：new 了没 delete —— **内存泄漏**
模板|//
模板|//     void 干活() {
模板|//         int* p = new int[1000];
模板|//         // ... 用了 p ...
模板|//         return;              // ✗ 忘了 delete[] p
模板|//     }
模板|//
模板|// 你会看到：**什么都没发生** —— 程序照跑，第一次调用也没事。
模板|// 但每调一次就漏掉 4KB，一个循环里调一百万次就是 4GB。
模板|// 症状是"程序跑一阵子越来越慢，最后被系统杀掉"。
模板|// ⇒ 这是**最难查的一类 bug**：错误和症状之间隔得很远。
模板|//   现代做法就是**别用裸 new** —— 用 vector，它会在析构时自己释放。
模板|//
模板|// ⚠ 坑 2：delete 之后继续用（悬垂指针）
模板|//
模板|//     int* p = new int[10];
模板|//     delete[] p;
模板|//     p[0] = 5;                // ✗ 那块内存已经还回去了
模板|//
模板|// 你会看到：多半**看起来是好的**（那块内存还没被别的东西拿走），
模板|// 但它是"别人的地方"了 —— 一旦程序里别处申请了内存，就会撞在一起，
模板|// 表现为"改 A 的值，B 变了"。
模板|// ⇒ 还完之后立刻 `p = nullptr;` —— 这样再用就是明确的崩溃（更好查）。
模板|//
模板|// ⚠ 坑 3：同一块内存 delete 两次
模板|//
模板|//     int* p = new int[10];
模板|//     int* q = p;
模板|//     delete[] p;
模板|//     delete[] q;              // ✗ 同一块，删了两次
模板|//
模板|// 你会看到：程序直接崩（堆管理器发现异常）——
模板|// 这个错**反而是好事**：它当场就崩，不像前两个那样悄悄进行。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────

模板|//        用 new int[n] 造一个数组，把第 i 个填成 i * i，返回它
模板|//        ⚠ 一定要 new（栈上的数组在函数返回时就没了，返回它的地址是错的）
模板|//
模板|//   ② `int 求和(int* 数们, int n)` —— 返回前 n 个元素的和

模板|//   ③ main 里：
模板|//        int* a = 造数组(4);

答案|#include <stdio.h>
答案|
答案|// ⚠ 为什么这里**必须** new：栈上的数组在函数返回时就销毁了，
答案|//   把它的地址返回出去 ⇒ 用的时候那块内存已经是别人的了。
答案|//   （这类错叫"返回局部变量的地址"，编译器**通常会警告**但不阻止你。）
答案|int* 造数组(int n) {
答案|    int* p = new int[n];        // 堆上要 n 个 int
答案|    for (int i = 0; i < n; i++) {
答案|        p[i] = i * i;           // p[i] 就是 *(p + i)，两种写法等价
答案|    }
答案|    return p;
答案|}
答案|
答案|// ⚠ 数组当参数会"退化"成一个地址 ⇒ 长度必须**另外传**
答案|int 求和(int* 数们, int n) {
答案|    int 和 = 0;
答案|    for (int i = 0; i < n; i++) {
答案|        和 += 数们[i];
答案|    }
答案|    return 和;
答案|}
答案|
答案|int main(void) {

答案|    }
答案|    delete[] a;                 // ⚠ 数组用 delete[]，不是 delete
答案|    a = nullptr;                // 好习惯：还完就清掉，之后误用会明确崩
答案|
