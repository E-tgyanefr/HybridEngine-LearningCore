要求|1. 确认 g++ 和 dotnet 都装好（本课会真的去调它们）
要求|2. 搞清楚 C++ 和 Python 的流程差别：编译 → 链接 → 运行
要求|3. 让编译器报一次错，并且学会从第一条 error 读起
模板|// 第 00 课：跑通第一个程序 —— 把工具链装好
模板|//
模板|// 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
模板|// ─────────────────────────────────────────────────────
模板|//  这一课你会学到
模板|// ─────────────────────────────────────────────────────
模板|//    把编译器装好、跑通第一个程序，以及怎么读第一条报错
模板|//
模板|//  需要先会
模板|//    没有 —— 这是第一课
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：为什么要单独占一课
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// C++ 要先把源码**编译**成可执行文件，而这需要一个**单独安装的编译器**。
模板|// 大多数教程里，「卡在装工具」是放弃率最高的一步 ——
模板|// 所以它值得单独占一课，而不是塞在第一课的注释里。
模板|//
模板|//  跑通之后你拿到的是**信心**：知道自己的机器真的能编、能跑，
模板|// 后面每一课的报错才都是「我写错了」，而不是「环境又怎么了」。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、需要装两样（都免费）
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//   ① .NET SDK —— 课程运行器。它替你敲 g++ 命令、跑起来看结果。
模板|//
模板|//        winget install Microsoft.DotNet.SDK.8
模板|//
模板|//      ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
模板|//
模板|//   ② g++ —— 真正的 C++ 编译器。
模板|//
模板|//        winget install BrechtSanders.WinLibs.POSIX.UCRT
模板|//
模板|//      装完**重开一个窗口**（让 PATH 生效），敲：
模板|//
模板|//        g++ --version
模板|//
模板|//      能看到版本号就成了（本机实测是 g++ 16.1.0）。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、C++ 比 C 多一步：编译 → **链接** → 运行
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//      main.cpp
模板|//         ↓  编译         每个 .cpp 单独变成「目标文件」
模板|//      main.o
模板|//         ↓  链接         把目标文件和标准库拼成一个可执行文件
模板|//      main.exe
模板|//         ↓  运行
模板|//
模板|// 为什么值得知道「链接」这一步：**链接错误和编译错误说的是不同的事**。
模板|//
模板|//     编译错误  →  「你这行代码语法不对」         例如漏了分号
模板|//     链接错误  →  「你用了某个东西，但我找不到它」 例如函数只有声明没定义
模板|//
模板|// `undefined reference to ...` 就是典型的**链接**错误 ——
模板|// 看到它别去改语法，去查「那个函数到底定义了没有」。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  三、这一课唯一要练的手艺：读第一条 error
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 报错长这样（这是**故意写错**的代码：漏了分号）：
模板|//
模板|//     main.cpp:4:28: error: expected ';' before 'std'
模板|//
模板|// 拆开看四样：
模板|//
模板|//     main.cpp  哪个文件
模板|//     4         **第几行**   ← 先看这个
模板|//     28        第几列（次要）
模板|//     error     严重程度
模板|//
模板|// 两条铁律：
模板|//
模板|//  ① **只看第一条 error。** 后面那几十条多数是它引起的连锁反应。
模板|//     C++ 的模板报错尤其能滚出一屏 —— 全都不是你要修的。
模板|//
模板|//  ② **报错行号常常要往上多看一行。** 编译器是读到「它不认识的东西」
模板|//     才报的错，而那个东西往往是**上一行**漏了什么造成的。
模板|//
模板|// ⚠ error 和 warning 不一样：
模板|//
模板|//     error    编译**停了**，不会产生可执行文件
模板|//     warning  编译**继续**，但它在提醒你「这里很可能是 bug」
模板|//
模板|// ⚠⚠ **不要忽略 warning。** 「能编译」不等于「能跑对」。
模板|//   这门课后面会专门讲几个「只给 warning、但结果一定是错的」的坑。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  这一课没有算法要写，只有三件事：
模板|//
模板|//    1. 确认 g++ 和 dotnet 都装好了
模板|//       （界面首页的「环境自检」会显示；命令行敲 g++ --version 也行）
模板|//
模板|//    2. 让编译器**报一次错**，并且读懂它
模板|//       下面留了一个 main。先故意漏掉一个分号 → 检查 → 看报错 →
模板|//       把分号补上 → 再检查。
模板|//
模板|//    3. 让它打印出这三行，就算跑通了：

模板|//          我准备好学 C++ 了
模板|//          编译 → 链接 → 运行
