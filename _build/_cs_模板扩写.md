// 第 02 课：类型与计算 —— int 和 double 不是一回事
//
// ─────────────────────────────────────────────────────
//  先介绍：C# 要你先说清楚"这是什么"
// ─────────────────────────────────────────────────────
//
// 第 01 课你已经会"记住一个数"了：
//
//     int 甲 = 6;
//
// 那行开头的 `int` 就是**类型**。Python 里你从来不用想这件事 —— Python 自己猜。
// C# 不猜：**类型由你写下来，编译器照着检查**。
//
// 好处有两个：机器知道该用哪套算法；错误能在你**运行之前**被发现。
// 代价是：**整数和小数是两套完全不同的算法** —— 混了不会报错，只会算错。
//
//     7 / 2    →  3       ← 整数除法，小数被**扔掉**
//     7 / 2.0  →  3.5     ← 只要一边是小数，才是小数除法
//
// ⚠ 这不是"精度不够"，是**规则不同**：`/` 两边都是 int 时做的是整除
//   （和 Python 的 `//` 一样），余数交给 `%`。
//
// 这一课要写的是"算圆的面积"，而面积一定是小数 ⇒
// 你得先搞清楚：**哪些写法会把小数丢掉**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 三个最常用的类型
//
//     int     整数     6 · -3 · 0
//     double  小数     3.14159 · 2.5 · -0.75
//     bool    真/假    true · false
//
//   ⚠ `3.14159` 这种**带小数点**的字面量，类型就是 double。
//     所以 `3.14159 * 半径 * 半径` 整个式子会被提升成 double —— 这正是我们要的。
//
// ② 整数除法 vs 小数除法
//
//     int a = 7, b = 2;
//
//     Console.WriteLine(a / b);          ⇒ 3
//     Console.WriteLine(a / 2.0);        ⇒ 3.5
//     Console.WriteLine((double)a / b);  ⇒ 3.5
//     Console.WriteLine(a % b);          ⇒ 1      （余数）
//
//   `(double)a` 叫**强制转换**：先把 a 变成小数再参与运算。
//   式子里只要有**一个** double，整个式子就按小数算。
//
//   ⚠ 括号的位置会改变结果，这两行**不一样**：
//
//     Console.WriteLine((double)a / b);    ⇒ 3.5   ← 先转，再除
//     Console.WriteLine((double)(a / b));  ⇒ 3     ← 先整除（小数已经没了），再转
//
// ③ 整数除零会崩，小数除零不会
//
//     int x = 5, y = 0;
//     Console.WriteLine(x / y);          ⇒ 崩：DivideByZeroException
//
//     double p = 5, q = 0;
//     Console.WriteLine(p / q);          ⇒ ∞     （有值可表示，不崩）
//
// ④ 本课要写的方法长这样
//
//     static double 算面积(int 半径)
//     {
//         return 3.14159 * 半径 * 半径;
//     }
//
//   读作："给我一个整数半径，我还你一个小数面积"。
//
//     算面积(5)  ⇒ 78.53975
//     算面积(1)  ⇒ 3.14159
//     算面积(10) ⇒ 314.159
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：拿整数算圆周率，小数悄悄没了
//
//     return 22 / 7 * 半径 * 半径;      // ← 22 / 7 先按 int 算成 3
//
// 你会看到：**编译通过、程序照跑** —— 算面积(5) 打印 75，不是 78.53975。
// 为什么：`22 / 7` 两边都是 int ⇒ 整除得 3，后面的乘法才轮到小数，已经晚了。
// ⇒ 想用小数就把小数**写出来**：`3.14159`。
//
// ⚠ 坑 2：返回类型写成 int
//
//     static int 算面积(int 半径)
//     {
//         return 3.14159 * 半径 * 半径;
//     }
//
// 你会看到：error CS0266: 无法将类型“double”隐式转换为“int”。存在一个显式转换(是否缺少强制转换?)
// 为什么：double 塞进 int 会丢小数，C# 不让你**悄悄**丢 ——
//         真要丢必须自己写 `(int)` 明说。
// ⇒ 本课的方法声明必须是 `static double 算面积(int 半径)`。
//
// ⚠ 坑 3：有一条分支没 return
//
//     static double 算面积(int 半径)
//     {
//         if (半径 > 0) return 3.14159 * 半径 * 半径;
//         // 半径 <= 0 的时候呢？
//     }
//
// 你会看到：error CS0161: “学生代码.算面积(int)”: 并非所有的代码路径都返回值
//          （`学生代码` 是课程骨架包住你代码的那个类名，不用管它）
// 为什么：声明了要还一个 double，编译器要保证**每条路**都有东西可还。
// ⇒ 别把 return 包在 if 里，直接写一句。
//
// ⚠ 坑 4：整数除以 0
//
//     int a = 5, b = 0;
//     Console.WriteLine(a / b);
//
// 你会看到：未处理异常 System.DivideByZeroException: Attempted to divide by zero.
//          （运行时异常的原文是英文，意思是"试图除以零"）
// 为什么：整数除零没有可表示的结果 ⇒ 直接抛。同样的式子换成 double 得到 ∞，不抛。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写

// 第 03 课：条件判断 —— switch 与 if 的选择
//
// ─────────────────────────────────────────────────────
//  先介绍：程序不能只会"照着算"
// ─────────────────────────────────────────────────────
//
// 前两课的程序都是**一条路走到底**：打印、算面积。
// 真实程序几乎每一步都在分岔：
//
//     够 90 分吗？→ 优秀；否则够 60 吗？→ 及格；否则不及格
//
// 这就是"条件"：**同一段代码，按情况走不同的路**。
//
// C# 的条件写法有两种，这一课两种都要用上：
//
//     if / else if / else   按**范围**判断（分数 ≥ 90）
//     switch                按**具体值**挑（1 → 周一，2 → 周二）
//
// ⚠ 但 C# 的 switch 和 C / C++ / Java 的旧式 switch 有一处**根本不同**：
//   它**不允许 case 之间"掉落"**。忘写 break / return 不是"串烧"，
//   而是**直接编译不过**。这是 C# 故意的 —— 忘 break 是 C 里最经典的一类 bug。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① if / else if / else
//
//     if (分 >= 90)      Console.WriteLine("优秀");
//     else if (分 >= 60) Console.WriteLine("及格");
//     else               Console.WriteLine("不及格");
//
//   条件必须是一个 **bool**（true / false）。
//   比较用 `>=` `>` `==` `!=` `<` `<=`；组合用 `&&`（且） `||`（或） `!`（非）。
//
//   ⚠ 相等是 `==`（两个等号）。一个 `=` 是**赋值**，写法上错了编译器会拦你。
//
// ② 老式 switch 语句：每个分支必须"走掉"
//
//     switch (n)
//     {
//         case 1: return "周一";
//         case 2: return "周二";
//         default: return "不是星期";
//     }
//
//   每个 case 必须以 `break;` 或 `return` 结束。
//
//   ⚠ 唯一允许的例外是**空的 case 并列**，它没有"掉落"：
//
//         case 1:
//         case 2: return "周一周二都算";
//
// ③ switch 表达式（推荐，短得多，而且不会忘 break）
//
//     return n switch
//     {
//         1 => "周一",
//         2 => "周二",
//         3 => "周三",
//         4 => "周四",
//         5 => "周五",
//         6 => "周六",
//         7 => "周日",
//         _ => "不是星期",      // `_` 是"其余所有情况"，放最后
//     };
//
//   · 用 `=>` 而不是 `case ... :`
//   · 每支末尾是**逗号**（最后那支的逗号可有可无）
//   · 它是个**表达式**：可以直接 return，也可以放在赋值右边
//
// ④ 本课要写的两个方法
//
//     static string 判等级(int 分)   95/90→优秀 · 60→及格 · 59→不及格
//     static string 星期几(int n)    1→周一 … 7→周日 · 8→不是星期
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：case 之间"掉落"
//
//     switch (n)
//     {
//         case 1: return "周一";
//         case 2:
//             Console.WriteLine("周二");     // ← 这里既没 break 也没 return
//         case 3: return "周三";
//     }
//
// 你会看到：error CS0163: 控制不能从一个 case 标签(“case 2:”)贯穿到另一个 case 标签
// 为什么：C# 从语言层面禁掉了 C 那种"串烧" —— 要出去就写 break 或 return。
//
// ⚠ 坑 2：switch 表达式漏了 `_`
//
//     return n switch { 1 => "周一", 2 => "周二" };
//
// 你会看到（⚠ 编译只是**警告**，不是错误）：
//     warning CS8509: switch 表达式不处理其输入类型的所有可能的值(它不是穷举)。例如，模式“0”未包含在内。
// 于是程序**编译过了**，但一喂 8 就崩：
//     未处理异常 System.Runtime.CompilerServices.SwitchExpressionException:
//     Non-exhaustive switch expression failed to match its input.
//     Unmatched value was 9.
//
// 为什么：switch 表达式必须**穷举**所有可能的值；int 有四十多亿种，你列不全
//         ⇒ 只能靠 `_` 兜底。
// ⇒ ⚠ 这条最阴：不报错，只在**某个输入**上崩。写完一定要喂一个越界值试试。
//
// ⚠ 坑 3：if 里少写一个等号
//
//     if (分 = 90) return "优秀";      // ← 一个 = 是赋值
//
// 你会看到：error CS0029: 无法将类型“int”隐式转换为“bool”
// 为什么：赋值表达式的类型是 int，而 if 要 bool。
//         C# 故意不让它通过（C 里能过，于是 `if (x = 1)` 成了经典 bug）。
//
// ⚠ 坑 4：判等级的顺序写反了
//
//     if (分 >= 60) return "及格";
//     else if (分 >= 90) return "优秀";     // ← 永远轮不到
//
// 你会看到：**编译通过**，跑出来 95 分被判成"及格"。
// 为什么：第一个条件先命中就 return 了。
// ⇒ **范围窄的条件写在前面**：先判 ≥ 90，再判 ≥ 60。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
//   写两个方法：
//
//     1. static string 判等级(int 分)

//     2. static string 星期几(int n)

//        ⚠ 这一课**要求用 switch 表达式**：

//   期望结果：

//     星期几:  1 → 周一 … 7 → 周日    8 → 不是星期

//   ⚠ 两件事：
//     · 两个签名**都给你了**，你只写方法体

// 第 04 课：循环与集合 —— List 与 foreach
//
// ─────────────────────────────────────────────────────
//  先介绍：一个变量装不下"一列东西"
// ─────────────────────────────────────────────────────
//
// 到第 03 课为止，我们都是一个变量装一个值：
//
//     int 甲 = 6;
//     int 乙 = 7;
//
// 现在要算"全班 40 个人的总分"。你不会想写 40 个变量，
// 更不会想把同一句"加起来"抄 40 遍。
//
// 这一课解决两件事，它们是配套的：
//
//     集合  →  一个名字装**一列**值     int[]、List<int>
//     循环  →  让同一段代码**重复做**   foreach、for、while
//
// ⚠ C# 有两种最常用的集合，先分清它们的分工：
//
//     int[]        **定长**数组 —— 长度一开始就定死，不能加也不能删
//     List<int>    **可变**列表 —— 能 Add / Remove，长度自己长
//
//   ⇒ 拿不准就用 `List<int>`。C# 新手最常见的一类麻烦，
//     就是拿定长数组当可变列表用。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 数组：长度固定
//
//     int[] 甲 = { 1, 2, 3 };
//     Console.WriteLine(甲.Length);     ⇒ 3
//     Console.WriteLine(甲[0]);         ⇒ 1      （下标从 0 开始）
//
//   ⚠ 只有 0 / 1 / 2 三个格子，`甲[3]` 不存在。
//
// ② List：能增能删
//
//     var 数 = new List<int> { 1, 2, 3 };
//     数.Add(4);                        // 末尾加一个
//     Console.WriteLine(数.Count);      ⇒ 4
//     Console.WriteLine(数[3]);         ⇒ 4
//
//   ⚠ 数组用 `.Length`，List 用 `.Count` —— 这两个**最容易记混**。
//   ⚠ `List<int>` 住在 `System.Collections.Generic` 里。本课的答题文件
//     **顶部已经替你写好了 using**（课程骨架带的），你不用管。
//
// ③ foreach：把一列东西挨个过一遍
//
//     foreach (var x in 数)
//         Console.WriteLine(x);
//
//   读作"对 数 里的每个 x"。**不需要下标**，也不该在循环里改这个集合。
//
// ④ for：需要下标时用它
//
//     for (int i = 0; i < 数.Count; i++)
//         Console.WriteLine($"{i}: {数[i]}");
//
//   ⚠ 边界是 `<` 而不是 `<=`：最大下标是 `Count - 1`。
//
// ⑤ 本课要写的两个形状
//
//     int 和 = 0;                                 // ⚠ 必须先初始化成 0
//     foreach (var x in 数) 和 += x;               // 累加
//
//     var 出 = new List<int>();
//     foreach (var x in 数)
//         if (x % 2 == 0) 出.Add(x);               // 筛选，装进新列表
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：忘了 using，编译器不认识 `List`
//
//     static int 求和(List<int> 数) { ... }     // 文件顶部没有 using
//
// 你会看到：error CS0246: 未能找到类型或命名空间名“List<>”(是否缺少 using 指令或程序集引用?)
// 为什么：`List<>` 住在 `System.Collections.Generic` 里，不写 using 就找不到。
// ⇒ 本课答题文件的 using 已经带好了；你自己另开 .cs 文件时要记得加那一行。
//
// ⚠ 坑 2：把定长数组当 List 用
//
//     int[] 数 = { 1, 2, 3 };
//     数.Add(4);
//
// 你会看到：error CS1061: “int[]”未包含“Add”的定义，并且找不到可接受第一个“int[]”类型参数的可访问扩展方法“Add”(是否缺少 using 指令或程序集引用?)
// 为什么：数组长度固定，"加一个"这件事它根本做不到。
// ⇒ 要 Add 就声明成 `List<int>`。
//
// ⚠ 坑 3：Length 和 Count 记混
//
//     List<int> 数 = new List<int> { 1, 2, 3 };
//     Console.WriteLine(数.Length);
//
// 你会看到：error CS1061: “List<int>”未包含“Length”的定义，并且找不到可接受第一个“List<int>”类型参数的可访问扩展方法“Length”(是否缺少 using 指令或程序集引用?)
// 为什么：数组是 `.Length`，List 是 `.Count`；反过来写也一样不行。
//
// ⚠ 坑 4：下标越界（能编译，跑起来才崩）
//
//     int[] 数 = { 1, 2, 3 };
//     Console.WriteLine(数[3]);          // 合法下标只有 0 / 1 / 2
//
// 你会看到：未处理异常 System.IndexOutOfRangeException: Index was outside the bounds of the array.
//          （英文原文，意思是"索引超出了数组界限"）
//          ⚠ 换成 List 越界，异常名不一样：
//            System.ArgumentOutOfRangeException: Index was out of range. Must be
//            non-negative and less than the size of the collection. (Parameter 'index')
// 为什么：长度 3 的数组只有 3 个格子。
// ⇒ 最常见的来源是 for 写成了 `i <= 数.Count`（应该是 `<`）。
//
// ⚠ 坑 5：在 foreach 里改那个集合
//
//     foreach (var x in 数)
//         if (x == 2) 数.Add(9);          // ← 边遍历边改
//

//
// ─────────────────────────────────────────────────────
//  先介绍：方法拿到的是"复印件"
// ─────────────────────────────────────────────────────
//
// 一个方法像个黑盒：给它几个值，它算完还你一个值。
//
//     static int 平方(int x) { return x * x; }
//
// 但有一件事新手几乎一定会踩：
//
//     **方法里的参数，是调用者那个变量的"复印件"。**
//
//     static void 加一(int x) { x = x + 1; }     // 改的是复印件
//     int 我的数 = 5;
//     加一(我的数);
//     Console.WriteLine(我的数);                 ⇒ 还是 5
//
// 这个设计不是坑，是**保护**：方法不会顺手改掉你外面的一堆变量。
// 但有时候你**就是**想让它改到外面（把一个数翻倍、把一个字符串转成数字）。
//
// C# 给了两个关键字专门干这件事：
//
//     ref   我允许你改这个变量本身
//     out   这个变量我进去时没有值，你出来时**必须**给我一个
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 普通参数：复印件
//
//     static int 平方(int x) => x * x;
//

//
// ② ref：让方法改到外面
//
//     static void 加倍(ref int x) { x = x * 2; }
//
//     int a = 5;
//     加倍(ref a);            // ⚠ 调用时也必须写 ref
//     Console.WriteLine(a);   ⇒ 10
//
//   ⚠ `ref` **两边都要写**：声明处写，调用处也写。
//   ⚠ 传进去的必须是个**变量**，而且**已经赋过值**（方法里会先读它）。
//
// ③ out：方法"顺带"给你一个结果
//
//     static bool 试着转成整数(string s, out int 值)
//     {
//         return int.TryParse(s, out 值);

//

//

//
//   为什么要有 out：一个方法只能 return 一个值。

//

// 第 06 课：字符串 —— 不可变与插值
//
// ─────────────────────────────────────────────────────
//  先介绍：字符串是"改不动"的
// ─────────────────────────────────────────────────────
//
// 数字能改：
//
//     int 分 = 60;
//     分 = 分 + 10;        // 分 变成 70
//
// 字符串长得很像，但**行为完全不同**：
//
//     string s = "abc";
//     s.ToUpper();              // ← 这行什么也没发生
//     Console.WriteLine(s);     ⇒ 还是 abc
//
// 因为 C# 的字符串是**不可变（immutable）**的：
// **一旦造出来，这个字符串本身永远不会变。**
//
// 所有"看起来在改字符串"的方法（ToUpper、Replace、Substring、Trim…），
// 真实做的事都是：**照着原串造一个新的，然后把新的还给你**。
// 你不管那个返回值，它就静静地被扔掉了。
//
//     s = s.ToUpper();          // ← 把新串接回来，这才是"改"
//
// ⚠ 为什么要设计得这么"别扭"：字符串到处被共享（变量、参数、字典的键…），
//   如果能就地修改，任何一处改动都会**悄悄影响所有引用它的人**。
//   不可变换来的是"拿到一个字符串就可以放心用"；代价就是**忘了接收返回值**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 三个"返回新串"的常用方法
//
//     string s = "  Hello  ";
//     s.Trim()             ⇒ "Hello"        （去掉两头空白）
//     s.ToUpper()          ⇒ "  HELLO  "
//     s.Replace("l", "L")  ⇒ "  HeLLo  "
//
//   ⚠ 三行里的 `s` 本身**都没变**。要用结果就得接住：`s = s.Trim();`
//
// ② 长度和单个字符
//
//     string s = "abc";
//     Console.WriteLine(s.Length);         ⇒ 3     ⚠ 属性，不加括号
//     Console.WriteLine(s[0]);             ⇒ a     （下标从 0 开始，类型是 char）
//     Console.WriteLine(s.IndexOf('z'));   ⇒ -1    （找不到返回 -1，不是 0）
//
//   ⚠ `s.Length()` 是编译错误 —— `Length` 是**属性**（一个值），不是方法（一段行为）。
//     Java 那边恰好相反，是 `s.length()`。两门语言在这里不一样。
//
// ③ 拼串 vs 插值
//
//     string 名字 = "小明";  int 年龄 = 9;
//
//     Console.WriteLine("你好，" + 名字 + "，今年 " + 年龄 + " 岁");

//

//         Console.WriteLine($"{3.14159:F2}");      ⇒ 3.14
//   ⚠ `+` 是**从左往右**算的，所以下面两个不一样：
//         Console.WriteLine("a" + 1 + 2);     ⇒ a12
//         Console.WriteLine(1 + 2 + "a");     ⇒ 3a
//
// ④ 字符串比"内容"，不比"地址"
//
//     string a = "abc";
//     string b = new string(new char[] { 'a', 'b', 'c' });   // 另一个对象
//     Console.WriteLine(a == b);      ⇒ True    ← 比的是**内容**
//
//   ⚠ 这一点和 Java 不同：Java 的 `==` 比引用，要 `.Equals` 才比内容。

//  常见坑

//
//     Console.WriteLine(s.Length());
//

// 第 07 课：类与对象 —— 把数据和行为放在一起
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么要把"数据"和"改数据的规则"关在一起
// ─────────────────────────────────────────────────────
//
// 假设要写一个银行账户。没有类的时候，你会这么写：
//
//     int 余额 = 0;
//     void 存(int n) { 余额 += n; }
//     void 取(int n) { 余额 -= n; }        // ⚠ 忘了检查够不够
//
// 这段代码本身没错，但有个隐患：**余额是个谁都能改的变量**。
//
//     余额 = -500;  取(999999);         // 编译器一声不吭，余额直接变负数
//
// 问题不在"有人写错了"，而在**规则没有唯一的出口**：
// "余额不能变负"这条规则，散落在每一个用到余额的地方。
//
// 类要做的事只有一件：**把数据和改数据的规则放进同一个盒子**。
//
//     class 银行账户
//     {
//         public int 余额 { get; private set; }     // 外面只能读
//         public void 存(int n) { ... }
//         public bool 取(int n) { ... }             // 唯一的出口，里面有检查
//     }
//
// 现在想把余额改成负数？做不到 —— 外面只能**读** `余额`，
// 唯一的入口是 `存` / `取`，而 `取` 会检查。
//
//   ⇒ 这叫**封装**。它不是"把东西藏起来"，而是**让规则只有一个出口**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 一个最小的类
//
//     class 计数器
//     {
//         public int 值 { get; private set; }     // 属性：外面读得到、改不了
//
//         public 计数器(int 初值 = 0)             // 构造函数：与类同名、没有返回类型
//         {
//             值 = 初值;
//         }
//
//         public void 加(int n) => 值 += n;       // 方法
//         public void 重置() => 值 = 0;
//     }
//
// ② new 出一个对象，再调用它的方法
//
//     var 甲 = new 计数器();        // 用默认值 0
//     var 乙 = new 计数器(100);     // 从 100 开始
//
//     甲.加(3);  甲.加(4);
//     Console.WriteLine(甲.值);     ⇒ 7
//     甲.重置();
//     Console.WriteLine(甲.值);     ⇒ 0
//     Console.WriteLine(乙.值);     ⇒ 100     （甲乙互不影响）
//
//   ⚠ `甲` 和 `乙` 是**两个不同的对象**，各自有一份自己的 `值`。
//
// ③ 字段 vs 属性
//
//     public int 值;                        // 字段：外面能直接读写，没法保护
//     public int 值 { get; private set; }    // 属性：外面读得到，只有类自己能写
//     public int 值 { get; }                 // ⚠ 只有 get：**连类自己都改不了**
//
//   ⚠ 只有 get 是"构造完就冻住"。本课的 `加` / `重置` 要能改它，所以必须写 `private set`。
//     三种位置：外面读 甲.值 ✅ ｜ 外面写 甲.值 = 5; ❌ ｜ 类里写 值 += n; ✅
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：写成 `{ get; }`，然后类自己的方法去改它
//
//     public int 值 { get; }
//     public void 加(int n) { 值 += n; }        // ← 编译不过
//
// 你会看到：error CS0200: 无法为属性或索引器“学生代码.计数器.值”赋值 - 它是只读的
// 为什么：`{ get; }` 只生成了一个 getter，**根本没有 setter** —— 类自己也一样改不了。
// ⇒ 要"外面不能写、自己能写"，写成 `{ get; private set; }`。
//
// ⚠ 坑 2：以为加了 private set 外面就还能写
//
//     甲.值 = 5;
//
// 你会看到：error CS0272: 属性或索引器“学生代码.计数器.值”不能用在此上下文中，因为 set 访问器不可访问
// 为什么：`private set` 只对**类内部**开放。这正是封装想要的效果 ——
//         外面想动余额，只能走 `存` / `取`。
//
// ⚠ 坑 3：把属性当方法调
//
//     Console.WriteLine(甲.值());
//
// 你会看到：error CS1955: 不可调用的成员“学生代码.计数器.值”不能像方法一样使用。
// 为什么：属性是**值**不是方法 —— 方法带括号，属性不带。
//
// ⚠ 坑 4：构造函数前面多写了返回类型
//
//     public void 计数器(int 初值 = 0) { }      // ← 多了 void
//
// 你会看到：error CS0542: “计数器”: 成员名不能与它们的封闭类型相同
// 为什么：构造函数**没有返回类型**。写上 `void` 它就变成普通方法，
//         而 C# 不允许方法名和类名相同。
//
// ⚠ 坑 5：构造函数没有默认值，却写 `new 计数器()`
//        （而它是 `public 计数器(int 初值)` —— 少了 `= 0`）
// 你会看到：error CS7036: 未提供与“学生代码.计数器.计数器(int)”的所需参数“初值”对应的参数
// ⇒ 本课要求默认为 0，所以要写 `= 0`。
//
// ⚠ 坑 6：取钱的顺序写反了
//
//     public bool 取(int n) { 余额 -= n; return 余额 >= 0; }   // ← 先扣再检查
//
// 你会看到：**编译通过**，取 999 之后余额变成负数 —— 钱已经被扣掉了。
// 为什么：检查必须在**扣之前**。
// ⇒ 正确顺序：**先检查（n 合法 且 n <= 余额），通过了才扣**；取不出来就 `return false;`。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
//   把骨架里两个类填完整（签名都给你了）：

//          public int 值 { get; private set; }     只读属性（外面读得到、改不了）

// 第 08 课：继承与接口 —— 各做各的，同一套调用
//
// ─────────────────────────────────────────────────────
//  先介绍：让"调用方"不必认识"实现方"
// ─────────────────────────────────────────────────────
//
// 要写一段代码，把一批图形逐个描述出来。不知道图形都有哪些时，你只能一个个问：
//
//     foreach (var g in 们)
//         if (g is 圆) { ... }
//         else if (g is 矩形) { ... }
//         else if (g is 三角形) { ... }      // ← 每加一种就要回来改这里
//
// 它跟"到底有哪些图形"死死绑在一起：**明天加个三角形，它就得改。**
//
// 接口把这件事翻过来：
//
//     interface 图形 { double 面积(); string 名字(); }
//
//     foreach (var g in 们)
//         Console.WriteLine($"{g.名字()} 面积={g.面积():F2}");
//
// 这段代码**不知道**自己拿到的是圆还是矩形，它只问两件事：
// "你叫什么""你多大面积"，每个类自己回答。
//
//   ⇒ 明天加一个"三角形"，这段代码**一个字都不用改**。
//     这就是接口的价值：**调用方与实现方解耦**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 接口：一份"必须会做什么"的清单
//
//     interface 图形 { double 面积(); string 名字(); }
//
//   ⚠ 接口里**只写声明**（签名后面直接一个分号），不写实现，也不写 public ——
//     接口成员默认就是公开的。
//
// ② 实现接口：用 `:`（C# 没有 Java 的 implements 关键字）
//
//     class 圆 : 图形
//     {
//         private readonly double 半径;
//         public 圆(double 半径) { this.半径 = 半径; }
//         public double 面积() => 3.14159 * 半径 * 半径;
//         public string 名字() => "圆";
//     }
//
//   ⚠ 实现出来的两个方法**必须写 public**，少了编译器直接拦住。
//   ⚠ `this.半径 = 半径;` 用来区分"字段"和"同名参数"。
//
// ③ 继承：复用已经写好的类
//
//     class 矩形 : 图形
//     {
//         protected readonly double 宽, 高;
//         public 矩形(double 宽, double 高) { this.宽 = 宽; this.高 = 高; }
//         public virtual double 面积() => 宽 * 高;      // virtual = 允许子类改写
//         public virtual string 名字() => "矩形";
//     }
//
//     class 正方形 : 矩形                                // 正方形**是**一种矩形
//     {
//         public 正方形(double 边长) : base(边长, 边长) { }   // 边长同时当宽和高
//         public override string 名字() => "正方形";          // 只改写名字
//     }
//
//   `virtual` / `override` 是一对：基类说"这个方法可以被改写"，
//   子类说"我改写它"。基类少了 `virtual`，子类的 `override` 就编译不过。
//
// ④ 多态：同一行调用，各做各的
//
//     var 们 = new List<图形> { new 圆(1), new 矩形(3, 4), new 正方形(5) };
//     foreach (var g in 们) Console.WriteLine($"{g.名字()} / {g.面积():F2}");
//
//     ⇒ 圆 / 3.14      矩形 / 12.00      正方形 / 25.00
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：实现接口时忘了写 public
//
//     class 圆 : 图形 { double 面积() => 1;  public string 名字() => "圆"; }
//     //                 ↑ 少了 public
//
// 你会看到：error CS0737: “学生代码.圆”不实现接口成员“学生代码.图形.面积()”。
//          “学生代码.圆.面积()”无法实现接口成员，因为它不是公共的。
// 为什么：接口成员默认公开，实现也必须公开；C# 里不写修饰符 = 最窄的可见性。
// ⇒ 实现接口的方法**全都加 public**。
//
// ⚠ 坑 2：漏实现一个成员
//
//     class 圆 : 图形 { public double 面积() => 1; }      // 名字() 没写
//
// 你会看到：error CS0535: “学生代码.圆”不实现接口成员“学生代码.图形.名字()”
// 为什么：接口是**一份完整清单**，签了就得全做到。
//
// ⚠ 坑 3：类声明忘了写 `: 图形`
//
//     class 圆 { public double 面积() => 1; public string 名字() => "圆"; }
//     // 而用到它的地方写的是： new List<图形> { new 圆(1) }
//
// 你会看到：error CS0266: 无法将类型“学生代码.圆”隐式转换为“学生代码.图形”。存在一个显式转换(是否缺少强制转换?)
// 为什么：方法名字一样**不等于**实现了接口 —— 继承关系必须写明。
//
// ⚠ 坑 4：改写一个没标 virtual 的方法
//
//     class 矩形 { public string 名字() => "矩形"; }          // 没有 virtual
//     class 正方形 : 矩形 { public override string 名字() => "正方形"; }
//
// 你会看到：error CS0506: “学生代码.正方形.名字()”: 继承成员“学生代码.矩形.名字()”未标记为 virtual、abstract 或 override，无法进行重写
// 为什么：基类没允许被改写。⇒ 要让子类能改写，基类那个方法必须写 `virtual`。
//
// ⚠ 坑 5：忘了调基类构造
//
//     class 正方形 : 矩形 { public 正方形(double 边长) { } }   // ← 没告诉矩形宽和高
//
// 你会看到：error CS7036: 未提供与“学生代码.矩形.矩形(double, double)”的所需参数“宽”对应的参数
// 为什么：子类构造时会先构造基类那部分，而矩形的构造函数要求两个参数。
// ⇒ 写 `: base(边长, 边长)`。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
//   把骨架填完整（接口、三个类、一个方法都给你了）：
//
//     1. interface 图形          double 面积();  string 名字();
//     2. class 圆     : 图形      构造拿半径；面积 = 3.14159 × 半径 × 半径
//     3. class 矩形   : 图形      构造拿宽高；面积 = 宽 × 高；两个方法加 virtual

//     圆(1) → 圆 / 3.14     矩形(3,4) → 矩形 / 12.00     正方形(5) → 正方形 / 25.00
//     报告([正方形(2), 圆(2)]) 里要同时出现"正方形"和"圆"，面积是 4.00 和 12.57
