## 第 09 课：元组、结构与记录类型 —— 值语义 vs 引用语义

### 要求

1. 定义 `struct 分数 { public int 得分; }`，写 `static 分数 数值改不掉(分数 s)` —— 里面写 `s.得分 = 90;` 然后 `return s;`
2. 定义记录类型 `record 成绩记录(string 名字, int 分数);`，写 `static (string 名字, bool 及格) 取名字(成绩记录 r)` —— 及格是 `分数 >= 60`
3. 定义 `static (int 最低, int 最高) 取最高最低(int[] 数们)` —— 数组为空时返回 `(0, 0)`

### 讲解

```
// 第 09 课：元组、结构与记录类型 —— 值语义 vs 引用语义
//
// ══ 先介绍：这一课要拆掉一个几乎所有 C# 新手都有的错误直觉 ══
//
//   你在第 07 课写过 class。从那一课起，脑子里大概有了个印象：
//
//       把东西传给方法，方法改了它，外面就跟着变。
//
//   这个印象**只对一半的类型成立**。C# 的类型分两族，赋值与传参的行为完全不同：
//
//      值类型（value type）：  int / double / bool / struct / record struct
//      引用类型（reference type）：class / record / string / 数组 / List<T> / 接口
//
//   区别的根源就一句话：
//
//      **变量里装的是"值本身"，还是"东西在哪里的地址"。**
//
//   值类型变量装的就是数据本身 —— 所以复制变量 = 复制整份数据。
//   引用类型变量装的是地址 —— 所以复制变量 = 复制地址，两个名字指向**同一个对象**。
//
//   这一课你会发现：`struct` 和 `record` 都能改一个东西的两个名字是否互相影响，
//   而选错会写出"方法里改了、外面没变"这种**不报错、只出错**的 bug。
//
//
// ══ 一、值语义 vs 引用语义：一次看明白 ══
//
//   ┌─ 值类型：赋值 = 复印一份 ────────────────────────────┐
//
//       struct 分数 { public int 得分; }
//
//       分数 a = new 分数();
//       a.得分 = 80;
//       分数 b = a;            // ← 复印：b 是**另一份**数据
//       b.得分 = 50;
//       Console.WriteLine(a.得分);   // 80   ← a 没被影响
//       Console.WriteLine(b.得分);   // 50
//
//   └──────────────────────────────────────────────────────┘
//
//   ┌─ 引用类型：赋值 = 又抄了一个地址 ────────────────────┐
//
//       class 成绩单 { public int 得分; }
//
//       成绩单 a = new 成绩单();
//       a.得分 = 80;
//       成绩单 b = a;          // ← 变量里那份**地址**被复制
//       b.得分 = 50;
//       Console.WriteLine(a.得分);   // 50   ← a 也变了！同一个对象
//
//   └──────────────────────────────────────────────────────┘
//
//   把这张对照表记牢，这一课就过了一半：
//
//       int / double / bool / char / 枚举 / struct / record struct
//                                        ⇒ 赋值、传参都**复制**
//
//       string / 数组 / List<T> / class / record / 接口 / 委托
//                                        ⇒ 赋值、传参都只**复制地址**
//
//   ⚠ string 是引用类型，但它有个额外特性：**不可变**。
//     你以为在"改"字符串，其实每次都造了一个新串。所以它表现得像值类型。
//
//   ⚠ record **默认是引用类型**（`record 名字(...)` 等价于 `record class`）。
//     想要值语义得写 `record struct 名字(...)`。
//     这是最容易记反的一处：record ≠ 值类型，record **只是相等语义是值语义**。
//
//
// ══ 二、那"值语义"到底在哪里咬人？ ══
//
//   不在赋值上 —— 赋值写错了编译器不管，但你自己看得见。
//   咬人的地方是**传参**：方法拿到的是一个副本，改了不影响调用者。
//
//       struct 分数 { public int 得分; }
//
//       static void 加分(分数 s)          // s 是**副本**
//       {
//           s.得分 += 10;                 // ✅ 编译通过
//       }
//
//       var 甲 = new 分数();
//       甲.得分 = 80;
//       加分(甲);
//       Console.WriteLine(甲.得分);       // 还是 80 ❗
//
//   ⚠⚠ 注意这个 bug 的**症状**：**不报错、不警告，方法里那句 `+= 10` 是合法的，
//      编译器只是默默改了一个马上要被扔掉的副本。**
//      你盯着代码看不出问题，只有打印出来才发现数字没变。
//
//   想真的改到外面，只能把"改好的整份"**返回**出去（这一课要写的 `数值改不掉`
//   就是这个演示 —— 返回值里有 90，但外面那个变量纹丝不动）。
//
//
// ══ 三、struct / record / class：三个都写"数据"，怎么选？ ══
//
//   ① `class`  —— 有身份的东西
//        人、订单、连接、窗口…… 两个"内容一样"的订单仍然是**两个**订单。
//        默认比较是"是不是同一个对象"（引用相等）。
//
//   ② `record`（引用类型）—— 一张**内容说了算**的纸
//        一条成绩记录、一个坐标、一条日志行、一个 API 返回值。
//        内容一样就是相等：
//
//            var a = new 成绩记录("甲", 90);
//            var b = new 成绩记录("甲", 90);
//            Console.WriteLine(a == b);      // True  ← 逐字段比内容
//            Console.WriteLine(a.Equals(b)); // True
//
//        如果是 `class`，同样的两行会打印 **False**（比的是地址）。
//
//        ⚠ 还有两个白送的好处：
//           · `ToString()` 自动是 `成绩记录 { 名字 = 甲, 分数 = 90 }` 这种能读的样子
//             （class 默认是 "类型名"，打印出来毫无信息）
//           · `with` 表达式能"改一个字段、其余照抄"：
//                 var 乙 = a with { 分数 = 60 };   // 新对象，a 不变
//
//   ③ `struct`（值类型）—— 一小把数字，**并且你明确要值语义**
//        · 字段少（官方建议 ≤ 16 字节左右，别塞 List 和 string 进去）
//        · 生命周期短、数量多（坐标、颜色、范围）
//        · 你**希望**复制是独立的
//
//   ⚠ 选错的代价不对称：
//      · 该用 record 却用了 class ⇒ 相等判断悄悄变成"比地址"，去重/查找全失效
//      · 该用 class 却用了 struct ⇒ 传参开始复制，改一处不生效（上面那个 bug）
//      两样都不报错。⇒ **拿不准就先用 class 或 record**，struct 留给"我很确定"的场合。
//
//
// ══ 四、元组：不想为"就这两个值"专门造一个类型 ══
//
//   方法只能 return 一个值。以前你要么写个 out 参数，要么专门定义一个类。
//   元组让"一次交回两个结果"变成一行：
//
//       static (int 最低, int 最高) 取最高最低(int[] 数们)
//       {
//           int 低 = 数们[0], 高 = 数们[0];
//           for (int i = 1; i < 数们.Length; i++)
//           {
//               if (数们[i] < 低) 低 = 数们[i];
//               if (数们[i] > 高) 高 = 数们[i];
//           }
//           return (低, 高);
//       }
//
//   定义处写 `(int 最低, int 最高)`，返回处写 `(低, 高)` —— 位置一一对应。
//
//   接的时候两种写法：
//
//       var 一对 = 取最高最低(数们);
//       Console.WriteLine(一对.最低);        // ← 有名字，.名字 取
//
//       var (低, 高) = 取最高最低(数们);      // ← 解构，一次拆成两个变量
//
//   ⚠ 元组是**值类型**（`ValueTuple`），所以它也是复制语义。
//   ⚠ 元组适合"两三个值、就地用完就扔"。超过三四个，或者它要在
//     好几个方法之间传来传去 ⇒ **给它起个名字，用 record**。
//     满屏的 `(int, string, double, bool)` 三周后没人看得懂。
//
//
// ══ 五、常见坑 ══
//
//   坑 1：以为改了 struct 参数，外面就变了
//
//       static void 加分(分数 s) { s.得分 += 10; }
//       加分(甲);
//       Console.WriteLine(甲.得分);    // 80，不是 90
//
//     症状：方法里改了，打印出来没变，也不报任何错。
//     为什么：struct 是按值传参，方法里的 `s` 是一个**副本**。
//     改法：返回值带出来（`return s;`），或者参数写 `ref 分数 s`
//           （`ref` 是第 05 课学的，它绕过复制）。
//
//   坑 2：以为 `record` 是值类型，也以为它传参不会共享
//
//       record 成绩记录(string 名字, int 分数);
//
//       static void 改(成绩记录 r) { r.分数 = 100; }   // ❌ 编译不过
//
//     症状：`error CS0200: 属性或索引器"成绩记录.分数"不能分配给 —— 它是只读的`。
//     为什么：位置式 record 自动生成的是 `{ get; init; }` 属性，
//           **只有 init，没有 set** ⇒ 构造完了就不能再赋值。
//     要改只能造一个新的：`var 新 = r with { 分数 = 100 };`
//
//     还有一层：record 本身是**引用类型**，`r` 参数确实是共享的 ——
//     但它的属性不允许你写，所以这个"共享"反而害不到你。
//     别把"相等是值语义"和"传参是值语义"混成一句话记。
//
//   坑 3：相等判断选错了类型，`Contains` / `==` / `Distinct` 悄悄失灵
//
//       class 成绩记录 { public string 名字; public int 分数; }   // 本该用 record
//       var 表 = new List<成绩记录> { new 成绩记录{名字="甲",分数=90} };
//       Console.WriteLine(表.Contains(new 成绩记录{名字="甲",分数=90}));  // False
//
//     症状：明明"一样"的两条，去重去不掉、查查找不到。
//     为什么：class 的 == 和 Equals 默认比**地址**；两条是不同对象 ⇒ False。
//     改法：类型改成 `record`（或 `record struct`），相等自动逐字段比。
//
//   坑 4：把元组的名字当成了类型的一部分
//
//       static (int 最低, int 最高) 取最高最低(int[] 数们) { ... }
//       var 一对 = 取最高最低(数们);
//       Console.WriteLine(取最高最低(数们).最小);   // ❌ 编译不过
//
//     症状：`error CS1061: "ValueTuple<int, int>" 未包含"最小"的定义`。
//     为什么：`(int 最低, int 最高)` 和 `(int 甲, int 乙)` 是**同一个类型**，
//           名字只是给编译器和你自己看的标签，跟着**定义那一处**走。
//
//   坑 5：数组为空时去读 `数们[0]`
//
//       int 低 = 数们[0];        // 空数组 ⇒ IndexOutOfRangeException
//
//     症状：传进空数组就崩，报 `System.IndexOutOfRangeException`。
//     为什么：`数们[0]` 在长度为 0 的数组上根本没有那个格子。
//     改法：开头先 `if (数们.Length == 0) return (0, 0);`
//          —— 初值也从 `数们[0]` 起（不要写 `int 低 = 0;`，
//          那在全负数时会返回 0，跟第 16 课 C 里那个坑一模一样）。
//
//
// ══ 轮到你了 ══
//
//   写三样东西（都在下面，不用写 Main、不用写 class Program）：
//
//     1. struct 分数 { public int 得分; }
//        再加  static 分数 数值改不掉(分数 s)
//            里面 `s.得分 = 90;` 然后 `return s;`
//        —— 这个函数的**返回值**是 90，而调用者的变量应该一点没变。
//
//     2. record 成绩记录(string 名字, int 分数);
//        再加  static (string 名字, bool 及格) 取名字(成绩记录 r)
//            及格 = `r.分数 >= 60`
//
//     3. static (int 最低, int 最高) 取最高最低(int[] 数们)
//            数组为空返回 (0, 0)；否则返回最小和最大
//
// ⚠ record 那一行**末尾有分号**（是"位置式 record"的简写），
//   写成带 `{ }` 的完整形式也行。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 09
```

### 参考答案

```csharp
// ── 1. struct：值语义 ──
struct 分数
{
    public int 得分;
}

static 分数 数值改不掉(分数 s)
{
    // ⚠ 这里改的是**副本** —— 编译器不报错，但调用者的变量不会变
    s.得分 = 90;
    return s;
}

// ── 2. record：内容说了算的相等 ──
record 成绩记录(string 名字, int 分数);

static (string 名字, bool 及格) 取名字(成绩记录 r)
{
    // ⚠ 位置式 record 的属性是 { get; init; }，不能写 r.分数 = ...
    return (r.名字, r.分数 >= 60);
}

// ── 3. 元组：一次交回两个结果 ──
static (int 最低, int 最高) 取最高最低(int[] 数们)
{
    // ⚠ 空数组要特判，否则 数们[0] 直接 IndexOutOfRangeException
    if (数们.Length == 0)
    {
        return (0, 0);
    }

    // ⚠ 初值从第一个元素起 —— 写 0 的话全负数就错了
    int 低 = 数们[0];
    int 高 = 数们[0];
    for (int i = 1; i < 数们.Length; i++)
    {
        if (数们[i] < 低) 低 = 数们[i];
        if (数们[i] > 高) 高 = 数们[i];
    }
    return (低, 高);
}
```

### 检查规格

```
record 类型真的写了 | 代码包含 | record 成绩记录
struct 类型真的写了 | 代码包含 | struct 分数
数值改不掉：返回值是 90，且那个字段是 int | 函数用例 | 数值改不掉 | new 分数 { 得分 = 80 } | (90, int)
取名字：及格线 60 两边都要对 | 函数用例 | 取名字 | new 成绩记录("甲", 60) | (甲, True) | new 成绩记录("乙", 59) | (乙, False)
取最高最低：多组都对，含全负数与单元素 | 函数用例 | 取最高最低 | new int[]{3,1,4,1,5} | (1, 5) | new int[]{-5,-1,-9} | (-9, -1) | new int[]{7} | (7, 7) | new int[]{0,0} | (0, 0)
```

> 给编写检查的人：`数值改不掉` 那条也可以换成一个更能说明问题的两段调用 ——
> `var __甲 = new 分数 { 得分 = 80 }; var __回 = 数值改不掉(__甲); Console.WriteLine(__回.得分 + ":" + __甲.得分);`
> 期望输出 `90:80`，一句话就把"返回值变了、外面没变"钉死。

## 第 10 课：属性与访问控制 —— 字段为什么不该是 public

### 要求

1. 写 `class 学生`：构造器 `public 学生(string 名字, int 成绩)`，属性 `public string 名字 { get; }`、`public int 成绩 { get; private set; }`，方法 `public void 改成绩(int 分)` —— 分不在 0~100 之间就**什么都不做**；`public string 报告()` 返回 `"名字 成绩"` 一行
2. 写 `class 计数器`：属性 `public int 值 { get; private set; }`，方法 `public void 加(int n)`、`public void 设为(int v)`（v 为负数时不做任何事）、`public void 重置()`
3. 两个类里都要有一条 `readonly` 字段

### 讲解

```
// 第 10 课：属性与访问控制 —— 字段为什么不该是 public
//
// ══ 先介绍：从"谁都能改"到"只有我能改" ══
//
//   第 07 课你已经把数据和行为关在一起了。但那时候你多半是这么写的：
//
//       class 学生
//       {
//           public string 名字;
//           public int 成绩;          // ← public 字段：外面随便写
//       }
//
//       var 甲 = new 学生();
//       甲.成绩 = -999;               // ✅ 编译通过 —— 但这是垃圾数据
//       甲.成绩 = 99999;              // ✅ 也通过
//
//   问题不在"能不能写"，而在**没有任何地方能拦住它**。
//   等到某天要统计平均分，你拿到一堆 -999，回头去查是谁写的 —— 无处可查，
//   因为每一个 `甲.成绩 = ...` 都是一个合法的写入点。
//
//   属性（property）解决的正是这件事：
//
//       class 学生
//       {
//           public int 成绩 { get; private set; }   // 外面只能读
//
//           public void 改成绩(int 分)
//           {
//               if (分 < 0 || 分 > 100) return;     // ← 唯一入口，唯一的规则
//               成绩 = 分;
//           }
//       }
//
//   ⇒ 这就是**封装**：不是"藏起来让你看不见"，而是让
//     **规则只有一个出口**。想把成绩改成 -999？做不到。
//
//
// ══ 一、属性 vs 字段：写起来像字段，其实是方法 ══
//
//   最简形式（自动实现属性，最常用）：
//
//       public string 名字 { get; set; }              // 可读可写
//       public string 名字 { get; }                    // 只读：只有构造器能赋
//       public int 成绩 { get; private set; }          // 外人能读，本类能写
//       public int 值 { get; init; }                   // 只能在**创建时**写
//
//   编译器在背后给你造了一个隐藏字段 + 两个方法（get_名字 / set_名字）。
//   所以 `甲.成绩` 用起来像字段，其实是**调用了一个方法** —— 这正是它能带逻辑的原因。
//
//   想亲手写逻辑时，用完整形式：
//
//       private int 成绩_存;                            // 私有字段，外面看不见
//       public int 成绩
//       {
//           get { return 成绩_存; }
//           set
//           {
//               if (value < 0 || value > 100)             // value = 即将写入的值
//                   throw new ArgumentOutOfRangeException(nameof(value));
//               成绩_存 = value;
//           }
//       }
//
//   `value` 是 setter 里的**关键字**（不是你自己起的名字），表示"外面想写进来的那个值"。
//
//   ⚠ 什么时候用哪种：
//     · 不需要校验、不需要计算 ⇒ **自动属性** `{ get; set; }`，别自己造字段
//     · 需要校验、需要惰性计算、需要触发别的动作 ⇒ 完整形式
//
//
// ══ 二、访问修饰符：默认值是什么？ ══
//
//       public      谁都能访问
//       private     只有**本类内部**能访问          ← 类成员的默认值！
//       protected   本类 + 派生类能访问
//       internal    同一个程序集（同一个项目）能访问  ← **顶层类型**的默认值
//       protected internal / private protected      组合，用到再说
//
//   ⚠⚠ 两个默认值必须记牢，它们相反：
//        **类里面的成员（字段/方法/属性）默认是 `private`**
//        **顶层的 class / struct / record / interface 默认是 `internal`**
//
//     症状 1：只写 `int 成绩;` 不写 public，从外面 `甲.成绩` 会报
//             `error CS0122: "学生.成绩"不可访问，因为它具有一定的保护级别`。
//     症状 2：只写 `class 学生`，别的项目引用你这个库时找不到它 ——
//             因为它是 internal，出了这个程序集就没了。
//     ⇒ 想给外面用，**必须显式写 public**。
//
//   ⚠ 别给什么都加 public。判断标准很简单：
//     "这个成员是不是这个类的**对外承诺**？" 不是 ⇒ 私有。
//
//
// ══ 三、`readonly`：给"不该变的字段"上锁 ══
//
//   `readonly` 只能用在**字段**上（不能用在属性上，也不能用在局部变量上）：
//
//       class 银行账户
//       {
//           private readonly string 账号;        // 开户时定了就不许再改
//           public 银行账户(string 账号) { this.账号 = 账号; }
//       }
//
//   规则：**只能在声明处或构造器里赋值**，之后任何地方再写 `账号 = ...`
//        都是 `error CS0191: 只读字段不能作为赋值目标（除非在构造函数中）`。
//
//   ⚠ 三个容易混的：
//     · `readonly` 字段   —— 运行期不能改，但**值可以是运行时才知道的**
//                            （比如构造器参数）
//     · `const`           —— 编译期就定死，必须写死一个字面量，
//                            而且**自动是 static**，只能配基本类型和 string
//     · `readonly` 修饰引用类型的字段 ⇒ 锁的是"指向哪个对象"，
//                            **不是对象内容**！`readonly List<int> a` 里
//                            照样可以 `a.Add(1)`。
//
//   ⚠ 和 `{ get; }` 属性的区别：
//     · `{ get; }` 外面能读，不能写           ← 给外人看的只读
//     · `readonly` 字段 外面连读都读不到（除非你自己加个属性暴露出去）
//     ⇒ 通常成对用：私有 readonly 字段 + 公开的 `{ get; }` 属性。
//
//
// ══ 四、`required` 与 `init`（现代 C# 的"必须填"）══
//
//   老写法靠构造器强制："想 new 出对象？必须把参数交齐。"
//   新写法可以让属性本身就是必填的：
//
//       class 配置
//       {
//           public required string 名字 { get; init; }
//           public int 超时秒 { get; init; } = 30;      // 有默认值，可不填
//       }
//
//       var c = new 配置 { 名字 = "主库" };              // ✅
//       var d = new 配置();                              // ❌ 编译错误
//       // error CS9035: 必须设置必需成员"配置.名字"
//
//   ⚠⚠ `required` 有一个**极其常见的连锁反应**：
//
//     一旦某个属性写成 `required`，所有 `new 配置()` 的地方都编译不过了 ——
//     包括你自己以前写的、包括测试代码。报错是
//     `error CS9035: 必须设置必需成员`。
//     所以 `required` 适合**新写的类型**；给已有类型补 `required` 之前，
//     先确认所有创建点都改得过来。
//
//   ⚠ 本课的两个类**不要求**用 required（构造器已经把必填项管住了）。
//     记住它是什么、报错长什么样就够了。
//
//
// ══ 五、常见坑 ══
//
//   坑 1：用 public 字段代替属性，规则就散掉了
//
//       class 学生 { public int 成绩; }
//       甲.成绩 = -999;
//
//     症状：程序能跑、能编译，但统计结果离谱；而且**查不出是哪儿写坏的**。
//     为什么：字段没有"入口"，任何一行赋值都直接落到数据上。
//     改法：字段改私有（或删掉换自动属性），公开一个 `{ get; private set; }`
//           + 一个带校验的方法。
//
//   坑 2：以为"自动生成的无参构造器"一直都在
//
//       class 学生 { public 学生(string 名字) { ... } }
//       var 甲 = new 学生();          // ❌ 编译不过
//
//     症状：`error CS7036: 未提供与"学生.学生(string)"的所需参数对应的实参`。
//     为什么：**只要你写了任何一个构造器，编译器就不再送你无参的那个了。**
//           这是官方专门讲过的点，很多人被它绊一次。
//     改法：要么给参数加默认值 `public 学生(string 名字 = "")`，
//          要么显式再写一个 `public 学生() { }`。
//
//   坑 3：`{ get; private set; }` 里 set 的权限记反了
//
//       public int 成绩 { get; private set; }
//       甲.成绩 = 90;                   // ❌ 编译不过
//
//     症状：`error CS0272: 属性或索引器"学生.成绩"不能用在此上下文中 --
//           set 访问器不可访问`。
//     为什么：`private set` 的意思是"**只有这个类自己**能写"，
//           **外面（包括 Main、包括检查器）都不能写** ⇒ 编译期就拦住了。
//           这正是你要的效果，只是第一次撞见会以为写错了。
//     改法：谁都别想在类外面写 —— 想要那种自由就写 `set;`，
//          但那就等于把规则又扔掉了。
//
//   坑 4：把 `readonly` 当成"字段指向的对象不能变"
//
//       private readonly List<int> 缓冲 = new List<int>();
//       缓冲.Add(1);                     // ✅ 编译通过！
//
//     症状：以为加了 readonly 就"内容也冻住了"，结果照样被改。
//     为什么：引用类型字段里装的是**地址**。readonly 锁的是这个地址
//           （不许 `缓冲 = new List<int>()`），**不是**堆上那个列表。
//     改法：要冻内容得靠 `IReadOnlyList<int>` 之类的**类型**去限制，
//           或者干脆不要暴露可变集合。
//
//   坑 5：构造器里参数名和属性名撞了，直接写 `名字 = 名字;`
//
//       public 学生(string 名字) { 名字 = 名字; }      // ❌ 什么都没干
//
//     症状：构造完了一打印，属性是 null / 0。
//     为什么：两边都写 `名字` 时，靠得近的那个（参数）胜出 ⇒ 变成
//           "把参数赋给参数"，属性压根没被碰过。
//     改法：写 `this.名字 = 名字;`，把 `this.` 明确指向字段/属性。
//
//
// ══ 轮到你了 ══
//
//   写两个类（不用写 Main）：
//
//     class 学生
//     {
//         public string 名字 { get; }               // 只读
//         public int 成绩 { get; private set; }     // 外面只读，本类能写
//         public 学生(string 名字, int 成绩)
//         public void 改成绩(int 分)   // 不在 0~100 ⇒ 什么都不做
//         public string 报告()          // "名字 成绩"
//     }
//
//     class 计数器
//     {
//         public int 值 { get; private set; }
//         public void 加(int n)
//         public void 设为(int v)       // v < 0 ⇒ 什么都不做
//         public void 重置()
//     }
//
//   ⚠ 两个类里**都要有一条 readonly 字段**（比如 `private readonly string 学号;`）。
//     只读字段必须在构造器里赋上值。
//
//   ⚠ 构造器里别写 `名字 = 名字;` —— 要写 `this.名字 = 名字;`。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 10
```

### 参考答案

```csharp
class 学生
{
    // readonly 字段：只能在声明处或构造器里赋值
    private readonly string 学号;

    public string 名字 { get; }              // 只读：外面改不了
    public int 成绩 { get; private set; }    // 外面只读，本类能写

    public 学生(string 名字, int 成绩)
    {
        this.名字 = 名字;                    // ⚠ this. 不能省 —— 否则是"参数 = 参数"
        学号 = "S-" + 名字;                  // readonly 字段在这里赋值，合法
        this.成绩 = 成绩 < 0 ? 0 : (成绩 > 100 ? 100 : 成绩);
    }

    public void 改成绩(int 分)
    {
        if (分 < 0 || 分 > 100) return;      // ⚠ 非法就什么都不做，不能先写再检查
        成绩 = 分;
    }

    public string 报告() => 名字 + " " + 成绩;
}

class 计数器
{
    private readonly int 步长;               // readonly 字段

    public int 值 { get; private set; }

    public 计数器(int 步长 = 1)
    {
        this.步长 = 步长;
        值 = 0;
    }

    public void 加(int n) => 值 += n * 步长;

    public void 设为(int v)
    {
        if (v < 0) return;                   // ⚠ 负数直接拒绝，值保持不变
        值 = v;
    }

    public void 重置() => 值 = 0;
}
```

### 检查规格

```
两个公开属性都写成属性而不是字段 | 代码包含 | { get;
成绩的 set 是私有的 | 代码包含 | private set
用了 readonly 字段 | 代码包含 | readonly
学生：非法分数被拒绝，合法分数生效 | 连调用 | 学生 | new 学生("甲", 70).报告() | "甲 70" | new 学生("甲", 70).改成绩(999).报告() | "甲 70"
计数器：加 / 设为 / 重置 串起来都对 | 连调用 | 计数器 | new 计数器(1).值 | "0" | new 计数器(1).加(3).值 | "3"
```

> 给编写检查的人：`连调用` 的「第 N 次」格子是**表达式文本**，检查器会把它包进
> `Console.WriteLine(...)` 再比字符串。所以 `new 学生("甲", 70).报告()` 要能当表达式用 ——
> 学员的 `报告()` 若写成返回 `string` 就没问题；若他写成 `void 报告()` 打印，这条会编译不过，
> 那正好也是一条有效反馈。

## 第 11 课：`virtual` / `override` / `new` —— 覆写与隐藏不是一回事

### 要求

1. 写 `class 动物`：构造器 `public 动物(string 名字)` 把名字存进 `public string 名字 { get; }`，`public virtual string 叫声()` 返回 `"..."`，`public string 介绍()` 返回 `"名字 说 叫声"`
2. 写 `class 狗 : 动物`：构造器 `public 狗(string 名字) : base(名字)`，用 `sealed override` 写 `叫声()` 返回 `"汪汪"`；再写 `class 玩具狗 : 狗`，用 `new` 隐藏叫声（返回 `"玩具叫"`）
3. 写 `class 汽车`：`public string 品牌 { get; }`、`public int 最高速 { get; }`，构造器 `public 汽车(string 品牌, int 最高速)`；再写 `class 跑车 : 汽车`，构造器 `public 跑车(string 品牌, int 最高速, int 零百加速) : base(品牌, 最高速)`，属性 `public int 零百加速 { get; }`，方法 `public string 简介()` 返回 `"品牌 最高速 零百加速"`

### 讲解

```
// 第 11 课：virtual / override / new —— 覆写与隐藏不是一回事
//
// ══ 先介绍：多态是怎么生效的 ══
//
//   第 08 课你让三个图形共用一套调用。那时候你可能没细想：
//   `g.面积()` 里的 `g` 是接口类型，为什么能调到"圆"的实现？
//
//   答案在**方法分派**上。C# 里方法有两种绑定时机：
//
//     编译时绑定：看**变量的类型**，定死调哪个方法
//     运行时绑定：看**对象的实际类型**，到运行时才决定调哪个
//
//   C# 的默认是**编译时绑定**。`virtual` 是唯一把某个方法切换到
//   运行时绑定的开关 —— 而 `override` 是"我要接这个开关"。
//
//   ══ 三个词各管什么 ══
//
//     `virtual`   写在**基类**：这个方法允许被改写
//     `override`  写在**派生类**：我要改写它，并且保持"看实际类型"
//     `new`       写在**派生类**：我要**换一个同名方法**，跟基类那个没关系
//
//   关键在于 `new` 和 `override` 的差别 —— 这一个字的差别，
//   决定了"通过基类类型调用时，到底跑哪一个"。
//
//
// ══ 一、最小对照实验：这一课的全部内容都在这 12 行里 ══
//
//       class 动物
//       {
//           public virtual string 叫声() => "...";
//       }
//
//       class 狗 : 动物
//       {
//           public override string 叫声() => "汪汪";     // 覆写
//       }
//
//       class 玩具狗 : 狗
//       {
//           public new string 叫声() => "玩具叫";         // 隐藏
//       }
//
//   现在把两种东西都当成"动物"来用，调同一个 `叫声()`：
//
//       动物 a1 = new 狗("旺财");
//       动物 a2 = new 玩具狗("小玩具");
//
//       Console.WriteLine(a1.叫声());   // 汪汪     ← override 生效
//       Console.WriteLine(a2.叫声());   // ...      ← ❗ new 不生效！
//
//   ⚠⚠ `a2` 那里是 `...`（狗从动物继承来的实现），不是 `玩具叫`。
//
//   为什么：`new` **没有**接上运行时绑定。编译器看到 `a2` 的**声明类型**
//   是 `动物`，就定死调 `动物.叫声()` —— 运行时根本不去问对象到底是什么。
//
//   想真的调到"玩具叫"，得把变量声明成 `玩具狗`：
//
//       玩具狗 t = new 玩具狗("小玩具");
//       Console.WriteLine(t.叫声());   // 玩具叫    ← 编译时看到的是玩具狗
//
//   ⇒ 一句话记法：
//
//       **override 是"换掉实现"，new 是"另起一个同名的方法"。**
//
//   再来一个更刺眼的对照 —— 同一个对象，两种声明方式，两种结果：
//
//       玩具狗 t = new 玩具狗("小玩具");
//       Console.WriteLine(t.叫声());             // 玩具叫
//       Console.WriteLine(((动物)t).叫声());     // ...     ← 把地址"看成"动物，就变了
//
//   注意：**对象从头到尾只有一个**。变的只是"编译器允许你看见哪个方法"。
//
//
// ══ 二、什么时候该用哪个？ ══
//
//   · 派生类想**改变行为**、而且希望"外面用基类类型调用时也生效"
//       ⇒ `override`（前提：基类那个方法标了 `virtual` / `abstract`）
//
//   · 基类的方法**没有**标 virtual，你就是想提供一个同名的新方法
//       ⇒ 编译器会逼你写 `new`（不写只是警告 `CS0108`，但一定要写）
//       ⚠ 这种"隐藏"通常是**设计事故的信号**：先问一句
//         "是不是该回基类加 virtual？"
//
//   · 想彻底禁止别人继续覆写
//       ⇒ 在 override 上加 `sealed`：
//            public sealed override string 叫声() => "汪汪";
//          这样 `玩具狗 : 狗` 再写 `override 叫声()` 会报
//            `error CS0239: "玩具狗.叫声()": 无法重写继承成员"狗.叫声()"，
//             因为它已密封`
//          —— 本课的玩具狗因此只能用 `new`。
//
//   ⚠ `sealed` 也可以整个加在类上（`sealed class 玩具狗`），
//     意思是"这个类不许被继承"。那和 `sealed override` 是两回事。
//
//
// ══ 三、构造器链 `: base(...)` ══
//
//   派生类**从来不继承构造器**。你必须自己写一个，并且负责把基类需要的东西递上去。
//
//       class 汽车
//       {
//           public string 品牌 { get; }
//           public int 最高速 { get; }
//           public 汽车(string 品牌, int 最高速)
//           {
//               this.品牌 = 品牌;
//               this.最高速 = 最高速;
//           }
//       }
//
//       class 跑车 : 汽车
//       {
//           public int 零百加速 { get; }
//
//           public 跑车(string 品牌, int 最高速, int 零百加速)
//               : base(品牌, 最高速)            // ← 这一行把前两个参数交上去
//           {
//               this.零百加速 = 零百加速;        // ← 然后才轮到自己的
//           }
//       }
//
//   ⚠⚠ **`: base(...)` 是这个顺序里的第一步，永远在派生类构造器体之前跑。**
//     所以派生类构造器里能安全地读基类的属性（因为那时候基类已经初始化好了）。
//
//   ⚠⚠ 忘了写 `: base(...)` 会怎样？**不是运行时出错，是编译不过**：
//
//       跑车(string 品牌, int 最高速, int 零百加速) { ... }
//       // error CS7036: 未提供与"汽车.汽车(string, int)"的所需参数
//       //               对应的实参
//
//     为什么：编译器默认帮你插一句 `: base()`（**无参**的），
//           而 `汽车` 只有带参数的构造器 ⇒ 找不到无参的那个 ⇒ 编译失败。
//     什么时候能省：基类**有**无参构造器时（比如你自己写了一个，
//           或者基类一个构造器都没写、编译器送了它一个无参的）。
//
//   ⚠ 每一步顺序（背下来，报错时对得上号）：
//       ① 派生类的**字段初始化器**（`public int x = 5;`）
//       ② 基类构造器（`: base(...)`，它会递归地继续往上）
//       ③ 派生类构造器的**函数体**
//
//
// ══ 四、常见坑 ══
//
//   坑 1：该写 override 却写了 new ⇒ 变成隐藏
//
//       class 狗 : 动物 { public new string 叫声() => "汪汪"; }
//       动物 a = new 狗("旺财");
//       Console.WriteLine(a.叫声());        // ...
//
//     症状：派生类自己的测试全过，但**别人拿着基类类型一调用就变回基类行为**；
//           而且**不报错**（最多一条 `CS0108` 警告让你加 new）。
//     为什么：new 不会接上运行时绑定，编译时按声明类型定死。
//     改法：把 `new` 改成 `override`。若编译器说"没有可重写的成员"，
//           说明基类那个方法没标 `virtual` —— 回基类补上。
//
//   坑 2：基类漏写 `virtual`
//
//       class 动物 { public string 叫声() => "..."; }        // 忘了 virtual
//       class 狗 : 动物 { public override string 叫声() => "汪汪"; }
//
//     症状：`error CS0506: "狗.叫声()": 无法重写继承成员"动物.叫声()"，
//           因为它未标记为 virtual、abstract 或 override`。
//     为什么：`override` 需要一个"允许被改写"的基类成员，`virtual` 就是那个许可。
//     改法：基类 `public virtual string 叫声()`。
//           —— 这条报错信息本身已经把答案说出来了，照着改就行。
//
//   坑 3：以为派生类会继承构造器
//
//       class 动物 { public 动物(string 名字) { ... } }
//       class 狗 : 动物 { }                    // 什么都没写
//       var d = new 狗("旺财");                 // ❌
//
//     症状：`error CS7036: 未提供与"动物.动物(string)"的所需参数对应的实参`，
//           而且报错**指向 `class 狗` 那一行**，你会以为是狗写错了。
//     为什么：狗需要一个能接收 名字 的构造器，而它一个都没有；
//           编译器送的那个是 `狗() : base()`，而 `动物` 没有无参构造器。
//     改法：给狗写 `public 狗(string 名字) : base(名字) { }`。
//
//   坑 4：在构造器里调用虚方法
//
//       class 基
//       {
//           public 基() { 初始化(); }
//           protected virtual void 初始化() { }
//       }
//       class 派 : 基
//       {
//           private readonly int[] 数据 = new int[10];
//           protected override void 初始化() { 数据[0] = 1; }   // 💥
//       }
//
//     症状：`NullReferenceException`，而且堆栈指向基类构造器那一行 ——
//           看起来完全不像自己写的代码出错。
//     为什么：基类构造器跑的时候，**派生类的字段还没初始化**（顺序见上），
//           `数据` 还是 null，而虚方法已经被派发到派生类的实现上了。
//     改法：构造器里别调虚方法；真要调，就在派生类自己构造完之后再调。
//
//   坑 5：`sealed override` 之后继续 override
//
//       class 狗 : 动物 { public sealed override string 叫声() => "汪汪"; }
//       class 玩具狗 : 狗 { public override string 叫声() => "玩具叫"; }
//
//     症状：`error CS0239: "玩具狗.叫声()": 无法重写继承成员"狗.叫声()"，
//           因为它已密封`。
//     为什么：`sealed` 的语义就是"到此为止"。
//     改法：这一课**故意**让你撞这个错，然后用 `new` 绕过去 ——
//           绕过去了也就能亲眼看到隐藏和覆写的差别了。
//
//
// ══ 轮到你了 ══
//
//     class 动物                          // 名字属性 + virtual 叫声 + 介绍
//     class 狗     : 动物                 // sealed override 叫声 → "汪汪"
//     class 玩具狗 : 狗                   // new 隐藏叫声 → "玩具叫"
//
//     class 汽车                          // 品牌 / 最高速
//     class 跑车   : 汽车                 // : base(...) + 零百加速 + 简介()
//
//   ⚠ 玩具狗必须用 `new`（因为狗的叫声是 sealed override）。
//     这正是本课要看的东西：`动物 a = new 玩具狗(...); a.叫声()` 返回的是
//     狗的实现，不是玩具狗的。
//
//   ⚠ `介绍()` 要写成 `名字 + " 说 " + 叫声()` —— 这样它调的是**虚**方法，
//     运行时按实际类型走。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 11
```

### 参考答案

    public string 名字 { get; }

    public 动物(string 名字)
    {
        this.名字 = 名字;            // ⚠ this. 不能省

    public new string 叫声() => "玩具叫";

## 第 12 课：泛型与常用集合 —— `List<T>` 与 `Dictionary<TKey,TValue>`

### 要求

1. 写 `static int 数满足<T>(List<T> 们, Func<T, bool> 条件)` —— 返回满足条件的元素个数
2. 写 `static bool 查到了(Dictionary<string, int> 表, string 键, out int 值)` —— 用 `TryGetValue`
3. 写 `static string 名次表(Dictionary<string, int> 表)` —— 按分数从高到低排，每行 `"名字 分数"`，用换行 `\n` 连接，末尾不带换行；空字典返回 `""`

### 讲解

```
// 第 12 课：泛型与常用集合 —— List<T> 与 Dictionary<TKey,TValue>
//
// ══ 先介绍：数组不够用的时候 ══
//
//   第 04 课用的是数组：长度定死，一旦建立就改不了。
//   可现实里数据是长出来的 —— 学生一个个录进来、日志一行行写进来。
//   你需要"能加、能删、能查"的容器。C# 里最常用的两个：
//
//       List<T>                       有序的一串，能增能删能按位置取
//       Dictionary<TKey, TValue>      键 → 值 的查表，按键查是**瞬间**的
//
//   `<T>` 里的 `T` 是**类型参数** —— 一个占位符，用来之前替换成真类型。
//   第 04 课你已经用过 `List<int>` 了，这一课把它和泛型本身讲透。
//
//
// ══ 一、为什么需要泛型（而不是啥都装 object 的 ArrayList）══
//
//   老 C# 只有 `ArrayList`，里面装的是 `object`，什么都塞得进去：
//
//       var 旧表 = new ArrayList();
//       旧表.Add(1);
//       旧表.Add("字符串");                 // 也让它进 —— 编译通过
//       int x = (int)旧表[1];              // 💥 运行时 InvalidCastException
//
//   两个问题：
//     ① 装进去 / 拿出来要**装箱拆箱**，慢
//     ② 类型错误要等到**运行时**才炸
//
//   泛型把这两件事都解决了：
//
//       var 新表 = new List<int>();
//       新表.Add(1);
//       新表.Add("字符串");                 // ❌ 编译不过，当场拦住
//       int x = 新表[1];                    // 不用强转，类型已知
//
//   ⇒ **泛型的价值：把类型错误从运行时提前到编译时。**
//     写 `List<int>` 之后，编译器全程知道里面只有 int，
//     所以它既能帮你拦错误，又不用装箱。
//
//
// ══ 二、List<T> 的常用操作 ══
//
//       var 名单 = new List<string>();        // 空表
//       var 数们 = new List<int> { 3, 1, 4 };  // 集合初始化器
//
//       名单.Add("甲");                        // 追加到末尾
//       名单.AddRange(new[] { "乙", "丙" });    // 一次加一串
//       名单.Insert(0, "顶");                  // 插到下标 0
//
//       名单.Count                             // ⚠ 是 Count，不是 Length
//       名单[0]                                // 按位置取（下标从 0）
//       名单[^1]                               // 最后一个（^ 是"从末尾数"）
//       名单.Contains("甲")                    // 有没有
//       名单.IndexOf("乙")                     // 第几个；没有是 -1
//
//       名单.Remove("甲");                     // 按**值**删（删第一个匹配的）
//       名单.RemoveAt(0);                      // 按**下标**删
//       名单.RemoveAll(x => x.Length > 1);      // 删掉所有满足条件的
//       名单.Clear();                          // 清空
//       名单.Sort();                           // 就地排（会改自己）
//
//   ⚠ `List<T>` 的 `Count` 是**属性**，数组的 `Length` 也是属性 ——
//     但一个叫 Count 一个叫 Length。列表用 Count，数组用 Length。
//     （List 上写 `.Length` 编译不过：
//       `error CS1061: "List<int>"未包含"Length"的定义`。）
//
//
// ══ 三、Dictionary<TKey, TValue>：按键查表 ══
//
//       var 分数表 = new Dictionary<string, int>();
//       分数表["甲"] = 90;                    // 写：键不存在就新增
//       分数表["甲"] = 95;                    // 写：键已存在就覆盖
//
//       int s = 分数表["甲"];                  // 读
//
//       Console.WriteLine(分数表.Count);        // 2
//       Console.WriteLine(分数表.ContainsKey("甲"));   // True
//
//       foreach (var 对 in 分数表)
//           Console.WriteLine(对.Key + "=" + 对.Value);
//
//   ⚠⚠ **两种取值方式，行为完全不同 —— 这是这一课最重要的坑：**
//
//       int a = 分数表["不存在的键"];              // 💥 KeyNotFoundException
//       if (分数表.ContainsKey("不存在的键"))       // ✅ 先问再取
//           int b = 分数表["不存在的键"];
//       if (分数表.TryGetValue("不存在的键", out int c))   // ✅✅ 一步到位
//           Console.WriteLine(c);
//
//     · 索引器 `表[键]`：键不存在 ⇒ **抛异常**（不是返回 null / 0）
//     · `TryGetValue`：返回 bool，找到就把值写进 out 参数
//
//   ⇒ 只要键**可能不存在**，就用 `TryGetValue`。
//     它是"查表"这个动作的标准写法，比 ContainsKey + 索引器少查一遍。
//
//   ⚠ 字典**没有顺序**。`foreach` 出来的顺序不保证是你插入的顺序，
//     也不保证每次都一样。要固定顺序 ⇒ 遍历前用 OrderBy 排一下。
//
//   ⚠ 键不能是 null，也必须是"可做哈希"的：
//     用自定义的 class 当键时，它默认按**引用**比较 ⇒ 内容一样的两个对象
//     是两个不同的键。要用内容当键 ⇒ 用 `record`（第 09 课），
//     它自带逐字段的相等与哈希。
//
//
// ══ 四、泛型方法：自己写一个 `<T>` ══
//
//   方法名后面加上 `<T>`，`T` 就成了这个方法里的一个"类型占位符"：
//
//       static int 数满足<T>(List<T> 们, Func<T, bool> 条件)
//       {
//           int 计 = 0;
//           foreach (var 项 in 们)
//               if (条件(项)) 计++;          // 条件 是个"收 T、返回 bool"的函数
//           return 计;
//       }
//
//   用的时候编译器**自己推断** T：
//
//       var 数们 = new List<int> { 1, 2, 3, 4 };
//       Console.WriteLine(数满足(数们, n => n % 2 == 0));      // 2
//
//       var 名单 = new List<string> { "甲", "乙丙" };
//       Console.WriteLine(数满足(名单, s => s.Length == 1));   // 1
//
//   同一份代码，`T` 分别变成了 `int` 和 `string` —— 这就是泛型。
//
//   `Func<T, bool>` 是"**收一个 T，返回一个 bool** 的函数"的类型
//   （`Func<...>` 的最后一个是返回类型；不收参数用 `Action`）。
//   第 08 课你写的接口是"一个对象的契约"，`Func` 是"一个函数的契约"。
//
//   ⚠ 泛型约束 `where`：想在泛型里**用** T 的某个能力，就得先声明它有那个能力。
//
//       static T 取大的<T>(T a, T b) where T : IComparable<T>
//       {
//           return a.CompareTo(b) >= 0 ? a : b;      // ← 有约束才敢调 CompareTo
//       }
//
//     常见的几个：
//       where T : class            必须是引用类型
//       where T : struct           必须是值类型
//       where T : new()            必须有无参构造器（才能写 new T()）
//       where T : 基类名 / 接口名    必须继承自它
//
//     不加约束时，编译器只知道 T 是"某个类型" —— 你连 `a > b` 都写不了，
//     报错是 `error CS0019: 运算符">"无法应用于"T"和"T"类型的操作数`。
//     这不是刁难：泛型代码要为**所有** T 成立，而 T 可能是没有 `>` 的类型。
//
//   ⚠ 约束**不能**写成"随便哪个类型"之外的运行时检查 ——
//     `where T : int` 这种是写不了的（int 是密封值类型，没意义）。
//
//
// ══ 五、常见坑 ══
//
//   坑 1：用 `表[键]` 去查一个可能不存在的键
//
//       var 表 = new Dictionary<string, int> { ["甲"] = 90 };
//       Console.WriteLine(表["乙"]);          // 💥
//
//     症状：`System.Collections.Generic.KeyNotFoundException:
//           给定关键字不在字典中`，程序直接终止。
//     为什么：索引器的语义是"**给我这个键的值**"，键不在就只能报错 ——
//           它没法凭空返回一个值（int 的"没有"是什么？0 吗？那和真的 0 混了）。
//     改法：`表.TryGetValue("乙", out int v)`，先看返回的 bool。
//
//   坑 2：在 `foreach` 里增删这个集合
//
//       foreach (var x in 数们)
//           if (x < 0) 数们.Remove(x);        // 💥
//
//     症状：`System.InvalidOperationException: 集合已修改；可能无法执行枚举操作。`
//     为什么：foreach 内部拿的是一个"版本号"，它要求遍历期间集合的版本不变。
//           你 Remove 一次，版本号就变了 ⇒ 下一轮 move next 直接抛。
//     改法：
//       · 最省事： 数们.RemoveAll(x => x < 0);
//       · 或者倒着用 for：
//             for (int i = 数们.Count - 1; i >= 0; i--)
//                 if (数们[i] < 0) 数们.RemoveAt(i);
//
//   坑 3：以为 `表[键] = 值` 只做"修改"
//
//       表["新键"] = 1;                        // 键不存在 ⇒ **新增**，不报错
//
//     症状：循环里反复写同一个键，结果 Count 一直涨，最后发现多了一堆
//           你以为是重复的键。
//     为什么：索引器的 set 是"有则改、无则加"（upsert）。
//     改法：想"只在键已存在时才写"就 `if (表.ContainsKey(k)) 表[k] = v;`。
//           —— 这也正是"统计词频"里 `表[词] = 表.GetValueOrDefault(词) + 1;`
//           能一行搞定的原因。
//
//   坑 4：`List<T>` 的浅拷贝陷阱 —— `List<int> b = a;` 不是复制
//
//       var a = new List<int> { 1, 2 };
//       var b = a;                              // ← 只是抄了地址
//       b.Add(3);
//       Console.WriteLine(a.Count);            // 3 ❗
//
//     症状：改 b 影响了 a，两个变量像是被绑在一起。
//     为什么：`List<T>` 是**引用类型**（第 09 课那张表）—— 变量里装的是地址。
//     改法：要真的复制一份内容：`var b = new List<int>(a);`
//
//   坑 5：泛型里对 T 用了它不一定有的运算
//
//       static T 加起来<T>(T a, T b) => a + b;      // ❌
//
//     症状：`error CS0019: 运算符"+"无法应用于"T"和"T"类型的操作数`。
//     为什么：不加约束时，T 可能是任何类型，包括没有 `+` 的类型。
//           C# 里没有"数值类型"这个约束可加。
//     改法：别写通用加法 —— 老老实实写具体的重载
//           （`加起来(int, int)` / `加起来(double, double)`），
//           或者用 `dynamic`（那是拿掉类型检查，得不偿失）。
//
//
// ══ 轮到你了 ══
//
//   写三个方法：
//
//     static int 数满足<T>(List<T> 们, Func<T, bool> 条件)
//
//     static bool 查到了(Dictionary<string, int> 表, string 键, out int 值)
//         —— 键在 ⇒ true 且 值 = 表[键]；键不在 ⇒ false（用 TryGetValue）
//
//     static string 名次表(Dictionary<string, int> 表)
//         —— 按分数**从高到低**排，每行 "名字 分数"，用 '\n' 连接
//            空字典返回 ""（没有任何多余换行）
//
//   ⚠ `out` 参数在方法里**每条路径都必须赋值**
//     （第 05 课讲过）—— 用 `TryGetValue` 正好天然满足。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 12
```

### 参考答案

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

static int 数满足<T>(List<T> 们, Func<T, bool> 条件)
{
    int 计 = 0;
    foreach (var 项 in 们)
    {
        if (条件(项)) 计++;
    }
    return 计;
}

static bool 查到了(Dictionary<string, int> 表, string 键, out int 值)
{
    // ⚠ 不能写 值 = 表[键]; —— 键不在会抛 KeyNotFoundException
    return 表.TryGetValue(键, out 值);
}

static string 名次表(Dictionary<string, int> 表)
{
    if (表.Count == 0) return "";

    var 行 = 表.OrderByDescending(对 => 对.Value)
               .ThenBy(对 => 对.Key, StringComparer.Ordinal)   // 同分时按名字排，结果稳定
               .Select(对 => 对.Key + " " + 对.Value);

    return string.Join("\n", 行);      // ⚠ 末尾不会多一个换行
}
```

### 检查规格

```
数满足 用了泛型参数 T | 代码包含 | <T>
查到了 用的是 TryGetValue | 代码包含 | TryGetValue
数满足：int 与 string 两种 T 都对 | 连调用 | 数满足 | 数满足(new List<int>{1,2,3,4}, n => n % 2 == 0) | "2" | 数满足(new List<string>{"甲","乙丙"}, s => s.Length == 1) | "1"
查到了：键在 / 键不在两条路都对 | 连调用 | 查到了 | 查到了(new Dictionary<string,int>{["甲"]=90}, "甲", out int v1) + ":" + v1 | "True:90" | 查到了(new Dictionary<string,int>{["甲"]=90}, "乙", out int v2) | "False"
名次表：按分数从高到低 | 函数用例 | 名次表 | new Dictionary<string,int>{["甲"]=70,["乙"]=90,["丙"]=80} | 乙 90\n丙 80\n甲 70
```

> ⚠ 给编写检查的人：最后那条的期望值里 `\n` 是**真实换行**（C# 插值/普通字符串里
> `"\n"` 就是一个换行符），不是字面的反斜杠 n。写测试时用真实换行拼：
> `"乙 90\n丙 80\n甲 70"`。
> 另外「名次表」的返回是**一条含换行的字符串**，用 `函数用例` 比对时
> 骨架的 `%d` 打印要换成整体打印 —— 或者改用 `连调用` + `Console.WriteLine(名次表(表))`。

## 第 13 课：异常处理与 `using` —— 出错的时候怎么办

### 要求

1. 写 `class 分数越界异常 : Exception`，构造器 `public 分数越界异常(string 消息) : base(消息)`；再写 `static int 查成绩(int[] 表, int 下标)` —— 下标越界时 `throw new 分数越界异常(...)`
2. 写 `static double 算平均(int[] 数们)` —— 空数组时 `throw new ArgumentException("数组不能为空")`，否则返回平均值
3. 写 `static int 带资源算(int 数)` —— 用 `using` 开一个 `StringWriter`，往里写一行字，最后 `return 数 * 2`（证明 `using` 和 `return` 能共存）

### 讲解

```
// 第 13 课：异常处理与 using —— 出错的时候怎么办
//
// ══ 先介绍：什么该用异常 ══
//
//   先分清两类"不对"：
//
//     ① **可以预料的、调用方应该处理的**：用户输入了 "abc" 要转成数字
//        ⇒ 用返回值表达：`int.TryParse(s, out int v)` 返回 bool（第 05 课）
//
//     ② **不正常的、继续往下跑没意义的**：数组下标越界、除数为 0、
//        文件被别人删了、网络断了
//        ⇒ 用**异常**：throw 出去，谁处理谁 catch
//
//   ⚠ 判断标准不是"严重不严重"，而是：
//     **"调用方有没有可能合理地处理它？"**
//     转不了的数字 ⇒ 有（提示用户重输）⇒ 用返回值
//     下标越界 ⇒ 没有（代码写错了）⇒ 抛
//
//   异常还有一个隐藏的好处：**它让"正常路径"保持干净。**
//
//       // 不用异常：每一步都要检查，主逻辑被淹没
//       int a = 读(...);   if (a < 0) return -1;
//       int b = 读(...);   if (b < 0) return -1;
//       int c = 算(a, b);  if (c < 0) return -1;
//
//       // 用异常：正常路径一目了然，"出错"只在发生的地方说一次
//       int a = 读(...);
//       int b = 读(...);
//       return 算(a, b);
//
//
// ══ 一、try / catch / finally 三段各管什么 ══
//
//       try
//       {
//           // 可能出事的代码
//       }
//       catch (特定的异常类型 ex)
//       {
//           // 处理它。⚠ 只有类型**匹配**才进来
//       }
//       catch (Exception ex)
//       {
//           // 兜底。⚠ 必须放在**具体类型之后**
//       }
//       finally
//       {
//           // 无论如何都跑：正常结束、return、异常，都跑
//       }
//
//   ⚠⚠ catch 是**按顺序匹配**的，编译器还额外要求你把具体的写在前面：
//
//       catch (Exception ex) { }             // 放前面
//       catch (ArgumentException ex) { }     // ⇒ error CS0160:
//       // "上一个 catch 子句已经捕获此类型或超类型的所有异常"
//
//     为什么：`Exception` 是所有异常的祖先，第一个 catch 就把一切都吃掉了，
//           后面那个永远轮不到。编译器直接判它多余 —— 这是好事，
//     它省得你在运行时才发现"我的 catch 从来不执行"。
//
//   不写 catch 的 try/finally 是合法的，而且很有用：
//
//       try { ... }
//       finally { 清理(); }        // 没有 catch ⇒ 异常继续往上传，但清理一定会做
//
//
// ══ 二、`throw`、`throw ex`、`throw new`：三者的堆栈差很多 ══
//
//   堆栈跟踪（stack trace）就是"错误是怎么一层层传上来的"那张清单。
//   排查线上问题时，它比错误消息本身更重要。
//
//   ┌─ ① `throw;`   —— 原样再抛，**堆栈完整保留** ────────────┐
//
//       catch (Exception ex)
//       {
//           Console.WriteLine("记一笔日志：" + ex.Message);
//           throw;                 // ✅ 起始点是**最初出事的那一行**
//       }
//
//   └────────────────────────────────────────────────────────┘
//
//   ┌─ ② `throw ex;` —— 从**这一行**重新开始，原始堆栈被砍掉 ──┐
//
//       catch (Exception ex)
//       {
//           throw ex;              // ❌ 堆栈从这里开始
//       }
//
//     症状：日志里堆栈最上面是**你自己的 catch 那一行**，
//           再往上什么都没有 —— 你只知道"出过错"，不知道**在哪里出的**。
//     为什么：`throw ex` 是一次新的抛出，CLR 认为"起点就是这里"。
//           它和 `throw new Exception(...)` 在这一点上没有区别。
//     改法：**只写 `throw;`**，不要带那个 `ex`。
//
//   └────────────────────────────────────────────────────────┘
//
//   ③ `throw new XxxException("...", ex);` —— 想**换成自己的异常类型**时用。
//      把原异常当 `InnerException` 传进去，堆栈虽然重开，
//      但原始的错还在 `ex.InnerException` 里，不算丢。
//
//       catch (IOException ex)
//       {
//           throw new 我的异常("保存失败", ex);     // ✅ 换了类型，但没丢原因
//       }
//
//   ⚠ 三句口诀：
//       要原样上抛    ⇒ `throw;`
//       要换类型上抛  ⇒ `throw new 类型(msg, ex);`
//       `throw ex;`    ⇒ **永远不写**
//
//
// ══ 三、什么时候**不**该 catch ══
//
//   官方的话是："Don't catch an exception unless you can handle it."
//   翻成大白话：**你 catch 了，就得做点什么。**
//
//   什么算"做了点什么"？
//     · 恢复了（用默认值重试、换个路径）
//     · 转成用户能懂的话（"文件不存在，请先保存"）
//     · 加一条有用的日志，然后 `throw;` 继续上抛
//     · 转成别的异常类型上抛，带上 InnerException
//
//   什么不算？
//     · `catch (Exception) { }`                ← 空 catch，"吞异常"
//     · `catch (Exception ex) { }`             ← 变量声明了却不用，编译器还会警告
//     · `catch (Exception ex) { return null; }` ← 把错误伪装成"没有数据"
//
//   ⚠⚠ 空 catch 是**最坏的一种 bug 制造机**：
//     症状是"程序不崩，但结果不对/什么都没发生"，而且**日志里一个字都没有**。
//     你会花一整天去找一个本来一行日志就能指出的问题。
//     如果实在要忽略（极少见），至少写清楚为什么：
//         catch (Exception) { /* 这里确实可以忽略：删临时文件失败无所谓 */ }
//
//   ⚠ 还有一条：**别用异常做正常流程控制**。
//        try { return 表[键]; } catch (KeyNotFoundException) { return 0; }
//     能跑，但异常构造很贵，而且把"正常"和"异常"混成一件事了 ——
//     该用 `TryGetValue`（第 12 课）。
//
//
// ══ 四、`IDisposable` 与 `using` ══
//
//   有些东西**用完必须还**：文件句柄、网络连接、数据库连接、图形资源。
//   C# 用接口 `IDisposable` 表达这件事，它只有一个方法：
//
//       public interface IDisposable { void Dispose(); }
//
//   谁实现了它，谁就承诺"调用 Dispose() 会把我占的资源放掉"。
//
//   老写法（啰嗦，而且容易漏）：
//
//       var w = new StringWriter();
//       try { w.WriteLine("..."); }
//       finally { w.Dispose(); }        // 必须自己记得
//
//   新写法：`using` **声明**
//
//       using var w = new StringWriter();
//       w.WriteLine("...");
//       // 方法/作用域结束的时候，自动 Dispose() —— 出了异常也照样 Dispose
//
//   或者 `using` **语句**，能限定更小的范围：
//
//       using (var w = new StringWriter())
//       {
//           w.WriteLine("...");
//       }   // ← 出了这个花括号就 Dispose
//
//   ⚠ 两者的区别只是**作用域**：`using var` 管到所在块的末尾，
//     `using (...)` 管到那个花括号。功能上等价 —— 编译器都会把它
//     展开成 try/finally + Dispose。
//
//   ⚠⚠ `using` 和 `return` 能共存，而且顺序是确定的：
//
//       static int 带资源算(int 数)
//       {
//           using var w = new StringWriter();
//           w.WriteLine("干活");
//           return 数 * 2;          // ← 先算好返回值，**再 Dispose**，最后才真的返回
//       }
//
//     不用担心"return 会不会跳过 Dispose" —— **不会**。
//     这正是 finally 的语义。这条你要是自己想明白了，这一课就通了。
//
//   ⚠ `using` 只对**实现了 IDisposable** 的类型有效。
//     对一个没实现的类型写 `using var x = new 我的类();` 报
//     `error CS1674: "我的类": using 语句中使用的类型必须可隐式转换为
//      "System.IDisposable"`。
//
//
// ══ 五、常见坑 ══
//
//   坑 1：`catch (Exception) { }` 吞掉一切
//
//       try { 危险操作(); } catch (Exception) { }
//       正常继续();
//
//     症状：程序**不崩**，但后面拿到的数据是错的 / 该保存的没保存；
//           更糟的是**没有任何日志**，你不知道刚才发生过什么。
//     为什么：异常的全部信息（类型 + 消息 + 堆栈）都被扔了。
//     改法：要么真的处理，要么 `catch (Exception ex) { 记日志(ex); throw; }`。
//
//   坑 2：`throw ex;` 而不是 `throw;`
//
//       catch (Exception ex) { throw ex; }
//
//     症状：日志里的堆栈最上面是你的 catch 那一行，源头不见了。
//     为什么：`throw ex;` 是一次**新的抛出**，起点就是这一行。
//     改法：`throw;`。就少打四个字符，但堆栈是天壤之别。
//
//   坑 3：catch 顺序写反
//
//       catch (Exception ex) { ... }
//       catch (ArgumentException ex) { ... }     // ❌
//
//     症状：`error CS0160: 上一个 catch 子句已经捕获此类型或超类型的所有异常`。
//     为什么：Exception 是 ArgumentException 的祖先，第一个就吃完了。
//     改法：**具体的写前面，笼统的写后面**。
//
//   坑 4：以为 C# 有 Java 那样的"受检异常"
//
//       // Java 里必须写 throws IOException，C# 里**不需要**
//       public static int 读文件(string 路径) { ... }
//
//     症状：看到别人的签名里没有异常声明，以为"这个方法不会抛异常"。
//     为什么：C# **所有异常都是非受检的**，签名里不体现，
//           编译器也不强制你 catch。能不能抛，只能看文档 / 看实现。
//     改法：把这当成"要自己操心的事" —— 调别人的方法时，
//           想一想"它可能抛什么"。
//
//   坑 5：用异常做正常的流程判断
//
//       static int 取(Dictionary<string,int> 表, string 键)
//       {
//           try { return 表[键]; }
//           catch (KeyNotFoundException) { return 0; }        // ❌
//       }
//
//     症状：能跑，但"键不存在"和"值真的是 0"混成同一个结果，无法区分；
//           而且这一行的开销比正常查表大得多。
//     为什么：异常构造要抓堆栈，是重活；而且语义上"没查到"根本不是异常。
//     改法：`表.TryGetValue(键, out int v)` + 返回 bool（第 12 课的写法）。
//
//   坑 6：自己造的异常没有可读的消息
//
//       throw new Exception("错了");
//
//     症状：线上日志里一堆"错了"，谁也判断不出发生了什么。
//     为什么：消息是**给人看的唯一线索**，得写"哪个值、什么范围、期望什么"。
//     改法：`throw new ArgumentException($"分数 {分} 超出 0~100 的范围");`
//           而且尽量用**标准异常类型**（ArgumentException /
//           ArgumentOutOfRangeException / InvalidOperationException /
//           NotSupportedException），只有这样调用方才能可靠地 catch。
//           自定义异常留给"调用方需要单独处理"的业务错误。
//
//
// ══ 轮到你了 ══
//
//     class 分数越界异常 : Exception
//     {
//         public 分数越界异常(string 消息) : base(消息) { }
//     }
//
//     static int 查成绩(int[] 表, int 下标)
//         —— 下标 < 0 或 >= 表.Length ⇒ throw new 分数越界异常(...)
//            否则返回 表[下标]
//
//     static double 算平均(int[] 数们)
//         —— 空数组 ⇒ throw new ArgumentException("数组不能为空")
//            否则返回平均值
//
//     static int 带资源算(int 数)
//         —— using 一个 StringWriter，往里写一行，返回 数 * 2
//
//   ⚠ 顶部已经 using System; / System.Collections.Generic; / System.Linq;
//     `StringWriter` 在 `System.IO` 里 —— 写全名 `System.IO.StringWriter`，
//     或者自己在文件顶上加一行 `using System.IO;`。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 13
```

### 参考答案

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;

class 分数越界异常 : Exception
{
    public 分数越界异常(string 消息) : base(消息) { }
}

static int 查成绩(int[] 表, int 下标)
{
    if (下标 < 0 || 下标 >= 表.Length)
    {
        // ⚠ 消息要写清"哪个值、什么范围" —— 这是将来唯一的线索
        throw new 分数越界异常($"下标 {下标} 超出 0~{表.Length - 1} 的范围");
    }
    return 表[下标];
}

static double 算平均(int[] 数们)
{
    if (数们.Length == 0)
    {
        throw new ArgumentException("数组不能为空");
    }

    int 和 = 0;
    for (int i = 0; i < 数们.Length; i++)
    {
        和 += 数们[i];
    }
    // ⚠ 至少一边要是 double，否则这里是整数除法（向零取整）
    return (double)和 / 数们.Length;
}

static int 带资源算(int 数)
{
    // using var：作用域结束时自动 Dispose —— 出了异常也照样 Dispose
    using var 写手 = new StringWriter();
    写手.WriteLine("干活");

    // ⚠ return 不会跳过 Dispose：先算好返回值，再 Dispose，最后才返回
    return 数 * 2;
}
```

### 检查规格

```
自定义异常写了，而且继承了 Exception | 代码包含 | : Exception
真的用了 throw | 代码包含 | throw new
算平均 用了浮点除法（不是整数除法） | 代码包含 | (double)
带资源算 用了 using | 代码包含 | using
查成绩：越界真的抛异常，合法下标取得到 | 函数用例 | 查成绩 | new int[]{10,20,30}, 1 | 20 | new int[]{10,20,30}, 2 | 30
带资源算：using 与 return 共存，值还是对的 | 函数用例 | 带资源算 | 21 | 42 | 0 | 0 | -5 | -10
算平均：平均值是小数（不是向零取整的整数） | 函数用例 | 算平均 | new int[]{1,2} | 1.5 | new int[]{90,80,70} | 80
```

> ⚠ 给编写检查的人：`算平均(new int[]{1,2})` 必须是 **1.5** ——
> 这一条专门抓"忘了转 double、写成整数除法得 1"的错（调研点名的坑）。
> `查成绩` 的"越界真的抛异常"没法用 `函数用例` 表达（它会抛），
> 要单独写一条 `运行后` 的检查：调用点里套 try/catch，
> 捕获 `分数越界异常` 并打印 `"抛了"`，比对输出。

## 第 14 课：模式匹配 —— `is`、switch 表达式、`and`/`or`/`not`

### 要求

1. 写 `static string 描述(int 分)` —— 用 **switch 表达式**：`< 0` 返回 `"无效"`、`>= 90` 返回 `"优"`、`>= 80` 返回 `"良"`、`>= 60` 返回 `"及格"`、其余返回 `"不及格"`
2. 写 `record 成绩记录(string 名字, int 分数);` 和 `static bool 至少一门不及格(成绩记录 r)` —— 用**属性模式 + `or`**：名字为空 **或** 分数不在 0~100 之间 ⇒ 返回 `true`
3. 写 `static string 描述对象(object 东西)` —— 用 `is` 类型模式 + `when`：`int n` 且 `n > 0` ⇒ `"正数 n"`；`string s` 且非空 ⇒ `"字符串: s"`；`string` 但是空串 ⇒ `"空字符串"`；其他 ⇒ `"不认识的类型"`

### 讲解

```
// 第 14 课：模式匹配 —— 让"判断+取值"变成一件事
//
// ══ 先介绍：老写法里那些重复的啰嗦 ══
//
//   假设你有个 `object 东西`，想知道它是不是 int、是的话值多少：
//
//       // 老写法
//       if (东西 is int)
//       {
//           int n = (int)东西;          // ← 刚刚才判断过，现在又要强转一次
//           Console.WriteLine(n + 1);
//       }
//
//   `is` 判断了一次类型，`(int)` 又转了一次 —— 两次说的是同一件事。
//
//   模式匹配把这两步合成一步：
//
//       if (东西 is int n)              // ← 判断成功的同时，n 就已经是 int 了
//       {
//           Console.WriteLine(n + 1);   // 直接用，不用强转
//       }
//
//   ⇒ 这就是模式匹配的全部动机：**把"检查形状"和"取出里面的东西"合并**，
//     顺带让编译器能证明"你取的时候它一定是对的"。
//
//
// ══ 一、`is` 的五种模式 ══
//
//   ① 类型模式：`东西 is int n`
//
//        if (东西 is string s && s.Length > 0)     // ⚠ && 后面 s 就能用了
//            Console.WriteLine(s.ToUpper());
//
//      ⚠ 在同一个条件里 `is` 之后可以放心用 s ——
//        因为 `&&` 短路：s 有值才可能走到后半句。
//
//   ② 常量 / 关系模式：`is 0`、`is >= 90`、`is < 0`
//
//        if (分 is >= 0 and <= 100)               // 等价于 分 >= 0 && 分 <= 100
//
//   ③ 逻辑模式：`and` / `or` / `not`
//
//        if (分 is < 0 or > 100)   Console.WriteLine("无效");
//        if (分 is not 0)          Console.WriteLine("不是零");
//
//      ⚠ 是关键字 `and` / `or` / `not`，**不是** `&&` / `||` / `!`。
//        两者别混：`分 is >= 0 && 分 <= 100` 里 `&&` 两边必须是完整表达式；
//        `分 is >= 0 and <= 100` 里 `and` 两边是**模式**，右边那个 `<= 100`
//        自己不带左操作数（左操作数就是被匹配的那个值）。
//
//   ④ 属性模式：`东西 is 成绩记录 { 分数: >= 90 }`
//
//        if (r is { 分数: >= 90, 名字: not "" })
//            Console.WriteLine(r.名字 + " 优秀");
//
//      `{ 属性名: 模式 }` —— 意思是"这个对象是成绩记录，而且它的 `分数` 属性
//      本身匹配 `>= 90` 这个模式"。可以一次写好几个属性，逗号隔开（相当于 and）。
//
//   ⑤ 位置模式（record 专用，因为 record 有自动解构）：
//
//        if (r is (var 名, >= 90))
//            Console.WriteLine(名 + " 优秀");
//
//      `(var 名, >= 90)` 按**声明顺序**对应 `成绩记录(名字, 分数)`。
//
//
// ══ 二、switch 表达式：一条链的判断，写成一张表 ══
//
//       static string 描述(int 分) => 分 switch
//       {
//           < 0          => "无效",
//           >= 90        => "优",
//           >= 80        => "良",
//           >= 60        => "及格",
//           _            => "不及格",
//       };
//
//   和老 `switch` 语句的差别，一眼就能看出来：
//
//       老 switch 语句                      switch 表达式
//       ─────────────────────────────       ────────────────────────────
//       switch (分) { ... }                分 switch { ... }
//       case 90: ...                        >= 90 => "优",
//       **每条都要 break;**                  用逗号，不用 break
//       是**语句**，不返回值                 是**表达式**，整体有个值
//       一个 case 只能写一个常量             `>= 90`、`< 0`、`int n` 都行
//
//   ⚠ 四个语法点，写错一个就编译不过：
//     ① `switch` 在**后面**：`分 switch` —— 不是 `switch (分)`
//     ② 每个分支 `模式 => 值`，**末尾是逗号**
//     ③ 整体是一个表达式 ⇒ 可以直接 `return ... ;`，或者用 `=>` 方法体
//     ④ 必须**穷尽**：所有可能的值都要被某个分支（或 `_`）接住
//
//   ⚠ 漏了兜底会怎样？
//
//       static string 描述(int 分) => 分 switch { >= 60 => "及格" };
//       // warning CS8509: 表达式不涵盖其输入类型的所有可能值
//       //                 （它不处理 < 60）
//
//     症状：**是一条警告，不是错误** —— 编译能过，但你输入 30 的时候，
//           程序在运行时抛"非穷举的 switch 表达式"（SwitchExpressionException）。
//     为什么：switch 表达式要"整体有个值"，没匹配上就没有值可给。
//     改法：加一条 `_ => ...`。**int 这种类型永远需要兜底**，
//           因为编译器不可能枚举完 40 亿个 int。
//     什么时候不用兜底：`bool` 两个都写了，或者枚举每个成员都写了。
//
//   ⚠ 分支是**从上往下**匹配的，第一个命中的赢：
//
//          >= 60 => "及格",
//          >= 90 => "优",          // ← 到不了这里！95 在第一行就被 60 接住了
//
//     ⇒ **从最严格写到最宽松**（和第 03 课的 if 链是同一个坑）。
//
//   ⚠ `when` 子句：模式之外还想再加个条件时用它：
//
//       分 switch
//       {
//           int n when n > 1000 => "爆表",
//           _ => "正常",
//       }
//
//
// ══ 三、模式匹配的两种用法：值 vs 类型 ══
//
//   · 匹配**值**（数字、字符串、枚举）⇒ 关系模式 + switch 表达式最好用
//   · 匹配**类型**（一个 object / 基类引用，可能是好几种东西）
//     ⇒ `is` 类型模式 + switch 表达式的类型模式
//
//       static string 描述对象(object 东西) => 东西 switch
//       {
//           int n when n > 0      => "正数 " + n,
//           int n                 => "非正数 " + n,
//           string s when s == "" => "空字符串",
//           string s              => "字符串: " + s,
//           null                  => "什么都没有",
//           _                     => "不认识的类型",
//       };
//
//     顺序在这里是**必须**的：`string s when s == ""` 一定得写在 `string s` 前面。
//
//
// ══ 四、常见坑 ══
//
//   坑 1：`is` 里声明了变量却在外面用
//
//       if (东西 is int n) { }
//       Console.WriteLine(n);          // ❌ 编译不过
//
//     症状：`error CS0103: 当前上下文中不存在名称"n"`。
//     为什么：模式变量的作用域就是"这个 `is` 为真的那个分支"。编译器
//           不能保证它在那之外有值 ⇒ 干脆不让它在外面存在。
//     改法：把要用的代码挪进 if；或者换个名字并预先声明一个变量接住。
//
//   坑 2：`is` 里声明的变量类型不是你以为的那个
//
//       if (东西 is int s) { s.ToUpper(); }   // ❌
//
//     症状：`error CS1061: "int"未包含"ToUpper"的定义`。
//     为什么：模式变量的类型**由模式决定** —— `is int s` 里 s 就是 `int`。
//     改法：想当字符串用就 `is string s`。
//           （另一种写法是 `is var x`，那 x 就是**原来的类型**，别搞混。）
//
//   坑 3：用 `as` 代替 `is`，然后忘了判 null
//
//       string s = 东西 as string;
//       Console.WriteLine(s.Length);      // 💥 东西不是 string 时 s 是 null
//
//     症状：`NullReferenceException`，而且崩在**下一行**，看起来跟 as 无关。
//     为什么：`as` 转换失败时**返回 null，不抛异常**；null 上取 `.Length` 才炸。
//     改法：用 `is` 模式，一步到位：
//             if (东西 is string s) Console.WriteLine(s.Length);
//           非要用 as 就得紧跟着判 null。
//
//   坑 4：switch 表达式漏兜底（见上面）—— 编译只警告，运行时才炸
//
//       static string 分类(int x) => x switch { > 0 => "正" };
//       Console.WriteLine(分类(-1));      // 💥 非穷举的 switch 表达式
//
//     症状：`警告 CS8509` 你可能根本没看，运行到 -1 才崩。
//     为什么：表达式必须在所有情况下都有一个值。
//     改法：`_ => "非正"`。对 int / string 这类开放类型，**兜底是必需项**。
//
//   坑 5：`is` 里面用 `&&`，把模式当表达式写
//
//       if (分 is >= 0 && <= 100)         // ❌
//
//     症状：`error CS1525: 表达式项"<="无效`。
//     为什么：`&&` 是**逻辑运算符**，它两边要的是完整表达式，
//           而 `<= 100` 缺左操作数，不是表达式。`and` 才是**模式**的连接词。
//     改法：`分 is >= 0 and <= 100`。
//
//   坑 6：`and` / `or` 当成 `&&` / `||` 用在整个表达式上
//
//       if (分 >= 0 and 分 <= 100)        // ❌
//
//     症状：也是 `CS1525` / `CS1003` 一类"语法无效"的报错。
//     为什么：`and` 只能出现在 `is` 模式的**里面**。
//           左边那个 `分 >= 0` 是普通比较表达式，接不上 `and`。
//     改法：要么全程普通写法 `分 >= 0 && 分 <= 100`，
//           要么全程模式 `分 is >= 0 and <= 100`。**别混。**
//
//   坑 7：属性模式里把 `:` 写成 `=` 或 `.`
//
//       r is 成绩记录 { 分数 = >= 90 }      // ❌
//       r is 成绩记录 { 分数.>= 90 }        // ❌
//       r is 成绩记录 { 分数: >= 90 }       // ✅
//
//     症状：`error CS1003: 语法错误，应输入","`（因为 `=` 被当成别的东西了）。
//     为什么：属性模式固定是 `{ 属性名: 模式 }`，`:` 是分隔符。
//
//   坑 8：一个模式变量被 `or` 的两个分支各声明一次，然后拿去用
//
//       if (东西 is int n or string n)        // ❌ 编译不过
//           Console.WriteLine(n);             //    这里 n 没有被确定赋值
//
//     症状：`error CS0128: 已在当前范围中定义名为"n"的局部变量`
//           （同名重复声明），或者说变量"未赋值"。
//     为什么：`or` 两个分支是**互相排斥**的可能路径 —— 只走其中一条，
//           编译器没法保证 n 一定被赋了值。
//     改法：两个分支用不同的名字（`int a or string b`），
//           或者在分支各自内部把值取出来用。
//
//   坑 9：`object` 上的 `==` 和模式匹配混着用
//
//       if (东西 == 1) Console.WriteLine("是一");         // 能编译
//       if (东西 is 1)  Console.WriteLine("是一");        // 也是它
//
//     症状：`东西 = 1`（装箱的 int）时两种都对，但 `==` 对 object 走的是
//           **引用比较**，换个装箱方式结果就会不一样。
//     为什么：`object == object` 比的是引用（string 有自己的 == 重载，是例外）。
//     改法：判类型/判值一律用模式 —— `东西 is int n && n == 1`，意图清楚。
//
//
// ══ 轮到你了 ══
//
//     static string 描述(int 分)              // switch 表达式，含负数 => "无效"
//     record 成绩记录(string 名字, int 分数);
//     static bool 至少一门不及格(成绩记录 r)     // 属性模式 + or
//     static string 描述对象(object 东西)       // is 类型模式 + when
//
//   ⚠ 描述里的分支顺序：**最严格的先写**（`< 0` 在最前面，不能掉进 `_`）。
//   ⚠ 描述对象的顺序：`string` 的空串判断要在"一般字符串"之前。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 14
```

### 参考答案

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

static string 描述(int 分) => 分 switch
{
    < 0      => "无效",        // ⚠ 负分要单独接住，不能掉进 _ 里
    >= 90    => "优",
    >= 80    => "良",
    >= 60    => "及格",
    _        => "不及格",      // ⚠ 兜底：int 永远需要
};

record 成绩记录(string 名字, int 分数);

static bool 至少一门不及格(成绩记录 r)
{
    // 属性模式 + or：名字空 或 分数越界 ⇒ 数据有问题，也算"不及格"
    return r is { 名字: "" } or { 分数: < 0 or > 100 };
}

static string 描述对象(object 东西) => 东西 switch
{
    int n when n > 0           => "正数 " + n,
    string s when s.Length > 0 => "字符串: " + s,
    string                     => "空字符串",       // ⚠ 必须排在"一般字符串"之前，
                                                    //   其实上面那条 when 已经把它排掉了，
                                                    //   这一条只兜剩下的 string
    null                       => "什么都没有",
    _                          => "不认识的类型",
};
```

> ⚠ 给编写检查的人，两处要点：
> 1. `代码包含 | or` 这条太松（`or` 是常见子串）。建议换成更硬的片段，
>    比如 `| 代码包含 | 名字: "" } or ` 或者干脆用 `函数用例` 覆盖行为。

>    `-7` 是 int，第一个分支 `int n when n > 0` 不满足，

>    另外 `(object)(-7)` 的写法是必要的 —— 不写 `(object)` 的话字面量 `-7`
>    会以 `int` 传参，那也没问题，但显式写出来意图更清楚。

## 第 15 课：LINQ 入门 —— `Where` / `Select` / `OrderBy` 与延迟执行

### 要求

1. 写 `static int[] 挑偶数(int[] 数们)` —— 用 `Where` 挑出偶数，返回**数组**（用 `ToArray()`）
2. 写 `static List<成绩记录> 加一分(List<成绩记录> 们)` —— 用 `Select` 造出"分数 +1"的**新**记录（原列表一个字都不能变），返回 `List<成绩记录>`
3. 写 `static void 演示延迟()` —— 建一个 `List<int> 数们 = new List<int> { 1, 2, 3 }`，先定义查询 `var 查 = 数们.Where(数 => 数 > 1);`，然后 `数们.Add(99);`，**最后**才 `foreach` 打印 —— 每行一个数，没有别的话
4. `record 成绩记录(string 名字, int 分数);` 由你自己补上（第 14 课写过）

### 讲解

```
// 第 15 课：LINQ 入门 —— Where / Select / OrderBy，以及"它到底什么时候跑"
//
// ══ 先介绍：把"遍历 + 判断 + 收集"压成一行 ══
//
//   没有 LINQ 的时候，想挑出所有偶数，你得这么写：
//
//       var 结果 = new List<int>();
//       foreach (var 数 in 数们)
//           if (数 % 2 == 0)
//               结果.Add(数);
//
//   三行，而且**意图被埋起来了** —— 你要先读完整段才知道它在干"筛选"。
//
//   LINQ 把这件事变成一行：
//
//       var 结果 = 数们.Where(数 => 数 % 2 == 0).ToList();
//
//   `Where` 收一个"每个元素 → 要不要它"的函数，返回筛选后的序列。
//
//   ⚠ 但这一课真正的主角不是这几个方法名 —— **是「延迟执行」。**
//     LINQ 最出名的坑就在这里，而且它的症状非常反直觉。
//
//
// ══ 一、五个最常用的操作 ══
//
//       var 分数 = new List<int> { 88, 42, 95, 60, 73 };
//
//   ┌ Where —— 筛选：留下满足条件的 ────────────────────────┐
//       var 及格 = 分数.Where(分 => 分 >= 60);
//       // 88, 95, 60, 73
//   └──────────────────────────────────────────────────────┘
//
//   ┌ Select —— 投影：把每个元素**变成**另一个东西 ──────────┐
//       var 标签 = 名单.Select(名 => 名 + " 同学");
//       var 编号 = 名单.Select((名, i) => i + 1);       // 带下标的重载
//   └──────────────────────────────────────────────────────┘
//
//   ┌ OrderBy / OrderByDescending —— 排序 ──────────────────┐
//       var 升 = 分数.OrderBy(分 => 分);
//       var 降 = 分数.OrderByDescending(分 => 分);
//       var 多级 = 们.OrderBy(项 => 项.班).ThenByDescending(项 => 项.分);
//       //   ↑ 第二级必须用 ThenBy，不能写第二个 OrderBy（那会覆盖第一级）
//   └──────────────────────────────────────────────────────┘
//
//   ┌ First / FirstOrDefault / Count / Sum / Average / Max ─┐
//       var 头名 = 分数.Max();
//       var 平均 = 分数.Average();                 // 返回 double
//       var 几个 = 分数.Count(分 => 分 >= 60);
//       var 第一个及格 = 分数.FirstOrDefault(分 => 分 >= 60);
//       //        ⚠ First 找不到 ⇒ 抛异常；FirstOrDefault ⇒ 给默认值(0)
//   └──────────────────────────────────────────────────────┘
//
//   ⚠ 这些方法的返回值是 `IEnumerable<T>`，**不是 List**。
//     想变成具体容器要显式收口：
//         .ToList()      变成 List<T>
//         .ToArray()     变成 T[]
//         .ToDictionary(x => x.键, x => x.值)
//     不收口也行 —— 直接 foreach 它、或者继续接下一个 LINQ 方法。
//
//
// ══ 二、延迟执行：这一课唯一必须搞懂的东西 ══
//
//   先看一个能让你愣住的例子：
//
//       var 数们 = new List<int> { 1, 2, 3 };
//
//       var 查 = 数们.Where(数 => 数 > 1);      // ← 这一行**什么都没做**
//
//       Console.WriteLine(查.Count());          // 2
//       Console.WriteLine(查.Count());          // 2     （只是又算了一遍）
//
//   再看：
//
//       var 数们 = new List<int> { 1, 2, 3 };
//       var 查 = 数们.Where(数 => 数 > 1);      // 定义查询
//
//       数们.Add(99);                            // ← 定义**之后**改数据
//
//       foreach (var 数 in 查)
//           Console.WriteLine(数);               // 2  3  99
//                                                  //        ↑ 99 也在里面！！
//
//   ⚠⚠ **99 是在查询定义之后才加进去的，但它出现在结果里了。**
//
//   为什么：`Where(...)` 这一行**只是描述了一个查询**，它一个元素都没看过。
//   真正的遍历发生在**你开始枚举它的时候** —— `foreach`、`Count()`、
//   `ToList()`、`ToArray()`、`Sum()`…… 每一次枚举都**重新跑一遍**查询，
//   而且读的是**当下**的数据。
//
//   ⇒ 一句话：**LINQ 查询是"配方"，不是"菜"。**
//     写 `Where` 那一行是在写菜谱；`foreach` 才是真的下锅。
//
//   这个设计有它的道理：
//     · 省事 —— 你写五个 Where 也只是一次遍历
//     · 能用在无限序列、数据库、网络流上（`IEnumerable<T>` 可以一个一个来）
//     · 组合查询不用产生中间集合
//
//   代价就是下面这些坑。
//
//   ⚠ 一个更隐蔽的后果：**同一个查询被枚举两次，就是算了两遍。**
//
//       var 查 = 数们.Where(数 => { Console.WriteLine("看了 " + 数); return 数 > 1; });
//       Console.WriteLine(查.Count());      // 打印了 3 行"看了 x"
//       Console.WriteLine(查.Count());      // **又**打印了 3 行
//
//     如果那个 lambda 里有开销大的操作（读文件、算哈希），
//     你就在不知情的情况下做了两次。⇒ 确定要复用结果时，
//     **立刻收口**：`var 查 = 数们.Where(...).ToList();`
//
//
// ══ 三、查询语法：同一件事的另一种写法 ══
//
//   C# 还有一种长得像 SQL 的写法，叫**查询语法**：
//
//       var 及格的名字 =
//           from 项 in 名单
//           where 项.分数 >= 60
//           orderby 项.分数 descending
//           select 项.名字;
//
//   等价的**方法语法**：
//
//       var 及格的名字 =
//           名单.Where(项 => 项.分数 >= 60)
//               .OrderByDescending(项 => 项.分数)
//               .Select(项 => 项.名字);
//
//   ⚠ 两者**完全等价** —— 查询语法在编译时就被翻译成方法调用。
//     选哪个纯看可读性：
//       · 只有 Where/Select/OrderBy ⇒ 方法语法更短
//       · 要 `join`、或者要 `let` 定义中间变量 ⇒ 查询语法清楚得多
//     本课**按方法语法考**（更常用，也更容易和 lambda 对上）。
//
//   ⚠ 查询语法有个硬性规定：**必须以 `select` 或 `group` 结尾**。
//     只写 `from x in 表 where ...` 是不完整的，编译不过。
//
//
// ══ 四、一个最容易踩的意外：延迟执行 + 可变数据 = 结果漂移 ══
//
//       var 们 = new List<成绩记录> { new("甲", 90), new("乙", 50) };
//       var 不及格 = 们.Where(项 => 项.分数 < 60);        // 现在有 1 个
//
//       们.Add(new 成绩记录("丙", 30));                    // 又来了一个
//
//       Console.WriteLine(不及格.Count());                 // 2 ！
//
//   ⚠ 如果这个查询是在"数据已经稳定"之后定义、但**在别处**被枚举，
//     你拿到的结果取决于**枚举那一刻**的数据 —— 排查这类问题时
//     你会觉得"同一个变量每次打印出来都不一样"。
//
//   ⇒ 经验法则：
//     · 结果要**存起来、传出去、用第二次** ⇒ 立刻 `.ToList()` / `.ToArray()`
//     · 只是当场 foreach 一遍 ⇒ 不用收口，省一次拷贝
//
//
// ══ 五、常见坑 ══
//
//   坑 1：以为 `Where` 已经执行了（本课的头号坑）
//
//       var 查 = 数们.Where(数 => 数 > 1);
//       Console.WriteLine("我筛完了");         // 你以为这里已经筛过了
//       // 其实一个元素都还没看
//
//     症状：断点打在 lambda 里，发现它在 `Where` 那一行**根本不停**，
//           而是停在你 `foreach` / `Count()` 的时候；
//           或者"我已经筛过了，后来又加的数据不该出现"—— 但它出现了。
//     为什么：Where 只是构造了一个查询对象，枚举时才逐个元素调你的 lambda。
//     改法：需要"现在就定下来"就收口 `.ToList()`。
//
//   坑 2：把同一个查询用两次，以为它缓存了
//
//       var 查 = 数们.Where(慢判断);
//       if (查.Count() > 0 && 查.First().分数 > 60)   // 慢判断跑了不止一遍
//
//     症状：日志里同一个元素被判断了好几次；性能莫名其妙地差。
//     为什么：每次枚举（`Count()` 一次、`First()` 又一次）都从头跑。
//     改法：`var 快 = 查.ToList();` 然后用 `快`。
//
//   坑 3：在 LINQ 的 lambda 里改原集合
//
//       foreach (var 项 in 们.Where(项 => 项.分数 < 60)) 们.Remove(项);   // 💥
//
//     症状：`System.InvalidOperationException: 集合已修改；可能无法执行枚举操作。`
//           —— 和第 12 课 `foreach` 里增删是同一个异常。
//     为什么：`Where` 是延迟的、且**共享**原集合的枚举器；
//           你在遍历途中改集合，版本号变了 ⇒ 抛。
//     改法：
//       · 先收口再改：`foreach (var 项 in 们.Where(条件).ToList()) 们.Remove(项);`
//       · 或者 `们.RemoveAll(项 => 条件);`（最省事，一步到位）
//
//   坑 4：用两个 `OrderBy` 想实现多级排序
//
//       var 排 = 们.OrderBy(项 => 项.班).OrderBy(项 => 项.分数);   // ❌
//
//     症状：班那一级**完全没起作用**，结果只按分数排。
//     为什么：第二个 `OrderBy` 是**重新排序**，它不记得前一次的键。
//     改法：第二级开始用 `ThenBy` / `ThenByDescending`：
//           `们.OrderBy(项 => 项.班).ThenBy(项 => 项.分数)`
//
//   坑 5：`First()` / `Single()` 在空序列上抛异常
//
//       var 头名 = 们.Where(项 => 项.分数 >= 100).First();     // 💥
//
//     症状：`System.InvalidOperationException: 序列不包含任何元素`。
//     为什么：`First()` 承诺"一定给你一个"，给不出就报错。
//     改法：可能为空就用 `FirstOrDefault()`（值类型给默认值、引用类型给 null），
//           或者先 `Any()` 问一句。
//     顺带一提 `Single()`：它要求**正好一个** —— 0 个抛、2 个也抛。
//
//   坑 6：在 lambda 里改了外部变量，然后奇怪它为什么变了
//
//       int 上限 = 60;
//       var 查 = 们.Where(项 => 项.分数 >= 上限);
//       上限 = 90;                                  // ← 改了
//       var 结果 = 查.ToList();                      // 用的是 **90**！
//
//     症状：结果和"写查询时的意图"不一致。
//     为什么：lambda 捕获的是**变量本身**（不是当时的值），
//           而且延迟执行让求值发生在**改之后**。
//           两个坑叠在一起，结果非常反直觉。
//     改法：把要用的值先复制到不会变的局部变量里，
//           或者定义完立刻收口 `.ToList()`。
//
//   坑 7：忘了 `using System.Linq;`
//
//     症状：一个方法都点不出来，报
//           `error CS1061: "List<int>"未包含"Where"的定义`
//           或者 `error CS0246: 未能找到类型或命名空间名"Enumerable"`。
//     为什么：LINQ 的扩展方法是 `System.Linq` 命名空间里的静态类
//           `Enumerable` 提供的，不 using 就看不见。
//     改法：文件顶部 `using System.Linq;`。
//           ⚠ 课程骨架的顶部**已经**有三个 using，`System.Linq` 在内。
//             但你自己新建 .cs 文件时要记得加 —— 这是新手最常撞的一个。
//
//
// ══ 轮到你了 ══
//
//     static int[] 挑偶数(int[] 数们)              // Where + ToArray
//
//     static List<成绩记录> 加一分(List<成绩记录> 们)   // Select 造**新**记录
//         —— 原列表里的记录一个都不能被改
//
//     static void 演示延迟()                        // 见下面的步骤
//         var 数们 = new List<int> { 1, 2, 3 };
//         var 查 = 数们.Where(数 => 数 > 1);         // 先定义
//         数们.Add(99);                              // 再改数据
//         foreach (var 数 in 查) Console.WriteLine(数);   // 最后才枚举
//
//     record 成绩记录(string 名字, int 分数);
//
//   ⚠ `演示延迟` 的输出应该是三行：2 / 3 / 99 —— 99 必须出现，
//     它出现才证明你真的把查询定义在 Add 之前了。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 15
```

### 参考答案

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

record 成绩记录(string 名字, int 分数);

static int[] 挑偶数(int[] 数们)
{
    return 数们.Where(数 => 数 % 2 == 0).ToArray();
}

static List<成绩记录> 加一分(List<成绩记录> 们)
{
    // ⚠ 位置式 record 的属性是 init-only，改不了 ⇒ 只能用 with 造新对象
    //    （所以"原列表不变"是天然成立的，但你不能去改 项.分数）
    return 们.Select(项 => 项 with { 分数 = 项.分数 + 1 }).ToList();
}

static void 演示延迟()
{
    var 数们 = new List<int> { 1, 2, 3 };

    // ⚠⚠ 这一行只是"配方"：一个元素都还没看
    var 查 = 数们.Where(数 => 数 > 1);

    // 查询定义**之后**才加的数据
    数们.Add(99);

    // 直到这里才真的开跑 —— 所以 99 也在结果里
    foreach (var 数 in 查)
    {
        Console.WriteLine(数);
    }
}
```

### 检查规格

```
用了 Where 和 Select | 代码包含 | .Where(
Select 用的是 with 造新记录（不是改原对象） | 代码包含 | with {
挑偶数：多组都对，含空数组 | 函数用例 | 挑偶数 | new int[]{1,2,3,4,5} | 2,4 | new int[]{1,3,5} | (空) | new int[]{2,4,6} | 2,4,6

延迟执行：查询定义在 Add 之前 ⇒ 99 必须出现 | 输出逐行 | 2 | 3 | 99

> ⚠ 给编写检查的人，三处要点：
> 1. `加一分` 的两条 `连调用` 其实测的是**同一个表达式**。真正要抓的是
>    "原列表没被改"，建议补一条：先在调用点里存下原对象，
>    调用后再打印它的分数，期望还是 `59`。
> 2. `延迟执行` 那条的调用点必须写成 `演示延迟();`（`void` 方法取不到返回值），
>    走"裸成员 + 骨架调用点"那条路，不能走 `函数用例`。
> 3. `挑偶数` 的「(空)」表示**空数组** —— 检查器期望 0 行输出，
>    或按你们的约定写成空字符串，别照抄字面量。

## 第 16 课：综合练习 —— 学生成绩统计

### 要求

1. 写 `static (int 人数, int 及格, double 平均, string 头名) 统计(List<成绩记录> 们, int 及格线)` —— 空列表返回 `(0, 0, 0, "")`；否则人数、及格人数、平均分（`Math.Round` 保留两位小数）、分数最高者的名字（同分按名字 `StringComparer.Ordinal` 排，保证稳定）
2. 写 `static bool 不及格(成绩记录 r, int 及格线)` —— 一行，用模式匹配
3. 写 `static string 报警(成绩记录 r)` —— 用 switch 表达式：空名字 ⇒ `"名字是空的"`、分数 `< 0` 或 `> 100` ⇒ `"数据异常"`、`< 60` ⇒ `"不及格"`、其余 ⇒ `"正常"`
4. 写 `static List<string> 名字们(List<成绩记录> 们)` —— LINQ：筛掉空名字 → 按分数从高到低 → 取名字 → `ToList`
5. `record 成绩记录(string 名字, int 分数);` 自己补上

### 讲解

```
// 第 16 课：综合练习 —— 学生成绩统计
//
// ══ 这一课不是新语法 ══
//
//   是把 09~15 拼起来做一个小东西。先把账对一下：
//
//     第 09 课  record + 元组         ← 成绩记录、统计的返回类型
//     第 10 课  属性与访问控制          ← record 的 init 属性
//     第 11 课  override / base       ← 想扩展时可以派生一个"带班号的记录"
//     第 12 课  List<T>               ← 数据放在哪
//     第 13 课  异常                  ← 空列表这个边界情况
//     第 14 课  模式匹配               ← 报警()
//     第 15 课  LINQ                  ← 名字们()
//
//   任务是：**统计一群学生的成绩**。
//
//
// ══ 一、先把数据形状定下来 ══
//
//   第 09 课讲过：一条"内容说了算"的数据 ⇒ **record**，不是 class。
//
//       record 成绩记录(string 名字, int 分数);
//
//   为什么是 record 而不是 class？回头看一眼第 09 课那张表：
//     · 两条内容一样的记录，`==` 相等、`Equals` 相等、`Contains` 找得到
//     · `ToString()` 是可读的
//     · `with` 能"改一个字段、其余照抄"
//   这三样在统计代码里全都要用（下面 `报警` 的测试就靠 `==` 比内容）。
//
//   ⚠ 位置式 record 的属性是 `{ get; init; }` —— **构造完就不能再赋值**。
//     想"分数加一"只能造新的：`项 with { 分数 = 项.分数 + 1 }`。
//     这一条是第 09 课的坑 2，这里会真的撞上。
//
//
// ══ 二、`统计` 的返回类型：为什么用元组 ══
//
//   要一次交回四样东西。四种做法：
//
//     ① 四个 out 参数 → 签名长得没法看，还要求调用方预先声明四个变量
//     ② 专门定义一个 `class 统计结果` → 为一次返回造一个类型，重了
//     ③ 返回 `List<object>` → 类型全丢了，取的时候要强转
//     ④ **元组** `(int 人数, int 及格, double 平均, string 头名)`  ✅
//
//   四个值、就地用完、有名字 ⇒ 元组正合适（第 09 课第四节）。
//   如果这东西要在十几个方法之间传，那就该给它起个名字用 record 了。
//
//   实现要点：
//
//       static (int 人数, int 及格, double 平均, string 头名) 统计(
//           List<成绩记录> 们, int 及格线)
//       {
//           if (们.Count == 0)
//               return (0, 0, 0, "");          // ⚠ 边界先处理掉
//
//           int 人数 = 们.Count;
//           int 及格数 = 们.Count(项 => 项.分数 >= 及格线);      // ← LINQ 的 Count
//           double 平均 = Math.Round(们.Average(项 => 项.分数), 2);
//           string 头名 = 们.OrderByDescending(项 => 项.分数)
//                          .ThenBy(项 => 项.名字, StringComparer.Ordinal)
//                          .Select(项 => 项.名字)
//                          .First();
//           return (人数, 及格数, 平均, 头名);
//       }
//
//   ⚠⚠ **空列表必须特判**，三个原因，一个比一个硬：
//
//     · `Average()` 在空序列上会抛
//       `System.InvalidOperationException: 序列不包含任何元素`
//     · `First()` 在空序列上抛同一个异常
//     · 就算你躲开了这两个，"平均分"在**零个人**时该是多少？没有定义。
//       ⇒ 返回 (0, 0, 0, "") 是明确说"没有数据"，比返回 0 清楚。
//
//     这和 C 课第 16 课那个 `if (个数 <= 0) return;` 是同一件事：
//     **统计函数的第一个 if 永远是"空的时候怎么办"。**
//
//   ⚠ `Average(项 => 项.分数)` 返回的是 `double`（分数虽然是 int，
//     但它会先转成 double 再算，**不会有整数除法的坑**）。
//     这跟第 13 课你自己手写 `(double)和 / 个数` 是一回事，LINQ 替你做掉了。
//
//   ⚠ 同分怎么办？`OrderByDescending` 只按分数排，两个人同为最高分时
//     `First()` 取到哪个**不保证**。要结果稳定就再加一级：
//         .ThenBy(项 => 项.名字, StringComparer.Ordinal)
//     （`StringComparer.Ordinal` 是按字符编码比，和区域设置无关 ⇒ 跨机器可复现。
//      第 12 课的 `名次表` 用的也是它。）
//
//
// ══ 三、`报警`：模式匹配的用武之地 ══
//
//   这一段有四种情况，而且**顺序有讲究** —— "名字空"最优先：
//
//       static string 报警(成绩记录 r) => r switch
//       {
//           { 名字: "" }              => "名字是空的",
//           { 分数: < 0 or > 100 }    => "数据异常",
//           { 分数: < 60 }            => "不及格",
//           _                         => "正常",
//       };
//
//   为什么"名字空"要排第一：一个名字为空 **且** 分数 200 的记录，
//   两条规则都命中 —— 谁在前面谁说了算。
//   数据本身就不合法时，"数据有问题"比"分数异常"更该先说。
//
//   ⚠ 属性模式的写法是 `{ 属性名: 模式 }`，冒号。
//     写成 `{ 名字 = "" }` 会报 `CS1003: 语法错误`（第 14 课的坑 7）。
//
//   ⚠ `{ 分数: < 0 or > 100 }` 里的 `or` 是**模式**的连接词，
//     不是 `||`。它是"分数这个位置上的值，匹配 `< 0` **或** `> 100`"。
//
//   ⚠ switch 表达式必须穷尽 ⇒ 保留 `_ => "正常"`。
//     漏了它只有一条警告，运行时遇到没覆盖的值直接抛。
//
//
// ══ 四、`名字们`：LINQ 三步，顺序别乱 ══
//
//       static List<string> 名字们(List<成绩记录> 们)
//       {
//           return 们.Where(项 => 项.名字 != "")            // ① 筛掉空名字
//                    .OrderByDescending(项 => 项.分数)      // ② 按分数降序
//                    .Select(项 => 项.名字)                 // ③ 只要名字
//                    .ToList();                             // ④ 收口
//       }
//
//   ⚠ **`Select` 必须在排序之后。** 顺序反了会怎样？
//
//         们.Select(项 => 项.名字).OrderByDescending(名 => 名)
//         //                               ↑ 现在 名 是 string
//         //                                  ⇒ 变成按**名字的字典序**排
//
//     症状：**不报错**，能编译（string 也能排序），但结果是按姓氏排的，
//           不是按分数排的。这是"能跑但错"的一类。
//     为什么：`Select` 之后元素就变成 string 了，后面所有操作都作用在 string 上。
//     ⇒ 记法：**先筛（Where）、再排（OrderBy）、后投影（Select）、最后收口。**
//        `Select` 把它左边的"丰富信息"压扁了，压扁之后就拿不回来了。
//
//   ⚠ 第 15 课的延迟执行在这里也踩得到：
//     这个方法**最后有 `.ToList()`**，所以返回的列表是**当下**数据的快照。
//     把 `.ToList()` 去掉（返回类型改成 `IEnumerable<string>`）也合法，
//     但那之后调用方每次遍历都会重新读一遍原列表 ——
//     **一边遍历一边往原列表加人**就会撞上 `集合已修改` 异常。
//
//   ⚠ `.Where(项 => 项.名字 != "")` 里比较的是**内容**（不是引用），
//     所以是对的。若换成 `!= null`，空串会漏过去 —— 两种"空"不一样。
//
//
// ══ 五、常见坑（这一课会真的撞上的）══
//
//   坑 1：空列表直接算 ⇒ 抛异常
//
//       double 平均 = 们.Average(项 => 项.分数);      // 们 是空列表
//
//     症状：`System.InvalidOperationException: 序列不包含任何元素`
//           —— 报错在 `Average` 那一行，但你会怀疑是数据源的问题。
//     为什么：平均值是"和 ÷ 个数"，个数是 0 —— 结果没有定义，所以抛。
//     改法：方法**第一行**就 `if (们.Count == 0) return (0, 0, 0, "");`
//
//   坑 2：想改 record 的字段
//
//       项.分数 += 1;                              // ❌
//
//     症状：`error CS0200: 属性或索引器"成绩记录.分数"不能分配给 —— 它是只读的`。
//     为什么：位置式 record 生成的是 `{ get; init; }`，只有 init 没有 set。
//     改法：`项 with { 分数 = 项.分数 + 1 }` 造一个新的（第 09 课坑 2 + 第 15 课）。
//
//   坑 3：`Select` 写在了 `OrderBy` 前面
//
//     见上一节。症状是**结果顺序不对但编译通过**。
//
//   坑 4：平均分算成了整数（自己手写循环时）
//
//       return (double)(和 / 个数);                 // ❌ 括号包错了
//
//     症状：平均分永远是整数，比如 87.5 变成 87。
//     为什么：`和 / 个数` 两边都是 int ⇒ **先**做了整数除法（向零取整），
//           取整完了才转 double —— 小数早就没了。
//     改法：`(double)和 / 个数` —— **强转要写在除法之前**，让其中一边先变成 double。
//           或者干脆用 `们.Average(...)`。
//
//   坑 5：switch 表达式漏了兜底
//
//       static string 报警(成绩记录 r) => r switch
//       {
//           { 分数: < 60 } => "不及格",
//       };
//
//     症状：`warning CS8509: 表达式不涵盖其输入类型的所有可能值`；
//           分数是 90 时运行期抛非穷举异常。
//     为什么：switch 表达式要"整体有一个值"，没匹配上就没值可给。
//     改法：`_ => "正常"`。对 record + 开放取值的属性，兜底是**必需项**。
//
//   坑 6：`First()` 用在可能空的序列上
//
//       string 头名 = 们.Where(项 => 项.分数 >= 100).Select(项 => 项.名字).First();
//
//     症状：`System.InvalidOperationException: 序列不包含任何元素`。
//     为什么：`First()` 承诺一定给一个。全都不到 100 分时它给不出。
//     改法：`FirstOrDefault()`（引用类型给 null），或者先 `Any()` 问一句。
//           ⚠ 但注意：`FirstOrDefault` 之后拿到的是 **null**，
//             再 `.Length` 就 NullReferenceException —— 换了个地方崩而已。
//             要真的稳妥，就 `?? ""` 兜一下。
//
//   坑 7：为了"快"用 Dictionary 统计，然后用 `表[键] += 1`
//
//       var 计数 = new Dictionary<string, int>();
//       foreach (var 项 in 们) 计数[项.名字] += 1;     // 💥 第一次就炸
//
//     症状：`System.Collections.Generic.KeyNotFoundException`。
//     为什么：`计数[名字] += 1` 展开是 `计数[名字] = 计数[名字] + 1` ——
//           先去**读** `计数[名字]`，而那个键第一次出现时还不存在 ⇒ 读就炸了。
//     改法：
//       · `计数[名字] = 计数.TryGetValue(名字, out int c) ? c + 1 : 1;`
//       · 或者 `计数[名字] = 计数.GetValueOrDefault(名字) + 1;`
//       · 或者干脆交给 LINQ：
//           `们.GroupBy(项 => 项.名字).ToDictionary(g => g.Key, g => g.Count())`
//     这是第 12 课坑 1 和坑 3 的组合拳，统计类代码里极常见。
//
//
// ══ 轮到你了 ══
//
//     record 成绩记录(string 名字, int 分数);
//
//     static (int 人数, int 及格, double 平均, string 头名) 统计(
//         List<成绩记录> 们, int 及格线)
//         —— 空列表 ⇒ (0, 0, 0, "")
//            平均分**保留两位小数**（用 Math.Round(x, 2)）
//            头名 = 分数最高者的名字（同分按名字 Ordinal 排，保证稳定）
//
//     static bool 不及格(成绩记录 r, int 及格线)
//         —— 一行，用模式匹配
//
//     static string 报警(成绩记录 r)
//         —— switch 表达式，四种结果
//
//     static List<string> 名字们(List<成绩记录> 们)
//         —— 筛空名字 → 按分数降序 → 取名字 → ToList
//
//   ⚠ 元组返回的**平均分是 double 且已经四舍五入到两位**，
//     所以你 `Console.WriteLine(统计(...).平均)` 会看到 86.67 这样的数。
//
// 写完后运行：dotnet run --project csharp/cs-lessons 检查 16
```

### 参考答案

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

record 成绩记录(string 名字, int 分数);

static (int 人数, int 及格, double 平均, string 头名) 统计(
    List<成绩记录> 们, int 及格线)
{
    // ⚠ 统计函数的第一件事永远是"空的时候怎么办"
    //   Average / First 在空序列上都会抛 InvalidOperationException
    if (们.Count == 0)
    {
        return (0, 0, 0, "");
    }

    int 人数 = 们.Count;
    int 及格数 = 们.Count(项 => 项.分数 >= 及格线);
    double 平均 = Math.Round(们.Average(项 => 项.分数), 2);   // Average 自己就是 double

    // ⚠ 同分时加一级名字排序，结果才稳定（不然 First 取到谁不保证）
    string 头名 = 们.OrderByDescending(项 => 项.分数)
                    .ThenBy(项 => 项.名字, StringComparer.Ordinal)
                    .Select(项 => 项.名字)
                    .First();

    return (人数, 及格数, 平均, 头名);
}

static bool 不及格(成绩记录 r, int 及格线)
{
    // 模式匹配一行搞定 —— 等价于 r.分数 < 及格线
    return r is { 分数: < 及格线 };
}

static string 报警(成绩记录 r) => r switch
{
    // ⚠ 顺序：数据本身不合法的最优先说
    { 名字: "" }           => "名字是空的",
    { 分数: < 0 or > 100 } => "数据异常",
    { 分数: < 60 }         => "不及格",
    _                      => "正常",
};

static List<string> 名字们(List<成绩记录> 们)
{
    // ⚠ 顺序不能乱：先筛、再排、后投影、最后收口
    //   把 Select 提到 OrderBy 前面 ⇒ 变成按"名字"的字典序排，而且不报错
    return 们.Where(项 => 项.名字 != "")
             .OrderByDescending(项 => 项.分数)
             .Select(项 => 项.名字)
             .ToList();
}
```

> ⚠ 给编写检查的人，两条要点：
> 1. `连调用` 的「统计」第一格是**表达式**，检查器包进 `Console.WriteLine(...)` 比对字符串。
>    `86.67` 这个期望值依赖 `Math.Round` 的舍入 —— `(90 + 80 + 90) / 3 = 86.666…`，
>    `Math.Round(86.66666666666667, 2)` 是 `86.67`（默认银行家舍入在这里不受影响，
>    因为第三位小数是 6）。如果将来换数据，要重新算一遍。
> 2. `统计(...).头名` 期望 `"甲"` 这件事**依赖 `ThenBy(StringComparer.Ordinal)`**：
>    甲(90) 和 丙(90) 同分，Ordinal 下 `丙` 的码位大于 `甲`，所以 `甲` 排在前面。
>    学员如果漏了那一级 ThenBy，这条可能**碰巧过、也可能不过** ——
>    这正是我们想要的：漏了就不稳定，报错信息里应当点明"同分需要次级排序"。
