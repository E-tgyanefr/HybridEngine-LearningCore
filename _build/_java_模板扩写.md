// 第 00 课：跑通第一个程序 —— 把 JDK 装好
//
// ─────────────────────────────────────────────────────
//  先介绍：本课的唯一目标
// ─────────────────────────────────────────────────────
//
// ⚠⚠ 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
//
//    为什么把它排在第 00 课：
//      Java **不是"装上就能跑"的语言** —— 它要 JDK，而网上大量教程
//      让人装的是 JRE。**JRE 里没有 javac**，于是他永远编不过，
//      还找不到原因。这一步值得单独占一课。
//
//    还有一个理由：所有教程里，**"卡在装工具"是放弃率最高的一步**。
//      大多数人不是学不会编程，而是在"第一步就跑不起来"那里放弃了。
//
//    跑通之后你拿到的是**信心**：后面每一课的报错才都是"我写错了"，
//      而不是"环境又怎么了"。
//
// ─────────────────────────────────────────────────────
//  用法与例子：需要什么、Java 程序长什么样
// ─────────────────────────────────────────────────────
//
// 一、需要什么（两样，都是免费的）
//
// ① .NET SDK —— 课程运行器。它替你调 javac 和 java，并跑起来看结果。
//
//      winget install Microsoft.DotNet.SDK.8
//
//    ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
//
// ② JDK —— Java 的开发包。**不是 JRE。**
//
//      winget install Microsoft.OpenJDK.21     （或去 adoptium.net 下 Temurin）
//
//  ⚠⚠ **JDK ≠ JRE** —— 这是这一课最重要的一句话：
//
//        JRE = Java Runtime Environment    只能**运行**别人编好的程序
//        JDK = Java Development Kit        = JRE + **javac 编译器** + 工具
//
//    只装 JRE 的话，`java` 有、`javac` 没有 —— 而你要**自己写代码**，
//    就必须要 javac。报错会是「找不到 javac」或「不是内部或外部命令」。
//
//  装完**重开一个窗口**（让 PATH 生效），敲这两条，都能看到版本号才算成：
//
//      javac -version
//      java  -version
//
// 二、Java 的程序结构：和 C 完全不同的三点
//
// ① **不能有游离的代码。** 每一样东西都必须装在一个**类**里面。
//
//      Python 可以:   print("hi")                    ← 文件顶层直接写
//      C 可以:        int main() { printf(...); }    ← 函数里直接写
//      Java 不行:     必须 类 → 方法 → 语句，一层套一层
//
//   在文件顶层直接写一句 System.out.println("hi"); 会报：
//      Main.java:1: 错误: 需要类、接口、批注类型、枚举、记录、方法或字段
//
// ② **入口方法长这样**，一个字都不能错：
//
//      public static void main(String[] args) { ... }
//      ↑      ↑      ↑    ↑      ↑
//      公开   静态   无返回 方法名  参数（一个字符串数组）
//
//   少了 static ⇒ 老版本 JDK 上程序起不来 —— Java 新手最常卡的第一处。
//   ⚠ 但 **JDK 25 放宽了这条**：漏 static、漏 public、甚至没参数，
//     实测都能编译能跑。所以「在我机器上能跑」不等于写对了。
//
// ③ **public 的类名必须和文件名一致**（区分大小写）：文件叫 Main.java，
//   类就必须叫 `public class Main`；写成 public class main 会编译报错。
//   这一条**别的语言都没有**。C 的 main 是小写的函数，而 Java 的 main 是
//   方法、类才是外壳 —— 别把两件事混起来。
//
// ④ 它还多一层：字节码（不是机器码）
//
//      Main.java  --(javac)-->  Main.class  --(java Main)-->  结果
//                                 ↑ 字节码，由 JVM 在运行时翻译
//
//   ⚠ 所以运行的时候写的是 **java Main**（一个**类名**，不带后缀）：
//        java Main.class     ✗ 错误: 找不到或无法加载主类 Main.class
//        java Main.java      ⚠ 新版 JDK（11 起）碰巧也能跑 —— 它把源码
//                              直接编译再运行，另一套机制。别依赖它。
//
// 三、这一课唯一要练的手艺：读第一条 error
//
//  Java 的报错长这样（这是**故意写错**的代码）：
//
//      Main.java:5: 错误: 需要';'
//          System.out.println("你好")
//                                 ^
//      1 个错误
//
//  拆开看：**哪个文件、第几行、什么错**。先看行号。
//
//  ⚠⚠ **两条铁律**：① **只看第一条 error** —— 后面那几十条多数是它引起的
//   连锁反应；② **报错行号常常要往上多看一行** —— 编译器是读到"它不认识的
//   东西"才报的错，而那个东西往往是**上一行**漏了什么造成的。
//
//  ⚠ 本机是中文环境，javac 的报错就是中文的。换一台英文环境的机器，
//    同样的错会写成 `error: ';' expected` —— **是同一件事**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：装的是 JRE，不是 JDK
//
//     winget install Microsoft.OpenJDK.21     ← 对的
//     （网上很多教程让人装"Java 运行时 / JRE"—— 那个**没有 javac**）
//
// 你会看到：敲 `javac -version` 说「不是内部或外部命令」，或者课程检查
//   一上来就红，写着「工具链还没装好」。
// 为什么：**编译器 javac 只在 JDK 里**；JRE 是给"只想运行别人程序"的人用的。
// ⇒ 再装一次 JDK 就好，两个可以共存，不用先卸。
//   ⚠ 这条**不是你代码的问题** —— 第一项检查专门在说这件事。
//
// ⚠ 坑 2：装完不重开窗口
//
// 你会看到：`javac` 还是"不是内部或外部命令"—— 明明刚才装的时候提示成功了。
// 为什么：安装程序改的是 **PATH 环境变量**，而已经打开的窗口用的是
//   **打开那一刻**的 PATH 副本。
// ⇒ 关掉窗口重新开一个（或者干脆注销一次）。
//   ⚠ 这个坑在 C 线（装 gcc）和 C# 线（装 .NET SDK）**一模一样**，
//     凡是"装完说找不到命令"，先想这一条。
//
// ⚠ 坑 3：运行的时候把 .class / .java 也写上去
//
//     java Main.class
//
// 你会看到：错误: 找不到或无法加载主类 Main.class
//   原因: java.lang.ClassNotFoundException: Main.class
// 为什么：`java` 收的是**类名**，它自己去 classpath 上找 Main.class；
//   你多写的那截后缀被当成了类名的一部分，自然找不到。
//   ⚠ 这条**不是编译错误** —— 编译早就成功了，是"运行"那一步的命令写错了。
//
// ⚠ 坑 4：类名和文件名不一致
//
//     public class main { ... }        ← 文件叫 Main.java，类却叫 main
//
// 你会看到：Main.java:1: 错误: 类 main 是公共的, 应在名为 main.java 的文件中声明
// 为什么：**一个 .java 文件里的 public 类，名字必须和文件名一模一样**
//   （连大小写都要一样）。这是 Java 独有的规矩。
// ⇒ 这个文件叫 Main.java，所以类只能叫 `public class Main`。
//
// ─────────────────────────────────────────────────────
//  轮到你了
// ─────────────────────────────────────────────────────
//
//  这一课没有算法要写，只有三件事：
//
//    1. 确认 javac、java、dotnet 都在
//       （界面首页的「环境自检」会显示；命令行敲 javac -version 也行）
//
//    2. 让编译器**报一次错**，并且读懂它
//       下面留了一个完整的程序。先故意漏掉一个分号 → 检查 → 看报错 →
//       把分号补上 → 再检查。为什么要你故意写错一次：**报错是编译器在
//       跟你说话**，第一次被它骂过的人，第二次才不慌。
//
//    3. 让它打印出下面这三行，就算跑通了（**顺序**别改）
//
//          工具链就绪
//          我准备好学 Java 了
//          类 → main → 语句
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────
//   点界面上的「检查」。命令行（在源码目录里）：
//
//       dotnet run --project csharp/java-lessons 检查 00
//
//   看这一课要干什么：dotnet run --project csharp/java-lessons 00
//   看答案（先自己写一遍）：dotnet run --project csharp/java-lessons 答案 00
//
//   ⚠ 如果第一项检查（工具链）就红了，**那是环境问题，不是你代码的问题** ——
//     按上面「常见坑」的坑 1 / 坑 2 排查，别去改代码。
//
// ── 在下面写你的代码 ──

public class Main {
    public static void main(String[] args) {
        System.out.println("工具链就绪");
        /* ⚠ 先故意把下面这一行的分号删掉，检查一次，看看 javac 怎么说。

// 第 01 课：输出与变量 —— 让程序开口说话
//
// ─────────────────────────────────────────────────────
//  先介绍：程序得先能"说话"
// ─────────────────────────────────────────────────────
//
// 一个程序如果什么都不输出，你就**看不见它在干什么** —— 算得对不对、
// 走到哪一步了、是不是根本没跑，你全不知道。所以每一门语言的第一课
// 都是同一件事：**把东西打到屏幕上**。
//
// 第二件事是**记住数据**：
//
//     System.out.println(6 + 7);        ← 只能算这一次
//     int 甲 = 6;                        ← 把 6 存进一个叫「甲」的格子
//     int 乙 = 7;
//     System.out.println(甲 + 乙);       ← 以后想算几次算几次
//
// 变量的价值不在"少打几个字"，而在**给数据起了名字**：以后要改，只改
// 声明那一行，用到它的地方全都跟着变。把答案 13 写死，这个程序就永远
// 只会算这一道题。
//
// ⚠ Java 和前面几门语言最不一样的一点：**什么都得写在类里面**。
//   Python 可以在文件顶层写 print("hi")；C 可以在 main 里直接写；而 Java
//   里**每一样东西都必须装在一个类里面** —— 没有游离的代码。所以第一课
//   先把这条链路走通：**类 → main 方法 → 语句**，三层缺一不可。
//   忘了这条会看到：错误: 需要类、接口、批注类型、枚举、记录、方法或字段
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 一个能跑的最小程序
//
//     public class Main {
//         public static void main(String[] args) {
//             System.out.println("你好，Java");
//         }
//     }
//
//   public class Main 是**外壳**（名字必须和文件名一致），main 是**入口**
//   （程序从这一行开始跑），里面那条才真正干活。
//
// ② println 和 print 差一个换行；文字要用双引号包起来
//
//     System.out.println("你好，Java");     打了之后**换行**（ln = line）
//     System.out.print("你好，Java");       打了之后**不换行**
//     System.out.println(你好，Java);       ✗ 编译器会去找一个叫「你好」的东西
//
//   引号里的内容**原样打出来**，包括空格和标点 —— 一个字符都不会变。
//
// ③ 变量：先写类型，再写名字，再给初值
//
//     int 甲 = 6;                            ← int 是"装整数的格子"
//     int 乙 = 7;
//     System.out.println(甲 + 乙);           ⇒ 13
//
//   ⚠ 类型**必须写**。Python 写 甲 = 6 就行，Java 必须写 int 甲 = 6;
//   ⚠ 等号是**英文**的 =，分号是**英文**的 ;，中文标点编译器不认。
//
// ④ + 有两种意思，看两边是什么
//
//     System.out.println(甲 + 乙);           ⇒ 13      ← 两边都是数字：加法
//     System.out.println("和=" + 甲);        ⇒ 和=6    ← 有一边是文字：拼接
//     System.out.println("和=" + 甲 + 乙);   ⇒ 和=67   ✗
//     System.out.println("和=" + (甲 + 乙)); ⇒ 和=13   ✓ 想先算加法就加括号
//
// ⑤ 变量可以改：甲 = 甲 + 1; 之后 甲 就是 7（右边先算，再存回左边的格子）。
// ⑥ 注释：// 后面这一行不算代码，编译器直接跳过。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：类名和文件名对不上
//
//     public class main {            ← 文件叫 Main.java，这里却写了小写 main
//
// 你会看到：错误: 类 main 是公共的, 应在名为 main.java 的文件中声明
// 为什么：**一个 .java 文件里的 public 类，名字必须和文件名一模一样**，
//   连大小写都要一样。Java 的规矩，别的语言没有这一条。
// ⇒ 你的答题文件叫 Main.java，所以类只能叫 `public class Main`。
//
// ⚠ 坑 2：分号打成了中文的 ；
//
//     System.out.println("你好，Java")；        ← 最后这个是全角的 ；
//
// 你会看到：错误: 非法字符: '\uff1b'      （\uff1b 就是全角分号的编号）
// 为什么：javac 只认**半角符号**。中文输入法下打标点很容易出这个错，而且
//   它长得和 ; 几乎一样，肉眼很难发现。同类还有中文逗号、括号、引号。
// ⇒ 写 Java 代码时把输入法切到英文，或者至少切到"英文标点"。
//
// ⚠ 坑 3：引号用了中文的 “ ”，或者文字里的标点跟题目不一样
//
//     System.out.println(“你好，Java”);
//
// 你会看到：错误: 进行语法分析时已到达文件结尾
// 为什么：编译器不认全角的 “ ”，它以为这个字符串到文件末尾都没结束。
//   ⚠ 这条报错的**行号会指到最后一行**，看着像"别的地方出错了"——
//     其实问题就在你写引号的那一行。
// ⇒ 它还有个**更隐蔽**的版本：字符串里的逗号用了中文的
//     System.out.println("你好，Java");     ← 这样**不报错**
//   编译完全通过，只是打出来的是「你好，Java」而不是「你好,Java」——
//   检查一比对文字就红了。**字符串里的标点也要和题目一模一样。**
//
// ⚠ 坑 4：把「拼接」当成了「加法」
//
//     System.out.println("和=" + 甲 + 乙);       ⇒ 和=67      ✗
//
// 你会看到：**什么都不报**，程序跑得好好的，只是结果不对。
// 为什么：+ 从左往右算。先算 "和=" + 甲 —— 左边是文字，于是这一步变成
//   **拼接**，得到 "和=6"；再 + 乙 还是拼接 → "和=67"。一旦 + 的某一边是
//   String，它就变成拼接，而且**改不回来**了。
// ⇒ 想先算加法就把算式用括号圈起来："和=" + (甲 + 乙)
//   ⚠ 它的错法是**静默的**：不报错、不警告，只有结果悄悄不对。
//
// ⚠ 坑 5：语句写在了类外面
//
//     System.out.println("你好，Java");        ← 文件里就这么孤零零一句
//
// 你会看到：错误: 需要类、接口、批注类型、枚举、记录、方法或字段
// 为什么：Java **没有游离的代码**，每条语句都必须待在「类 → 方法 → 语句」
//   这三层里面。忘了写 main、或者花括号配对搞错，也会得到同一句话。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
// ⚠ 要写一个**完整程序**：public class Main + main 方法，两样都要有。
//
//   1. 打印一行：你好，Java
//   2. 定义两个 int 变量：甲 = 6、乙 = 7
//   3. 打印它们的和（应该是 13）
//      ⚠ 必须**真的用变量相加**，不要把 13 写死：
//            System.out.println(13);              ✗ 检查会看穿（见下）
//            System.out.println(甲 + 乙);         ✓
//        为什么较这个真：把答案写死，这个程序就只能算这一道题。
//
// ⚠ 记住三件事（这一课的门槛全在这儿）：
//   · 入口方法必须写成 public static void main(String[] args)
//   · 打印用 System.out.println(...)
//   · 每条语句末尾要有分号 ;（半角）
//
// ⚠ 一个 .java 文件里 public 类只能有一个，而且必须叫 Main。
//
// 期望输出两行：你好，Java / 13
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────
//   点界面上的「检查」。命令行（在源码目录里）：

//
// ── 在下面写 ──

// 第 02 课：输入与计算 —— 让程序接收数据
//
// ─────────────────────────────────────────────────────
//  先介绍：程序得能"听"
// ─────────────────────────────────────────────────────
//
// 第 01 课的程序只会自己说话，不会听 —— 想换一组数据，只能改代码再跑。
// 这一课让程序**接收输入**：从此同一个程序能处理不同的数据。
//
// 但"输入 + 计算"在 Java 里带来两个**不报错的坑**，这一课的重点全在这里：
//
//   ① **两个 int 相除，结果还是 int**：7 / 2 得 3，不是 3.5。
//      编译不报错、运行不警告 —— 它就这么安安静静地把小数丢掉了。
//
//   ② **nextInt() 读到不是整数的东西会抛异常**：InputMismatchException，
//      不处理的话程序**当场结束**。
//      ⚠ 这一点和 C++ **相反**：C++ 的 cin 是"静默失败"（不抛异常、把变量
//      写成 0、后面的读入全部失效，程序照跑）；Java 是"当场抛异常"，
//      把问题立刻摆出来。两种设计各有代价，你必须知道自己这门是哪种。
//
// 为什么这两件事值得单占一课：因为它们都是"**看起来成功了，其实错了**"的
//   类型 —— 初学者最怕这种。报错反而好办，不报错才难查。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① Scanner：Java 读输入的标准工具
//
//     import java.util.Scanner;                        ← 写在文件**最上面**
//
//     public class Main {

//   算的时候就已经丢了小数，存的时候救不回来。

// ⇒ 读之前先问一句：if (!输入.hasNextInt()) { ...; return; }
//
// ⚠ 坑 4：先 nextInt() 再 nextLine()，那个 nextLine 读到的是"剩下的东西"
//
//     int 甲 = 输入.nextInt();          ← 输入这一行是 "7 2"

//   回车，那它读到的是**空串**。程序不报错，只是名字是空的。
// 为什么：nextInt() 只吃掉**数字本身**，把这一行剩下的东西（空格、以及结尾

// 第 03 课：条件判断 —— 让程序会做选择
//
// ─────────────────────────────────────────────────────
//  先介绍：程序要会"分岔"
// ─────────────────────────────────────────────────────
//
// 到上一课为止，程序只会一条道走到黑。但真实的需求几乎都是"看情况"：
// 猜的数字比 42 大就告诉他"大了"；分数够 90 就是"优秀"；
// 今年是闰年 2 月就多一天。条件判断让程序**分岔** —— 同一段代码，
// 不同的数据走不同的路。这是"程序开始像在思考"的第一步。
//
// Java 的条件和别的语言长得差不多，但有**一条特别值得讲**：它对 `=` 和 `==`
// 的检查比 C/C++ 严 —— 可是**只严一半**。
//
//     if (分数 = 3)        编译不过（int 不是 boolean，Java 当场拦住你）
//     if (年 % 4 = 0)      编译不过（报「意外的类型」）
//     if (标志 = true)     **能编译、零警告，而且条件永远为真**  ← 真正的坑
//
// 前两种编译器替学生挡了，第三种挡不住。所以这一课的核心就盯它。
// （这三条都是本机 javac 25.0.3 实测的结果。）
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① if / else if / else：从上往下试，**第一个为真的就进去**
//
//     if (分数 >= 90) {
//         return "优秀";
//     } else if (分数 >= 60) {
//         return "及格";
//     } else {
//         return "不及格";
//     }
//
//   ⚠ 顺序是有意义的：95 同时满足 >= 90 和 >= 60，但它在**第一条**就被接走
//     了。所以判断范围要从"最窄"往"最宽"写。分数 = 105 该走哪条？也是这个理。
//
// ② 比较运算符（结果是 boolean：true 或 false）
//
//     == 等于    != 不等于    > 大于    < 小于    >= 大于等于    <= 小于等于
//
//   ⚠ 等于号是**两个**：判断相等用 ==，一个 = 是**赋值**（把右边存进左边）。
//
// ③ 把几个条件连起来：&& （并且）  || （或者）  ! （取反）
//
//     分数 < 0 || 分数 > 100                              ← 越界判断（两头都要写）
//     (年 % 4 == 0 && 年 % 100 != 0) || 年 % 400 == 0      ← 闰年的完整条件
//
//   ⚠ 优先级：&& 比 || 先算。所以上面那层的括号其实可以省，但**写上更好读**。
//
// ④ boolean 变量：先把结论算出来，再用它判断
//
//     boolean 是闰年 = (年 % 4 == 0 && 年 % 100 != 0) || 年 % 400 == 0;
//     if (是闰年) { return "闰年"; }
//
//   好处：条件太长时**读起来清楚**，而且这个结论还能复用。
//   ⚠ 用 boolean 变量时**直接写它**就行：if (是闰年)。写 if (是闰年 == true)
//     也对，但多打一遍就多一次手滑机会（见坑 1）。
//
// ⑤ switch：一个值对好几个固定选项时，比一串 if 清爽
//
//     switch (星期几) {
//         case 1:  return "星期一";
//         default: return "没有这个星期";       ← default 是兜底，建议写上
//     }
//
// ⑥ 方法里每个分支都要能 return —— Java 会检查"所有能走到的路径都有返回值"。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：把 == 写成了 =（本课最重要的一个坑，它有**三种下场**）
//
//     if (分数 = 3) { }              ← 第一种
//
// 你会看到：错误: 不兼容的类型: int无法转换为boolean
// 为什么：一个 = 是赋值，`分数 = 3` 这个表达式的类型是 **int**，而 if 的括号
//   里**必须是 boolean**。类型对不上，Java 直接拒绝编译。
//   ✅ 好消息：**这一点 Java 比 C/C++ 严** —— C/C++ 对 if (x = 3) 顶多给个
//      警告（甚至不警告），Java 直接不让你编。
//
//     if (年 % 4 = 0) { }            ← 第二种
//
// 你会看到：错误: 意外的类型   /   需要: 变量   /   找到: 值
// 为什么：= 的优先级最低，这一行会被理解成"把 0 存进 年 % 4"—— 可 年 % 4 是
//   一个**算出来的值**，不是变量，存不进去。
//
//     boolean 标志 = false;
//     if (标志 = true) { ... }       ← 第三种：**编译通过，零警告**
//
// 你会看到：什么都不报，而那个分支**永远会进去**（赋值的结果就是刚存进去的
//   true）。这是 Java 唯一挡不住的那一种，也最危险 —— 程序照跑，结果全错。
// ⇒ 防身三招：① 判断相等一律用 ==；② boolean 变量直接写 if (标志)；
//   ③ 把常量写在左边：if (42 == 猜) —— 手滑写成 = 会直接编译不过。
//
// ⚠ 坑 2：漏了 return，或者分支没兜全
//
//     static String 猜数字(int 猜) {
//         if (猜 == 42) { return "对了"; }
//         // 猜比 42 小、比 42 大的情况都没写
//     }
//
// 你会看到：错误: 缺少返回语句
// 为什么：方法声明了要返回 String，可编译器发现"如果 猜 不是 42，这个方法走到
//   末尾也没交出任何东西"—— 它不允许这种可能。
// ⇒ 用 else 兜住剩下的所有情况，或者最后写一句无条件的 return：
//       if (猜 == 42) { return "对了"; }
//       if (猜 < 42) { return "小了"; }
//       return "大了";                 ← 前面都没接住，那一定是大了
//
// ⚠ 坑 3：switch 忘了 break —— "贯穿"，x = 1 时三行全打
//
//     switch (x) {
//         case 1: System.out.println("一");
//         case 2: System.out.println("二");
//         default: System.out.println("其他");
//     }
//
// 你会看到：什么都不报，只是 x = 1 时把「一 / 二 / 其他」三行**全打了出来**。
// 为什么：switch 的规矩是"**从匹配上的那个 case 开始，一路往下执行**"，直到
//   碰上 break 或者整块结束。这叫 fall-through（贯穿），是设计不是 bug。
// ⇒ 每个 case 结尾加 break;（或者像本课这样直接 return，return 本身就跳出了）。

// ⚠ 坑 4：边界写成 > 而不是 >=
//
//     if (分数 > 90) return "优秀";        ← 90 分会掉进下一档

// 你会看到：什么都不报，只是 90 分被判成"及格"、60 分被判成"不及格"。
// 为什么：>= 和 > 只差一个字符，意思差一整档。本课的检查专门放了

// 第 04 课：循环 —— 让程序重复做事，并且重复得**正好**
//
// ─────────────────────────────────────────────────────
//  先介绍：循环是"程序能干活"的开始
// ─────────────────────────────────────────────────────
//
// 求和、计数、查找、遍历 —— 这些活全都是"把同一件事做很多遍"。
// 没有循环，你只能把一行代码抄十遍，改一个地方要改十处。
//
// 但循环有一类和前面完全不同的错法：**它不报错、也不崩**，只是把结果算错
// 一点点，而那一点点很难看出来：
//
//     差一错误（off-by-one）：for (int i = 1; i < n; i++) 少跑一次。
//       算 1..10 的和，它给你 45 —— 看上去像个正常答案。
//     写反方向的差一：for (int i = 0; i <= 次数; i++) 多跑一次，
//       重复 3 遍变成 4 遍 —— 同样一声不吭。
//
// 所以这一课真正的功夫不在"会写循环"，而在**数清楚它跑几遍**。
//
// 还有一个**好消息**：Java 里"累加变量没给初值"是**编译错误**，不是"碰巧算对"。
//       C++：int 和; 里面是内存里的残留值，程序照跑，可能碰巧算出"正确答案"；
//       Java：直接报「可能尚未初始化变量和」，程序根本编译不出来。
//   Java 用一条编译错误，把这类"结果时对时错"的 bug 从你身上拿走了。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① for：**次数已知**的时候用它（最常用）
//
//     for (int i = 1; i <= n; i++) { 和 += i; }     ← 从 1 数到 n（含 n）
//     for (int i = 0; i < n; i++) { 结果 += 文字; }  ← 从 0 数起，一共 n 个
//
//   三个部分读作：**开始**（i = 1）；**继续的条件**（i <= n）；**每次做完
//   干什么**（i++ 就是 i = i + 1）。
//
//   ⚠ 这两种写法都对，但**别混**：
//       从 1 数到 n（含 n）  →  条件写 <= n
//       从 0 数起、一共 n 个  →  条件写 < n
//
// ② while：**以条件为主**，不知道要跑几次
//
//     int 试 = 2;
//     while (试 < n) {
//         if (n % 试 == 0) { ... }
//         试++;
//     }
//
//   先看条件，为真才进。**可能一次都不跑。**
//
// ③ do-while：**至少执行一次**（先做一遍，再看条件）
//
//     do {
//         位++;
//         剩 /= 10;
//     } while (剩 > 0);
//
//   ⚠ 注意结尾那个**分号**，是 do-while 独有的。什么时候非它不可：数位数。
//     n = 0 也是 1 位数，可 while (剩 > 0) 在 n = 0 时一次都不跑，会给出 0 位。
//
// ④ 增强 for：把数组/集合里的元素一个一个拿出来
//
//     for (int x : 数字) { ... }         ← 读作"对于 数字 里的每一个 x"
//
// ⑤ break 和 continue：两个方向的中断
//
//     break      立刻跳出**整个**循环（后面的轮次都不跑了）
//     continue   跳过**这一轮**剩下的部分，直接进入下一轮
//
//   ⚠ 用 continue 时最容易踩的坑：忘了让循环变量往前走 → 死循环（见坑 3）。
//
// ⑥ 累加变量必须给初值：int 和 = 0;（累加用 0）   int 积 = 1;（累乘用 1）
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：差一错误（off-by-one）—— 少跑一次 / 多跑一次
//
//     for (int i = 1; i < n; i++) 和 += i;         ← 少跑一次（最后一个没加）
//     for (int i = 0; i <= 次数; i++) 结果 += 文字;  ← 多跑一次
//
// 你会看到：**什么都不报**。
//   求和(1) 会给出 0（正确答案是 1）；重复("*", 1) 会给出 "[**]"（应该是 "[*]"）。
// 为什么：循环跑几次只由条件决定，编译器不知道"你心里想跑几次"。
// ⇒ **写完循环，一定拿 n = 0 和 n = 1 各在心里走一遍**：n = 0 时该不该跑？
//   n = 1 时该跑几次？这两问答对了，差一错误就躲开了。
//   本课有一条检查专门盯这里，而且它会告诉你**是哪一种**：是"少跑了最后一次"，
//   还是"多跑了一轮"。
//
// ⚠ 坑 2：累加变量没给初值
//
//     int 和;
//     for (int i = 1; i <= n; i++) 和 += i;
//
// 你会看到：错误: 可能尚未初始化变量和
// 为什么：**局部变量必须先赋初值才能用**，Java 会一条一条路径地检查。
//   ✅ 这里必须说一句：**这是 Java 的优点，不是刁难** —— 同样的写法在 C++ 里
//     能编译能运行，因为未初始化的局部变量装的是内存里的残留值：这次碰巧是 0，
//     你的累加就"算对了"，换个编译器、换个运行顺序它又变成别的数 —— 那是最
//     难查的一类 bug。Java 直接不让你编译，等于把这类 bug 拿走了。
// ⇒ 声明的时候就写清楚：int 和 = 0;   int 积 = 1;
//
// ⚠ 坑 3：用 continue 时忘了让循环变量往前走 —— 死循环
//
//     int i = 0;
//     while (i < 10) {
//         if (i % 2 == 0) { continue; }      ← 跳过了下面的 i++，i 永远不变
//         i++;
//     }
//
// 你会看到：程序**一直不结束**（界面上的检查会卡到超时）。不是崩溃，不是报错，
//   就是没完没了。
// 为什么：continue 跳到"下一轮"，而 while 的下一轮又是从同一个条件开始 ——
//   i 一直没变，条件永远为真。
// ⇒ 用 while + continue 时，把"往前走"那一步放在 continue **之前**，或者干脆
//   用 for（for 的 i++ 写在头部，continue 跳不过它）。
//
// ⚠ 坑 4：在 for 的括号里声明的变量，出了循环就没了
//
//     for (int i = 0; i < 3; i++) { ... }
//     System.out.println(i);          ← 这里用不了 i
//
// 你会看到：错误: 找不到符号   符号: 变量 i   位置: 类 Main
// 为什么：`for (int i = ...)` 里的 i 是**这个循环专有的**，它的活动范围就是
//   循环那一对花括号。出去就不认识了。
// ⇒ 要在循环外用到这个数，就把它声明在外面：
//       int i = 0;   for (i = 0; i < 3; i++) { ... }
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
// ⚠ 写五个**方法**（不用写 main、不用写 class、不用写 import ——
//   检查时会自动套进 class Main 里调用）。五个都要写 static。
//
//   1. static int 求和(int n)                ← 用 **for**
//        1 + 2 + ... + n；n <= 0 时返回 0
//
//   2. static String 重复(String 文字, int 次数)   ← 用 **for**
//        例如 重复("*", 3) 得到 "***"
//        次数 <= 0 时返回**空字符串** ""（不是 null，也不是 "null"）
//
//   3. static int 数位数(int n)              ← 必须用 **do-while**
//        n 有几位数字：0 → 1   7 → 1   10 → 2   12345 → 5（n 保证 >= 0）
//      ⚠ 0 也要数出 1 位 —— 想想为什么这一题**非 do-while 不可**：
//        while (剩 > 0) 这种写法在 n = 0 时一次都不跑，会给出 0 位。
//
//   4. static int 最小因数(int n)             ← 用 **while**，找到后用 **break** 跳出
//        n 的最小因数（能整除 n、并且 >= 2 的最小的数）
//          9 → 3      10 → 2      4 → 2      49 → 7
//        n < 2 时返回 -1；找不到因数（n 是质数）就返回 n 本身：7 → 7
//
//   5. static int 偶数个数(int[] 数字)        ← 用**增强 for**，用 **continue** 跳过奇数
//        偶数个数(new int[]{1, 2, 3, 4}) → 2；空数组 → 0
//
// 三种循环的分工：for 次数已知（最常用）；while 以条件为主；do-while **至少

// 第 05 课：函数与 static —— 把计算打包，想用几次用几次
//
// ─────────────────────────────────────────────────────
//  先介绍：给一段计算起个名字
// ─────────────────────────────────────────────────────
//
// 前三课的代码都是一条道写到底。可有些计算你会用很多次：
//
//     int a = 6 * 2;
//     int b = 7 * 2;
//     int c = n * 2;
//
// 抄三遍还行，抄三十遍就有两个问题：**打错一个字就错一处**，而且想改规则
// （比如改成乘 3）得挨个改。
//
// 方法（Java 里"函数"就叫**方法**）解决的就是这件事：
// **把一段计算打包、起个名字，以后叫名字就行。**
//
//     static int 加倍(int n) {
//         return n * 2;              ← 交出去的东西
//     }
//
//     System.out.println(加倍(6));   ⇒ 12
//     System.out.println(加倍(100)); ⇒ 200
//
// 关键在那个参数 n：**同一个方法，喂不同的数据，给不同的结果**。这才叫
// "打包"，否则只是把一行代码挪个地方。
//
// ⚠ 但 Java 的方法比 C++ / Python 多一道门槛：**static**。原因是 Java 里所有
//   方法都住在类里面，而"调用一个方法"有两种方式：
//
//     · 写了 static 的方法属于**类**   —— 直接写名字就能调用
//     · 不写 static 的方法属于**对象** —— 必须先 new 一个对象出来
//
//   而 main 是 static 的：程序刚启动的那一刻一个对象都还没有，所以从 main 里
//   直接写名字调用的方法，**也必须是 static 的**。漏写 static，你会看到：
//       错误: 无法从静态上下文中引用非静态 方法 加倍(int)
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 一个方法有四个部分，缺一不可
//
//     static  返回类型  方法名 (参数类型 参数名) {
//         方法体
//         return 结果;
//     }
//
//     static int 加倍(int n) {
//         return n * 2;
//     }
//
//     · static   —— 属于类，能直接从 main 里叫（这一课的重点）
//     · 返回类型  —— 交出整数写 int，交出文字写 String，什么都不交写 void
//     · 方法名    —— 要和题目一模一样（Java **区分大小写**）
//     · 参数      —— 要几个写几个，每个都要写**类型**：int n，不是只写 n
//
//   ⚠ 方法名后面的括号和花括号都不能省，而**末尾不要写分号**
//     （这一点和变量声明相反：int n = 1; 有分号，方法没有）。
//
// ② return：把结果**交出去**；void：只做事，不交值（所以不写 return）
//
//     static int 加倍(int n) { return n * 2; }        ⇒ 加倍(4) 给调用者 8
//     static void 打印星星(int n) {
//         for (int i = 0; i < n; i++) {
//             System.out.print("*");     ← 打到屏幕上，不换行（println 才会换行）
//         }
//     }
//
// ③ 「交出结果」和「打印出来」是两件事（最容易混的一处）
//
//     static int 加倍(int n) { System.out.println(n * 2); }   ✗ 打印了，没交出值
//     static int 加倍(int n) { return n * 2; }                ✓ 这才叫交给调用者
//
//   为什么前者不行：调用 加倍(4) 的地方**拿不到任何东西**，编译器也会拦你
//   —— 你会看到 错误: 缺少返回语句。
//   一句话：**print 是给别人看的，return 是给程序用的。**
//
// ④ 想用几次用几次，而且换个输入就换个结果：加倍(3) → 6，加倍(0) → 0，
//   加倍(-4) → -8。
//
//   ⚠ 如果一个方法不管给什么都返回同一个数，那它多半是把答案写死了：
//         static int 加倍(int n) { return 6; }     ✗ 6 和 n 没有关系
//     判断一个方法写对没有，靠的就是**换几组输入多试几次**。
//
// ⑤ 为什么这一课不用你写 main：课程会替你补一个标准的 public static void
//   main(String[] args)，从里面调用你的四个方法。好处有两个 —— 你专心写方法
//   本身；而且漏写 static 时那条错误**一定会出现**（见坑 1 的说明）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：方法忘了写 static（本课第一大坑）
//
//     int 加倍(int n) { return n * 2; }        ← 少了 static
//
// 你会看到：错误: 无法从静态上下文中引用非静态 方法 加倍(int)
// 为什么：检查时你的方法会被放进 class Main 里、**从 static 的 main 调用**：
//       public class Main {
//           int 加倍(int n) { return n * 2; }        ← 你的方法
//           public static void main(String[] args) {
//               System.out.println(加倍(4));         ← 从这里调用 → 编译不过
//           }
//       }
//   不写 static 的方法属于"对象"，得先 new 一个出来才能用：
//       Main m = new Main();   System.out.println(m.加倍(4));
// ⇒ 纯计算的方法就该写 static，这一课全用这种。
//   ⚠ 顺便记住（**新版 JDK 25 起**）：如果你**自己**写 main，而且写成不带
//     static 的 void main(String[] args)，那么它里面的非 static 方法调用

//     环境，就会撞墙。所以"在这台机器上能跑"不等于写对了。这也正是本课不让
//     你写 main 的原因：把这条错误稳定地暴露出来。
//
// ⚠ 坑 2：声明了返回类型，方法里却没有 return
//
//     static int 加倍(int n) {
//         System.out.println(n * 2);        ← 打印了，但什么都没交出去
//     }
//
// 你会看到：错误: 缺少返回语句
// 为什么：你答应了"这个方法交出一个 int"，可它走到末尾也没交出任何东西。
//   ⚠ 注意这里的因果：**打印不等于返回**。System.out.println 只是把字打到
//     屏幕上，方法本身什么都没给调用者。
// ⇒ 有返回类型的方法，**每条可能的路径最后都要 return**。如果确实是"只做事、

//

// 为什么：void 方法**没有值**，你没法把它塞进字符串拼接或者 println 的参数里。

// ⇒ 分清这一课的两个方法：星星(int n) 要**返回**一个字符串（String），调用处

//
// 你会看到（第一行）：错误: 不兼容的类型: String无法转换为int
//   （第二行）：错误: 找不到符号   符号: 方法 加倍2(int)   位置: 类 Main
// 为什么：Java 的参数类型是**硬约束**，不会替你自动转换；方法名也**区分大小写**，
//   中文标识符一个字符都不能差 —— 多一个字、少一个字，编译器就认为你没写。
// ⇒ 传之前先看方法要什么（加倍 要一个整数、最大值 要两个）；方法名照题目抄。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写

// ⚠ 只写**方法**：不用写 class、不用写 main、不用写 import —— 课程会替你补上。

//   · 数组 int[]   —— 长度**固定**，用 a[i] 取，长度写在 a.length

//
//         ArrayList<Integer> 表 = new ArrayList<>();
//         表.size()           ← 方法：一个"动作"，**要加括号**
//
//   一句话记住：**数组的 length 是"东西"，字符串和集合的 length()/size()
//   是"动作"。**
//
//   好消息是：写错了 javac **会当场报错**，不像整数除法那样静默出错。所以
//   这一课的任务不是"小心别写错"，而是"看到那句报错时知道它说的是这件事"。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 数组：定长、按下标取
//
//     int[] 数们 = new int[3];              ← 三个格子，元素**自动全是 0**
//     int[] 分数 = {90, 85, 77};            ← 直接给值（花括号，不用 new）
//
//     分数[0] ⇒ 90     分数[1] ⇒ 85     分数[2] ⇒ 77     分数.length ⇒ 3
//     下标**从 0 开始**；⚠ 长度那里没有括号。
//
//   ⚠ 两个和 C++ 不一样的地方，务必记牢：
//     · **new int[3] 之后元素自动全是 0**（Java 会初始化）。C++ 里 new int[3]
//       读出来是随机值 —— 别把那个直觉带过来。
//     · **Java 会检查下标**：分数[3] 不是"读到隔壁的内存"，而是当场抛
//       ArrayIndexOutOfBoundsException，程序立刻停下。这是好事（错误暴露得
//       早），但你要用 .length 先把范围判断好。
//
// ② ArrayList：会长大、用方法操作
//
//     ArrayList<Integer> 表 = new ArrayList<>();
//
//     表.add(9);           ← 加到最后（**它会改变这张表本身**）
//     表.get(0)            ← 取第 0 个（从 0 开始数）
//     表.size()            ← 有几个元素（⚠ 是方法，要括号）
//
//   ⚠ 尖括号里写的是 **Integer**，不是 int。Java 的泛型只收"对象类型"，基本
//     类型要先包一层：int → Integer、double → Double、boolean → Boolean。
//     写成 ArrayList<int> 会报：错误: 意外的类型 / 需要: 引用 / 找到: int
//
// ③ 两个容器的对照表（背下来最省事）
//
//                    数组 int[]              ArrayList<Integer>
//     怎么建         new int[3] / {1,2,3}    new ArrayList<>()
//     取第 i 个      a[i]                    表.get(i)
//     有几个         a.length   （无括号）    表.size()   （有括号）
//     加一个         做不到（长度固定）        表.add(值)
//     长度会变吗     不会                    会
//
// ④ 遍历：增强 for 对两者都适用（for (int x : 数们) 和 for (int x : 表)）。
// ⑤ 本课不用你写 import：课程已经在文件最上面写好了 import java.util.ArrayList;
//   —— **自己再写一遍反而会编译不过**（见坑 4）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：数组的 length 后面加了括号（本课第一大坑）
//
//     int[] a = {1, 2, 3};
//     System.out.println(a.length());          ← 多了两个括号
//
// 你会看到：错误: 找不到符号   符号: 方法 length()   位置: 类型为int[]的变量 a
//   （它在找一个**方法**，而数组上没有这个方法）
// 为什么：数组是 Java 语言**内建**的东西，它的长度是一个**属性**（字段），
//   不是一个方法。属性就是"一个东西"，所以没有括号。
// ⇒ 去掉括号：a.length
//   ⚠ 之所以老写错，是因为**字符串正好相反**（见坑 3）。三个一起记：
//         int[] a;      a.length       数组：**不加括号**
//         String s;     s.length()     字符串：**要括号**
//         ArrayList 表;  表.size()       集合：**要括号**
//
// ⚠ 坑 2：集合的 size 少了括号
//
//     ArrayList<Integer> 表 = new ArrayList<>();
//     System.out.println(表.size);             ← 少了两个括号
//
// 你会看到：错误: size 在 ArrayList 中是 private 访问控制
//   （这句话看着吓人，其实说的就是"你碰到了一个不该直接碰的东西"）
// 为什么：ArrayList 内部的**字段**确实叫 size，但它是 private 的；对外提供的
//   那个是**方法** size()。你光写 表.size，编译器就去找字段，一找就撞上私有的。
// ⇒ 加上括号：表.size()
//   ⚠ 另一种写法是干脆用错了名字：表.length 会报
//     错误: 找不到符号   符号: 变量 length —— ArrayList 上**根本没有 length**。
//
// ⚠ 坑 3：字符串的 length 少了括号，或者下标算错走到数组外面
//
//     String s = "hi";   System.out.println(s.length);      ← 少了两个括号
//
// 你会看到：错误: 找不到符号   符号: 变量 length   位置: 类型为String的变量 s
//   （注意和坑 1 正好对称：那次是"找不到方法"，这次是"找不到变量"）
// 为什么：String 是**人写出来的类**，长度只能做成方法 length()；而数组的长度

// 第 07 课：字符串 —— Java 最著名的那个坑
//
// ─────────────────────────────────────────────────────
//  先介绍：最常用的东西，也最容易骗你
// ─────────────────────────────────────────────────────
//
// 字符串是用来装文字的类型，你几乎每一课都在用它。但它身上有两个
// **和别的类型完全不一样**的脾气，不知道就会吃大亏：
//
//   ① **比较内容要用 .equals()，不能用 ==。**
//      而最坑的是：用 == **有时候是对的** —— 于是你以为自己会了。
//
//          String a = "hi";
//          String b = new String("hi");
//          a == b            ⇒ false   ← 明明内容一样！
//          a.equals(b)       ⇒ true
//
//          String c = "hi";  ← 直接写出来的字面量
//          a == c            ⇒ true    ← 碰巧对，骗人的
//
//      为什么碰巧对：直接写在代码里的字面量 "hi" 会被 Java 放进一个"常量池"，
//      同一个内容共用一个对象。所以两个都是字面量时 == 恰好为真。一旦字符串
//      是 **new 出来的、拼出来的、从文件/输入读进来的**，== 立刻就变成 false。
//
//      **== 不是一直错，是"有时候碰巧对"—— 那才是最危险的。**
//
//   ② **字符串改不了（immutable）。** 凡是"改"字符串的方法，都是返回一个**新**
//      字符串：s.toUpperCase(); 什么都没发生；s = s.toUpperCase(); 才是接住了。
//      对照第 06 课的 ArrayList：表.add(x) 会**当场改变表本身**，两者不一样。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 最常用的五个方法（**每一个都带括号**，它们是方法不是属性）
//
//     s.length()            有几个字符          "你好".length()  ⇒ 2
//     s.charAt(0)           第 0 个字符         下标从 0 开始，和数组一样
//     s.toUpperCase()       转成大写（返回**新**字符串，s 本身不变）
//     s.indexOf("na")       片段第一次出现的下标；**找不到返回 -1**
//     s.substring(0, 3)     从下标 0 到 3 **之前**（含 0 不含 3）
//
//   ⚠ 两个最容易记错的地方：**找不到是 -1，不是 0**（在开头找到才是 0）；
//     **substring 是半开区间**（含 0 不含 3，取的是下标 0、1、2）。
//
// ② 比较内容：equals。a.equals(b) ⇒ true（比**内容**）；a == b ⇒ false（比
//   **是不是同一个对象**）。一句话记住：== 比"是不是同一张身份证"，
//   equals 比"两个东西长得一不一样"。
//
//   ⚠ 小技巧：a 万一是 null，a.equals(b) 会抛 NullPointerException。老手会把
//     不可能为 null 的那边写在前面："hi".equals(a) —— 常量不可能是 null。
//   ⚠ 这个坑不只坑字符串：Integer 也一样。
//       Integer 甲 = 127, 乙 = 127;   甲 == 乙  ⇒ true
//       Integer 丙 = 128, 丁 = 128;   丙 == 丁  ⇒ false
//     （因为 -128~127 有缓存，超出范围就各自 new 一个。所以 127 对、128 错。）
//
// ③ 单引号和双引号是两种东西：'j' 是**字符**（char），"j" 是**字符串**（String）。
//   看着像，类型完全不同，别混。字符串可以拼接："你好，" + 姓名 ⇒ 你好，小明。
//
// ④ 为什么"改"字符串要接住返回值
//
//     String s = "hello";
//     s.toUpperCase();              ← 什么都没发生（s 还是 hello）
//     s = s.toUpperCase();          ← 把新字符串接回 s（现在才是 HELLO）
//
// ⑤ 这一课不用写 import：String 和 char 都在 java.lang 里，自动可见。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：用 == 比字符串内容（本课第一大坑）
//
//     static boolean 内容相同(String a, String b) {
//         return a == b;                   ← 错
//     }
//
// 你会看到：**什么都不报**。而且它**时对时错**：
//     内容相同("hi", "hi")                            ⇒ true    ← 碰巧对
//     内容相同(new String("hi"), "hi")                 ⇒ false   ✗ 应该 true
//     内容相同(new String("你好"), new String("你好"))  ⇒ false   ✗ 应该 true
// 为什么：== 比的不是内容，是"**这两个变量是不是指向同一个对象**"。直接写出来
//   的字面量共用常量池里的同一个对象，所以碰巧为真；只要有一边是 new 出来的、
//   拼出来的、从输入读进来的，立刻变 false。
// ⇒ 判断内容一律用 equals：return a.equals(b);
//   ⚠ 这个坑的危险程度就在于"它有时候是对的" —— 你自己试一组字面量，会觉得
//     没问题；等到数据从别处来时才突然炸。
//   把它当成一条纪律：**看到比较字符串，就用 equals。**
//
// ⚠ 坑 2：字符串的 length 少了括号
//
//     String s = "hi";
//     System.out.println(s.length);            ← 少了两个括号
//
// 你会看到：错误: 找不到符号   符号: 变量 length   位置: 类型为String的变量 s
//   （它在找一个叫 length 的**字段**，而 String 上根本没有这个字段）
// 为什么：String 是人写出来的类，长度只能做成方法 length()。
// ⇒ 加上括号：s.length()

// 第 08 课：类与对象 —— 自己造一种"东西"
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么需要"自己造一种类型"
// ─────────────────────────────────────────────────────
//
// 前面七课用的都是 Java 自带的东西：int、String、ArrayList。可现实里的东西，
// Java 一个都没带：一只猫有名字、有年龄，会打招呼、会长大。
//
// 用一个 int 装年龄、一个 String 装名字，它们**其实是同一条数据的两半** ——
// 可编译器不知道这件事，你也没法把它们一起传来传去、一起返回。
//
// `class` 就是干这个的：**把"有什么"（字段）和"能做什么"（方法）捆成一个
// 新的类型**。从此 `猫` 就和 `int` 一样是个类型了：
//
//     class 猫 {
//         String 名字;         ← 字段：这只猫"有什么"
//         int 年龄;
//         String 打招呼() {    ← 方法：这只猫"能做什么"
//             return "喵～我是" + 名字;
//         }
//     }
//
// ⚠ 一定要分清这两个词，它们是这一课的骨架：
//
//     class 猫 { ... }               ← **图纸**：说清"猫有什么、能做什么"
//     猫 甲 = new 猫("咪咪", 3);      ← 照着图纸**造一只真的猫**
//
//   图纸只有一份，猫可以造很多只 —— 而且每一只**各有各的名字和年龄**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 三个部件：字段、构造方法、普通方法
//
//     class 猫 {
//         String 名字;                    ← 字段（每个对象各有一份）
//         int 年龄;
//
//         猫(String 名字, int 年龄) {      ← 构造方法（**没有返回类型**！）
//             this.名字 = 名字;
//             this.年龄 = 年龄;
//         }
//
//         String 打招呼() { return "喵～我是" + 名字; }    ← 普通方法
//     }
//
// ② new 的那一刻：照着图纸要一块新地方 → 把 "咪咪" 和 3 交给构造方法 → 构造
//   方法把两个值填进字段 → 把这只猫的地址交给变量 甲。你**从来不直接"调用"
//   构造方法** —— 它是 new 的那一刻自动执行的。
//
// ③ 用 `.` 访问对象自己的东西：甲.打招呼() ⇒ 喵～我是咪咪；甲.几岁了() ⇒ 3
//
// ④ this 的意思是"我自己这个对象"。字段名和参数名一样时（都叫 名字），右边的
//   名字 指**参数**，要写 this.名字 才指得到**字段**。忘了 this、写成
//   `名字 = 名字;` 是把参数赋给自己 —— 字段永远是 null / 0。
//
// ⑤ new 两次就是两个互不相干的对象；但 `猫 乙 = 甲;` **不是**拷贝
//
//     猫 甲 = new 猫("咪咪", 3);   猫 乙 = new 猫("大黄", 5);   甲.长大一岁();
//     甲.几岁了() ⇒ 4   ← 甲变了      乙.几岁了() ⇒ 5   ← 乙一点没受影响
//
//     猫 乙 = 甲;                ← 这一句不是拷贝！只是给同一只猫起了第二个名字
//     乙.长大一岁();
//     甲.几岁了() ⇒ 4            ← 甲也变了，因为它们**是同一只猫**
//
//   Java 的类类型变量里装的不是对象本身，而是"对象在哪里"（引用/地址）。
//   `猫 乙 = 甲;` 只是把地址抄了一份。想造真正的第二只，得再 new 一次。
//   ⚠ 这一点和 C++ 的值语义**相反** —— 那边 猫 乙 = 甲; 会复制一份。
//
// ⑥ 这一课不用你写 Main：课程会在你的类后面补一个 public class Main 当入口，
//   所以你只写 `class 猫` 就行。**别自己写 class Main** —— 一个 .java 文件里
//   public 类只能有一个，那个位置留给课程了。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：给构造方法写了返回类型（本课最隐蔽的坑）
//
//     class 猫 { void 猫(String 名字, int 年龄) { ... } }     ← 多了个 void
//
// 你会看到的是**在 new 的那一行**：
//     错误: 无法将类 猫中的构造器 猫应用到给定类型
//        需要: 没有参数
//        找到: String,int
//        原因: 实际参数列表和形式参数列表长度不同
//   ⚠ 报错里**根本看不到 void 两个字** —— 这就是它难查的原因。
// 为什么：构造方法的两条硬规矩是 ① 名字必须和类名**完全一样**（大小写也一样）；
//   ② **没有返回类型** —— 连 void 都不能写。写上 void 之后，`void 猫(...)` 就
//   只是一个**名字碰巧和类名一样的普通方法**，编译器不觉得这是语法错误。于是
//   猫 这个类实际上**没有任何构造方法**，new 猫("咪咪", 3) 自然对不上。
// ⇒ 把返回类型删掉（前面最多只能写 public / private 这种访问修饰符）：
//       猫(String 名字, int 年龄) {        ✓ 这才是构造方法
//           this.名字 = 名字;   this.年龄 = 年龄;
//       }
//
// ⚠ 坑 2：构造方法里忘了 this
//
//     猫(String 名字, int 年龄) { 名字 = 名字; 年龄 = 年龄; }   ← 把参数赋给了自己
//
// 你会看到：什么都不报。只是 new 出来的猫**名字是 null、年龄是 0**：
//     甲.打招呼() ⇒ 喵～我是null        甲.几岁了() ⇒ 0
// 为什么：字段名和参数名一样时，**右边的 名字 指参数**。所以 `名字 = 名字;`
//   是把参数赋值给它自己，字段一点没动。
// ⇒ 用 this 指名道姓：this.名字 = 名字;   this.年龄 = 年龄;
//   ⚠ 顺便记住 Java 的默认值：字段不赋值不是"空着"，而是各自类型的零值 ——
//     对象类型（String）是 **null**，int 是 **0**，boolean 是 **false**。
//
// ⚠ 坑 3：给字段加了 static —— 所有对象共用一份
//
//     class 猫 { static int 年龄; }    ← 这一份属于**类**，不属于某只猫
//
// 你会看到：什么都不报。只是造两只猫、改其中一只，**两只一起变**：
//     甲 = new 猫(3);  乙 = new 猫(5);   甲.年龄 = 甲.年龄 + 1;
//     甲.年龄 ⇒ 6        乙.年龄 ⇒ 6      ← 乙明明没动过，却跟着变了
// 为什么：**static 的东西属于"类"，只存一份；不写 static 的属于"对象"，每个
//   对象各一份。**
// ⇒ 这一课要的正是"每个对象各有一份"，所以字段和方法都**不要写 static**。

// 第 09 课：封装与访问控制 —— 把字段关进盒子里
//
// 先介绍：为什么要"封装"
//
// 现在你的字段是长这样的：
//
//     class 人 {
//         String 名字;
//         int 年龄;
//     }
//
// 用起来：
//
//     人 甲 = new 人();
//     甲.年龄 = -5;          ← 编译通过！跑起来也不报错！
//     甲.年龄 = 99999;       ← 也通过
//
// 问题就在这：**你写 人 这个类的时候，脑子里有一条规矩** ——
// "年龄必须是 0 到 150 之间的整数"。可这条规矩没地方写，
// 它只活在你脑子里。任何人拿到 人 这个类，都能把 年龄 改成 -5，
// 你的程序就此带着一个不可能的数据一路跑下去，等你发现的时候
// 已经是"某个人的年龄是 -5，所以他免票"这种莫名其妙的 bug。
//
// 那能不能在"每次用到年龄"的地方都写一遍检查？
// 不能 —— 你不知道以后有多少个地方会用到它。而且总有人忘。
//
// 封装的思路是：**把规矩焊死在数据旁边**。
//   ① 字段不许别人直接碰  → private
//   ② 想读，走 取年龄()   → getter
//   ③ 想改，走 改年龄(v)  → setter，**检查写在里面**
//
// 这样"年龄永远是合法的"就成了这个类**自己保证**的事，
// 而不是"每个用它的人都记得要检查"。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// private 的意思很直白：**只有这个类自己看得见**。
//
//     class 人 {
//         private int 年龄;          ← 外面看不见了
//
//         public int 取年龄() {      ← 给外面开一扇窗：只能看
//             return 年龄;
//         }
//
//         public void 改年龄(int 值) {   ← 给外面开一扇门：检查了才放进来
//             if (值 < 0 || 值 > 150) {
//                 return;            ← 非法值？当没听见
//             }
//             this.年龄 = 值;
//         }
//     }
//
// 外面的世界随之改变：
//
//     甲.年龄 = -5;         // ✗ 编译错误：年龄 在 人 中是 private 访问控制
//     甲.改年龄(-5);        // ✓ 编译通过 —— 但值被拒绝了，年龄没变
//     甲.改年龄(30);        // ✓ 改成功
//     int 岁 = 甲.取年龄();  // ✓ 读得到
//
// ⚠ 注意第二行和第三行的区别，这是封装真正的价值：
//   **它不是"不让你改"，而是"只能按规矩改"。**
//   非法的调用不再是一个错误，而是一个**被忽略的请求**。
//
// 套路的形状是固定的：名字 → 取名字()/改名字(String)，年龄 → 取年龄()/改年龄(int)。
// 方法名怎么起随你（很多书用 getName / setAge），关键是**成对出现**：一个读、一个写。
//
// ─────────────────────────────────────────────────────
//  Java 的四种访问修饰符（按可见范围从小到大）
// ─────────────────────────────────────────────────────
//
//     private      只有**本类**里面能碰
//     （不写）      同一个**包**里能碰        ← 什么都不写叫"包访问权限"
//     protected    同包 + **子类**能碰（下一课讲继承时会用到）
//     public       谁都能碰
//
// 两条要立刻记住的：
//
//   ① **不写修饰符 = 包访问权限**，不是 private！
//      你以前写的 `String 名字;` 就是这个级别，所以同一个文件里别的类也能改它。
//
//   ② 字段一律 private，方法一律 public，这条"默认搭配"能覆盖九成情况。
//
// ⚠ 一个文件里能放好几个类，但 public 的**只能有一个**，而且必须叫 Main。
//   所以下面写的 人 不能加 public —— 加上会报：
//       错误: 类 人 是公共的, 应在名为 人.java 的文件中声明
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：setter 里忘了 this —— 症状是"字段永远是 0 / null"
//
//     public void 改年龄(int 年龄) {      ← 参数也叫 年龄
//         年龄 = 年龄;                   ← 把参数赋给参数自己
//     }
//
// 你会看到：调用 甲.改年龄(30) 之后 甲.取年龄() 打印出来是 **0**，
// 一次都没改成功，也不报任何错。
// 为什么：参数名和字段名一样时，**光写名字指的是参数**（离得近的赢）。
// 要真进到字段里必须写 this.年龄 = 年龄;
// 更省事的办法是给参数换个名字（参考答案用的就是这个）：
//     public void 改年龄(int 值) { ... 年龄 = 值; }   ← 一眼知道谁是谁
//
// ⚠ 坑 2：以为 getter 返回的是"复印件"
//
//     int 岁 = 甲.取年龄();     ← int 是基本类型，确实是拷贝，改 岁 不影响 甲
//     String 名 = 甲.取名字();  ← String 不可变，也安全
//
// 但换成对象类型就危险了（以后会撞上）：如果字段是 int[] 或 ArrayList，
// getter 直接把那个**引用**交出去，外面 列表.add(...) 就等于绕过 setter 改了字段。
// 症状：明明没人调 setter，字段却变了。
// 记住一句话：**getter 交出引用 = 封装破了个洞。**
//
// ⚠ 坑 3：只给 setter 加了校验，构造方法没加
//
//     new 人("张三", -5);      ← 绕过了所有 setter，直接造出一个非法对象
//
// 你会看到：用 setter 时校验好好的，可对象刚 new 出来就已经是坏的。
// 为什么：构造方法也是"往字段里写值"的入口，封装要封的是**所有入口**。
// 这一课我们没写构造方法，但下一课一学就要记得把同样的检查搬进去。
//

// 第 10 课：构造方法重载与 this() —— 造对象的不同入口
//
// 先介绍：为什么会有"好几个构造方法"
//
// 上一课我们是这么造对象的：
//
//     人 甲 = new 人();
//     甲.改名字("张三");
//     甲.改年龄(20);
//
// 三行才能得到一个"能用的"对象。如果这个对象有八个字段呢？八行。
// 而且**中间任何一步忘掉，你手上就是一个半成品** ——
// 名字有了、年龄还是 0，后面用起来全是坑。
//
// 构造方法解决的就是这件事：**让对象一诞生就是完整的**。
//
//     人 甲 = new 人("张三", 20);     ← 一行，而且不可能忘
//
// 但事情没这么简单。现实里"造一个学生"的场合有好几种：
//
//     · 报到的时候只知道名字        → 分数、班级还不知道
//     · 考完试了，知道名字和分数    → 班级还不知道
//     · 转班进来，三样都知道        → 齐全
//
// 三种场合，你不可能要求调用者"你自己把不知道的填空了再传进来"。
// 于是就有**三个构造方法**，各自负责一种场合 —— 这就是构造方法重载。
//
// 重载（overload）的规矩很简单：
//   **方法名一样（对构造方法来说就是类名），参数列表不一样。**
//   参数个数不同、类型不同、顺序不同都算不一样。
//   ⚠ 光**返回类型**不同不算重载 —— 而构造方法本来就没有返回类型，
//     所以构造方法的重载只能靠参数区分。
//
// ─────────────────────────────────────────────────────
//  用法与例子：三个构造方法，最"全"的那个干实事
//
//     class 学生 {
//         private String 名字;
//         private int 分数;
//         private String 班级;
//
//         public 学生(String 名字, int 分数, String 班级) {   ← 干实事的那个
//             this.名字 = 名字;
//             this.分数 = 分数;
//             this.班级 = 班级;
//         }
//
//         public 学生(String 名字, int 分数) {
//             this(名字, 分数, "未分班");      ← 调用上面那个，补一个默认班级
//         }
//
//         public 学生(String 名字) {
//             this(名字, 0, "未分班");         ← 补两个默认值
//         }
//     }
//
// 用起来是这样，编译器**按参数找**该用哪个：
//
//     new 学生("小明", 92, "三班")   → 第一个（三个参数）
//     new 学生("小明", 92)           → 第二个（两个参数）
//     new 学生("小明")               → 第三个（一个参数）
//
// `this(...)` 这个写法值得单独说一句：
//   它**不是**"我自己这个对象"（那是 this.分数 里的 this），
//   在这里它是一个**调用另一个构造方法的指令**，
//   意思是"先把那个构造方法跑完，再回来"。
//   所以 new 学生("小明") 实际发生的是：
//       学生("小明") → 学生("小明", 0, "未分班") → 在里面逐字段赋值
//   一条链走到底，赋值只写了一处。
//
// 为什么要这么绕？因为**默认值只应该写在一个地方**。
// 如果三个构造方法各自写一遍 "未分班"，哪天要改成"待定"，
// 你得改三处，漏一处就是一个查不出来的不一致。
//
// ⚠ 还有一件事上一课欠着：构造方法里也要校验
//
//     public 学生(String 名字, int 分数, String 班级) {
//         if (分数 < 0) { 分数 = 0; }        ← 改的是**参数**，不是字段
//         if (分数 > 100) { 分数 = 100; }
//         this.分数 = 分数;                  ← 夹紧之后再存进字段
//     }

// 先夹紧**参数**、最后统一存一次。如果写成 this.分数 = 分数; 之后再判断，
// 那判断就白做了。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：给构造方法写了返回类型 —— 症状是 new 的时候说"找不到构造器"
//
//     public void 学生(String 名字) { ... }      ← 多了个 void
//
// 你会看到：
//     错误: 无法将类 学生中的构造器 学生应用到给定类型;
//     需要: 没有参数

// ⚠ 坑 2：this(...) 没放在第一行

// 你会看到：

// 第 11 课：static 与 final —— 属于类的东西
//
// 先介绍：static 解决的是"这份数据不属于任何一个对象"
//
// 前面几课，每个字段都是**每个对象各有一份**：
//
//     计数器 甲 = new 计数器();
//     计数器 乙 = new 计数器();
//     甲 有自己的字段，乙 也有自己的 —— 改甲不动乙。
//
// 这个模型很好用，但有一类数据它装不下：**"一共造了几个对象"**。
//
// 这个数字属于谁？属于 甲 吗？可 乙 也是造出来的，凭什么算在 甲 头上？
// 它不属于任何一个对象，它属于**整个类**。
//
// static 就是给这种成员准备的：
//
//     不加 static  →  属于**对象**，每个对象各一份
//     加了 static  →  属于**类**，只有一份，所有对象共用
//
//     class 计数器 {
//         private static int 个数 = 0;    ← 类成员：全类只有一份
//         private String 名字;            ← 实例成员：每个对象一份
//     }
//
// 直觉检验很简单：**这个值需要"每个对象一个"吗？**
//   人的名字、猫的年龄 → 需要 → 不用 static
//   造了几个对象、全局的常量、纯计算的工具方法 → 不需要 → 用 static
//
// 顺带一个现实证据：main 方法自己就是 static 的。
//   `public static void main(String[] args)` —— 程序刚启动的时候
//   **一个对象都还没有**，哪来的实例方法给你调用？
//   所以入口必须是 static：它不依赖任何对象就能跑。
//
// ─────────────────────────────────────────────────────
//  用法与例子：三种 static 成员
// ─────────────────────────────────────────────────────
//
// ① 静态字段 —— 全类一份
//
//     public static void 加一() { 个数 = 个数 + 1; }
//
//     计数器 甲 = new 计数器();
//     计数器 乙 = new 计数器();
//     甲.加一();
//     乙.加一();
//     System.out.println(甲.报数());    ⇒ 2      ← 不是 1！
//     System.out.println(乙.报数());    ⇒ 2
//     连"报数"都该这么调（更像"类的事"）：
//     System.out.println(计数器.报数());  ⇒ 2
//
//   ⚠ 上面 甲.加一() 和 计数器.加一() **都能编译**，做的事完全一样。
//     Java 允许你"用对象名去调静态方法"，但这是在骗自己 ——
//     它容易让人误以为 个数 是 甲 的。**能写 类名.方法() 就用类名。**
//
// ② 静态常量 —— static + final
//
//     public static final int 起始值 = 0;
//                 ↑      ↑
//              属于类   只能赋一次值
//
//     这是 Java 里"常量"的标准写法：`public static final` 三个词连用。
//     读法是"公开的、全类共用的、不可改的值"。
//     以后你会在 JDK 自己身上看到一模一样的形状：
//         Math.PI      （Math 类里的 public static final double）
//         Integer.MAX_VALUE
//
// ③ 静态方法 —— 不碰实例字段的方法
//
//     public static int 平方(int x) { return x * x; }
//
//     为什么它可以（而且应该）是 static：
//     **它算出来的东西只跟参数有关，跟"哪一个对象"毫无关系。**
//     这类方法用 static 有个好处：不需要先 new 一个对象就能用。
//
//         int r = 计数器.平方(7);      ← 直接调，没有 new
//
//     Java 自己的 Math 类就是这么干的：Math.sqrt(2)、Math.abs(-3)，
//     谁也不觉得需要先 new 一个 Math。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：在静态方法里用实例字段 —— 症状是"无法从静态上下文中引用非静态变量"
//
//     public static void 打招呼() {
//         System.out.println(名字);        ← ✗
//     }
//
// 你会看到：错误: 无法从静态上下文中引用非静态 变量 名字
// 为什么：这是编译器的实话 —— 静态方法属于**类**，它被调用的时候
// **可能一个对象都还没造出来**（甚至永远不会造）。那 `名字` 该是谁的名字？
// ⚠ 反过来是允许的：实例方法里用静态字段完全没问题
//   （实例方法被调用时，类肯定已经加载了，静态字段一定存在）。
//   记成一句话：**静态的看不见实例的，实例的看得见静态的。**
//
// ⚠ 坑 2：以为"final 修饰一个引用，对象内容也改不了了"
//
//     public static final int[] 表 = {1, 2, 3};
//     表[0] = 99;                    // ✓ 编译通过！跑起来真的改了
//     表 = new int[]{4, 5, 6};       // ✗ 编译错误：无法为最终变量 表 指定值
//
// 你会看到：明明标了 final，数组里的值还是被改了 —— 于是你以为 final 没生效。
// 为什么：final 锁住的是**变量这一格**，也就是"表 这个名字只能指向那一个数组"。
// 而数组是**对象**，`表` 里装的是它的地址；改 表[0] 是"顺着地址进去改内容"，
// 没有给 表 重新赋值，所以 final 管不着。
// 一句话：**final 管"指向谁"，不管"指向的东西里面是什么"。**
//
// ⚠ 坑 3：直接用一个"其实每个对象不一样"的值，却给它加了 static
//
//     class 计数器 {
//         public static String 名字;         ← 手滑加了 static
//     }
//     计数器 甲 = new 计数器();  计数器 乙 = new 计数器();
//     System.out.println(甲.名字);          ⇒ 后造的那个
//
// 你会看到：造了两个对象，但它们"同名"，都是后造的那个。
// 为什么：名字加了 static 就只剩一份了，第二个对象把它盖掉了。
// **同一个 bug 在第 08 课也出现过**（两只猫的年龄一起变），
// 所以看到"多个对象莫名同步变化"，第一个念头就是：这个字段是不是 static？
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   main 里按这个顺序打印（检查就是按这个顺序比对的）：
//
//     System.out.println("起始值=" + 计数器.起始值);        ← 用**类名**读静态常量
//     System.out.println("平方(7)=" + 计数器.平方(7));      ← 用**类名**调静态方法
//
//     计数器.加一();      // 第一次：个数 0 → 1
//     计数器.加一();      // 第二次：个数 1 → 2
//     System.out.println("加一两次后=" + 计数器.报数());
//
//     计数器 甲 = new 计数器();

//     甲.加一();
//     System.out.println("一个加=" + 甲.报数());

//     System.out.println("两个看到=" + 甲.报数());
//
//     计数器.重置();

// 第 12 课：继承 —— extends、super、方法覆写
//
// 先介绍：两个类有八成内容是一样的，怎么办
//
// 假设你写了一个 狗 类、一个 猫 类，写完会发现它们是这样的：
//
//     class 狗 {
//         private String 名字;
//         public String 取名字() { return 名字; }
//         public String 介绍() { return 名字 + "说" + 叫声(); }
//         public String 叫声() { return "汪"; }
//     }
//     class 猫 {
//         private String 名字;                        ← 一模一样
//         public String 取名字() { return 名字; }      ← 一模一样
//         public String 介绍() { ... }                ← 一模一样
//         public String 叫声() { return "喵"; }        ← 只有这里不一样
//     }
//
// 四样东西里三样完全相同，只有 叫声 不同。
// 这不是"差不多"，这是**同一段代码抄了两遍**。抄两遍的代价是：
//   ① 以后 介绍 的格式要改（比如"说"改成"叫道"），你得改两个地方，
//      有了十种动物就改十处 —— 漏一个就是一个不一致的 bug。
//   ② 名字 这个字段在两个类里是**两套**，你没法写一个方法同时收狗和猫。
//
// 继承就是为这件事准备的：**把共同的部分写一次，放在父类里，子类去拿。**
//
//     class 动物 { ...名字、取名字、介绍、叫声... }        ← 共同的部分，写一次
//     class 狗 extends 动物 { ...只要写 叫声... }          ← 拿过来用
//     class 猫 extends 动物 { ...只要写 叫声... }
//
// `extends` 读作"继承自"，`狗 extends 动物` 的意思是
// **"狗 是一种 动物，动物 有的 狗 全都有，另外 狗 还能有自己的东西"**。
//
// ─────────────────────────────────────────────────────
//  用法与例子：三个关键字
// ─────────────────────────────────────────────────────
//
// ① extends —— 建立父子关系
//
//     class 狗 extends 动物 {
//         // 这里什么都不写，狗 就已经有 名字、取名字()、介绍()、叫声() 了
//     }
//
//   拿过来的东西**不用再声明一遍**。子类自动拥有父类的字段和方法
//   （private 字段也在，只是子类不能直接碰，得走父类的 getter —— 见坑 2）。
//
// ② super —— 指"父类那一份"
//
//   父类的构造方法不会被继承（构造方法是"造这个类"的步骤，不能照搬），
//   所以子类的构造方法**必须自己把父类需要的值交上去**：
//
//     public 狗(String 名字) {
//         super(名字);            ← 调用父类的构造方法：动物(String 名字)
//     }
//
//   ⚠ super(...) 必须是子类构造方法的**第一条语句** —— 和上一课的 this(...) 一样。
//     道理也一样：**父类的部分要先构造好**，子类的部分才有地方放。
//
//   `super` 还有第二种用法，不带括号：
//     super.叫声()        ← 明确地说"我要调父类那一版的 叫声"
//
// ③ @Override —— 覆写
//
//   子类里写一个**和父类同名、同参数、同返回类型**的方法，就把父类那版盖掉了：
//
//     class 狗 extends 动物 {
//         @Override
//         public String 叫声() { return "汪"; }
//     }
//
//   @Override 这个注解**不影响运行**，它是写给编译器看的：
//   它说"我打算覆写父类的某个方法，你帮我核对一下"。
//   **对不上它就报错**，这正是它的价值（见坑 1）。
//
//   覆写的三条硬要求：
//     · 方法名和参数列表必须**完全一样**（有一个字不同就变成另一个方法了）
//     · 返回类型必须一样（或者更"窄"）
//     · 访问权限**不能变小**：父类是 public，子类也得是 public
//
// ⚠ 一个值得先记住的写法：介绍() 里调用的是 `叫声()`，**不是**写死的"……"。
//   父类的方法里调另一个方法时，实际执行的是**子类覆写的那一版**。
//   于是 介绍() 只写了一次，狗和猫各自说出来的是"汪"和"喵"。
//   （这是下一课"多态"的全部秘密，今天先记住这个写法。）
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：覆写时参数写错 —— 症状是"它怎么还是父类的行为"
//
//     class 狗 extends 动物 {
//         public String 叫声(String 后缀) { return "汪" + 后缀; }     ← 多了个参数！
//     }
//     System.out.println(狗.叫声());        ⇒ ……        ← 你以为会打"汪"
//
// 你会看到：明明写了 叫声，调出来还是父类那个"……"，而且**不报错**。
// 为什么：参数不一样就是**另一个方法**了（叫重载，第 10 课学过），
// 它跟父类的 叫声() 并存，谁也没盖住谁。调 叫声() 时找到的还是父类那版。
//
// 这就是 @Override 存在的意义：加上它，编译器会替你核对 ——
// 会直接报：错误: 方法不会覆盖或实现超类型的方法
// **一句话：只要你打算覆写，就先打 @Override。**
//
// ⚠ 坑 2：想在子类里直接碰父类的 private 字段
//
//     class 狗 extends 动物 {
//         public String 打招呼() { return "我是" + 名字; }      ← ✗
//     }
//
// 你会看到：错误: 名字 在 动物 中是 private 访问控制
// 为什么：**private 是"只有本类"，子类也算"外面"。**
// 继承拿过来的是"存在"，不是"看得见"。

// 第 13 课：多态与抽象类 —— 一个变量，多种形状
//
// 先介绍：一个变量，能装好几种东西
//
// 上一课的结尾埋了一个细节：`介绍()` 里调的是 `叫声()`。
// 这次把那件事讲清楚 —— 它叫**多态**，是继承真正的回报。
//
// 先说一个更要紧的问题：父类那个兜底版本是不是很尴尬？
//
//     class 动物 {
//         public String 叫声() { return "……"; }      ← 这个"……"到底是什么意思
//     }
//
// 现实里"一个动物"叫起来是什么声音？**答不出来。**
// 只有具体的狗、猫、牛才有叫声。"一般的动物"这个概念是抽象的，
// 它只是我们用来把狗和猫归成一类的一个说法。
//
// 硬给它编一个"……"是自欺欺人 —— 更糟的是，它会**掩盖错误**：
// 你新写了一个 牛 类忘了覆写 叫声，程序照跑不误，
// 只是牛叫起来是"……"，你要过很久才发现。
//
// 所以 Java 让你把这层意思直接写出来：
//
//     abstract class 形状 {
//         public abstract double 面积();        ← 只写签名，没有方法体
//     }
//
// 这句话的意思是："**凡是形状，都必须能算面积；但怎么算，我不知道，你们自己说。**"
// 于是：
//     · 形状 自己**不能 new**（它不完整，new 出来面积算什么呢）
//     · 每个子类**必须**把 面积() 实现出来，不写就编译不过
//     · 忘了写？编译器当场拦住你，而不是等到"牛叫起来是……"
//
// 那多态在哪？在这里：
//
//     形状 甲 = new 圆(2);          ← 左边是 形状，右边是 圆
//
// 一个"形状"变量装了一个"圆"对象，这叫**向上转型**。
// 合法，因为圆**是**形状（继承关系保证了这一点）。接下来才是魔法：
//
//     甲.说明()   →  里面调 面积()  →  执行的是 **圆** 那一版的 面积()
//
// 明明变量类型是 形状，跑的却是 圆 的代码。
// 这就是**动态绑定**：调用哪个方法，不看变量声明成什么类型，
// **看运行时这个变量实际指向的是哪个对象**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 抽象类长什么样
//
//     abstract class 形状 {
//         public abstract double 面积();          ← 只有签名，末尾分号
//         public String 说明() {                   ← 具体方法：有方法体，照旧
//             return "面积=" + Math.round(面积());
//         }
//     }
//
//   两条规矩：
//     · 有抽象方法的类**必须**标 abstract
//     · 抽象类**不能 new**：`new 形状()` 会报
//         错误: 形状是抽象的; 无法实例化
//   它只能当**类型**用 —— 当变量类型、当参数类型、当数组元素类型。
//
// ② 子类必须交作业
//
//     class 圆 extends 形状 {
//         private double 半径;
//         public 圆(double 半径) { this.半径 = 半径; }
//         @Override
//         public double 面积() { return Math.PI * 半径 * 半径; }
//     }
//
//   ⚠ 如果你忘了写 面积()：
//        错误: 圆不是抽象的, 并且未覆盖形状中的抽象方法面积()
//     这条报错很直白，而且**在编译期**就拦住你 —— 这就是抽象类最实在的好处。
//
// ③ 动态绑定：同一行代码，两种行为
//
//     形状 甲 = new 圆(2);
//     形状 乙 = new 长方形(4, 5);
//     System.out.println(甲.说明());      ⇒ 面积=13      （圆：3.14159*2*2 ≈ 12.57）
//     System.out.println(乙.说明());      ⇒ 面积=20      （长方形：4*5）
//
//   两行**调的是同一个方法**（都写在 形状 里，只有一份），结果却不一样。
//   差别来自"甲指向谁、乙指向谁"。
//
// ④ 真正省事的地方：数组 + 循环
//
//     形状[] 图形们 = new 形状[2];        ← 元素类型是父类
//     图形们[0] = new 长方形(4, 5);
//     图形们[1] = new 圆(2);
//     for (形状 图 : 图形们) {
//         System.out.println(图.说明());    ← 不用判断"这是圆还是长方形"
//     }
//
//   这一段是这一课的重点。注意循环体里**没有 if，没有类型判断** ——
//   因为它不需要：图.说明() 自己会找对正确的 面积()。
//   以后再加一个 三角形 类，这个循环一个字都不用改。
//
// ⚠ 向上转型之后，能调用什么？
//
//     形状 甲 = new 圆(2);
//     甲.面积();        ✓ 形状 里有这个方法
//     甲.说明();        ✓ 形状 里有这个方法
//     甲.半径          ✗ 编译错误：找不到符号
//
// 一句话记法：**编译器只看左边（变量声明成什么类型），
//             运行时才看右边（实际是哪个对象）。**
// 真想拿子类特有的东西，就得**向下转型**，并且先用 instanceof 确认：
//
//     if (甲 instanceof 圆) {
//         圆 圆甲 = (圆) 甲;             ← 强转，把类型"说回去"
//         System.out.println(圆甲.半径);
//     }
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：忘了实现抽象方法 —— 症状是"这个类也得是抽象的"
//
// 你会看到：错误: 圆不是抽象的, 并且未覆盖形状中的抽象方法面积()
// 为什么：抽象方法就是一张**必须签收的合同**。父类说"每个形状都得能算面积"，
// 你继承了它就得交作业。交不出，那你也是抽象的。
// ⚠ 报错里说的"未覆盖"，就是"没写 @Override 那个方法"。
//
// ⚠ 坑 2：想 new 抽象类 / 想 extends 两个类
//
//     new 形状();                    // ✗ 错误: 形状是抽象的; 无法实例化
//     class 圆 extends 形状, 可画 {}  // ✗ 错误: 需要'{'  ← 语法就不对
//
// 症状一：想拿抽象类当"临时对象"用，编译器不让 ——
//   说明你需要的是**另一个具体的子类**，或者那个方法本来就该是 static。
// 症状二：语法错误，因为 **Java 只能单继承**：一个类只能 extends 一个父类。
//   想"同时是两样东西"怎么办？这是下一课接口的内容。
//
// ⚠ 坑 3：跳过 instanceof 就向下转型
//
//     形状 甲 = new 长方形(4, 5);
//     圆 圆甲 = (圆) 甲;                 ← 编译**通过**了！
//     圆甲.面积();                       ← 跑起来才崩
//
// 你会看到：编译通过 —— 但运行时抛
//     Exception in thread "main" java.lang.ClassCastException:
//         class 长方形 cannot be cast to class 圆
// 为什么：编译器只看类型（形状 转 圆 是可能的，它放行），
// 是不是真的圆要**跑起来才知道**。长方形不是圆，所以崩。
// ⚠ 规矩是：**向下转型之前先问一句 instanceof。**
//
// ⚠ 坑 4：抽象方法写了方法体，或者忘了 abstract
//
//     public abstract double 面积() { return 0; }      // ✗
//     你会看到：错误: 抽象方法不能有主体
//     public double 面积();                            // ✗ 少了 abstract
//     你会看到：错误: 缺少方法主体, 或声明抽象
//   抽象方法就两条：**签名 + 分号**，没有花括号，并且必须带 abstract。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写

//

// 第 14 课：接口 —— 契约，不是血缘
//
// 先介绍：只继承一个，可我就是"两样都是"
//
// 上一课结尾留了个问题：**Java 只能 extends 一个类**。
// 可现实里一个东西常常同时是好几样东西：
//
//     一个圆    是形状、也是可命名的
//     一部手机  能打电话、也能当相机
//     一个学生  是人、也是可比较的（能跟别人比大小）
//
// 硬要你用继承表达"手机 既 extends 电话 又 extends 相机" —— 做不到。
// 而且更根本的问题是：**"能拍照"这件事不该靠血缘来表达。**
// 相机能拍照，是因为它是相机；手机能拍照，跟它爹是谁没关系。
// "能拍照"是一种**能力/约定**，不是一种**出身**。
//
// 接口就是给"能力/约定"用的：
//
//     interface 形状 {
//         double 面积();                 ← 只有签名，末尾分号
//     }
//
// 念法是"**凡是实现 形状 的类，都保证有 面积()**"。
// 它是一个**契约**：我不管你是什么、你爹是谁，
// 你只要签了这个约，我就知道你一定能算面积 —— 于是我就敢调。
//
// 写"签合同"的关键字不是 extends，而是 **implements**：
//
//     class 圆 implements 形状, 可命名 { ... }
//                                  ↑ 逗号隔开，想实现几个就几个
//
// 一个类 **extends 只能一个，implements 可以很多个**。
// 这是接口最重要的本事，也是它存在的第一理由。
//
// ─────────────────────────────────────────────────────
//  用法与例子：接口长什么样
// ─────────────────────────────────────────────────────
//
// ① 接口声明
//
//     interface 形状 {
//         double 面积();                          ← 抽象方法（可省 public abstract）
//         default String 说明() {                  ← default 方法：**有方法体**
//             return "面积=" + Math.round(面积());
//         }
//     }
//
//   几个容易记混的点：
//     · 接口**不是类**：写 interface，不写 class。它不能被 new。
//     · 方法默认就是 public 的，而且**必须**是 public。
//       所以 `double 面积();` 就等于 `public abstract double 面积();`。
//     · default 方法是个例外：**它带方法体**。
//       为什么允许 —— 因为要"加一个新方法又不弄坏所有已经实现的类"。
//       这一课用它，是为了让 说明() 这套拼字符串的活儿只写一次。
//     · 接口可以**多继承接口**：`interface A extends B, C` —— 这是允许的，
//       因为接口没有字段、没有实现细节，不会撞车。
//
// ② 实现
//
//     class 圆 implements 形状, 可命名 {
//         private double 半径;
//         public 圆(double 半径) { this.半径 = 半径; }
//         @Override public double 面积() { return Math.PI * 半径 * 半径; }
//         @Override public String 名字() { return "半径为" + 半径 + "的圆"; }
//     }
//
//   ⚠ 实现接口的方法**必须是 public** —— 接口里的方法本来就是 public，
//     实现时权限不能变小（和上一课覆写的规矩是同一条）。
//     忘了写 public 会报：正在尝试分配更低的访问权限; 以前为public
//
// ③ 用接口当类型
//
//     形状 甲 = new 圆(2);         ← 和上一课的向上转型一模一样
//     可命名 乙 = new 圆(2);
//
//     System.out.println(甲.面积());        ⇒ 12.566370614359172
//     System.out.println(乙.名字());        ⇒ 半径为2.0的圆
//
//   注意 甲 和 乙 是**同一个类的两个视角**：
//   通过 甲 你只看得见 面积/说明（形状 这个契约里有的），
//   通过 乙 你只看得见 名字。
//   ⚠ 所以 `甲.名字()` 编译不过 —— 形状 这个接口里没有 名字。
//
// ④ 接口和抽象类怎么选
//
//     问题                          用哪个
//     ────────────────────────────────────────────────
//     子类共用的**字段**和构造方法    抽象类（接口没有实例字段）
//     表达"**是一种**"（狗是动物）    抽象类
//     表达"**能做**/遵守某个约定"     接口
//     一个类要同时具备好几种能力      接口（可以 implements 很多个）
//
//   一句话：**is-a 用抽象类，can-do 用接口。**
//   拿不准的时候用接口 —— 它更松，不会把你的继承名额（只有 1 个）用掉。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：在接口里写实例字段
//
//     interface 形状 {
//         private double 半径;             ← ✗ 编译错误
//     }
//
// 你会看到：错误: 接口不能有私有字段 / 修饰符 private 不合法
// 为什么：接口是"约定"，约定不能被某个实现改来改去。
// 接口里**只能有常量**（`int 最大 = 100;` 会被自动当成
// `public static final int 最大 = 100;`，因为接口里没有"实例"可言）。
// 想存数据就得在**实现类**里存 —— 这就是 圆 里那个 半径 的意义。
// ⚠ 顺带一个后果：接口里的字段全是 static final，所以它**全类共用一份**，
//   千万别想着在接口里放"每个对象不一样"的值。
//
// ⚠ 坑 2：忘了实现接口里的某个方法
//
// 你会看到：错误: 圆不是抽象的, 并且未覆盖可命名中的抽象方法名字()
// 为什么：签了合同就得交作业 —— 和上一课抽象方法一模一样的道理。
// ⚠ 注意报错会**指名道姓说是哪个接口的哪个方法**（这里写的是 可命名 中的 名字），
//   所以这条报错非常好用：它直接告诉你缺哪一份作业。
//

// 第 15 课：异常处理 —— 出错了怎么办
//
// 先介绍：程序出错时，"谁来收拾"
//
// 先看这段：
//
//     int[] 数们 = {10, 20, 30};
//     System.out.println(数们[9]);
//
// 跑起来是这样：
//
//     Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException:
//         Index 9 out of bounds for length 3
//             at Main.main(Main.java:7)
//     （程序到此为止，后面一行都不执行了）
//
// 注意最后那句：**后面的代码一行都没跑**。程序**整个停在那**。
//
// 这在学习的时候没什么 —— 你看到报错，改一改再跑。
// 但在真正给人用的程序里，这是灾难：
//   一个输入框里少打了一个逗号 → 整个程序白屏退出，用户刚才填的半小时全没了。
//   一个文件不存在 → 批处理跑到一半死掉，前面处理过的数据状态不明。
//
// 而且很多时候**出错是正常的、可以预料的**：
//   用户输入的东西本来就可能是错的（"请输入年龄"→ 他打的是"abc"）
//   要读的文件本来就可能不在（U 盘拔了）
//   除法的分母本来就可能是 0（用户填的）
// 这些不是"你的程序有 bug"，是**世界的常态**。
//
// 异常机制就是让程序能说这句话：
// **"这一步可能会出事，出事了我知道该怎么办，别整个死掉。"**
//
//     try {
//         可能会出事的代码
//     } catch (Exception e) {
//         出事了就在这里收拾
//     } finally {
//         不管出没出事都要做的事
//     }
//
// 三个块的分工，用一句话记住：
//     try     —— 我试试
//     catch   —— 出事了，我来处理（**程序从这里继续往下跑**）
//     finally —— 不管怎样都执行（收尾：关文件、断连接）
//
// ─────────────────────────────────────────────────────
//  用法与例子：三个块各就各位
// ─────────────────────────────────────────────────────
//
//     int[] 数们 = {10, 20, 30};
//
//     try {
//         System.out.println(数们[0]);        ← 正常
//         System.out.println(数们[1]);        ← 正常
//         System.out.println(数们[9]);        ← 出事了！从这里跳出去
//         System.out.println("这行不会执行");  ← 被跳过了
//     } catch (Exception e) {
//         System.out.println("出事:" + e.getMessage());
//     } finally {
//         System.out.println("这行总会执行");
//     }
//     System.out.println("程序继续往下跑");    ← 这行**会**执行
//
// 关键的一条（很多人第一次都会想错）：
// **try 块里出错之后，剩下的语句全部跳过，直接跳到 catch。**
// 它不是"跳过这一行、继续下一行"，是**整套跳出去**。
//
// ① 异常对象 e 里有什么
//
//     e.getMessage()      → 出事的说明文字，比如 "Index 9 out of bounds for length 3"
//     e.printStackTrace() → 把那一大串"at Main.main(Main.java:7)"打到屏幕上
//
// 平时给人看的界面里用 getMessage()（短、能懂），
// 自己调试的时候用 printStackTrace()（信息全）。
//
// ② 常见的内置异常，认名字就知道是什么事
//
//     ArrayIndexOutOfBoundsException   数组下标越界     数们[9]
//     NullPointerException             对 null 调方法    甲.取名字() 而 甲 是 null
//     ArithmeticException              算术错误         10 / 0
//     NumberFormatException            字符串转数字失败  Integer.parseInt("abc")
//     IllegalArgumentException         参数不合法       你自己抛的
//     ClassCastException               转型转错了       (圆) 一个长方形
//
//   注意 ArithmeticException 那条：**整数除法除以 0** 会抛异常。
//   （小数不一样：10.0 / 0 得到的是 Infinity，不抛异常。别记混。）
//
// ③ 自己抛异常：throw new ...
//
//   有时候"出错"不是 Java 报的，而是**你**觉得不合理：
//
//     public static int 取元素(int[] 数们, int 下标) {
//         if (下标 < 0) {
//             throw new IllegalArgumentException("下标不能是负数");
//         }
//         return 数们[下标];
//     }
//
//   念法是："下标是负数这件事，我认为它不合法 —— 我不打算硬着头皮往下算，
//   我要**当场把问题扔出去**，让调用我的人去处理。"
//
//   ⚠ throw 和 throws 长得像，意思不一样，别混：
//       throw  new IllegalArgumentException(...);   ← 动作："扔一个"
//       throws IllegalArgumentException              ← 声明："我这个方法可能会扔"
//
// ④ 受查异常：编译器盯着你必须处理的那种
//
//   Java 的异常分两大家族：
//
//     运行时异常（RuntimeException 及其子类）   编译器**不管**
//         ArrayIndexOutOfBounds / NullPointer / Arithmetic / IllegalArgument ...
//
//     受查异常（其他 Exception）                编译器**强制**你处理
//         最典型的就是文件操作：new FileReader("a.txt") 会扔 IOException
//         你不处理就**编译不过**，报：
//             错误: 未报告的异常错误IOException; 必须对其进行捕获或声明以便抛出
//
//   两种"处理"方式，二选一：
//         try { ... } catch (IOException e) { ... }      ← 当场接住
//         public void 读文件() throws IOException { ... } ← 往上甩给调用者
//
//   这一课不碰文件，所以练习里都是运行时异常（编译器不逼你）。
//   但**看到"未报告的异常错误"这句话，你就知道碰上受查异常了**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：catch 里什么都不做（"吞掉"异常）—— 最坏的一种写法
//
//     try {
//         某件重要的事();
//     } catch (Exception e) {
//     }                          ← 空的花括号
//
// 你会看到：程序"跑得好好的"，一点报错都没有 —— 然后你发现某件重要的事**根本没做成**。
// 为什么：异常的全部价值就是"告诉你出事了"。空 catch 等于把报警器拆了。
// 这是最难查的一类 bug，因为你连"哪里出事了"都不知道。
// 至少也要打印一句：
//     catch (Exception e) { System.out.println("出事了:" + e.getMessage()); }
// ⚠ 而且 catch (Exception e) 本身就已经很宽了 —— 它会把
//   NullPointer、ClassCast 这些**代码 bug** 一起吞掉。
//   写具体一点（catch (ArrayIndexOutOfBoundsException e)）能少吞很多东西。
//
// ⚠ 坑 2：把父类异常写在子类前面
//
//     } catch (Exception e) {                        ← 太宽，什么都接住了
//         System.out.println("一般错误");
//     } catch (ArrayIndexOutOfBoundsException e) {   ← 永远轮不到这里
//         System.out.println("下标越界");
//     }
//
// 你会看到：明明越界了，打印出来的却是"一般错误"。
// 为什么：catch 是**从上往下**试的，第一个能接住的就接走了。
// Exception 是所有异常的父类，它能接住一切 —— 后面那些具体的就没机会了。
// ⚠ 有的情况下编译器直接报错：错误: 已捕获到异常错误...（在更通用的之后被捕获）
//   看到那条别慌，就是顺序问题：**从最具体的往最笼统的写。**
//
// ⚠ 坑 3：在 finally 里 return
//
//     public static int 算() {
//         try {
//             return 1;
//         } finally {
//             return 2;          ← 把上面那个 1 覆盖掉了
//         }
//     }
//     System.out.println(算());       ⇒ 2      ← 不是 1
//
// 你会看到：try 里明明 return 1，方法却返回了 2，而且**编译器不报错**。
// 为什么：finally 的语义是"无论如何都要执行"，它连 return 前面那一瞬间都能插进去，
// 于是它里面的 return 直接把外层的返回值换掉了。
// **规矩：finally 里不要写 return**（也别写 break/continue）——
// 它只应该用来收尾：关文件、关连接、删临时文件。
//
// ⚠ 坑 4：以为"出了异常的循环会整个停下"
//
//     for (int i = 0; i < 数们.length; i++) {
//         try {
//             System.out.println(数们[i]);
//         } catch (Exception e) {
//             System.out.println("这个位置没有");
//         }
//     }
//
// 你会看到：循环**继续**跑完了（挨个打印"这个位置没有"）。
// 为什么：try/catch 在**循环体里面**。每次出事都被当场接住，
// 接住以后继续下一轮 —— 循环控制完全没有被打断。
// 反过来说：如果 try 在循环**外面**，第一次出事就会跳出整个循环。
// **try 放在哪一层，决定了"出事以后从哪儿继续"。** 这个位置是你写的，要自己想清楚。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   main 里这么写（顺序就是检查比对的顺序）：
//
//     int[] 数们 = {10, 20, 30};
//
//     try {
//         System.out.println(取元素(数们, 0));      → 10
//         System.out.println(取元素(数们, 1));      → 20
//         System.out.println("第三个也拿到了");      → 第三个也拿到了
//         System.out.println(取元素(数们, 9));      → 这里出事！9 越界
//         System.out.println(除(10, 0));           → 这一行永远到不了
//     } catch (Exception e) {
//         System.out.println("出事:" + e.getMessage());
//     } finally {
//         System.out.println("这行总会执行");
//     }
//
// 期望输出（五行）：
//     10
//     20
//     第三个也拿到了
//     出事:Index 9 out of bounds for length 3
//     这行总会执行
//
// ⚠ 三件要想清楚的事：
//   ① "第三个也拿到了" 打印了，说明前三行都正常跑完了；
//   ② 出事那行之后、catch 之前，try 里**剩下的语句全被跳过** ——
//      所以 除(10, 0) 从来没被执行；
//   ③ finally 那行在 catch 之后照样打印。
//
// 取元素 里那句 throw 单独说：负数下标的检查在练习里不会被触发

// 这就是"自己抛异常"的样子：不是等 Java 报错，而是你主动拒绝不合理的输入。

// 第 16 课：集合与泛型入门 —— 数组装不下的时候
//
// 先介绍：数组的两个硬伤
//
// 第 07 课学的数组有三件事做不到：
//
//     ① **长度固定。** int[] 数们 = new int[3]; 之后想塞第 4 个？没门。
//        现实里"名单"是会长大的 —— 今天三个学生，明天转来一个。
//        你能做的只有"猜一个大一点的数"，猜小了不够用，猜大了浪费。
//
//     ② **没有现成的方法。** 想知道"名单里有没有小红"，数组没有这个功能，
//        你得自己写个 for 循环一个个比。删掉一个人？自己搬后面的元素。
//
//     ③ **类型要么写死，要么全丢。** 数组很安全（String[] 里只能放 String），
//        但一旦你想写"能装任何东西的容器"，就只能退回 Object[] ——
//        然后每次拿出来都要强转，转错了运行时才崩。
//
// 集合（collections）就是补这三个洞的：
//
//     ArrayList<String> 名单 = new ArrayList<>();
//     名单.add("小明");                ← 想加几个加几个，长度自己长
//     名单.contains("小红")            ← 有没有，直接问，不用自己写循环
//     名单.get(1)                      ← 拿第 2 个
//
// 尖括号里的 <String> 叫**泛型参数**，意思是"这个名单里装的是 String"。
// 有了它：
//     · 放别的东西进去 → **编译期**就报错（而不是运行时才崩）
//     · 拿出来就是 String → **不用强转**
//
//     名单.add(123);                              // ✗ 编译错误：不兼容的类型
//     String 第一个 = 名单.get(0);                 // ✓ 直接就是 String
//
// 集合的家族要认一下名字（这一课只用两个）：
//     List    有序、可以重复、按下标取      实现类 ArrayList
//     Set     不重复                       实现类 HashSet
//     Map     键 → 值，按键取值             实现类 HashMap
//
// ⚠ 注意 List / Map 是**接口**（上一课刚学的东西！）。
//   写 `List<String> 名单 = new ArrayList<>();` 才是老手写法：
//   左边是契约，右边是具体实现。这一课为了少一层概念，直接写 ArrayList，也没问题。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① ArrayList：会自己变长的列表
//
//     ArrayList<String> 名单 = new ArrayList<>();
//     名单.add("小明");              ← 加到末尾
//     名单.add("小红");
//     名单.add("小刚");
//
//     名单.size()                   ⇒ 3         ⚠ 是**方法**（有括号）
//     名单.get(0)                   ⇒ 小明      ⚠ 下标从 0 开始，和数组一样
//     名单.get(2)                   ⇒ 小刚
//     名单.contains("小红")          ⇒ true
//     名单.remove("小红")            ← 按**内容**删（后面元素自动往前挪）
//     名单.remove(0)                ← 按**下标**删 —— 同名两个方法，看参数类型区分
//
//   ⚠ size() 和数组的 length 千万别混：
//         数组：   数们.length        ← 没有括号，它是字段
//         ArrayList：名单.size()      ← 有括号，它是方法
//     写 数们.length() 或 名单.size 都是编译错误。这是本课第一个必考的点。
//
//   遍历（增强 for，和第 07 课数组的写法一模一样）：
//
//     for (String 名字 : 名单) {
//         System.out.println(名字);
//     }
//
//   ⚠ 需要自己数编号（"第1个"）就得另外维护一个计数器 ——
//     增强 for 不给你下标。
//
// ② HashMap：键 → 值
//
//     HashMap<String, Integer> 分数表 = new HashMap<>();
//     分数表.put("小明", 92);        ← 存：键 → 值
//     分数表.put("小红", 88);
//
//     分数表.get("小明")             ⇒ 92
//     分数表.get("小刚")             ⇒ **null**      ← ⚠ 键不存在，不是 0！
//     分数表.containsKey("小明")      ⇒ true
//     分数表.size()                 ⇒ 2
//
//   ⚠ 两个尖括号**不能省**：HashMap<String, Integer>，一个是键的类型，
//     一个是值的类型。键必须是对象类型 —— 所以写 Integer，不能写 int。
//
//   ⚠ 键不存在时 get 返回 null，这是这一课最容易踩的一脚。
//     如果你写 int 分数 = 分数表.get("小刚"); 会**当场崩**：
//         Exception in thread "main" java.lang.NullPointerException
//     因为 Java 要把 null 拆回 int（拆箱），拆不了。
//     安全写法是先问一句：if (分数表.containsKey("小刚")) { ... }
//
// ③ 泛型类：自己造一个能装任何东西的盒子
//
//     class 盒子<T> {
//         private T 里面;                  ← T 是"占位符"：用的时候才定
//         public void 放(T 值) { this.里面 = 值; }
//         public T 取() { return 里面; }
//     }
//
//   用的时候把 T 填上：
//
//     盒子<String> 名盒 = new 盒子<>();      ← T = String
//     名盒.放("Java");
//     String s = 名盒.取();                  ← 拿出来直接是 String，不用强转
//
//     盒子<Integer> 数盒 = new 盒子<>();     ← T = Integer。⚠ 不能写 <int>
//     数盒.放(300);
//
//   ⚠ 泛型里**不能用基本类型**：<int> <double> <char> 都是编译错误，
//     要写它们的包装类 <Integer> <Double> <Character>。
//     （为什么：泛型是靠"擦除"实现的，T 最终会被当成 Object 处理，
//       而 int 不是 Object。这条现在只要记住结论就行。）
//
//   ⚠ `new 盒子<>()` 里那对空尖括号是"类型推断"：右边不用重复写一遍 String。
//
// ④ 泛型方法：<T> 写在返回类型**前面**
//
//     public static <T> void 打印两次(T 值) {
//         System.out.println(值);
//         System.out.println(值);
//     }
//
//   调用的时候不用指定 T，编译器看你传什么就定什么：
//     打印两次("泛型");      → T 推断成 String
//     打印两次(7);           → T 推断成 Integer（7 自动装箱）
//
//   ⚠ 位置容易写错：<T> 必须在**返回类型之前**。
//         public static <T> void 打印两次(T 值)     ✓
//         public static void <T> 打印两次(T 值)     ✗ 语法错误
//   记法：先声明"我这儿有个类型占位符 T"，再说"我是干嘛的"。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：把 size() 写成 size，或者把数组的 length 写成 length()
//
//     名单.size            // ✗ 错误: 找不到符号  变量 size
//     数们.length()        // ✗ 错误: 找不到符号  方法 length()
//
// 你会看到两种不一样但都看不懂的报错。为什么：
//   **数组的 length 是字段**（数组是特殊对象，长度是它的一个成员变量）
//   **集合的 size 是方法**（ArrayList 自己实现的一个方法）
// 一句话记：**数组 length 没括号，集合 size() 有括号。** 检查里专门看了这条。
//
// ⚠ 坑 2：遍历中往集合里加东西 / 删东西
//
//     for (String 名字 : 名单) {
//         if (名字.equals("小红")) {
//             名单.remove(名字);            ← ✗ 抛异常
//         }
//     }
//
// 你会看到：
//     Exception in thread "main" java.util.ConcurrentModificationException
// 为什么：增强 for 底下其实是用"迭代器"一个个往下走的，
// 它在心里记着"我走到第几个了"。你在外面把元素删掉，集合的长度变了，
// 它记的位置就对不上了 —— 于是它宁可报错也不敢继续瞎走。
// 正确做法：先把要删的**记下来**，遍历结束后再删。
// ⚠ 注意 `==` 和 equals 在这里也是同一个老坑：
//     名字.equals("小红")   ✓ 比内容        名字 == "小红"        ✗ 比地址
//
// ⚠ 坑 3：HashMap 的 get 返回 null，直接当数字用
//
//     int 分 = 表.get("不存在的人");        // ✗ 运行时 NullPointerException
//
// 你会看到：编译**通过**（Integer 能自动变成 int），跑起来崩在那一行，
// 报的是 NullPointerException，位置指向这个赋值 —— 看着莫名其妙，
// 因为那一行根本没有 "." 调用。
// 为什么：Integer → int 的自动拆箱在 null 上做不了（null 不是一个数）。
// 安全写法：
//     Integer 分 = 表.getOrDefault("不存在的人", 0);      ← 给个默认值
//     或者先 containsKey 判断。
//
// ⚠ 坑 4：以为 ArrayList 的 get 越界会返回 null
//
//     名单.get(99);         // ✗ 抛 IndexOutOfBoundsException
//
// 你会看到：Exception in thread "main" java.lang.IndexOutOfBoundsException:
//     Index 99 out of bounds for length 3
// 为什么：ArrayList 的下标越界和数组一样是**抛异常**，不是返回 null。
// （Map 那边不同：键不存在返回 null。这两个别记混 ——
//   **List 越界抛异常，Map 键不存在返回 null。**）
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   main 里四步 + 一次遍历，顺序就是检查比对的顺序：
//
//     ① ArrayList
//        打印 名单.size()                → 3
//        打印 名单.get(1)                → 小红
//        打印 名单.contains("小红")       → true
//
//     ② HashMap
//        打印 分数表.get("小明")          → 92
//        打印 分数表.get("小刚")          → null
//        （⚠ 这一行千万**不要**赋给 int，直接 println 就行）
//
//     ③ 泛型类
//        打印 名盒.取()                  → Java

//     ④ 遍历 名单（用增强 for，配一个自己数的计数器 i）

//
//     ⑤ 泛型方法
//        打印两次("泛型")                → 泛型 / 泛型
//        打印两次(7)                     → 7 / 7
