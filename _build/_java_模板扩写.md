// 第 00 课：跑通第一个程序 —— 把 JDK 装好
//
// ─────────────────────────────────────────────────────
//  先介绍：本课的唯一目标
// ─────────────────────────────────────────────────────
//
// ⚠⚠ 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
//
//    为什么把它排在第 00 课：
//      Java **不是"装上就能跑"的语言** —— 它要 JDK，而网上大量教程
//      让人装的是 JRE。**JRE 里没有 javac**，于是他永远编不过，
//      还找不到原因。这一步值得单独占一课。
//
//    还有一个理由：所有教程里，**"卡在装工具"是放弃率最高的一步**。
//      大多数人不是学不会编程，而是在"第一步就跑不起来"那里放弃了。
//
//    跑通之后你拿到的是**信心**：知道自己的机器真的能编、能跑，
//      后面每一课的报错才都是"我写错了"，而不是"环境又怎么了"。
//
// ─────────────────────────────────────────────────────
//  用法与例子：需要什么、Java 程序长什么样
// ─────────────────────────────────────────────────────
//
//  一、需要什么（两样，都是免费的）
//
//  ① .NET SDK  —— "课程运行器"。它替你调 javac 和 java，并跑起来看结果。
//
//        winget install Microsoft.DotNet.SDK.8
//
//     ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
//
//  ② JDK       —— Java 的开发包。**不是 JRE。**
//
//        winget install Microsoft.OpenJDK.21
//
//     或者去 https://adoptium.net 下 Temurin。
//
//     装完**重开一个窗口**（让 PATH 生效），然后敲这两条：
//
//        javac -version
//        java  -version
//
//     两条都能看到版本号才算成。
//
//  ⚠⚠ **JDK ≠ JRE** —— 这是这一课最重要的一句话：
//
//        JRE = Java Runtime Environment    只能**运行**别人编好的程序
//        JDK = Java Development Kit        = JRE + **javac 编译器** + 工具
//
//     只装 JRE 的话，`java` 有、`javac` 没有 ——
//     而你要**自己写代码**，就必须要 javac。
//     报错会是「找不到 javac」或者「不是内部或外部命令」。
//
//  二、Java 的程序结构：和 C 完全不同的三点
//
//  ① **不能有游离的代码。** 每一样东西都必须装在一个**类**里面。
//
//        Python 可以:   print("hi")                    ← 文件顶层直接写
//        C 可以:        int main() { printf(...); }    ← 函数里直接写
//        Java 不行:     必须 类 → 方法 → 语句，一层套一层
//
//     在文件顶层直接写一句 System.out.println("hi"); 会报：
//         Main.java:1: 错误: 需要类、接口、批注类型、枚举、记录、方法或字段
//
//  ② **入口方法长这样**，一个字都不能错：
//
//        public static void main(String[] args) { ... }
//        ↑      ↑      ↑    ↑      ↑
//        公开   静态   无返回 方法名  参数（一个字符串数组）
//
//     少了 static ⇒ 老版本 JDK 上程序起不来。这是 Java 新手最常卡的第一处。
//     ⚠ 但要知道：**JDK 25（新版本）放宽了这条** —— 漏 static、漏 public、
//       甚至没参数，实测都能编译能跑。所以「在我机器上能跑」不等于写对了。
//       **照标准写法写**，换台机器、换个 JDK 也不慌。
//
//  ③ **public 的类名必须和文件名一致**（区分大小写）。
//
//        文件叫 Main.java  ⇒  类必须叫 public class Main
//        写成 public class main  ⇒ 编译报错
//
//     这一条**别的语言都没有**。C 的 main 是小写的函数，
//     而 Java 的 main 是方法、类才是外壳 —— 别把两件事混起来。
//
//  三、Java 比 C 还多一层：字节码
//
//        Main.java
//           ↓  javac Main.java        ← 编译器
//        Main.class                    ← **字节码**（不是机器码！）
//           ↓  java Main               ← JVM 解释执行
//        结果
//
//  C 编译出来的是**你这台机器的机器码**（换台机器就跑不了）。
//  Java 编译出来的是**字节码**，由 JVM 在运行时翻译 ——
//  所以同一份 .class 在 Windows、Linux、Mac 上都能跑。
//
//  ⚠ 运行的时候写的是 **java Main**：一个**类名**，不带任何后缀。
//
//        java Main             ✓ 标准写法
//        java Main.class       ✗ 错误: 找不到或无法加载主类 Main.class
//        java Main.java        ⚠ 新版 JDK（11 起）**碰巧也能跑** ——
//                                它把 .java 当源码直接编译再运行，那是另一套机制。
//                                别依赖它：课程检查走的是 javac + java Main 这条路。
//
//  四、这一课唯一要练的手艺：读第一条 error
//
//  Java 的报错长这样（这是**故意写错**的代码）：
//
//      Main.java:5: 错误: 需要';'
//          System.out.println("你好")
//                                 ^
//      1 个错误
//
//  拆开看：**哪个文件、第几行、什么错**。先看行号。
//
//  ⚠⚠ **两条铁律**：
//
//   ① **只看第一条 error。** 后面那几十条多数是它引起的连锁反应。
//      一个没写对的括号能让编译器抱怨一整屏。
//
//   ② **报错行号常常要往上多看一行。** 编译器是读到"它不认识的东西"
//      才报的错，而那个东西往往是**上一行**漏了什么造成的。
//
//  ⚠ Java 的报错里还有一个**中文**提示要注意：
//
//        错误: 类 Main 是公共的, 应在名为 Main.java 的文件中声明
//
//    这是"类名和文件名不一致"。Java 特有的，看到它就去改类名。
//
//  ⚠ 本机是中文环境，javac 的报错就是中文的。换一台英文环境的机器，
//    同样的错会写成 `error: ';' expected` —— **是同一件事**，别被语言吓住。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：装的是 JRE，不是 JDK
//
//     winget install Microsoft.OpenJDK.21     ← 对的
//     （而网上很多教程让人装"Java 运行时 / JRE"—— 那个**没有 javac**）
//
// 你会看到：敲 `javac -version` 说「不是内部或外部命令」，
//   或者课程检查一上来就红，写着「工具链还没装好」。
// 为什么：**编译器 javac 只在 JDK 里。** JRE 是给"只想运行别人程序"的人用的。
// ⇒ 再装一次 JDK 就好，两个可以共存，不用先卸。
//   ⚠ 这条**不是你代码的问题** —— 第一项检查专门在说这件事。
//
// ⚠ 坑 2：装完不重开窗口
//
// 你会看到：`javac` 还是"不是内部或外部命令"——
//   明明刚才装的时候提示成功了。
// 为什么：安装程序改的是 **PATH 环境变量**，
//   而已经打开的窗口用的是**打开那一刻**的 PATH 副本。
// ⇒ 关掉窗口重新开一个（或者干脆注销一次）。
//   ⚠ 这个坑在 C 线（装 gcc）和 C# 线（装 .NET SDK）**一模一样**，
//     凡是"装完说找不到命令"，先想这一条。
//
// ⚠ 坑 3：运行的时候把 .class / .java 也写上去
//
//     java Main.class
//
// 你会看到：错误: 找不到或无法加载主类 Main.class
//   原因: java.lang.ClassNotFoundException: Main.class
// 为什么：`java` 收的是**类名**，它自己去 classpath 上找 Main.class。
//   你多写的那截后缀被当成了类名的一部分，自然找不到。
//   ⚠ 注意这条**不是编译错误** —— 编译早就成功了，是"运行"这一步的命令写错了。
//   两条路分清楚：javac 管"把源码变成 class"，java 管"把 class 跑起来"。
//
// ⚠ 坑 4：类名和文件名不一致
//
//     public class main { ... }        ← 文件叫 Main.java，类却叫 main
//
// 你会看到：Main.java:1: 错误: 类 main 是公共的, 应在名为 main.java 的文件中声明
// 为什么：**一个 .java 文件里的 public 类，名字必须和文件名一模一样**
//   （连大小写都要一样）。这是 Java 独有的规矩，别的语言都没有。
// ⇒ 这个文件叫 Main.java，所以类只能叫 `public class Main`。
//   ⚠ 这条会跟着你一路 —— 01~08 课每一课都在检查它。
//
// ─────────────────────────────────────────────────────
//  轮到你了
// ─────────────────────────────────────────────────────
//
//  这一课没有算法要写，只有三件事：
//
//    1. 确认 javac、java、dotnet 都在
//       （界面首页的「环境自检」会显示；命令行敲 javac -version 也行）
//
//    2. 让编译器**报一次错**，并且读懂它
//       下面留了一个完整的程序。先故意漏掉一个分号 → 检查 → 看报错 →
//       把分号补上 → 再检查。
//
//       为什么要你故意写错一次：**报错是编译器在跟你说话**。
//       第一次被它骂过的人，第二次才不慌。
//
//    3. 让它打印出下面这三行，就算跑通了
//
//          工具链就绪
//          我准备好学 Java 了
//          类 → main → 语句
//
//   三行的**顺序**别改 —— 检查是按顺序比对的。
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────
//   点界面上的「检查」。命令行（在源码目录里）：

// 第 01 课：输出与变量 —— 让程序开口说话
//
// ─────────────────────────────────────────────────────
//  先介绍：程序得先能"说话"
// ─────────────────────────────────────────────────────
//
// 一个程序如果什么都不输出，你就**看不见它在干什么** ——
// 它算得对不对、走到哪一步了、是不是根本没跑，你全不知道。
// 所以每一门语言的第一课都是同一件事：**把东西打到屏幕上**。
//
// 第二件事是**记住数据**。看这两行：
//
//     System.out.println(6 + 7);        ← 只能算这一次
//     int 甲 = 6;                        ← 把 6 存进一个叫「甲」的格子
//     int 乙 = 7;
//     System.out.println(甲 + 乙);       ← 以后想算几次算几次
//
// 变量的价值不在"少打几个字"，而在**给数据起了名字**：
// 以后要改，只改声明那一行，用到它的地方全都跟着变。
// 把答案 13 直接写死，程序就永远只会算这一个题。
//
// ⚠ Java 和前面几门语言最不一样的一点：**什么都得写在类里面**。
//   Python 可以在文件顶层写 print("hi")；C 可以在 main 里直接写；
//   而 Java 里**每一样东西都必须装在一个类里面** ——
//   没有游离的代码。所以第一课不讲语法细节，先把这条链路走通：
//
//       类  →  main 方法  →  语句
//
//   三层，缺一层都不行。在文件顶层直接写一句 System.out.println("hi");
//   会报：错误: 需要类、接口、批注类型、枚举、记录、方法或字段
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① 一个能跑的最小程序
//
//     public class Main {
//         public static void main(String[] args) {
//             System.out.println("你好，Java");
//         }
//     }
//
//   读法：public class Main 是**外壳**（名字必须和文件名一致），
//        main 是**入口**（程序从这一行开始跑），
//        里面那条才是**真正干活**的语句。
//
// ② 打印：println 和 print 差一个换行
//
//     System.out.println("你好，Java");     打了之后**换行**
//     System.out.print("你好，Java");       打了之后**不换行**
//
//   名字里的 ln 就是 line。要求"不换行"的时候用 print（第 05 课会用到）。
//
// ③ 文字要用双引号包起来
//
//     System.out.println("你好，Java");     ✓ 双引号里的是**文字本身**
//     System.out.println(你好，Java);       ✗ 编译器会去找一个叫「你好」的东西
//
//   引号里的内容**原样打出来**，包括空格和标点 —— 一个字符都不会变。
//
// ④ 变量：先写类型，再写名字，再给初值
//
//     int 甲 = 6;              ← int 是"装整数的格子"
//     int 乙 = 7;
//     System.out.println(甲 + 乙);           ⇒ 13
//
//   ⚠ 类型**必须写**。这一点和 Python 不同：
//       Python 写 甲 = 6 就行，Java 必须写 int 甲 = 6;（告诉编译器它装整数）。
//     ⚠ 等号是**英文**的 =，分号是**英文**的 ;。中文标点编译器不认。
//
// ⑤ + 有两种意思，看两边是什么
//
//     int 甲 = 6, 乙 = 7;
//     System.out.println(甲 + 乙);           ⇒ 13      ← 两边都是数字：加法
//     System.out.println("和=" + 甲);        ⇒ 和=6    ← 只要有一边是文字：拼接
//
//   拼接就是"把两样东西接成一段文字"。这个规则看着简单，
//   但它埋着本课最容易踩的一个坑（见下面坑 4）。
//
// ⑥ 想算加法，就用括号圈起来
//
//     System.out.println("和=" + 甲 + 乙);      ⇒ 和=67     ✗ 想要的是 和=13
//     System.out.println("和=" + (甲 + 乙));    ⇒ 和=13     ✓
//
// ⑦ 变量可以改，也可以拿来算别的
//
//     int 甲 = 6;
//     甲 = 甲 + 1;                    ← 右边先算，再存回左边的格子
//     System.out.println(甲);         ⇒ 7
//
// ⑧ 注释：// 后面这一行不算代码
//
//     // 这是在解释给别人（和三个月后的自己）看的，编译器直接跳过
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：类名和文件名对不上
//
//     public class main {            ← 文件叫 Main.java，这里却写了小写 main
//
// 你会看到：错误: 类 main 是公共的, 应在名为 main.java 的文件中声明
// 为什么：**一个 .java 文件里的 public 类，名字必须和文件名一模一样**，
//   连大小写都要一样。Java 的规矩，别的语言没有这一条。
// ⇒ 你的答题文件叫 Main.java，所以类只能叫 `public class Main`。
//   ⚠ 写成 `class Main`（去掉 public）在别的场合也能跑，但这一课就照标准写。
//
// ⚠ 坑 2：分号打成了中文的 ；
//
//     System.out.println("你好，Java")；        ← 最后这个是全角的 ；
//
// 你会看到：错误: 非法字符: '\uff1b'
//   （\uff1b 就是全角分号这个字符的编号）
// 为什么：javac 只认**半角符号**。中文输入法下打标点很容易出这个错，
//   而且它长得和 ; 几乎一样，肉眼很难发现。
//   ⚠ 同类还有：中文逗号 ，、中文括号 （）、中文引号
// ⇒ 写 Java 代码时把输入法切到英文，或者至少切到"英文标点"。
//
// ⚠ 坑 3：引号用了中文的
//
//     System.out.println(「你好，Java」);
//
// 你会看到：错误: 进行语法分析时已到达文件结尾
// 为什么：编译器不认全角引号，它以为字符串到文件末尾都没结束。
//   ⚠ 这条报错的**行号会指到最后一行**，看着像"别的地方出错了" ——
//     其实问题就在你写引号的那一行。
// ⇒ 而且这个坑有个更隐蔽的版本：**文字里的逗号用了中文的**
//     System.out.println("你好，Java");     ← 字符串里的中文逗号**不报错**
//   编译完全通过，只是打出来的是「你好，Java」而不是「你好,Java」——
//   检查一比对文字就红了。**字符串里的标点也要和题目一模一样。**
//
// ⚠ 坑 4：把「拼接」当成了「加法」
//
//     int 甲 = 6;
//     int 乙 = 7;
//     System.out.println("和=" + 甲 + 乙);       ⇒ 和=67      ✗
//
// 你会看到：**什么都不报**，程序跑得好好的，只是结果不对。
// 为什么：+ 是从左往右算的。先算 "和=" + 甲 —— 左边是文字，
//   于是这一步变成**拼接**，得到字符串 "和=6"；再 + 乙，还是拼接 → "和=67"。
//   一旦 + 的某一边是 String，它就变成拼接，而且**改不回来**了。
// ⇒ 想先算加法，就用括号把算式圈起来：
//       System.out.println("和=" + (甲 + 乙));    ⇒ 和=13
//   ⚠ 这是本课最值得记的一条：**它的错法是静默的** ——
//     编译器不报错、运行不警告，只有结果悄悄不对。
//
// ⚠ 坑 5：语句写在了类外面
//
//     System.out.println("你好，Java");        ← 文件里就这么孤零零一句
//
// 你会看到：错误: 需要类、接口、批注类型、枚举、记录、方法或字段
// 为什么：Java **没有游离的代码**。每一条语句都必须待在
//   「类 → 方法 → 语句」这三层里面，一层都不能省。
// ⇒ 把它放进 main 的花括号里。忘了写 main、或者把花括号配对搞错，
//   也会得到同一句话（编译器认为你"在类里写了不该写的东西"）。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
// ⚠ 要写一个**完整程序**：public class Main + main 方法，两样都要有。
//
//   1. 打印一行：你好，Java
//
//   2. 定义两个 int 变量：甲 = 6、乙 = 7
//
//   3. 打印它们的和（应该是 13）
//      ⚠ 必须**真的用变量相加**，不要把 13 写死：
//            System.out.println(13);              ✗ 检查会看穿（见下）
//            System.out.println(甲 + 乙);         ✓
//        为什么较这个真：把答案写死，这个程序就只能算这一道题，

// 第 03 课：条件判断 —— 让程序会做选择
//
// ─────────────────────────────────────────────────────
//  先介绍：程序要会"分岔"
// ─────────────────────────────────────────────────────
//
// 到上一课为止，程序只会一条道走到黑：第一行、第二行、第三行……
// 但真实的需求几乎都是"看情况"：
//
//     猜的数字比 42 大？→ 告诉他"大了"
//     分数够 90 吗？    → 够就是"优秀"，不够再看下一档
//     今年是闰年吗？    → 是就 2 月多一天
//
// 条件判断让程序**分岔**：同一段代码，不同的数据走不同的路。
// 这是"程序开始像在思考"的第一步，也是从"计算器"变成"工具"的分界线。
//
// Java 的条件和别的语言长得差不多，但有**一条特别值得讲**：
// 它对 `=` 和 `==` 的检查比 C/C++ 严 —— 可是**只严一半**。
//
//     if (分数 = 3)        编译不过（int 不是 boolean，Java 当场拦住你）
//     if (年 % 4 = 0)      编译不过（报「意外的类型」）
//     if (标志 = true)     **能编译、零警告，而且条件永远为真**   ← 真正的坑
//
// 前两种编译器替学生挡了，第三种挡不住。所以这一课的核心就盯它。
// （这三条都是本机 javac 25.0.3 实测的结果。）
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① if / else if / else：从上往下试，**第一个为真的就进去**
//
//     if (分数 >= 90) {
//         return "优秀";
//     } else if (分数 >= 60) {
//         return "及格";
//     } else {
//         return "不及格";
//     }
//
//   ⚠ 顺序是有意义的：95 同时满足 >= 90 和 >= 60，但它在**第一条**就被接走了。
//     所以判断范围要从"最窄"往"最宽"写。
//
// ② 比较运算符（结果是 boolean：true 或 false）
//
//     ==   等于        !=   不等于
//     >    大于        <    小于
//     >=   大于等于    <=   小于等于
//
//   ⚠ 等于号是**两个**：判断相等用 ==，一个 = 是**赋值**（把右边存进左边）。
//
// ③ 把几个条件连起来
//
//     &&   两边都为真，结果才为真     （并且）
//     ||   只要有一个为真，结果就为真 （或者）
//     !    取反：!是闰年 就是"不是闰年"
//
//     分数 < 0 || 分数 > 100            ← 越界判断（两头都要写）
//     (年 % 4 == 0 && 年 % 100 != 0) || 年 % 400 == 0     ← 闰年的完整条件
//
//   ⚠ 优先级：&& 比 || 先算。所以上面那层的括号其实可以省，
//     但**写上更好读** —— 半年后回来看，你会感谢自己。
//
// ④ boolean 变量：先把结论算出来，再用它判断
//
//     boolean 是闰年 = (年 % 4 == 0 && 年 % 100 != 0) || 年 % 400 == 0;
//     if (是闰年) {
//         return "闰年";
//     }
//
//   好处有两个：条件太长时**读起来清楚**，而且这个结论还能复用。
//   ⚠ 用 boolean 变量时**直接写它**就行：if (是闰年)。
//     写 if (是闰年 == true) 也对，但多打一遍就多一次手滑机会（见坑 1）。
//
// ⑤ switch：一个值对好几个固定选项时，比一串 if 清爽
//
//     switch (星期几) {
//         case 1:  return "星期一";
//         case 2:  return "星期二";
//         default: return "没有这个星期";
//     }
//
//   default 是"以上都不是"的兜底 —— 强烈建议写上，它是你的安全网。
//
// ⑥ 方法里每个分支都要能 return
//
//   Java 会检查"所有能走到的路径都有返回值"。用 if / else if / else
//   兜住全部情况，或者最后留一句无条件的 return，都能满足它。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：把 == 写成了 =（本课最重要的一个坑，它有**三种下场**）
//
//     if (分数 = 3) { }              ← 第一种
//
// 你会看到：错误: 不兼容的类型: int无法转换为boolean
// 为什么：一个 = 是赋值，`分数 = 3` 这个表达式的类型是 **int**，
//   而 if 的括号里**必须是 boolean**。类型对不上，Java 直接拒绝编译。
//   ✅ 好消息：**这一点 Java 比 C/C++ 严** —— C/C++ 对 if (x = 3) 顶多给个警告
//      （甚至不警告），Java 直接不让你编。
//
//     if (年 % 4 = 0) { }            ← 第二种
//
// 你会看到：错误: 意外的类型   /   需要: 变量   /   找到: 值
// 为什么：= 的优先级最低，这一行会被理解成"把 0 存进 年 % 4"——
//   可 年 % 4 是一个**算出来的值**，不是变量，存不进去。
//
//     boolean 标志 = false;
//     if (标志 = true) { ... }       ← 第三种：**编译通过，零警告**
//
// 你会看到：什么都不报。而那个分支**永远会进去**（赋值的结果就是刚存进去的 true）。
// 为什么：boolean 赋给 boolean 是**合法**的，编译器没有理由拦你。
//   这是 Java 唯一挡不住的那一种，也是最危险的 —— 程序照跑，结果全错。
// ⇒ 防身三招：
//     ① 判断相等一律用 ==；
//     ② boolean 变量直接写 if (标志)，不写 == true；
//     ③ 把常量写在左边：if (42 == 猜) —— 手滑写成 = 会直接编译不过。
//
// ⚠ 坑 2：漏了 return，或者分支没兜全
//
//     static String 猜数字(int 猜) {
//         if (猜 == 42) {
//             return "对了";
//         }
//         // 猜比 42 小、比 42 大的情况都没写
//     }
//
// 你会看到：错误: 缺少返回语句
// 为什么：方法声明了要返回 String，可编译器发现"如果 猜 不是 42，
//   这个方法走到末尾也没交出任何东西"—— 它不允许这种可能。
// ⇒ 用 else 兜住剩下的所有情况，或者最后写一句无条件的 return：
//       if (猜 == 42) { return "对了"; }
//       if (猜 < 42) { return "小了"; }
//       return "大了";                 ← 前面都没接住，那一定是大了
//
// ⚠ 坑 3：switch 忘了 break —— "贯穿"
//
//     switch (x) {
//         case 1: System.out.println("一");
//         case 2: System.out.println("二");
//         default: System.out.println("其他");
//     }
//     x = 1 时你会看到**三行全打**：一 / 二 / 其他
//
// 你会看到：什么都不报，只是多打了两行。
// 为什么：switch 的规矩是"**从匹配上的那个 case 开始，一路往下执行**"，
//   直到碰上 break 或者整块结束。这叫 fall-through（贯穿），不是 bug，是设计。
// ⇒ 每个 case 结尾加 break;（或者像本课这样直接 return，return 本身就跳出了）。
//   ⚠ 本课的四个方法都**直接 return**，所以不用写 break —— 但你要知道为什么。
//
// ⚠ 坑 4：方法忘了写 static
//
//     String 猜数字(int 猜) { ... }        ← 少了 static
//
// 你会看到：错误: 无法从静态上下文中引用非静态 方法 猜数字(int)
// 为什么：检查的时候，你的方法会被放进 class Main 里、**从 main 里调用**：
//       public class Main {
//           static String 猜数字(int 猜) { ... }     ← 你的方法
//           public static void main(String[] args) {
//               System.out.println(猜数字(10));      ← 从这里调用
//           }
//       }
//   main 是 static 的，它**只能直接调用 static 的方法**。
//   不写 static 的方法属于"对象"，得先 new 一个对象出来才能用。
// ⇒ 每个方法前面都加上 static（第 05 课会专门讲它是什么）。

// 第 04 课：循环 —— 让程序重复做事，并且重复得**正好**
//
// ─────────────────────────────────────────────────────
//  先介绍：循环是"程序能干活"的开始
// ─────────────────────────────────────────────────────
//
// 求和、计数、查找、遍历 —— 这些活全都是"把同一件事做很多遍"。
// 没有循环，你只能把一行代码抄十遍，改一个地方要改十处。
//
// 但循环有一类和前面完全不同的错法：**它不报错、也不崩**，
// 只是把结果算错一点点，而那一点点很难看出来：
//
//     差一错误（off-by-one）：for (int i = 1; i < n; i++) 少跑一次。
//       算 1..10 的和，它给你 45 —— 看上去像个正常答案。
//     写反方向的差一：for (int i = 0; i <= 次数; i++) 多跑一次，
//       重复 3 遍变成 4 遍 —— 同样一声不吭。
//
// 所以这一课真正的功夫不在"会写循环"，而在**数清楚它跑几遍**。
//
// 还有一个**好消息**要讲清楚：
//   Java 里"累加变量没给初值"是**编译错误**，不是"碰巧算对"。
//       C++：int 和; 里面是内存里的残留值，程序照跑，可能碰巧算出"正确答案"；
//       Java：直接报「可能尚未初始化变量和」，程序根本编译不出来。
//   Java 用一条编译错误，把这类"结果时对时错"的 bug 从你身上拿走了。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① for：**次数已知**的时候用它（最常用）
//
//     for (int i = 1; i <= n; i++) {      ← 从 1 数到 n（含 n）
//         和 += i;
//     }
//     for (int i = 0; i < n; i++) {       ← 从 0 数起，一共 n 个
//         结果 += 文字;
//     }
//
//   三个部分读作：**开始**（i = 1）；**继续的条件**（i <= n）；
//   **每次做完干什么**（i++ 就是 i = i + 1）。
//
//   ⚠ 这两种写法都对，但**别混**：
//       从 1 数到 n（含 n）  →  条件写 <= n
//       从 0 数起、一共 n 个  →  条件写 < n
//
// ② while：**以条件为主**，不知道要跑几次
//
//     int 试 = 2;
//     while (试 < n) {
//         if (n % 试 == 0) { ... }
//         试++;
//     }
//
//   先看条件，为真才进。**可能一次都不跑。**
//
// ③ do-while：**至少执行一次**（先做一遍，再看条件）
//
//     do {
//         位++;
//         剩 /= 10;
//     } while (剩 > 0);
//
//   ⚠ 注意结尾那个**分号**，是 do-while 独有的。
//   什么时候非它不可：数位数。n = 0 也是 1 位数，
//   可 while (剩 > 0) 在 n = 0 时一次都不跑，会给出 0 位 —— 错的。
//
// ④ 增强 for：把数组/集合里的元素一个一个拿出来
//
//     for (int x : 数字) {
//         ...
//     }
//
//   读作"对于 数字 里的每一个 x"。不用管下标，写起来最省事。
//
// ⑤ break 和 continue：两个方向的中断
//
//     break      立刻跳出**整个**循环（后面的轮次都不跑了）
//     continue   跳过**这一轮**剩下的部分，直接进入下一轮
//
//   ⚠ 用 continue 时最容易踩的坑：忘了让循环变量往前走 → 死循环（见坑 3）。
//
// ⑥ 累加变量必须给初值
//
//     int 和 = 0;        ← 累加（+=）用 0
//     int 积 = 1;        ← 累乘（*=）用 1
//
//   ⚠ 不给初值在 Java 里**编译不过** —— 这是好事，下面坑 2 细说。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：差一错误（off-by-one）—— 少跑一次 / 多跑一次
//
//     for (int i = 1; i < n; i++) 和 += i;        ← 少跑一次（最后一个没加）
//     for (int i = 0; i <= 次数; i++) 结果 += 文字; ← 多跑一次
//
// 你会看到：**什么都不报**。
//   求和(1) 会给出 0（正确答案是 1）；重复("*", 1) 会给出 "[**]"（正确答案是 "[*]"）。
// 为什么：循环跑几次只由条件决定，编译器不知道"你心里想跑几次"。
// ⇒ **写完循环，一定拿 n = 0 和 n = 1 各在心里走一遍**，问自己两句：
//       n = 0 时，该不该跑？
//       n = 1 时，该跑几次？
//   这两问答对了，差一错误就躲开了。
//   ⚠ 本课有一条检查专门盯这里，而且它会告诉你**是哪一种**：
//     是"少跑了最后一次"，还是"多跑了一轮"。
//
// ⚠ 坑 2：累加变量没给初值
//
//     int 和;
//     for (int i = 1; i <= n; i++) 和 += i;
//
// 你会看到：错误: 可能尚未初始化变量和
// 为什么：**局部变量必须先赋初值才能用**，Java 会一条一条路径地检查。
//   ✅ 这里必须说一句：**这是 Java 的优点，不是刁难** ——
//     同样的写法在 C++ 里能编译能运行，因为未初始化的局部变量装的是
//     内存里的残留值：这次碰巧是 0，你的累加就"算对了"，
//     换个编译器、换个运行顺序它又变成别的数 —— 那是最难查的一类 bug。
//     Java 直接不让你编译，等于把这类 bug 从你身上拿走了。
// ⇒ 声明的时候就写清楚：int 和 = 0;   int 积 = 1;
//
// ⚠ 坑 3：用 continue 时忘了让循环变量往前走 —— 死循环
//
//     int i = 0;
//     while (i < 10) {
//         if (i % 2 == 0) {
//             continue;          ← 跳过了下面的 i++，i 永远不变
//         }
//         i++;
//     }
//
// 你会看到：程序**一直不结束**（界面上的检查会卡到超时）。
//   不是崩溃，不是报错，就是没完没了。
// 为什么：continue 跳到"下一轮"，而 while 的下一轮又是从同一个条件开始 ——
//   i 一直没变，条件永远为真。
// ⇒ 用 while + continue 时，把"往前走"那一步放在 continue **之前**，
//   或者干脆用 for（for 的 i++ 写在头部，continue 跳不过它）。
//
// ⚠ 坑 4：在 for 的括号里声明的变量，出了循环就没了
//
//     for (int i = 0; i < 3; i++) { ... }
//     System.out.println(i);          ← 这里用不了 i
//
// 你会看到：错误: 找不到符号   符号: 变量 i   位置: 类 Main
// 为什么：`for (int i = ...)` 里的 i 是**这个循环专有的**，
//   它的活动范围就是循环那一对花括号。出去就不认识了。
// ⇒ 要在循环外用到这个数，就把它声明在外面：
//       int i = 0;
//       for (i = 0; i < 3; i++) { ... }
//       System.out.println(i);      ✓
//   ⚠ 顺带记住：报错里的「位置: 类 Main」不是说你写错了地方，
//     它只是在说"我在 Main 这个类里找不到叫 i 的东西"。
//
// ⚠ 坑 5：循环走到数组外面去了
//
//     int[] x = {1, 2, 3};
//     for (int i = 0; i <= x.length; i++) {
//         System.out.println(x[i]);
//     }
//
// 你会看到：前三行正常打印 1 / 2 / 3，然后
//     Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException:
//         Index 3 out of bounds for length 3
//   程序到此为止。
// 为什么：下标范围是 0 … length - 1，也就是 0、1、2。
//   `i <= x.length` 会跑到 i = 3，那一位不存在。
// ⇒ 两种对写法，挑一个：
//       for (int i = 0; i < x.length; i++)       ✓ 用 <
//       for (int v : x)                          ✓ 增强 for，压根不碰下标
//   ⚠ 这条报错是**好事**：Java 会检查下标，越界立刻停下，
//     而不是像 C++ 那样去读旁边的内存、读到什么都可能。
//

//        while (剩 > 0) 这种写法在 n = 0 时一次都不跑，会给出 0 位。

//   4. static int 最小因数(int n)             ← 用 **while**，找到后用 **break** 跳出
//        n 的最小因数（能整除 n、并且 >= 2 的最小的数）

//        找不到因数（说明 n 是质数）就返回 n 本身：  7 → 7

//   5. static int 偶数个数(int[] 数字)        ← 用**增强 for**，用 **continue** 跳过奇数
