@@@ 09_封装
标题|第 09 课：封装与访问控制 —— 把字段关进盒子里
要求|1. 写一个 人 类，字段必须 private：private String 名字; / private int 年龄;
要求|2. 写四个方法：取名字() / 取年龄() / 改名字(String) / 改年龄(int)
要求|3. 改年龄 要校验：小于 0 或大于 150 就不修改；改名字 要校验：null 或去掉空格后为空就不修改
要求|4. main 里依次打印三组：正常工作、非法值被拒绝、两个名字一个对象
模板|// 第 09 课：封装与访问控制 —— 把字段关进盒子里
模板|//
模板|// 先介绍：为什么要"封装"
模板|//
模板|// 现在你的字段是长这样的：
模板|//
模板|//     class 人 {
模板|//         String 名字;
模板|//         int 年龄;
模板|//     }
模板|//
模板|// 用起来：
模板|//
模板|//     人 甲 = new 人();
模板|//     甲.年龄 = -5;          ← 编译通过！跑起来也不报错！
模板|//     甲.年龄 = 99999;       ← 也通过
模板|//
模板|// 问题就在这：**你写 人 这个类的时候，脑子里有一条规矩** ——
模板|// "年龄必须是 0 到 150 之间的整数"。可这条规矩没地方写，
模板|// 它只活在你脑子里。任何人拿到 人 这个类，都能把 年龄 改成 -5，
模板|// 你的程序就此带着一个不可能的数据一路跑下去，等你发现的时候
模板|// 已经是"某个人的年龄是 -5，所以他免票"这种莫名其妙的 bug。
模板|//
模板|// 那能不能在"每次用到年龄"的地方都写一遍检查？
模板|// 不能 —— 你不知道以后有多少个地方会用到它。而且总有人忘。
模板|//
模板|// 封装的思路是：**把规矩焊死在数据旁边**。
模板|//   ① 字段不许别人直接碰  → private
模板|//   ② 想读，走 取年龄()   → getter
模板|//   ③ 想改，走 改年龄(v)  → setter，**检查写在里面**
模板|//
模板|// 这样"年龄永远是合法的"就成了这个类**自己保证**的事，
模板|// 而不是"每个用它的人都记得要检查"。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// private 的意思很直白：**只有这个类自己看得见**。
模板|//
模板|//     class 人 {
模板|//         private int 年龄;          ← 外面看不见了
模板|//
模板|//         public int 取年龄() {      ← 给外面开一扇窗：只能看
模板|//             return 年龄;
模板|//         }
模板|//
模板|//         public void 改年龄(int 值) {   ← 给外面开一扇门：检查了才放进来
模板|//             if (值 < 0 || 值 > 150) {
模板|//                 return;            ← 非法值？当没听见
模板|//             }
模板|//             this.年龄 = 值;
模板|//         }
模板|//     }
模板|//
模板|// 外面的世界随之改变：
模板|//
模板|//     甲.年龄 = -5;         // ✗ 编译错误：年龄 在 人 中是 private 访问控制
模板|//     甲.改年龄(-5);        // ✓ 编译通过 —— 但值被拒绝了，年龄没变
模板|//     甲.改年龄(30);        // ✓ 改成功
模板|//     int 岁 = 甲.取年龄();  // ✓ 读得到
模板|//
模板|// ⚠ 注意第二行和第三行的区别，这是封装真正的价值：
模板|//   **它不是"不让你改"，而是"只能按规矩改"。**
模板|//   非法的调用不再是一个错误，而是一个**被忽略的请求**。
模板|//
模板|// 套路的形状是固定的：名字 → 取名字()/改名字(String)，年龄 → 取年龄()/改年龄(int)。
模板|// 方法名怎么起随你（很多书用 getName / setAge），关键是**成对出现**：一个读、一个写。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  Java 的四种访问修饰符（按可见范围从小到大）
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     private      只有**本类**里面能碰
模板|//     （不写）      同一个**包**里能碰        ← 什么都不写叫"包访问权限"
模板|//     protected    同包 + **子类**能碰（下一课讲继承时会用到）
模板|//     public       谁都能碰
模板|//
模板|// 两条要立刻记住的：
模板|//
模板|//   ① **不写修饰符 = 包访问权限**，不是 private！
模板|//      你以前写的 `String 名字;` 就是这个级别，所以同一个文件里别的类也能改它。
模板|//
模板|//   ② 字段一律 private，方法一律 public，这条"默认搭配"能覆盖九成情况。
模板|//
模板|// ⚠ 一个文件里能放好几个类，但 public 的**只能有一个**，而且必须叫 Main。
模板|//   所以下面写的 人 不能加 public —— 加上会报：
模板|//       错误: 类 人 是公共的, 应在名为 人.java 的文件中声明
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：setter 里忘了 this —— 症状是"字段永远是 0 / null"
模板|//
模板|//     public void 改年龄(int 年龄) {      ← 参数也叫 年龄
模板|//         年龄 = 年龄;                   ← 把参数赋给参数自己
模板|//     }
模板|//
模板|// 你会看到：调用 甲.改年龄(30) 之后 甲.取年龄() 打印出来是 **0**，
模板|// 一次都没改成功，也不报任何错。
模板|// 为什么：参数名和字段名一样时，**光写名字指的是参数**（离得近的赢）。
模板|// 要真进到字段里必须写 this.年龄 = 年龄;
模板|// 更省事的办法是给参数换个名字（参考答案用的就是这个）：
模板|//     public void 改年龄(int 值) { ... 年龄 = 值; }   ← 一眼知道谁是谁
模板|//
模板|// ⚠ 坑 2：以为 getter 返回的是"复印件"
模板|//
模板|//     int 岁 = 甲.取年龄();     ← int 是基本类型，确实是拷贝，改 岁 不影响 甲
模板|//     String 名 = 甲.取名字();  ← String 不可变，也安全
模板|//
模板|// 但换成对象类型就危险了（以后会撞上）：如果字段是 int[] 或 ArrayList，
模板|// getter 直接把那个**引用**交出去，外面 列表.add(...) 就等于绕过 setter 改了字段。
模板|// 症状：明明没人调 setter，字段却变了。
模板|// 记住一句话：**getter 交出引用 = 封装破了个洞。**
模板|//
模板|// ⚠ 坑 3：只给 setter 加了校验，构造方法没加
模板|//
模板|//     new 人("张三", -5);      ← 绕过了所有 setter，直接造出一个非法对象
模板|//
模板|// 你会看到：用 setter 时校验好好的，可对象刚 new 出来就已经是坏的。
模板|// 为什么：构造方法也是"往字段里写值"的入口，封装要封的是**所有入口**。
模板|// 这一课我们没写构造方法，但下一课一学就要记得把同样的检查搬进去。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//   main 里按这个顺序写（检查就按这个顺序比对）：
模板|//
模板|//     System.out.println("== 正常工作 ==");
模板|//     // new 一个人，用 setter 改成：名字 "李四"，年龄 30
模板|//     // 打印："名字=" + 取名字()
模板|//     // 打印："年龄=" + 取年龄()
模板|//
模板|//     System.out.println("== 非法值被拒绝 ==");
模板|//     // 试 改年龄(200)  → 超过上界，应该不变
模板|//     // 试 改年龄(-1)   → 小于下界，应该不变
模板|//     // 试 改名字(null) → 应该不变
模板|//     // 打印："年龄还是=" + 取年龄()
模板|//     // 打印："名字还是=" + 取名字()
模板|//
模板|//     System.out.println("== 两个名字，一个对象 ==");
模板|//     // 再声明一个同类型的变量，把它**赋成**第一个人（不要 new）
模板|//     // 通过第二个名字 改年龄(40)
模板|//     // 打印："第一个名字看到=" + 第一个.取年龄()
模板|//
模板|// 判年龄：值 < 0 || 值 > 150 → return
模板|// 判名字：值 == null || 值.trim().isEmpty() → return
模板|// ⚠ 注意是 || 不是 &&：两个条件中一个就拒绝。
模板|//   写成 && 会变成"两个都满足才拒绝"，等于几乎没检查。
模板|

@@@ 10_构造方法
标题|第 10 课：构造方法重载与 this() —— 造对象的不同入口
要求|1. 写一个 学生 类，三个字段全部 private：private String 名字; / private int 分数; / private String 班级;
要求|2. 写三个构造方法：学生(名字,分数,班级) 全存；学生(名字,分数) 班级默认"未分班"；学生(名字) 分数默认 0、班级默认"未分班"
要求|3. 后两个构造方法必须用 this(...) 调用第一个，不许自己重复写赋值
要求|4. 写 public String 介绍() 返回 名字 + "/" + 分数 + "/" + 班级；main 里用三个构造方法各造一个对象并打印介绍()
模板|// 第 10 课：构造方法重载与 this() —— 造对象的不同入口
模板|//
模板|// 先介绍：为什么会有"好几个构造方法"
模板|//
模板|// 上一课我们是这么造对象的：
模板|//
模板|//     人 甲 = new 人();
模板|//     甲.改名字("张三");
模板|//     甲.改年龄(20);
模板|//
模板|// 三行才能得到一个"能用的"对象。如果这个对象有八个字段呢？八行。
模板|// 而且**中间任何一步忘掉，你手上就是一个半成品** ——
模板|// 名字有了、年龄还是 0，后面用起来全是坑。
模板|//
模板|// 构造方法解决的就是这件事：**让对象一诞生就是完整的**。
模板|//
模板|//     人 甲 = new 人("张三", 20);     ← 一行，而且不可能忘
模板|//
模板|// 但事情没这么简单。现实里"造一个学生"的场合有好几种：
模板|//
模板|//     · 报到的时候只知道名字        → 分数、班级还不知道
模板|//     · 考完试了，知道名字和分数    → 班级还不知道
模板|//     · 转班进来，三样都知道        → 齐全
模板|//
模板|// 三种场合，你不可能要求调用者"你自己把不知道的填空了再传进来"。
模板|// 于是就有**三个构造方法**，各自负责一种场合 —— 这就是构造方法重载。
模板|//
模板|// 重载（overload）的规矩很简单：
模板|//   **方法名一样（对构造方法来说就是类名），参数列表不一样。**
模板|//   参数个数不同、类型不同、顺序不同都算不一样。
模板|//   ⚠ 光**返回类型**不同不算重载 —— 而构造方法本来就没有返回类型，
模板|//     所以构造方法的重载只能靠参数区分。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：三个构造方法，最"全"的那个干实事
模板|//
模板|//     class 学生 {
模板|//         private String 名字;
模板|//         private int 分数;
模板|//         private String 班级;
模板|//
模板|//         public 学生(String 名字, int 分数, String 班级) {   ← 干实事的那个
模板|//             this.名字 = 名字;
模板|//             this.分数 = 分数;
模板|//             this.班级 = 班级;
模板|//         }
模板|//
模板|//         public 学生(String 名字, int 分数) {
模板|//             this(名字, 分数, "未分班");      ← 调用上面那个，补一个默认班级
模板|//         }
模板|//
模板|//         public 学生(String 名字) {
模板|//             this(名字, 0, "未分班");         ← 补两个默认值
模板|//         }
模板|//     }
模板|//
模板|// 用起来是这样，编译器**按参数找**该用哪个：
模板|//
模板|//     new 学生("小明", 92, "三班")   → 第一个（三个参数）
模板|//     new 学生("小明", 92)           → 第二个（两个参数）
模板|//     new 学生("小明")               → 第三个（一个参数）
模板|//
模板|// `this(...)` 这个写法值得单独说一句：
模板|//   它**不是**"我自己这个对象"（那是 this.分数 里的 this），

模板|// 第 11 课：static 与 final —— 属于类的东西
模板|//
模板|// 先介绍：static 解决的是"这份数据不属于任何一个对象"
模板|//
模板|// 前面几课，每个字段都是**每个对象各有一份**：
模板|//
模板|//     计数器 甲 = new 计数器();
模板|//     计数器 乙 = new 计数器();
模板|//     甲 有自己的字段，乙 也有自己的 —— 改甲不动乙。
模板|//
模板|// 这个模型很好用，但有一类数据它装不下：**"一共造了几个对象"**。
模板|//
模板|// 这个数字属于谁？属于 甲 吗？可 乙 也是造出来的，凭什么算在 甲 头上？
模板|// 它不属于任何一个对象，它属于**整个类**。
模板|//
模板|// static 就是给这种成员准备的：
模板|//
模板|//     不加 static  →  属于**对象**，每个对象各一份
模板|//     加了 static  →  属于**类**，只有一份，所有对象共用
模板|//
模板|//     class 计数器 {
模板|//         private static int 个数 = 0;    ← 类成员：全类只有一份
模板|//         private String 名字;            ← 实例成员：每个对象一份
模板|//     }
模板|//
模板|// 直觉检验很简单：**这个值需要"每个对象一个"吗？**
模板|//   人的名字、猫的年龄 → 需要 → 不用 static
模板|//   造了几个对象、全局的常量、纯计算的工具方法 → 不需要 → 用 static
模板|//
模板|// 顺带一个现实证据：main 方法自己就是 static 的。
模板|//   `public static void main(String[] args)` —— 程序刚启动的时候
模板|//   **一个对象都还没有**，哪来的实例方法给你调用？
模板|//   所以入口必须是 static：它不依赖任何对象就能跑。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：三种 static 成员
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ① 静态字段 —— 全类一份
模板|//
模板|//     public static void 加一() { 个数 = 个数 + 1; }
模板|//
模板|//     计数器 甲 = new 计数器();
模板|//     计数器 乙 = new 计数器();
模板|//     甲.加一();
模板|//     乙.加一();
模板|//     System.out.println(甲.报数());    ⇒ 2      ← 不是 1！
模板|//     System.out.println(乙.报数());    ⇒ 2

模板|//     System.out.println(计数器.报数());  ⇒ 2
模板|//
模板|//   ⚠ 上面 甲.加一() 和 计数器.加一() **都能编译**，做的事完全一样。

模板|//     它容易让人误以为 个数 是 甲 的。**能写 类名.方法() 就用类名。**

模板|// ② 静态常量 —— static + final
模板|//
模板|//     public static final int 起始值 = 0;
模板|//                 ↑      ↑
模板|//              属于类   只能赋一次值
模板|//
模板|//     这是 Java 里"常量"的标准写法：`public static final` 三个词连用。
模板|//     读法是"公开的、全类共用的、不可改的值"。

模板|// 第 12 课：继承 —— extends、super、方法覆写
模板|//
模板|// 先介绍：两个类有八成内容是一样的，怎么办
模板|//
模板|// 假设你写了一个 狗 类、一个 猫 类，写完会发现它们是这样的：
模板|//
模板|//     class 狗 {
模板|//         private String 名字;
模板|//         public String 取名字() { return 名字; }
模板|//         public String 介绍() { return 名字 + "说" + 叫声(); }
模板|//         public String 叫声() { return "汪"; }
模板|//     }
模板|//     class 猫 {
模板|//         private String 名字;                        ← 一模一样
模板|//         public String 取名字() { return 名字; }      ← 一模一样
模板|//         public String 介绍() { ... }                ← 一模一样
模板|//         public String 叫声() { return "喵"; }        ← 只有这里不一样
模板|//     }
模板|//
模板|// 四样东西里三样完全相同，只有 叫声 不同。
模板|// 这不是"差不多"，这是**同一段代码抄了两遍**。抄两遍的代价是：
模板|//   ① 以后 介绍 的格式要改（比如"说"改成"叫道"），你得改两个地方，
模板|//      有了十种动物就改十处 —— 漏一个就是一个不一致的 bug。
模板|//   ② 名字 这个字段在两个类里是**两套**，你没法写一个方法同时收狗和猫。
模板|//
模板|// 继承就是为这件事准备的：**把共同的部分写一次，放在父类里，子类去拿。**
模板|//
模板|//     class 动物 { ...名字、取名字、介绍、叫声... }        ← 共同的部分，写一次
模板|//     class 狗 extends 动物 { ...只要写 叫声... }          ← 拿过来用
模板|//     class 猫 extends 动物 { ...只要写 叫声... }
模板|//
模板|// `extends` 读作"继承自"，`狗 extends 动物` 的意思是
模板|// **"狗 是一种 动物，动物 有的 狗 全都有，另外 狗 还能有自己的东西"**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：三个关键字
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ① extends —— 建立父子关系
模板|//
模板|//     class 狗 extends 动物 {
模板|//         // 这里什么都不写，狗 就已经有 名字、取名字()、介绍()、叫声() 了
模板|//     }
模板|//
模板|//   拿过来的东西**不用再声明一遍**。子类自动拥有父类的字段和方法
模板|//   （private 字段也在，只是子类不能直接碰，得走父类的 getter —— 见坑 2）。
模板|//
模板|// ② super —— 指"父类那一份"
模板|//
模板|//   父类的构造方法不会被继承（构造方法是"造这个类"的步骤，不能照搬），
模板|//   所以子类的构造方法**必须自己把父类需要的值交上去**：
模板|//
模板|//     public 狗(String 名字) {
模板|//         super(名字);            ← 调用父类的构造方法：动物(String 名字)
模板|//     }
模板|//
模板|//   ⚠ super(...) 必须是子类构造方法的**第一条语句** —— 和上一课的 this(...) 一样。
模板|//     道理也一样：**父类的部分要先构造好**，子类的部分才有地方放。
模板|//
模板|//   `super` 还有第二种用法，不带括号：
模板|//     super.叫声()        ← 明确地说"我要调父类那一版的 叫声"
模板|//
模板|// ③ @Override —— 覆写
模板|//
模板|//   子类里写一个**和父类同名、同参数、同返回类型**的方法，就把父类那版盖掉了：
模板|//
模板|//     class 狗 extends 动物 {
模板|//         @Override
模板|//         public String 叫声() { return "汪"; }
模板|//     }
模板|//
模板|//   @Override 这个注解**不影响运行**，它是写给编译器看的：
模板|//   它说"我打算覆写父类的某个方法，你帮我核对一下"。
模板|//   **对不上它就报错**，这正是它的价值（见坑 1）。
模板|//
模板|//   覆写的三条硬要求：
模板|//     · 方法名和参数列表必须**完全一样**（有一个字不同就变成另一个方法了）
模板|//     · 返回类型必须一样（或者更"窄"）
模板|//     · 访问权限**不能变小**：父类是 public，子类也得是 public
模板|//
模板|// ⚠ 一个值得先记住的写法：介绍() 里调用的是 `叫声()`，**不是**写死的"……"。
模板|//   父类的方法里调另一个方法时，实际执行的是**子类覆写的那一版**。
模板|//   于是 介绍() 只写了一次，狗和猫各自说出来的是"汪"和"喵"。
模板|//   （这是下一课"多态"的全部秘密，今天先记住这个写法。）
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：覆写时参数写错 —— 症状是"它怎么还是父类的行为"
模板|//
模板|//     class 狗 extends 动物 {
模板|//         public String 叫声(String 后缀) { return "汪" + 后缀; }     ← 多了个参数！
模板|//     }
模板|//     System.out.println(狗.叫声());        ⇒ ……        ← 你以为会打"汪"
模板|//
模板|// 你会看到：明明写了 叫声，调出来还是父类那个"……"，而且**不报错**。
模板|// 为什么：参数不一样就是**另一个方法**了（叫重载，第 10 课学过），
模板|// 它跟父类的 叫声() 并存，谁也没盖住谁。调 叫声() 时找到的还是父类那版。

模板|// ⚠ 坑 2：想在子类里直接碰父类的 private 字段
模板|//
模板|//     class 狗 extends 动物 {
模板|//         public String 打招呼() { return "我是" + 名字; }      ← ✗
模板|//     }

模板|// 想读就走父类给的 getter：`return "我是" + 取名字();`
模板|// 什么时候用 protected？—— 当你确实希望子类直接碰这个字段时。
模板|// 但**大多数时候更好的答案是给个 getter**，字段仍然 private。
模板|//
模板|// ⚠ 坑 3：覆写时把访问权限改小了
模板|//
模板|//     class 狗 extends 动物 {
模板|//         String 叫声() { return "汪"; }        ← 不写 public
模板|//     }
模板|//
模板|// 你会看到：

模板|// 记法：**覆写时权限只能不变或者变大。** 照抄父类的 public 就行。

模板|// 相机能拍照，是因为它是相机；手机能拍照，跟它爹是谁没关系。
模板|// "能拍照"是一种**能力/约定**，不是一种**出身**。
模板|//
模板|// 接口就是给"能力/约定"用的：
模板|//
模板|//     interface 形状 {
模板|//         double 面积();                 ← 只有签名，末尾分号
模板|//     }
模板|//
模板|// 念法是"**凡是实现 形状 的类，都保证有 面积()**"。
模板|// 它是一个**契约**：我不管你是什么、你爹是谁，
模板|// 你只要签了这个约，我就知道你一定能算面积 —— 于是我就敢调。
模板|//
模板|// 写"签合同"的关键字不是 extends，而是 **implements**：
模板|//
模板|//     class 圆 implements 形状, 可命名 { ... }
模板|//                                  ↑ 逗号隔开，想实现几个就几个
模板|//
模板|// 一个类 **extends 只能一个，implements 可以很多个**。
模板|// 这是接口最重要的本事，也是它存在的第一理由。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：接口长什么样
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ① 接口声明
模板|//
模板|//     interface 形状 {
模板|//         double 面积();                          ← 抽象方法（可省 public abstract）
模板|//         default String 说明() {                  ← default 方法：**有方法体**
模板|//             return "面积=" + Math.round(面积());
模板|//         }
模板|//     }
模板|//
模板|//   几个容易记混的点：
模板|//     · 接口**不是类**：写 interface，不写 class。它不能被 new。
模板|//     · 方法默认就是 public 的，而且**必须**是 public。
模板|//       所以 `double 面积();` 就等于 `public abstract double 面积();`。
模板|//     · default 方法是个例外：**它带方法体**。
模板|//       为什么允许 —— 因为要"加一个新方法又不弄坏所有已经实现的类"。
模板|//       这一课用它，是为了让 说明() 这套拼字符串的活儿只写一次。
模板|//     · 接口可以**多继承接口**：`interface A extends B, C` —— 这是允许的，
模板|//       因为接口没有字段、没有实现细节，不会撞车。
模板|//
模板|// ② 实现
模板|//
模板|//     class 圆 implements 形状, 可命名 {
模板|//         private double 半径;
模板|//         public 圆(double 半径) { this.半径 = 半径; }
模板|//         @Override public double 面积() { return Math.PI * 半径 * 半径; }
模板|//         @Override public String 名字() { return "半径为" + 半径 + "的圆"; }
模板|//     }
模板|//
模板|//   ⚠ 实现接口的方法**必须是 public** —— 接口里的方法本来就是 public，
模板|//     实现时权限不能变小（和上一课覆写的规矩是同一条）。
模板|//     忘了写 public 会报：正在尝试分配更低的访问权限; 以前为public
模板|//
模板|// ③ 用接口当类型
模板|//
模板|//     形状 甲 = new 圆(2);         ← 和上一课的向上转型一模一样
模板|//     可命名 乙 = new 圆(2);
模板|//
模板|//     System.out.println(甲.面积());        ⇒ 12.566370614359172
模板|//     System.out.println(乙.名字());        ⇒ 半径为2.0的圆
模板|//
模板|//   注意 甲 和 乙 是**同一个类的两个视角**：
模板|//   通过 甲 你只看得见 面积/说明（形状 这个契约里有的），
模板|//   通过 乙 你只看得见 名字。
模板|//   ⚠ 所以 `甲.名字()` 编译不过 —— 形状 这个接口里没有 名字。
模板|//
模板|// ④ 接口和抽象类怎么选
模板|//
模板|//     问题                          用哪个
模板|//     ────────────────────────────────────────────────
模板|//     子类共用的**字段**和构造方法    抽象类（接口没有实例字段）
模板|//     表达"**是一种**"（狗是动物）    抽象类
模板|//     表达"**能做**/遵守某个约定"     接口
模板|//     一个类要同时具备好几种能力      接口（可以 implements 很多个）
模板|//
模板|//   一句话：**is-a 用抽象类，can-do 用接口。**
模板|//   拿不准的时候用接口 —— 它更松，不会把你的继承名额（只有 1 个）用掉。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：在接口里写实例字段
模板|//
模板|//     interface 形状 {
模板|//         private double 半径;             ← ✗ 编译错误
模板|//     }
模板|//
模板|// 你会看到：错误: 接口不能有私有字段 / 修饰符 private 不合法
模板|// 为什么：接口是"约定"，约定不能被某个实现改来改去。
模板|// 接口里**只能有常量**（`int 最大 = 100;` 会被自动当成
模板|// `public static final int 最大 = 100;`，因为接口里没有"实例"可言）。
模板|// 想存数据就得在**实现类**里存 —— 这就是 圆 里那个 半径 的意义。
模板|// ⚠ 顺带一个后果：接口里的字段全是 static final，所以它**全类共用一份**，
模板|//   千万别想着在接口里放"每个对象不一样"的值。
模板|//
模板|// ⚠ 坑 2：忘了实现接口里的某个方法
模板|//
模板|// 你会看到：错误: 圆不是抽象的, 并且未覆盖可命名中的抽象方法名字()
模板|// 为什么：签了合同就得交作业 —— 和上一课抽象方法一模一样的道理。
模板|// ⚠ 注意报错会**指名道姓说是哪个接口的哪个方法**（这里写的是 可命名 中的 名字），
模板|//   所以这条报错非常好用：它直接告诉你缺哪一份作业。
模板|//
模板|// ⚠ 坑 3：以为"接口能 new"
模板|//
模板|//     形状 甲 = new 形状();              // ✗
模板|// 你会看到：错误: 形状是抽象的; 无法实例化
模板|// 为什么：接口连方法体都没有（default 除外），new 出来一个"面积()"没法算的东西？
模板|// 接口只能当**类型**：变量类型、参数类型、数组元素类型、返回值类型。
模板|//
模板|// ⚠ 坑 4：实现方法时忘了 public
模板|//
模板|//     class 圆 implements 形状 {
模板|//         double 面积() { return 1; }       ← 不写 public
模板|//     }
模板|//
模板|// 你会看到：
模板|//     错误: 圆中的面积()无法实现形状中的面积()
模板|//     正在尝试分配更低的访问权限; 以前为public
模板|// **实现接口的方法一律写 public。** 这条和上一课覆写的规矩是同一条。
模板|//
模板|// ─────────────────────────────────────────────────────

要求|1. 写两个静态方法：取元素(int[] 数们, int 下标)（下标为负就 throw new IllegalArgumentException）；除(int 甲, int 乙)

要求|3. catch 里打印 "出事:" + e.getMessage()；finally 里打印 "这行总会执行"
要求|4. main 里要有 int[] 数们 = {10, 20, 30};
模板|// 第 15 课：异常处理 —— 出错了怎么办
模板|//
模板|// 先介绍：程序出错时，"谁来收拾"
模板|//
模板|// 先看这段：
模板|//
模板|//     int[] 数们 = {10, 20, 30};
模板|//     System.out.println(数们[9]);
模板|//
模板|// 跑起来是这样：
模板|//
模板|//     Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException:
模板|//         Index 9 out of bounds for length 3
模板|//             at Main.main(Main.java:7)
模板|//     （程序到此为止，后面一行都不执行了）
模板|//
模板|// 注意最后那句：**后面的代码一行都没跑**。程序**整个停在那**。
模板|//
模板|// 这在学习的时候没什么 —— 你看到报错，改一改再跑。
模板|// 但在真正给人用的程序里，这是灾难：
模板|//   一个输入框里少打了一个逗号 → 整个程序白屏退出，用户刚才填的半小时全没了。
模板|//   一个文件不存在 → 批处理跑到一半死掉，前面处理过的数据状态不明。
模板|//
模板|// 而且很多时候**出错是正常的、可以预料的**：
模板|//   用户输入的东西本来就可能是错的（"请输入年龄"→ 他打的是"abc"）
模板|//   要读的文件本来就可能不在（U 盘拔了）
模板|//   除法的分母本来就可能是 0（用户填的）
模板|// 这些不是"你的程序有 bug"，是**世界的常态**。
模板|//
模板|// 异常机制就是让程序能说这句话：
模板|// **"这一步可能会出事，出事了我知道该怎么办，别整个死掉。"**
模板|//
模板|//     try {
模板|//         可能会出事的代码
模板|//     } catch (Exception e) {
模板|//         出事了就在这里收拾
模板|//     } finally {
模板|//         不管出没出事都要做的事
模板|//     }
模板|//
模板|// 三个块的分工，用一句话记住：
模板|//     try     —— 我试试
模板|//     catch   —— 出事了，我来处理（**程序从这里继续往下跑**）
模板|//     finally —— 不管怎样都执行（收尾：关文件、断连接）
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：三个块各就各位
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int[] 数们 = {10, 20, 30};
模板|//
模板|//     try {
模板|//         System.out.println(数们[0]);        ← 正常
模板|//         System.out.println(数们[1]);        ← 正常
模板|//         System.out.println(数们[9]);        ← 出事了！从这里跳出去
模板|//         System.out.println("这行不会执行");  ← 被跳过了
模板|//     } catch (Exception e) {
模板|//         System.out.println("出事:" + e.getMessage());
模板|//     } finally {
模板|//         System.out.println("这行总会执行");
模板|//     }
模板|//     System.out.println("程序继续往下跑");    ← 这行**会**执行
模板|//
模板|// 关键的一条（很多人第一次都会想错）：
模板|// **try 块里出错之后，剩下的语句全部跳过，直接跳到 catch。**
模板|// 它不是"跳过这一行、继续下一行"，是**整套跳出去**。
模板|//
模板|// ① 异常对象 e 里有什么
模板|//
模板|//     e.getMessage()      → 出事的说明文字，比如 "Index 9 out of bounds for length 3"
模板|//     e.printStackTrace() → 把那一大串"at Main.main(Main.java:7)"打到屏幕上
模板|//
模板|// 平时给人看的界面里用 getMessage()（短、能懂），
模板|// 自己调试的时候用 printStackTrace()（信息全）。
模板|//
模板|// ② 常见的内置异常，认名字就知道是什么事
模板|//
模板|//     ArrayIndexOutOfBoundsException   数组下标越界     数们[9]
模板|//     NullPointerException             对 null 调方法    甲.取名字() 而 甲 是 null
模板|//     ArithmeticException              算术错误         10 / 0
模板|//     NumberFormatException            字符串转数字失败  Integer.parseInt("abc")
模板|//     IllegalArgumentException         参数不合法       你自己抛的
模板|//     ClassCastException               转型转错了       (圆) 一个长方形
模板|//
模板|//   注意 ArithmeticException 那条：**整数除法除以 0** 会抛异常。
模板|//   （小数不一样：10.0 / 0 得到的是 Infinity，不抛异常。别记混。）
模板|//
模板|// ③ 自己抛异常：throw new ...
模板|//
模板|//   有时候"出错"不是 Java 报的，而是**你**觉得不合理：
模板|//
模板|//     public static int 取元素(int[] 数们, int 下标) {
模板|//         if (下标 < 0) {
模板|//             throw new IllegalArgumentException("下标不能是负数");
模板|//         }
模板|//         return 数们[下标];
模板|//     }
模板|//
模板|//   念法是："下标是负数这件事，我认为它不合法 —— 我不打算硬着头皮往下算，
模板|//   我要**当场把问题扔出去**，让调用我的人去处理。"
模板|//
模板|//   ⚠ throw 和 throws 长得像，意思不一样，别混：
模板|//       throw  new IllegalArgumentException(...);   ← 动作："扔一个"
模板|//       throws IllegalArgumentException              ← 声明："我这个方法可能会扔"
模板|//
模板|// ④ 受查异常：编译器盯着你必须处理的那种
模板|//
模板|//   Java 的异常分两大家族：
模板|//
模板|//     运行时异常（RuntimeException 及其子类）   编译器**不管**
模板|//         ArrayIndexOutOfBounds / NullPointer / Arithmetic / IllegalArgument ...
模板|//
模板|//     受查异常（其他 Exception）                编译器**强制**你处理
模板|//         最典型的就是文件操作：new FileReader("a.txt") 会扔 IOException
模板|//         你不处理就**编译不过**，报：
模板|//             错误: 未报告的异常错误IOException; 必须对其进行捕获或声明以便抛出
模板|//
模板|//   两种"处理"方式，二选一：
模板|//         try { ... } catch (IOException e) { ... }      ← 当场接住
模板|//         public void 读文件() throws IOException { ... } ← 往上甩给调用者
模板|//
模板|//   这一课不碰文件，所以练习里都是运行时异常（编译器不逼你）。
模板|//   但**看到"未报告的异常错误"这句话，你就知道碰上受查异常了**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：catch 里什么都不做（"吞掉"异常）—— 最坏的一种写法
模板|//
模板|//     try {
模板|//         某件重要的事();
模板|//     } catch (Exception e) {
模板|//     }                          ← 空的花括号
模板|//
模板|// 你会看到：程序"跑得好好的"，一点报错都没有 —— 然后你发现某件重要的事**根本没做成**。
模板|// 为什么：异常的全部价值就是"告诉你出事了"。空 catch 等于把报警器拆了。
模板|// 这是最难查的一类 bug，因为你连"哪里出事了"都不知道。
模板|// 至少也要打印一句：
模板|//     catch (Exception e) { System.out.println("出事了:" + e.getMessage()); }
模板|// ⚠ 而且 catch (Exception e) 本身就已经很宽了 —— 它会把
模板|//   NullPointer、ClassCast 这些**代码 bug** 一起吞掉。
模板|//   写具体一点（catch (ArrayIndexOutOfBoundsException e)）能少吞很多东西。
模板|//
模板|// ⚠ 坑 2：把父类异常写在子类前面
模板|//
模板|//     } catch (Exception e) {                        ← 太宽，什么都接住了
模板|//         System.out.println("一般错误");
模板|//     } catch (ArrayIndexOutOfBoundsException e) {   ← 永远轮不到这里
模板|//         System.out.println("下标越界");
模板|//     }
模板|//
模板|// 你会看到：明明越界了，打印出来的却是"一般错误"。
模板|// 为什么：catch 是**从上往下**试的，第一个能接住的就接走了。
模板|// Exception 是所有异常的父类，它能接住一切 —— 后面那些具体的就没机会了。
模板|// ⚠ 有的情况下编译器直接报错：错误: 已捕获到异常错误...（在更通用的之后被捕获）
模板|//   看到那条别慌，就是顺序问题：**从最具体的往最笼统的写。**
模板|//
模板|// ⚠ 坑 3：在 finally 里 return
模板|//
模板|//     public static int 算() {
模板|//         try {
模板|//             return 1;
模板|//         } finally {
模板|//             return 2;          ← 把上面那个 1 覆盖掉了
模板|//         }
模板|//     }
模板|//     System.out.println(算());       ⇒ 2      ← 不是 1
模板|//
模板|// 你会看到：try 里明明 return 1，方法却返回了 2，而且**编译器不报错**。
模板|// 为什么：finally 的语义是"无论如何都要执行"，它连 return 前面那一瞬间都能插进去，
模板|// 于是它里面的 return 直接把外层的返回值换掉了。
模板|// **规矩：finally 里不要写 return**（也别写 break/continue）——
模板|// 它只应该用来收尾：关文件、关连接、删临时文件。
模板|//
模板|// ⚠ 坑 4：以为"出了异常的循环会整个停下"
模板|//
模板|//     for (int i = 0; i < 数们.length; i++) {
模板|//         try {
模板|//             System.out.println(数们[i]);
模板|//         } catch (Exception e) {
模板|//             System.out.println("这个位置没有");
模板|//         }
模板|//     }
模板|//
模板|// 你会看到：循环**继续**跑完了（挨个打印"这个位置没有"）。
模板|// 为什么：try/catch 在**循环体里面**。每次出事都被当场接住，
模板|// 接住以后继续下一轮 —— 循环控制完全没有被打断。
模板|// 反过来说：如果 try 在循环**外面**，第一次出事就会跳出整个循环。
模板|// **try 放在哪一层，决定了"出事以后从哪儿继续"。** 这个位置是你写的，要自己想清楚。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//   main 里这么写（顺序就是检查比对的顺序）：
模板|//
模板|//     int[] 数们 = {10, 20, 30};
模板|//
模板|//     try {
模板|//         System.out.println(取元素(数们, 0));      → 10

模板|//     } catch (Exception e) {

模板|// 这就是"自己抛异常"的样子：不是等 Java 报错，而是你主动拒绝不合理的输入。

模板|// 第 16 课：集合与泛型入门 —— 数组装不下的时候
模板|//
模板|// 先介绍：数组的两个硬伤
模板|//
模板|// 第 07 课学的数组有三件事做不到：
模板|//
模板|//     ① **长度固定。** int[] 数们 = new int[3]; 之后想塞第 4 个？没门。
模板|//        现实里"名单"是会长大的 —— 今天三个学生，明天转来一个。
模板|//        你能做的只有"猜一个大一点的数"，猜小了不够用，猜大了浪费。
模板|//
模板|//     ② **没有现成的方法。** 想知道"名单里有没有小红"，数组没有这个功能，
模板|//        你得自己写个 for 循环一个个比。删掉一个人？自己搬后面的元素。
模板|//
模板|//     ③ **类型要么写死，要么全丢。** 数组很安全（String[] 里只能放 String），
模板|//        但一旦你想写"能装任何东西的容器"，就只能退回 Object[] ——
模板|//        然后每次拿出来都要强转，转错了运行时才崩。
模板|//
模板|// 集合（collections）就是补这三个洞的：
模板|//
模板|//     ArrayList<String> 名单 = new ArrayList<>();
模板|//     名单.add("小明");                ← 想加几个加几个，长度自己长
模板|//     名单.contains("小红")            ← 有没有，直接问，不用自己写循环
模板|//     名单.get(1)                      ← 拿第 2 个
模板|//
模板|// 尖括号里的 <String> 叫**泛型参数**，意思是"这个名单里装的是 String"。
模板|// 有了它：
模板|//     · 放别的东西进去 → **编译期**就报错（而不是运行时才崩）
模板|//     · 拿出来就是 String → **不用强转**
模板|//
模板|//     名单.add(123);                              // ✗ 编译错误：不兼容的类型
模板|//     String 第一个 = 名单.get(0);                 // ✓ 直接就是 String
模板|//
模板|// 集合的家族要认一下名字（这一课只用两个）：
模板|//     List    有序、可以重复、按下标取      实现类 ArrayList
模板|//     Set     不重复                       实现类 HashSet
模板|//     Map     键 → 值，按键取值             实现类 HashMap
模板|//
模板|// ⚠ 注意 List / Map 是**接口**（上一课刚学的东西！）。
模板|//   写 `List<String> 名单 = new ArrayList<>();` 才是老手写法：
模板|//   左边是契约，右边是具体实现。这一课为了少一层概念，直接写 ArrayList，也没问题。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ① ArrayList：会自己变长的列表
模板|//
模板|//     ArrayList<String> 名单 = new ArrayList<>();
模板|//     名单.add("小明");              ← 加到末尾

模板|//     名单.add("小刚");

模板|//     名单.get(0)                   ⇒ 小明      ⚠ 下标从 0 开始，和数组一样
模板|//     名单.get(2)                   ⇒ 小刚
模板|//     名单.contains("小红")          ⇒ true
模板|//     名单.remove("小红")            ← 按**内容**删（后面元素自动往前挪）
模板|//     名单.remove(0)                ← 按**下标**删 —— 同名两个方法，看参数类型区分

模板|//         数组：   数们.length        ← 没有括号，它是字段
模板|//         ArrayList：名单.size()      ← 有括号，它是方法

模板|//   遍历（增强 for，和第 07 课数组的写法一模一样）：
模板|//
模板|//     for (String 名字 : 名单) {
模板|//         System.out.println(名字);
模板|//     }

模板|//     增强 for 不给你下标。

模板|// ② HashMap：键 → 值
模板|//
模板|//     HashMap<String, Integer> 分数表 = new HashMap<>();

模板|//     分数表.put("小红", 88);

模板|//     分数表.get("小刚")             ⇒ **null**      ← ⚠ 键不存在，不是 0！
模板|//     分数表.containsKey("小明")      ⇒ true
模板|//     分数表.size()                 ⇒ 2
模板|//
模板|//   ⚠ 两个尖括号**不能省**：HashMap<String, Integer>，一个是键的类型，
模板|//     一个是值的类型。键必须是对象类型 —— 所以写 Integer，不能写 int。

模板|// ③ 泛型类：自己造一个能装任何东西的盒子
模板|//
模板|//     class 盒子<T> {
模板|//         private T 里面;                  ← T 是"占位符"：用的时候才定
模板|//         public void 放(T 值) { this.里面 = 值; }
模板|//         public T 取() { return 里面; }
模板|//     }
模板|//
模板|//   用的时候把 T 填上：
模板|//
模板|//     盒子<String> 名盒 = new 盒子<>();      ← T = String
模板|//     名盒.放("Java");
模板|//     String s = 名盒.取();                  ← 拿出来直接是 String，不用强转
模板|//
模板|//     盒子<Integer> 数盒 = new 盒子<>();     ← T = Integer。⚠ 不能写 <int>
模板|//     数盒.放(300);
模板|//
模板|//   ⚠ 泛型里**不能用基本类型**：<int> <double> <char> 都是编译错误，
模板|//     要写它们的包装类 <Integer> <Double> <Character>。
模板|//     （为什么：泛型是靠"擦除"实现的，T 最终会被当成 Object 处理，
模板|//       而 int 不是 Object。这条现在只要记住结论就行。）
模板|//
模板|//   ⚠ `new 盒子<>()` 里那对空尖括号是"类型推断"：右边不用重复写一遍 String。
模板|//
模板|// ④ 泛型方法：<T> 写在返回类型**前面**
模板|//
模板|//     public static <T> void 打印两次(T 值) {
模板|//         System.out.println(值);
模板|//         System.out.println(值);
模板|//     }
模板|//
模板|//   调用的时候不用指定 T，编译器看你传什么就定什么：
模板|//     打印两次("泛型");      → T 推断成 String
模板|//     打印两次(7);           → T 推断成 Integer（7 自动装箱）
模板|//
模板|//   ⚠ 位置容易写错：<T> 必须在**返回类型之前**。
模板|//         public static <T> void 打印两次(T 值)     ✓
模板|//         public static void <T> 打印两次(T 值)     ✗ 语法错误
模板|//   记法：先声明"我这儿有个类型占位符 T"，再说"我是干嘛的"。

模板|// ⚠ 坑 1：把 size() 写成 size，或者把数组的 length 写成 length()
模板|//
模板|//     名单.size            // ✗ 错误: 找不到符号  变量 size

模板|// 你会看到两种不一样但都看不懂的报错。为什么：
模板|//   **数组的 length 是字段**（数组是特殊对象，长度是它的一个成员变量）
模板|//   **集合的 size 是方法**（ArrayList 自己实现的一个方法）
模板|// 一句话记：**数组 length 没括号，集合 size() 有括号。** 检查里专门看了这条。

模板|//     for (String 名字 : 名单) {
模板|//         if (名字.equals("小红")) {

模板|//         }
模板|//     }

模板|// 为什么：增强 for 底下其实是用"迭代器"一个个往下走的，
模板|// 它在心里记着"我走到第几个了"。你在外面把元素删掉，集合的长度变了，
模板|// 它记的位置就对不上了 —— 于是它宁可报错也不敢继续瞎走。
