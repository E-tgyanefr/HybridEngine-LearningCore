模板|//
模板|// 这一课讲一件事：**字段不许外面直接改，只能通过方法改**。
模板|//
模板|// ─────────────────────────────────────────────────────

模板|// ─────────────────────────────────────────────────────

模板|// 程序不会拦你 —— 而一只 -5 岁的猫是没意义的。
模板|//
模板|// 封装就一句话：**字段改成 private，只留方法对外**。
模板|// 于是「设置」这件事有了一个入口，你就能在入口处检查。
模板|//
模板|// ─────────────────────────────────────────────────────

@@@ 10_构造方法
标题|第 10 课：构造方法重载与 this() —— 造对象的不同入口
要求|1. 写一个 学生 类，三个字段全部 private：private String 名字; / private int 分数; / private String 班级;
要求|2. 写三个构造方法：学生(名字,分数,班级) 全存；学生(名字,分数) 班级默认"未分班"；学生(名字) 分数默认 0、班级默认"未分班"
要求|3. 后两个构造方法必须用 this(...) 调用第一个，不许自己重复写赋值
要求|4. 写 public String 介绍() 返回 名字 + "/" + 分数 + "/" + 班级；main 里用三个构造方法各造一个对象并打印介绍()
模板|// 第 10 课：构造方法重载与 this() —— 造对象的不同入口
模板|//
模板|// 这一课讲两件事：**同一个类可以有多个构造方法**、**用 this() 串起来**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：为什么想要好几个入口
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 建一个学生，有时候你知道全部信息，有时候只知道名字：
模板|//
模板|//     new 学生("小刚", 88, "三班")     信息齐全
模板|//     new 学生("小红", 92)             不知道班级
模板|//     new 学生("小明")                 只知道名字
模板|//
模板|// 三种都想要？那就写三个构造方法 —— 编译器**按参数个数/类型**挑该用哪个。
模板|// 这叫**重载**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、三个构造方法，最「全」的那个干实事
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     class 学生 {
模板|//         private String 名字;
模板|//         private int 分数;
模板|//         private String 班级;
模板|//
模板|//         public 学生(String 名字, int 分数, String 班级) {   ← 干实事的那个
模板|//             this.名字 = 名字;
模板|//             this.分数 = 分数;
模板|//             this.班级 = 班级;
模板|//         }
模板|//
模板|//         public 学生(String 名字, int 分数) {
模板|//             this(名字, 分数, "未分班");      ← 调用上面那个，补一个默认班级
模板|//         }
模板|//
模板|//         public 学生(String 名字) {
模板|//             this(名字, 0, "未分班");         ← 补两个默认值
模板|//         }
模板|//     }
模板|//
模板|// 用起来：编译器按**参数**找该用哪个：
模板|//
模板|//     new 学生("小明", 92, "三班")   → 三个参数的那个
模板|//     new 学生("小明", 92)           → 两个参数的那个
模板|//     new 学生("小明")               → 一个参数的那个
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、this(...) 是什么
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 这里有两个 this，意思**不一样**：
模板|//
模板|//     this.分数 = 分数;        this. 是「**我自己这个对象**的字段」
模板|//     this(名字, 分数, ...)    this(...) 是「**调用另一个构造方法**」
模板|//
模板|// 所以 `new 学生("小明")` 实际发生的是：
模板|//
模板|//     学生("小明") → 学生("小明", 0, "未分班") → 在里面逐字段赋值
模板|//
模板|// 一条链走到底，赋值只写了一处。
模板|//
模板|// 为什么要这么绕：**默认值只应该写在一个地方**。
模板|// 如果三个构造方法各自写一遍 "未分班"，哪天要改成 "待定"，
模板|// 你得改三处，漏一处就是一个查不出来的不一致。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 这一课唯一要记住的坑：给构造方法写了返回类型
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     class 学生 {
模板|//         void 学生(String 名字) { ... }      ← 多了个 void
模板|//     }
模板|//
模板|// 你会看到的是**在 new 那一行**：
模板|//
模板|//     错误: 无法将类 学生中的构造器 学生应用到给定类型
模板|//         需要: 没有参数
模板|//         找到: String
模板|//         原因: 实际参数列表和形式参数列表长度不同
模板|//
模板|// ⚠ 报错里**根本看不到 void 两个字** —— 这就是它难查的原因。
模板|//
模板|// 为什么：构造方法的两条硬规矩是
模板|//
模板|//     ① 名字必须和类名**完全一样**（大小写也一样）
模板|//     ② **没有返回类型** —— 连 void 都不能写
模板|//
模板|//   写上 void 之后，`void 学生(...)` 就只是一个**名字碰巧和类名一样的普通方法**，
模板|//   编译器不觉得这是语法错误。于是这个类实际上**没有任何构造方法**。
模板|//
模板|// ⇒ 把返回类型删掉（前面最多只能写 public / private）。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  这一课不碰什么
模板|// ─────────────────────────────────────────────────────
模板|//   static（属于类的东西）→ 第 11 课。
模板|//   继承里的 super(...) → 第 12 课。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  main 里就三件事，按顺序：
模板|//
模板|//     学生 甲 = new 学生("小明");                  ← 分数 0、班级 未分班
模板|//     学生 乙 = new 学生("小红", 92);              ← 班级 未分班
模板|//     学生 丙 = new 学生("小刚", 88, "三班");      ← 全都给
