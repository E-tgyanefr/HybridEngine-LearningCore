## 三、⭐ 最有价值的线索：**源码注释里已经描述过这个 bug**

`csharp/HybridEngineLight/CppLesson.cs` 的 `编译并运行` 里写着**两条不同的路径**：

```
① **骨架路径**（C#）：`调用点` 被替换进骨架里的 `入口.Main`
   ⇒ 整段程序直接编译运行。入口**已经由骨架提供**，
      所以下面传的 `entry` 只是"一个什么都不做的合法表达式"
      （库会拼成 `entry()`，传空串会生成 `();` ⇒ CS1525）。

② **C/C++**：走 gcc，骨架里有 main，同样不需要 entry。
```

而另一处注释（第 241~251 行）又写着：

```
// ⚠⚠ **入口表达式必须由"调用点"生成** —— 这是整条链的最后一环，
//   我漏了它 ⇒ 程序编译成功、却没有执行任何学员代码（输出是空的）。
//   …
//   写法：库会拼 `<entry>()`，所以 entry 要写成**立即执行的 lambda**：
//       "(() => { <调用点> })"   ⇒ 库拼成 (() => { ... })()  ✓
//   不加外层括号的话拼出来是 `() => { ... }()` ⇒ CS0149。
```

⇒ **后一段说的正是现在的现象**（"编译成功、输出是空的"）。
  ⇒ 说明**修法已经写在注释里了，但从没被实现**。

## 四、`entry` 现在传的是什么

`cs-lessons/Lessons/第00课_跑通第一个程序.cs:220-223`：

```csharp
private static CppRun 调用(string 代码, string 调用点)
{
    return CppCheck.编译并运行(代码, null, CppLesson.限定(代码, 调用点));
}
```

而 `CppLesson.限定(代码, 调用点)` 的**最后一行就是 `return 出;`**（第 847 行）——
`出` 是"把裸方法名加上 `学生代码.` 前缀"之后的**调用点文本**：

```csharp
出 = Regex.Replace(出, @"(?<![\w.])" + 名字 + @"\b", "学生代码." + 名字);
出 = 出.Replace("学生代码.学生代码.", "学生代码.");
return 出;                       // ← ⚠ 没有包成 lambda，也没去尾括号
```

⇒ 对第 00 课，`出` 大概是 `学生代码.跑通();` 之类。
  ⚠ 这个字符串当 `entry` 传进去，**很可能不是**库期望的"什么都不做的合法表达式"
  ⇒ 于是 `入口.Main` 里的调用点没被执行到（**具体机制没查证**）。
