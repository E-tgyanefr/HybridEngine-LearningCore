// 第 00 课：跑通第一个程序 —— 把工具链装好
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么这一课不教语法
// ─────────────────────────────────────────────────────
//
// ⚠⚠ 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
//
//    为什么把它排在第 00 课：
//      C / C++ / Java / C# 四门课都要**先把代码编译成可执行文件**，
//      而这需要外部工具链。调研过的主流教程里，"卡在装工具"是
//      **放弃率最高的一步** —— 比指针、比虚函数都更容易让人走掉。
//      所以它值得单独占一课，而不是塞在第一课的注释里。
//
//  一、需要什么（两样，都是免费的）
//
//  ① .NET SDK  —— 它是"课程运行器"。这门课用它来**编译并运行你的 C 代码**，
//                 所以你不需要自己敲 gcc 命令，它会替你敲。
//
//        winget install Microsoft.DotNet.SDK.8
//
//     或者去 https://dotnet.microsoft.com/download 下。
//     ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
//
//  ② gcc       —— 真正的 C 编译器。
//
//        winget install BrechtSanders.WinLibs.POSIX.UCRT
//
//     装完**重开一个窗口**（让 PATH 生效），然后敲：
//
//        gcc --version
//
//     能看到版本号就成了。
//
//  ⚠ 装完必须重开窗口：PATH 是"进程启动时"读进去的，
//    已经开着的窗口里永远看不到新装的东西 —— 这是最常见的"我明明装了"。
//
//  二、C 为什么要"两步"：先编译、再运行
//
//  Python 里你写 `python 脚本.py`，它**一边读一边执行**。
//  C 不是这样。C 的流程是：
//
//      你写的 hello.c
//          ↓  gcc hello.c -o hello.exe     ← 第一步：编译
//      hello.exe（机器码，人看不懂）
//          ↓  双击 / 敲 hello.exe           ← 第二步：运行
//      屏幕上出现结果
//
//  中间那个 hello.exe 是**真正的程序**：它不再需要 gcc，
//  也不需要你那份 .c 文件，拷给别人就能跑。
//
//  代价是：**你写的代码要先被人（编译器）检查一遍**。
//  语法有错，编译器当场拒绝，连失败的程序都不给你。
//  所以 C 的报错比 Python 多，但**很多错在运行之前就被拦住了** ——
//  这是编译型语言换来"跑得快"所付的钱。
//
//  ⚠ 这门课的流程是：
//
//        写代码  →  检查  →  自动编译 + 自动运行 + 看结果
//
//    "编译"和"运行"两步是**替你做的**，但你必须知道它们在发生 ——
//    不然你读不懂报错，也解释不了"为什么我的程序跑不起来"。
//
//  三、这一课唯一要练的手艺：读第一条 error
//
//  编译器的报错长这样（这是**故意写错**的代码）：
//
//      hello.c:3:1: error: expected ';' before '}' token
//         3 │ }
//           │ ^
//
//  拆开看就四样东西：
//
//      hello.c  :  哪个文件
//      3        :  **第几行**        ← 先看这个
//      1        :  第几列（次要）
//      error    :  严重程度
//
//  ⚠⚠ **两条铁律**：
//
//   ① **只看第一条 error。** 后面那几十条多数是它引起的连锁反应 ——
//      一个没写对的括号能让编译器抱怨一整屏。改完第一条再重新编译。
//
//   ② **报错行号常常要往上多看一行。** 编译器是在读到"它不认识的
//      东西"时才报错的，而那个东西往往是**上一行漏了分号**造成的。
//      上面那个例子说"第 3 行 } 前面少了分号"，真正该补分号的是第 2 行。
//
//  error 和 warning 是两回事：
//
//      error    —— 编译**停了**，没有可执行文件产生
//      warning  —— 编译**继续**，但它在提醒你"这里很可能是 bug"
//
//  ⚠⚠ **不要忽略 warning。** "能编译"不等于"能跑对"。
//     这门课后面会专门讲几个"只给 warning、但结果一定是错的"的坑
//     （比如 scanf 忘了写 &）。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  最小的 C 程序只有五行，记住它，以后每课都从它开始：
//
//      #include <stdio.h>          /* 头文件：printf 需要它 */
//
//      int main(void) {            /* 程序从这里开始跑 */
//          printf("你好\n");       /* 打印一行 */
//          return 0;               /* 告诉系统"正常结束" */
//      }
//
//  编译它（这条命令你在命令行里敲一次，体会一下"两步"）：
//
//      gcc -std=c11 -Wall hello.c -o hello.exe
//
//  ⚠ 这两个旗标要说一下：
//      -std=c11   用 C11 标准（就是这门课用的标准）
//      -Wall      打开常用警告（打开它，你才能看到 scanf 忘 & 这类提醒）
//
//  运行它：
//
//      .\hello.exe                 （PowerShell 里要写 .\ ，不能只写 hello）
//
//  输出：
//
//      你好
//
//  想知道程序"是不是正常结束"，看退出码：
//
//      echo $LASTEXITCODE          ⇒ 0      0 就是成功
//
//  故意让它失败（比如把 return 0; 改成 return 3;），退出码就变成 3。
//  这一课不要求你背命令，但要知道**界面上那个「检查」按下去时，
//  背后发生的正是上面这三件事**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：装完 gcc 不重开窗口 ⇒ 一直报"找不到 gcc"
//
//      错误写法（在**装之前**就打开的那个窗口里）：
//          gcc --version
//
//      你会看到什么：
//          gcc : 无法将"gcc"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
//
//      为什么：PATH 是**进程启动时**读进内存的。你那扇旧窗口里存的是
//      装 gcc 之前的老 PATH，所以它永远看不见新装的东西。
//      ⇒ 关掉窗口，重新开一个。
//
//  ⚠ 坑 2：装的是 .NET **Runtime**，不是 SDK
//
//      症状：gcc --version 有版本号，但一按「检查」就说找不到 dotnet，
//      或者报 "找不到任何已安装的 .NET SDK"。
//
//      为什么：Runtime 只能**运行**已经编好的程序，里面**没有编译器**。
//      这门课要用 dotnet 去调 gcc、还要编译课程本身 ⇒ 必须是 SDK。
//      验一下：dotnet --list-sdks 应该列出版本号；只装 Runtime 时这一行是空的。
//
//  ⚠ 坑 3：把编译器的 error 当成"课程坏了"
//
//      你会看到什么（这是真的报错原文）：
//
//          main.c:5:13: error: expected ';' before '}' token
//              5 │     return 0
//                │             ^
//                │             ;
//
//      为什么：编译器在 `return 0` 后面期待一个分号，却先看到了 `}`。
//      它在**第 5 行**报错，但真正的错就是第 5 行自己少了分号 ——
//      这一条跟前面那个"往上多看一行"的例子正好相反，
//      所以**不要死记行号规则，要读它说的那句话**。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────

// 第 01 课：printf —— 让程序开口说话
//
// ─────────────────────────────────────────────────────
//  先介绍：C 程序的骨架
// ─────────────────────────────────────────────────────
//
//   C 程序**一定**长这个样子，少一样都编译不过：
//
//       #include <stdio.h>          ← 头文件：printf 需要它（stdio = standard input/output）
//
//       int main(void) {            ← 主函数：程序从这里开始跑
//           ...                     ← 你的代码
//           return 0;               ← 告诉系统"正常结束"
//       }
//
// 三件必须记住的事：
//   ① 每条语句末尾要有**分号** ;    （漏了会报 expected ';'）
//   ② 代码块用**花括号** { }        （C 不看缩进，看括号）
//   ③ 打印用 printf("...")          （f = formatted，格式化输出）
//
// 换行要在引号里面写 \n —— 它不是"两个字符"，是一个换行符。
//   想打「你好」再换行：   printf("你好\n");
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 打印一段固定文字：把内容放在双引号里。
//
//      printf("你好，C\n");
//
//  ② 打印一个值：先用**格式符**占个位，再把值写在逗号后面。
//
//      printf("%d\n", 42);
//
//      %d 就是"这里放一个整数"。逗号后面的 42 会填进去。
//
//  ③ 一行里放多个值：占位符和值的**顺序一一对应**。
//
//      printf("%d 加 %d 等于 %d\n", 1, 2, 3);      ⇒ 1 加 2 等于 3
//
//  ④ 常用的四个格式符（这一课先记 %d 和 %s，后面几课都会用到）：
//
//      %d    整数          int
//      %f    小数          double
//      %s    字符串        char*
//      %c    单个字符      char
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int main(void) {
//          printf("你好，C\n");
//          printf("%d\n", 42);
//          printf("完成\n");
//          return 0;
//      }
//
//  输出（三行）：
//
//      你好，C
//      42
//      完成
//
//  ⚠ 注意输出里**看不到** `%d`，也看不到 `\n`：
//      %d 被 42 替换掉了，\n 变成了一个真正的换行。
//
//  ⚠ 如果不写 \n，两次 printf 的输出会挤在同一行：
//      printf("你好，C");    printf("完成");
//      ⇒ 你好，C完成
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：漏了 #include <stdio.h>
//
//      错误写法：
//          int main(void) {
//              printf("你好\n");
//              return 0;
//          }
//
//      你会看到什么（gcc 原文，下面的横线是编译器画的，原文里是竖线）：
//
//          main.c:2:5: error: implicit declaration of function 'printf' [-Wimplicit-function-declaration]
//              2 │     printf("你好\n");
//                │     ^~~~~~
//          main.c:1:1: note: include '<stdio.h>' or provide a declaration of 'printf'
//
//      为什么：printf 不是语言自带的关键字，它只是 stdio.h 里**声明**的一个函数。
//      编译器从上往下读，读到 printf 时没见过它，只好猜"它大概返回 int" ——
//      这个"猜"就是 implicit declaration（隐式声明）。
//      现代 C（C99 以后）已经把这个"猜"当成错误了。
//      ⇒ 看到这条，第一反应永远是：**头文件写了吗？**
//
//  ⚠ 坑 2：格式符和值的类型对不上
//
//      错误写法（用 %d 去打印字符串）：
//
//          printf("%d\n", "你好");
//
//      你会看到什么（gcc 原文）：
//
//          main.c:3:14: warning: format '%d' expects argument of type 'int', but argument 2 has type 'char *' [-Wformat=]
//              3 │     printf("%d\n", "你好");
//                │             ~^     ~~~~~~
//                │              │     │
//                │              │     │
//                │              │     char *
//                │              int
//                │             %s
//
//      运行时你看到的不是报错，而是**一个莫名其妙的整数**（内存地址）：
//
//          267931728
//
//      为什么：%d 告诉 printf"把这段内存当成一个 int 来解释"，
//      而 "你好" 是 char*（字符串第一个字符的地址）。
//      它照做了 —— 于是你得到一个地址，而不是你想要的文字。
//      ⚠ 好消息：gcc 会**警告**你，而且最后那行 `%s` 就是它给你的改法。
//      ⇒ **warning 要读，它经常直接告诉你该换成哪个格式符。**
//
//  ⚠ 坑 3：把 \n 写成了 /n，或者漏了分号
//
//      错误写法：
//          printf("你好/n");          /* 斜杠方向反了 */
//
//      你会看到什么：编译**通过**，但屏幕上真的印出「你好/n」四个字。
//
//      为什么：反斜杠 `\` 才叫"转义符"。`/` 只是个普通的斜杠字符，
//      C 不认识 `\n` 以外的写法，就把它原样打出来。
//
//      另一种更吵的错误 —— 漏分号：
//
//          printf("你好，C\n")
//          return 0;
//
//          main.c:3:17: error: expected ';' before 'return'
//              3 │     printf("你好，C\n")
//                │                 ^
//                │                 ;
//                │     return 0;
//                │     ~~~~~~
//
//      为什么：编译器读到 `return` 时才发现上一句没说"结束"。
//      ⚠ 报的是**第 3 行**，但该补分号的是**第 2 行** —— 往上多看一行。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   1. 打印一行文字：你好，C
//   2. 打印一个整数：42
//   3. 最后一行打印：完成
//
// 提示：完整程序，要自己写 #include 和 main。
//
// ⚠ 期望输出（三行，一字不差）：
//

//      完成

// 第 02 课：变量 —— 给一个值起个名字
//
// ─────────────────────────────────────────────────────
//  先介绍：变量 = 给一个值起个名字
// ─────────────────────────────────────────────────────
//
//     int 年龄 = 18;
//     ↑   ↑     ↑
//    类型  名字  值
//
// ⚠⚠ **C 和 Python 最大的区别就在这里：C 必须先说类型。**
//
//     Python：  年龄 = 18              不用写类型
//     C：       int 年龄 = 18;         必须写 int
//
// 为什么：C 是**编译型**语言，编译时要为每个变量分配固定的内存大小，
// 所以它必须知道你打算装什么。这也让 C 跑得很快。
//
// 这一课只用 int（整数）。小数（float/double）在第 04 课。
//
// ⚠ 常见的错：
//     年龄 = 18;              ❌ 没写类型 ⇒ 报 undeclared identifier
//     int 年龄 = 18           ❌ 漏了分号 ⇒ 报 expected ';'
//     int 年龄 = 18;          ✅
//
// 打印变量和打印常量一样，都是 printf：
//     printf("%d\n", 年龄);   ← %d 是"这里放一个整数"的占位符
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 声明并赋值（这一课只用这一种写法）：
//
//      int 年龄 = 18;          声明的同时给初值
//
//  ② 声明和赋值也可以分开写：
//
//      int 年龄;               先声明
//      年龄 = 18;              后赋值
//
//      ⚠ 中间那一小段时间里，年龄是**未初始化的**，
//        它的值是内存里的随机垃圾（第 07 课会专门讲这个）。
//        ⇒ 能一行写完就一行写完。
//
//  ③ 变量可以参与运算，也可以被重新赋值：
//
//      int 甲 = 17;
//      甲 = 甲 + 1;            ⇒ 18     右边先算，再存回左边
//
//  ④ 打印变量：格式符要和类型对上，int 就用 %d。
//
//      printf("%d\n", 年龄);
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int main(void) {
//          int 年龄 = 18;
//          int 学号 = 7;
//          printf("%d\n", 年龄);
//          printf("%d\n", 学号);
//          return 0;
//      }
//
//  输出（两行）：
//
//      18
//      7
//
//  ⚠ 名字的规则：字母、数字、下划线都行，**但不能用数字开头**，
//    也不能和关键字重名（int、return、if 这些）。中文名字 C 允许，
//    这门课大量用它，因为读起来最像你想的事情。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：忘了写类型
//
//      错误写法：
//          int main(void) {
//              年龄 = 18;
//              return 0;
//          }
//
//      你会看到什么（gcc 原文，中文名字会被它转义成 UCN 码点）：
//
//          main.c:2:5: error: '\U00005e74\U00009f84' undeclared (first use in this function)
//              2 │     年龄 = 18;
//                │     ^~~~
//          main.c:2:5: note: each undeclared identifier is reported only once for each function it appears in
//
//      为什么：`\U00005e74\U00009f84` 就是「年龄」两个字的 Unicode 码点 ——
//      gcc 在报错信息里把非 ASCII 名字转义了，**它说的就是你的变量名**。
//      "undeclared" = 我没见过这个名字 ⇒ 因为你没告诉它类型。

// 第 03 课：算术 —— 让程序算起来
//
// ─────────────────────────────────────────────────────

// 第 04 课：小数 —— float 与 double
//
// ─────────────────────────────────────────────────────
//  先介绍：C 里表示小数的两种类型
// ─────────────────────────────────────────────────────
//
//     float    单精度    大约 7 位有效数字
//     double   双精度    大约 15 位      ← **默认选它**
//
// ⚠ 日常写代码**一律用 double**：
//   float 省的那点内存现在毫无意义，而精度不够会在累加很多次之后露出来。
//

//
//     double x = 3.14;

//     printf("%.2f\n", x);      ⇒ 3.14          （保留 2 位）
//
// ⚠⚠ 用 %d 打小数是**经典的致命错**：
//     printf("%d\n", 3.14);     ⇒ 打印出一个完全莫名其妙的整数
//     （因为 %d 按整数去解释那段内存，而小数的内存布局不是整数。）
//     而且**编译器不一定报错** —— 你只会看到一个乱码般的数字。
//
// ⚠ 字面量 `3.14159` 天生就是 double；想写 float 要加后缀 `3.14f`。
//
// ⚠ 第 03 课那个坑在这里有解：
//     17 / 5        ⇒ 3        （整数除法）
//     17.0 / 5      ⇒ 3.4      （有小数参与 ⇒ 按小数算）
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 声明：类型写 double，值里带小数点。
//
//      double 圆周率 = 3.14159;
//
//  ② 打印：%f 打 double。想要几位小数就在 % 和 f 之间写 `.位数`。
//
//      printf("%f\n", 圆周率);         ⇒ 3.141590      默认 6 位
//      printf("%.2f\n", 圆周率);       ⇒ 3.14          两位
//      printf("%.4f\n", 圆周率);       ⇒ 3.1416        四位
//
//      ⚠ `%.2f` 会**四舍五入**，不是直接砍掉后面的位。
//
//  ③ 小数的运算和整数一模一样，只是结果带小数：
//
//      double 半径 = 2.0;
//      printf("%.2f\n", 圆周率 * 半径 * 半径);      ⇒ 12.57
//
//  ④ 只要算式里**有一个**小数，整个式子就按小数算：
//
//      printf("%f\n", 17 / 5);         ⇒ 见坑 1，是 0.000000
//      printf("%f\n", 17.0 / 5);       ⇒ 3.400000
//      printf("%f\n", 17 / 5.0);       ⇒ 3.400000
//

//

//

//      }

//

//

// 第 05 课：scanf —— 让程序会听
//
// ─────────────────────────────────────────────────────
//  先介绍：怎么从键盘读东西
// ─────────────────────────────────────────────────────
//
//     int 数;
//     scanf("%d", &数);         ← 读一个整数放进「数」
//                  ↑
//                  这个 & 是**取地址**，不能少！
//
// ⚠⚠⚠ **这一课唯一要记住的坑：scanf 必须写 `&`。**
//
//     为什么：printf 是"把值给出去"，只要值就行；
//     而 scanf 是"把读到的值**存进去**"，它必须知道**存到哪块内存**。
//     `&数` 就是"变量「数」所在的内存地址"。
//
//     写了 &  ⇒  正确
//     忘了 &  ⇒  程序**可能在运行时崩溃**（Segmentation fault），
//                也可能"看起来跑完了"但变量没被赋值 ——
//                编译器只给个警告，不报错。所以特别危险。
//
// ⚠ 格式符要和类型对上：
//     读 int      scanf("%d", &x);
//     读 double   scanf("%lf", &x);     ← ⚠ 是 %lf（有个 l），不是 %f
//     读字符      scanf("%c", &c);
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 读一个整数：
//
//      int 数;
//      scanf("%d", &数);              程序会在这里**停下来等你敲**
//
//  ② 读进来就能用 —— 和普通变量没有区别：
//
//      printf("%d\n", 数 + 1);
//
//  ③ 一次读两个值：两个占位符，两个地址，敲的时候用空格或回车隔开。
//
//      int 甲, 乙;
//      scanf("%d %d", &甲, &乙);      输入 "3 5" ⇒ 甲=3 乙=5
//
//  ④ ⚠ 读 double 和读 int 的格式符**不一样**，这是最容易记错的一处：
//
//      int x;      scanf("%d",  &x);      /* 读整数 */
//      double y;   scanf("%lf", &y);      /* ⚠ 读小数要写 %lf */
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int main(void) {
//          int 数;
//          scanf("%d", &数);           /* ⚠ 这个 & 是这一课的全部重点 */
//          printf("%d\n", 数 + 1);
//          return 0;
//      }
//
//  运行（假设你敲了 5）：
//
//      5                               ← 你敲的
//      6                               ← 程序打印的
//
//  ⚠ 界面上的「检查」会**替你敲**一个数进去，你不用手动输入。
//    但它敲几次、敲什么值，取决于这一课的检查项 ——
//    所以别写死任何前提（比如"假设用户一定输入正数"）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：scanf 忘了写 & —— 这一课的头号杀手
//
//      错误写法：
//          int 数;
//          scanf("%d", 数);            /* 少了 & */
//
//      你会看到什么（gcc 原文）：
//
//          main.c:4:13: warning: format '%d' expects argument of type 'int *', but argument 2 has type 'int' [-Wformat=]
//              4 │     scanf("%d", 数);
//                │            ~^   ~
//                │             │   │
//                │             │   │
//                │             │   int
//                │             int *
//
//      ⚠ 注意它说的是 `int *`（指针）而不是 `int` —— 这就是"我要的是地址"。
//      而且它只是 **warning**：编译照过，你会拿到一个 .exe。
//
//      运行时：数 仍然是个**随机垃圾值**（因为没有任何东西被写进去），
//      程序打印出一个莫名其妙的数字；某些环境下直接崩溃。
//
//      为什么：`数` 是那个变量的**值**（此刻还是随机的），
//      而 scanf 需要的是它的**地址**。scanf 会把"你给的那个数字"
//      当成地址去写 —— 写到一个几乎肯定不属于你的地方。
//      ⇒ 轻则数据没读到，重则程序崩掉。
//      ⚠ 这是本课程里最典型的"编译能过、结果一定错"的例子。
//

//                │            ~^   ~~
//                │             │   │
//                │             │   │
//                │             │   double *
//                │             float *
//                │            %lf
//
//      为什么：`%f` 在 **scanf 里**只认 float，读 double 必须写 `%lf`。
//      ⚠ 而且这里有个反直觉的地方：
//          printf 打 double 用 %f（不用 l）
//          scanf  读 double 用 %lf（必须有 l）
//      两个函数的规则**不一样**，只能分别记。
//      注意 gcc 最后那行 `%lf` 就是它给的正确答案。
//
//  ⚠ 坑 3：没有把 & 忘记，但把 & 写到了不该写的地方

//          通常**能编译、也常常能跑对** —— 所以这个坑才难发现。
//          在打开 -Wall 时可能什么都不报，也可能报一串指针类型不匹配。

//      再加一个 & 就是"地址的地址"，类型变成了 `char (*)[20]`。
//      C 的指针类型检查很松，所以它经常就这么混过去了。
//      ⇒ 规矩：**数组不用 &**，单个变量必须 &。
//          scanf("%d", &数);        单个 int      ✅ 要 &

// 第 06 课：if —— 让程序做选择
//
// ─────────────────────────────────────────────────────
//  先介绍：if 让程序分岔
// ─────────────────────────────────────────────────────
//
//     if (条件) {
//         条件成立时做的事
//     } else {
//         不成立时做的事
//     }
//
// ⚠ C 的 if 有**两处括号**，都要写：
//     if (分数 >= 90) {        ← 条件外面那对圆括号不能少
//         ...
//     }                        ← 花括号也别忘
//
// 比较运算符：
//     ==  等于      ⚠⚠ **两个等号**！一个等号是赋值
//     !=  不等于
//     >   大于      >=  大于等于
//     <   小于      <=  小于等于
//
// ⚠⚠ 最常见的错：
//     if (分数 = 90)           ❌ 这是**赋值**！把 90 塞进分数，然后判断 90 是不是真
//     if (分数 == 90)          ✅
//     而且 `if (分数 = 90)` **不一定报错** —— 它会永远成立（90 非 0 = 真）。
//     这就是最难查的一类错。看到 if 里只有一个等号，立刻改掉。
//
// ⚠ 判断的顺序很重要（和 Python 一样）：
//     if (分数 >= 60) return 2;
//     else if (分数 >= 90) return 3;   ← 到不了这里！
//   95 分在第一行就满足了。⇒ **从最严格的往最宽松的写**。
//
// ⚠ C 里没有"真/假"类型（C99 之前），约定：**0 是假，非 0 是真**。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 只有一种情况要处理，用不带 else 的 if：
//
//      if (分数 >= 60) {
//          printf("及格\n");
//      }
//
//  ② 两种情况，用 if / else：
//
//      if (分数 >= 60) {
//          printf("及格\n");
//      } else {
//          printf("不及格\n");
//      }
//
//  ③ 多种情况，用 else if 串起来 —— **从最严格写到最宽松**：
//
//      if (分数 >= 90) {
//          return 3;
//      } else if (分数 >= 60) {
//          return 2;
//      } else {
//          return 1;
//      }
//
//  ④ 组合条件：`&&` 是"并且"，逻辑或运算符 是"或者"，`!` 是"不"。
//
//      if (分数 >= 60 && 出勤 >= 0.8) { ... }
//      if (分数 < 0 逻辑或运算符 分数 > 100) { ... }        /* 分数不合法 */
//
//  ⑤ C 的"真假"约定：**0 是假，非 0 是真**。
//     所以 `if (分数)` 的意思是"分数不为 0 就成立"，
//     而 `if (分数 == 1)` 才是"分数等于 1"。两回事。
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 判等级(int 分) {
//          if (分 >= 90) {
//              return 3;
//          } else if (分 >= 60) {
//              return 2;
//          } else {
//              return 1;
//          }
//      }
//
//      int main(void) {
//          printf("%d\n", 判等级(95));      ⇒ 3
//          printf("%d\n", 判等级(90));      ⇒ 3
//          printf("%d\n", 判等级(60));      ⇒ 2
//          printf("%d\n", 判等级(59));      ⇒ 1
//          return 0;
//      }
//
//  ⚠ 上面四个数就是这一课要过的那四条边界 ——
//    95 和 90 都是 3（>= 不是 >）、60 是 2、59 是 1。
//    写 if 的时候**一定要拿边界值各走一遍**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：把 == 写成了 =
//
//      错误写法：
//          int x = 5;
//          if (x = 0) {
//              printf("真\n");
//          }
//
//      你会看到什么（gcc 原文，只是 warning）：
//
//          main.c:5:9: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
//              5 │     if (x = 0) { printf("真\n"); }
//                │         ^
//
//      运行时：`真` **不会**被打印（因为 x 被赋成 0，而 0 是假）——
//      但你的 x 已经被**悄悄改成了 0**！
//
//      为什么：`=` 是赋值，它的"结果"就是赋进去的那个值。
//      所以 `if (x = 0)` 走的是"把 0 存进 x，然后判断 0 是不是真"。
//      如果写成 `if (x = 1)`，条件就**永远成立**，而且 x 被改成了 1。
//      ⚠ 编译器那条 warning 的措辞很难懂，但它的意思是"你是不是想写 =="。
//      ⇒ **看到 if 的括号里只有一个等号，立刻停下来改。**
//
//  ⚠ 坑 2：判断顺序写反，后面的分支永远到不了
//
//      错误写法：
//          if (分 >= 60) {
//              return 2;
//          } else if (分 >= 90) {      /* ⚠ 永远走不到这里 */
//              return 3;
//          }
//
//      你会看到什么：
//          ⚠ **编译器不会给你任何提示**，一个 warning 都没有。
//          运行时 95 分返回 2，和 60 分一模一样。
//
//      为什么：if / else if 是**从上往下**挨个试的，第一个成立的就进去了。
//      95 满足 `>= 60`，所以它在第一个分支就返回了，
//      第二个条件再好也没有机会被看一眼。
//      ⇒ 写多分支时把条件**从最严格往最宽松**排，
//        或者干脆让每个条件互不重叠（比如 `分 >= 90` 和 `分 >= 60 && 分 < 90`）。
//
//  ⚠ 坑 3：if 后面多写了一个分号，分支体被架空
//
//      错误写法：
//          if (分数 >= 60);            /* ⚠ 多了一个分号 */
//          {
//              printf("及格\n");
//          }
//
//      你会看到什么：
//          gcc 通常会警告（`-Wempty-body`）：warning: suggest braces around empty body in an 'if' statement
//          运行结果：**不管多少分都打印「及格」**。
//
//      为什么：C 里 `;` 本身就是一个"空语句"。
//      `if (条件);` 的意思是"条件成立时，做一件空事"。
//      后面那个 `{ ... }` 跟 if 已经没有关系了，它只是一段**无条件执行**的代码块。
//      ⇒ 这类错的共同特征：**条件看起来完全正确，行为却不受条件影响**。
//        一旦出现"判断不生效"，先数 if 后面有没有多余的分号。
//

// 第 07 课：for —— 让程序重复做事
//
// ─────────────────────────────────────────────────────
//  先介绍：重复做一件事
// ─────────────────────────────────────────────────────
//
//     for (int i = 1; i <= 5; i++) {
//         printf("%d\n", i);
//     }
//
// for 的圆括号里有**三段**，用分号隔开：
//
//     for ( 初始化 ; 继续条件 ; 每轮之后做 )
//           int i=1   i <= 5      i++
//
//   · 初始化：循环开始前做一次
//   · 继续条件：每轮开始前检查，**为假就停**
//   · i++ 是 `i = i + 1` 的简写
//
// ⚠ 三段**都用分号隔开**，不是逗号：
//     for (int i = 1, i <= 5, i++)     ❌
//     for (int i = 1; i <= 5; i++)     ✅
//
// ⚠⚠ 这一课要记住的坑：**差一错误（off-by-one）**
//     i <= 5   跑 5 次（1,2,3,4,5）      ✅
//     i < 5    跑 4 次（1,2,3,4）        ← 少一次
//     i <= 5 但 i 从 0 开始 ⇒ 跑 6 次     ← 多一次
//   写循环时**一定要在脑子里数一遍**：第一次进循环时 i 是几？最后一次是几？
//
// 累加的套路（和 Python 一样，但**必须先初始化**）：
//     int 和 = 0;              ← ⚠ 忘了这行，和会是随机的垃圾值
//     for (...) 和 += x;
//
// ⚠ C 里未初始化的局部变量**不会自动是 0** —— 它是内存里的随机值。
//   这是 C 与 Python 的又一个大区别。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 数数（最典型的用法）：
//
//      for (int i = 1; i <= 5; i++) {
//          printf("%d\n", i);
//      }
//
//      输出：1 2 3 4 5（每个一行）
//
//  ② 累加：先准备一个"桶"，循环里往里加。
//
//      int 和 = 0;                         /* ⚠ 必须初始化 */
//      for (int i = 1; i <= 5; i++) {
//          和 += i;                        /* 和 = 和 + i 的简写 */
//      }
//      printf("%d\n", 和);                 ⇒ 15
//
//  ③ 从 0 开始、用来遍历数组（第 09 课就靠这个）：
//
//      for (int i = 0; i < 5; i++) {       /* ⚠ 从 0 起，条件就是 i < 5 */
//          printf("%d\n", 数据[i]);
//      }
//
//      ⚠ 这两种写法各自都对，但**不能混**：
//        「从 1 开始」配 `i <= n`
//        「从 0 开始」配 `i <  n`
//        混着写就是差一错误。
//
//  ④ 倒着数：三段都可以随便写，不一定非得加。
//
//      for (int i = 5; i >= 1; i--) { ... }        ⇒ 5 4 3 2 1
//
//  ⑤ 提前跳出：`break` 立刻结束整个循环，`continue` 跳过本轮剩下的部分。
//
//      for (int i = 1; i <= 10; i++) {
//          if (i == 4) break;              /* 到 4 就不干了 */
//      }
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 求和到(int n) {
//          int 和 = 0;
//          for (int i = 1; i <= n; i++) {
//              和 += i;
//          }
//          return 和;
//      }
//
//      int main(void) {
//          printf("%d\n", 求和到(5));      ⇒ 15
//          printf("%d\n", 求和到(1));      ⇒ 1
//          printf("%d\n", 求和到(0));      ⇒ 0
//          return 0;
//      }
//
//  ⚠ 注意 `求和到(0)`：条件 `i <= 0` 一开始就是假 ⇒ 一次都不进循环 ⇒
//    直接返回 0。这是**对的**，但它靠的是 `和 = 0` 那行初始化。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：忘了给累加器初始化
//
//      错误写法：
//          int 求和到(int n) {
//              int 和;                     /* ⚠ 没有 = 0 */
//              for (int i = 1; i <= n; i++) {
//                  和 += i;
//              }
//              return 和;
//          }
//
//      你会看到什么：
//          gcc 可能给一条 warning: '和' may be used uninitialized [-Wmaybe-uninitialized]
//          也可能**什么都不说**（取决于优化级别）。
//          运行时 求和到(5) 返回一个莫名其妙的数（比如 -858993445），每次还可能不一样。
//
//      为什么：C 的局部变量在栈上，**不会自动清零**。`int 和;`
//      只是把栈上那块地"认领"下来，地里原来是别的函数留下的垃圾。
//      `和 += i` 等价于 `和 = 和 + i` ⇒ 从垃圾值开始加，结果当然是垃圾。
//      ⚠ 这类 bug 阴险的地方：**同一个程序，换台机器/换个编译选项，结果就变了**。
//      ⇒ 累加器、计数器、最大值、最小值——**声明时一律给初值**。
//
//  ⚠ 坑 2：for 的三段用了逗号
//
//      错误写法：
//          for (int i = 1, i <= 5, i++) { ... }
//
//      你会看到什么：
//
//          main.c:3:22: error: expected identifier or '(' before '<=' token
//
//      为什么：在 for 的圆括号里，**逗号是另一件事** ——
//      它表示"再声明一个同类型的变量"（`int i = 1, j = 2;` 是合法的）。
//      所以编译器读到 `i <= 5` 时以为你在写第二个变量名，结果撞上 `<=` 就崩了。
//      ⇒ 三段之间**只能是分号**，永远。
//
//  ⚠ 坑 3：差一错误 —— 循环次数数错了
//
//      错误写法（想求 1 到 5 的和，却写了 <）：
//          int 和 = 0;
//          for (int i = 1; i < 5; i++) {
//              和 += i;
//          }
//
//      你会看到什么：
//          ⚠ **编译零警告**，程序正常跑完，输出 `10`（而你要的是 15）。
//          算出来的数字"看起来也很正常"，所以这个错特别难被发现。
//
//      为什么：`i < 5` 在 i 变成 5 的时候就停了，最后一个 5 没加进去。
//      ⇒ 一条能救命的自检习惯：**把循环次数和边界在纸上走一遍**。
//          i 从 1 开始，条件是 i <= 5 ⇒ 最后一次进循环时 i = 5 ⇒ 恰好 5 次 ✅
//          i 从 1 开始，条件是 i <  5 ⇒ 最后一次进循环时 i = 4 ⇒ 只有 4 次 ❌
//      ⚠ 遍历数组更危险：`i <= 个数` 会**越界读一个**（第 09 课的主题）。
//

//
// ─────────────────────────────────────────────────────
//  先介绍：函数 = 起个名字的一段计算
// ─────────────────────────────────────────────────────
//
//     int 平方(int x) {
//     ↑        ↑
//     返回类型  函数名(参数类型 参数名)

//         return 结果;
//     }
//
// ⚠⚠ **C 的函数必须写返回类型**（Python 可以不写）：
//     平方(x) { }              ❌ 老式写法，现代 C 不允许
//     int 平方(int x) { }      ✅
//
// ⚠ 参数也要写类型，而且**每个参数都要写**：
//     int 加(int a, b)         ❌ b 没类型
//     int 加(int a, int b)     ✅
//
// ⚠ `return` 之后函数立刻结束；不是 void 的函数**每条路径都要有 return**：
//     int 判(int x) {
//         if (x > 0) return 1;
//         /* 如果 x <= 0 就走到这里，没有 return ⇒ 返回随机值！ */
//     }
//     编译器会给警告（control reaches end of non-void function），
//     但**不一定报错** ⇒ 你会拿到随机结果。
//
// ⚠ 函数写在 main **前面**；写在后面要先声明（那是第 13 课）。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 不接收参数、不返回值的函数：返回类型写 void，参数写 void。
//
//      void 打个招呼(void) {
//          printf("你好\n");
//      }
//
//  ② 有参数、有返回值（最常见的形状）：
//
//      int 平方(int x) {
//          return x * x;
//      }
//
//  ③ 调用它：写函数名，括号里放实参。返回值可以直接用、可以打印、可以存起来。
//
//      printf("%d\n", 平方(3));        ⇒ 9        直接打印
//      int r = 平方(4);                           存进变量（r 是 16）
//
//  ④ 参数可以有多个，用逗号隔开：
//
//      int 较大(int a, int b) {
//          if (a > b) {
//              return a;
//          }
//          return b;               /* ⚠ 这条路径也要 return */
//      }
//
//  ⑤ void 函数里 `return;` 表示"提前结束"，不带值。
//
//      void 检查(int x) {
//          if (x < 0) {
//              return;             /* 负数就不往下做了 */
//          }
//          printf("正数\n");
//      }
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 平方(int x) {
//          return x * x;
//      }
//
//      int 较大(int a, int b) {
//          if (a > b) {
//              return a;
//          }
//          return b;
//      }
//
//      int main(void) {
//          printf("%d\n", 平方(3));        ⇒ 9
//          printf("%d\n", 平方(0));        ⇒ 0
//          printf("%d\n", 较大(1, 2));     ⇒ 2
//          printf("%d\n", 较大(5, 5));     ⇒ 5
//          return 0;
//      }
//
//  ⚠ 为什么"函数要写在 main 前面"：编译器从上往下读，
//    读到 `平方(3)` 那一行时，它得**先知道**平方长什么样。
//    写在前面它就知道了；写在后面就要先"声明"（第 13 课）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：不是每条路径都有 return
//
//      错误写法：
//          int 判(int x) {
//              if (x > 0) return 1;
//              /* x <= 0 时掉到这里，没有 return */
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:4:1: warning: control reaches end of non-void function [-Wreturn-type]
//              4 │ }
//                │ ^
//
//      ⚠ 只是 **warning** —— 编译照过，.exe 照生成。
//      运行时 `判(0)` 返回一个随机整数，每次跑都可能不一样。
//
//      为什么：函数说好返回 int，可 CPU 到达 `}` 时没有一个明确的返回值，
//      它就返回寄存在返回位置上的**残留值**（上一步运算留下的东西）。
//      ⇒ 规矩：**不是 void 的函数，最后一行也要有个 return**，
//        哪怕你觉得自己已经覆盖了所有情况。
//      上面那个例子最稳的写法是：
//          int 判(int x) {
//              if (x > 0) return 1;
//              return 0;               /* 兜底，明明白白 */
//          }
//
//  ⚠ 坑 2：参数忘了写类型
//
//      错误写法：
//          int 加(int a, b) {
//              return a + b;
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:2:15: error: unknown type name 'b'
//              2 │ int 加(int a, b) { return a + b; }
//                │               ^
//
//      为什么：C 的语法里，每个参数都是"类型 + 名字"的一个小声明。
//      编译器看到 `b` 就直接把它当成类型名去找 —— 找不到这个类型，报错。
//      ⚠ 有意思的是报错说的是 "unknown type name"，它**不会**提示"你漏了 int"，
//        所以第一次见容易懵。看到"某个变量的名字被当成类型名"，
//        先想：**是不是前一个类型忘了写**。
//      对了，`int a, b;` 在**变量声明**里是合法的（两个都是 int），
//      但在**参数列表**里不合法 —— 这点不一样，别混。
//
//  ⚠ 坑 3：把函数写在 main 后面，又没声明
//
//      错误写法：
//          #include <stdio.h>
//
//          int main(void) {
//              printf("%d\n", 平方(3));     /* ⚠ 平方还没出现过 */
//              return 0;
//          }
//
//          int 平方(int x) { return x * x; }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:4:20: error: implicit declaration of function '平方' [-Wimplicit-function-declaration]
//              4 │     printf("%d\n", 平方(3));
//                │                    ^~~~
//
//      为什么：编译器是**从上往下、一遍读完**的，它不做"先扫一遍全文"。
//      读到 `平方(3)` 的时候它压根没见过这个名字，只能猜"大概是个返回 int 的函数"。
//      这个"猜"在 C99 之后就是错误。
//      ⇒ 两种改法：把定义挪到 main 前面（本课推荐），
//        或者在 main 前面加一行声明 `int 平方(int x);`（第 13 课）。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────

//      较大(1,2) ⇒ 2       较大(5,5) ⇒ 5       较大(-3,-7) ⇒ -3

//   · 较大(5,5) 要是 5 —— 用 `>` 而不是 `>=` 也能过，但两条路径都要有 return。

// 第 09 课：数组 —— 一排格子
//
// ─────────────────────────────────────────────────────
//  先介绍：一排连续的格子
// ─────────────────────────────────────────────────────
//
//     int 成绩[5];                 ← 声明 5 个格子
//     int 成绩[5] = {90, 75, 60, 45, 88};
//
//     成绩[0]   ⇒ 90        ⚠ 下标**从 0 开始**
//     成绩[4]   ⇒ 88        最后一个
//
// ⚠⚠⚠ **这一课唯一要记住的坑：C 的数组不检查越界。**
//
//     成绩[5]   ← 越界了！但 C **不报错**，它会读/写到别的内存去。
//                 写越界可能让你后面完全不相干的变量莫名其妙变值，
//                 或者程序直接崩（Segmentation fault）。
//
//   为什么：C 追求速度，不做运行时检查。数组名本质上只是一个地址，
//   `成绩[5]` 被算成"地址 + 5 个格子"，它不问你是不是超出去了。
//   ⇒ **下标的正确性是你自己的责任。**
//
// ⚠ 数组**没有长度信息**：用 `sizeof(数组)/sizeof(数组[0])` 只能算
//   **在同一个函数内**声明的数组。传进函数的数组会"退化"成指针，
//   所以**必须另外传一个"个数"参数** —— 这就是这一课的函数有两个参数的原因。
//
//     int 求和(int 数们[], int 个数)     ← 个数必须自己传
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 声明并给初值：花括号里按顺序填。
//
//      int 成绩[5] = {90, 75, 60, 45, 88};
//
//  ② 只给一部分，剩下的自动是 0：
//
//      int 数们[5] = {1, 2};           ⇒ 1, 2, 0, 0, 0
//
//  ③ 让编译器自己数长度（推荐，不会写错）：
//
//      int 数们[] = {1, 2, 3, 4, 5};   ⇒ 长度自动是 5
//
//  ④ 读写单个格子：用 `名字[下标]`，下标从 **0** 到 **长度减一**。
//
//      数们[0] = 10;                  写
//      printf("%d\n", 数们[0]);       读
//
//  ⑤ 遍历：下标从 0 开始，条件写 `i < 长度`。
//
//      for (int i = 0; i < 5; i++) {
//          printf("%d\n", 数们[i]);
//      }
//
//      ⚠ 是 `< 长度`，不是 `<= 长度` —— 后者会越界读一个。
//
//  ⑥ 在**同一个函数内**想知道数组有几个元素：
//
//      int 个数 = sizeof(数们) / sizeof(数们[0]);      ⇒ 5
//
//      ⚠ 这一招**只在同一个函数里有效**，传进函数就失灵了（坑 1）。
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 求和(int 数们[], int 个数) {
//          int 和 = 0;
//          for (int i = 0; i < 个数; i++) {
//              和 += 数们[i];
//          }
//          return 和;
//      }
//
//      int main(void) {
//          int 数据[] = {1, 2, 3, 4, 5};
//          printf("%d\n", 求和(数据, 5));      ⇒ 15
//          return 0;
//      }
//
//  ⚠ 注意调用时**必须自己把 5 传进去** —— 函数那边是算不出长度的。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：在函数里用 sizeof 算传进来的数组长度
//
//      错误写法：
//          int 求和(int 数们[]) {
//              int 个数 = sizeof(数们) / sizeof(数们[0]);   /* ⚠ 这里算错了 */
//              ...
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:3:32: warning: 'sizeof' on array function parameter '数们' will return size of 'int *' [-Wsizeof-array-argument]
//              3 │     int 个数 = sizeof(数们) / sizeof(数们[0]);
//                │                                ^
//          main.c:2:15: note: declared here
//              2 │ int 求和(int 数们[]) {
//                │           ~~~~^~~~~~
//
//      运行结果：个数 变成 1（64 位机器上 sizeof(int*) 是 8，sizeof(int) 是 4）
//      ⇒ 你的函数永远只加第一个元素。
//
//      为什么：**数组作为参数会"退化"成指针**。函数里的 `数们` 类型是 `int *`，
//      `sizeof(int *)` 是"一个指针占几字节"，跟数组有几个元素毫无关系。
//      ⚠ 这条同时也是理解第 15 课的钥匙。
//      ⇒ 唯一正确的做法：**长度另外传一个参数**。
//
//  ⚠ 坑 2：下标写错一位 —— 经典的越界
//
//      错误写法（想给 5 个格子赋值）：
//          int 数据[5];
//          for (int i = 1; i <= 5; i++) {
//              数据[i] = i;            /* ⚠ 数据[5] 越界了 */
//          }
//
//      你会看到什么：
//          ⚠ **gcc 这一次一声不吭，-Wall 也不报。** 编译通过、程序照跑。
//          但 `数据[5]` 已经写到了数组外面 —— 它可能踩坏了旁边某个变量，
//          也可能什么都没发生（这次运气好）。
//
//      为什么：C 把 `数据[i]` 算成"首地址 + i × 每格大小"，**不做范围检查**。
//      这套写法错在两个地方：
//        ① 下标应该从 0 开始（你从 1 开始了）；
//        ② 5 个格子合法的下标是 0 到 4，`<= 5` 会碰到 数据[5]。
//      ⇒ 遍历数组就用这一个模板，背下来：
//          for (int i = 0; i < 长度; i++)
//      ⚠ 越界写是**最难查**的一类 bug：报错的地方往往离出错的地方很远。
//
//  ⚠ 坑 3：以为数组可以整体赋值、整体比较
//
//      错误写法：
//          int 甲[3] = {1, 2, 3};
//          int 乙[3];
//          乙 = 甲;                    /* ❌ */
//          if (甲 == 乙) { ... }       /* ❌ */
//
//      你会看到什么：
//
//          main.c:3:7: error: assignment to expression with array type
//
//      为什么：C 的数组**不是"值"**，它只是一个地址（第 15 课）。
//      地址不能被赋值，两个地址比较也不会去看内容。
//      ⇒ 想复制就一个个搬（`for` 循环），想比较就一个个比。
//      ⚠ 字符串（char 数组）是例外中的例外 —— 它有 `strcpy` 和 `strcmp`
//        这两个现成的函数，但那也是"函数帮你循环"，不是语言支持。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写

//      求和({1,2,3,4,5}, 5)    ⇒ 15
//      求和({1,100}, 2)        ⇒ 101
//      求和({3,-1,-2,-3}, 4)   ⇒ -3
//      求和({}, 0)             ⇒ 0
//
// ⚠ 个数是 0 的那组是**边界**：它专门检查你的 `和` 有没有初始化成 0、

// 第 10 课：字符串 —— 一串字符
//
// ─────────────────────────────────────────────────────
//  先介绍：C 的字符串其实是"字符数组 + 一个结尾标记"
// ─────────────────────────────────────────────────────
//
//     char 名字[] = "小明";
//
// 它在内存里长这样：
//     '小' '明' '\0'
//                ↑
//                结束标记（值是 0，写作 '\0'）
//
// ⚠⚠⚠ **C 的字符串靠 `\0` 判断"到哪结束"**，它**没有长度字段**。
//   所以你遍历字符串时，判据是"这个字符是不是 '\0'"，不是长度：
//
//     int i = 0;
//     while (文字[i] != '\0') {     ← 到结束标记就停
//         i++;
//     }
//
// ⇒ 这就是为什么这一课请你**自己数**（不用 strlen）：
//   数一遍你才会真正明白"字符串是怎么结束的"。
//
// ⚠ `'A'`（单引号）是一个**字符**；`"A"`（双引号）是一个**字符串**（含 '\0'）。
//   它们是不同类型，不能混：
//     char c = 'A';         ✅
//     char c = "A";         ❌ 类型不匹配（编译器会警告）
//
// ⚠ 中文一个字通常占 3 个字节（UTF-8），所以 `strlen("小明")` 是 6 不是 2。
//   检查里只用**英文**测长度，避免这个干扰。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 声明一个有内容的字符串（让编译器数长度，最省心）：
//
//      char 问候[] = "你好";          实际占 7 字节：你好(6) + '\0'(1)
//
//  ② 声明一个"空桶"，等以后往里装：
//
//      char 缓冲[32];                 ⚠ 里面是随机内容，还不是合法字符串
//
//  ③ 打印字符串用 `%s`（不是 %d、不是 %c）：
//
//      printf("%s\n", 问候);          ⇒ 你好
//
//  ④ 访问单个字符用下标，类型是 char：
//
//      char c = 问候[0];
//      printf("%c\n", c);             ⇒ 你
//
//  ⑤ 自己数长度（这一课的重点）：
//
//      int i = 0;
//      while (文字[i] != '\0') {
//          i++;
//      }
//      /* 循环结束时 i 就是长度 */
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 长度(char 文字[]) {
//          int i = 0;
//          while (文字[i] != '\0') {
//              i++;
//          }
//          return i;
//      }
//
//      int main(void) {
//          printf("%d\n", 长度(""));               ⇒ 0
//          printf("%d\n", 长度("a"));              ⇒ 1
//          printf("%d\n", 长度("abc"));            ⇒ 3
//          printf("%d\n", 长度("hello world"));    ⇒ 11
//          return 0;
//      }
//
//  ⚠ 空串 `""` 也能测：它的第 0 个字符就是 '\0' ⇒ 循环一次都不进 ⇒ 返回 0。
//    这一条正好验证你写的是"看结束标记"而不是"看长度"。
//
//  ⚠ 顺便记住两个现成的函数（`#include <string.h>`，本课不许用）：
//
//      strlen(文字)                数长度
//      strcmp(甲, 乙)              比内容：相等返回 0，甲小返回负数，甲大返回正数
//
//    `strcmp` 这一课先不写，但你一定要知道**它是唯一的正确比较方式**（坑 3）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：用单引号写字符串、用双引号写字符
//
//      错误写法：
//          printf("%c\n", "A");        /* 双引号 = 字符串 */
//
//      你会看到什么（gcc 原文）：
//
//          main.c:3:14: warning: format '%c' expects argument of type 'int', but argument 2 has type 'char *' [-Wformat=]
//              3 │     printf("%c\n", "A");
//                │             ~^     ~~~
//                │              │     │
//                │              │     │
//                │              int   char *
//                │             %s
//
//      运行时输出一个**乱码字符**，而不是 `A`。
//
//      为什么：`"A"` 的类型是 `char *`（一个地址），`%c` 要的是一个字符的编码。
//      printf 把那个**地址的低位**当成字符编码打出来 ⇒ 乱码。
//      ⇒ 反过来也错：`'A'` 是字符，`printf("%s\n", 'A')` 会警告
//        `format '%s' expects argument of type 'char *', but argument 2 has type 'int'`，
//        运行起来多半直接崩（它把你的字符编码 65 当成了地址）。
//      ⚠ 一句话记住：**单引号一个字符，双引号一串字符。**
//
//  ⚠ 坑 2：忘了 '\0' 这件事，数出了错误的长度
//
//      错误写法：
//          int 长度(char 文字[]) {
//              int i = 0;
//              while (文字[i] != 0) {      /* 这个其实是对的…… */
//                  i++;
//              }
//              return i;
//          }
//
//      换一种错法（更常见）：
//
//          int 长度(char 文字[]) {
//              int i = 0;

//      你把空格当标志，就等于让程序"闭着眼睛往前读"，读到哪算哪。

//          while (文字[i] != '\0') { i++; }

// 第 11 课：指针 —— 改参数，外面会不会变
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么需要指针
// ─────────────────────────────────────────────────────
//
// 先看一个"不生效"的函数：
//
//     void 加倍(int x) {
//         x = x * 2;            ← 改的是**拷贝**
//     }
//
//     int 数 = 5;
//     加倍(数);
//     printf("%d\n", 数);       ⇒ 还是 5！
//
// 为什么：C 的函数参数默认是**按值传递** —— 传进去的是一份**拷贝**。
// 函数里怎么改，都动不到外面那个变量。
//
// 想改到外面，就要传**地址**：
//
//     void 加倍(int *p) {       ← p 是"指向一个 int 的指针"
//         *p = *p * 2;          ← *p 是"p 指向的那个数"
//     }
//
//     int 数 = 5;
//     加倍(&数);                ← 传地址（那个 & 又出现了）
//     printf("%d\n", 数);       ⇒ 10  ✅
//
// ⚠⚠ 两个符号别搞混 —— 这是这一课唯一要记住的东西：
//
//     &数     取地址 —— "数在内存的哪里"
//     *p     取值   —— "p 指的那个地方**里面**是什么"
//
//   在**声明**里 `int *p` 的 `*` 是"这是个指针"；
//   在**表达式**里 `*p` 的 `*` 是"取出它指的东西"。同一个符号两种意思。
//
// ⚠ 第 05 课的 `scanf("%d", &数)` 就是这个道理 ——
//   它要改你那个变量，所以必须知道地址。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 先亲眼确认"按值传递改不到外面"（这段值得你跑一遍）：
//
//      #include <stdio.h>
//
//      void 加倍(int x) { x = x * 2; }        /* 改的是拷贝 */
//
//      int main(void) {
//          int 数 = 5;
//          加倍(数);
//          printf("%d\n", 数);                ⇒ 5   ← 没变！
//          return 0;
//      }
//
//  ② 换成指针，就改到了：
//
//      void 加倍(int *p) { *p = *p * 2; }
//
//      int main(void) {
//          int 数 = 5;
//          加倍(&数);                         /* ⚠ 传的是地址 */
//          printf("%d\n", 数);                ⇒ 10  ← 变了
//          return 0;
//      }
//
//  ③ 三个符号的读法（把这句话背下来就够用了）：
//
//      int 数 = 5;
//      int *p = &数;           p 存的是"数"的地址
//      printf("%d\n", 数);     ⇒ 5      数的值
//      printf("%d\n", *p);     ⇒ 5      p 指的那个东西的值
//      *p = 7;                 ⇒ 数 也变成 7
//
//  ④ 指针参数的意义："我要改你给我的那个变量"。
//     一个函数想"交回"多个结果时，就得靠它（第 16 课会用两个指针）。
//
//  ⚠ 为什么这一课的函数签名是 `void 加倍(int *p)`：
//    · 返回类型是 void —— 它不需要 return，结果直接写进你给的地址里；
//    · 参数是 `int *` —— 它要的是"一个 int 的地址"，不是那个 int 的值。
//  所以调用时必须写 `加倍(&数)`。写 `加倍(数)` 就类型不匹配了（坑 1）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：调用时忘了写 &
//
//      错误写法（函数已经有声明，main 里却传了值）：
//          void 加倍(int *p);
//
//          int main(void) {
//              int 数 = 5;
//              加倍(数);                   /* ⚠ 传的是值，不是地址 */
//              return 0;
//          }
//
//      你会看到什么（gcc 原文，函数名是中文时会被转义成 UCN 码点）：
//
//          main.c:4:10: error: passing argument 1 of '\U000052a0\U0000500d' makes pointer from integer without a cast [-Wint-conversion]
//              4 │     加倍(数);
//                │          ^~
//                │          │
//                │          int
//          main.c:4:10: note: possible fix: take the address with '&'
//              4 │     加倍(数);
//                │          ^~
//                │          &
//          main.c:1:16: note: expected 'int *' but argument is of type 'int'
//              1 │ void 加倍(int *p);
//                │           ~~~~~^
//
//      为什么：函数要的是一个"int 的地址"，你给了它一个 int 的值。
//      C 不允许把整数悄悄当成指针用 —— 所以这里是 **error**，不是 warning。
//      ⚠ 最贴心的是那条 `note: possible fix: take the address with '&'`：
//        gcc 直接把补丁画给你了。**看到它，就在那个参数前面加 &。**
//      ⚠ 还有一种更迷惑的写法：**函数没声明、也没定义在后面**时，
//        你写 `加倍(数);` 会先撞上另一条错：
//            error: implicit declaration of function '\U000052a0\U0000500d' [-Wimplicit-function-declaration]
//        那说的是"我不认识 加倍 这个名字"（第 13 课），
//        **和"忘了 &"是两回事**。分清这两条，能省很多时间。
//
//  ⚠ 坑 2：函数体里写 `p = p * 2`（少了一个星号）
//
//      错误写法：
//          void 加倍(int *p) {
//              p = p * 2;              /* ⚠ 改的是指针自己 */
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:2:11: error: invalid operands to binary * (have 'int *' and 'int')
//              2 │     p = p * 2;
//                │           ^
//
//      为什么：`p` 的类型是 `int *`（地址），`2` 是 `int`。
//      "地址乘 2"没有定义 ⇒ 编译直接拦下来。
//      ⚠ 这条反而是**运气好**的情况 —— 编译器替你抓到了。
//      真正危险的是下面这种：
//
//          void 加倍(int *p) {
//              p = p + 1;              /* 合法！但毫无用处 */
//          }
//
//      "地址加 1"是合法的（指针算术，第 15 课），所以它**编译零警告**，
//      可它只是把函数内部那个局部指针挪了一格 —— 外面的数一个字节都没变。
//      ⇒ 记住：**要改外面那个数，必须写 `*p`。**
//
//  ⚠ 坑 3：以为指针参数是"引用"，直接写变量名
//
//      错误写法：
//          void 加倍(int *p) {
//              数 = 数 * 2;            /* ⚠ 数 在这个函数里根本不存在 */
//          }
//
//      你会看到什么（gcc 原文，中文名会被转义）：
//
//          main.c:2:5: error: '\U00006570' undeclared (first use in this function)
//              2 │     数 = 数 * 2;
//                │     ^~
//
//      为什么：函数只能看见自己的参数和局部变量。
//      `数` 是 main 里的变量，这里只是个**错误的名字**。
//      指针参数给你的是"改外面那个变量的**通道**"，通道的名字叫 `*p`。
//      ⇒ 心里默念一句：**p 是门牌号，*p 是屋里那个人。**
//
// ─────────────────────────────────────────────────────

// 第 12 课：结构体 —— 把几个东西打成一包
//
// ─────────────────────────────────────────────────────
//  先介绍：把相关的数据放在一起
// ─────────────────────────────────────────────────────
//
// 一个学生有学号、有分数。用两个变量存很别扭：
//
//     int 学号1 = 7;  int 分数1 = 92;
//     int 学号2 = 8;  int 分数2 = 55;      ← 学生一多就疯了
//
// 结构体把它们打成**一个**类型：
//
//     struct 学生 {
//         int 学号;
//         int 分数;
//     };
//     ↑ 这个分号不能少！结构体定义末尾**一定要有分号**
//
// 用起来：
//
//     struct 学生 a;
//     a.学号 = 7;            ← 用 `.` 取里面的字段
//     a.分数 = 92;
//
//     struct 学生 b = {8, 55};      ← 也可以一次给全
//
// ⚠⚠ 这一课要记住的两个坑：
//
//   ① **结构体定义末尾的分号**：`};`
//      漏了会报一堆看不懂的错（因为它会以为你在声明变量）。
//
//   ② 类型名要写 `struct 学生`，**不能只写 `学生`**：
//        struct 学生 a;        ✅
//        学生 a;               ❌ unknown type name '学生'
//      （用 `typedef` 可以省掉 struct，那是以后的事。）
//
// ⚠ 结构体可以**整体传给函数**（按值传递，会拷贝一份）。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 先定义类型（写在所有函数前面），末尾带分号：
//
//      struct 学生 {
//          int 学号;
//          int 分数;
//      };
//
//  ② 造一个变量：类型名要写全 `struct 学生`。
//
//      struct 学生 a;                  ⚠ 是 "struct 学生"，不是 "学生"
//
//  ③ 逐个字段赋值 / 读取：用 `.`（读作"的"）。
//
//      a.学号 = 7;
//      a.分数 = 92;
//      printf("%d\n", a.分数);         ⇒ 92
//
//  ④ 一次给全：花括号里**按定义的顺序**填。
//
//      struct 学生 b = {8, 55};        ⇒ 学号=8, 分数=55
//      struct 学生 c = {9};            ⇒ 学号=9, 分数=0（剩下的自动 0）
//
//  ⑤ 结构体是**一个整体**，可以直接传参、直接返回、直接赋值。
//
//      struct 学生 复制品 = a;         /* 整包拷贝一份 */
//      int 是优等生(struct 学生 s);     /* 整包传进去 */
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      struct 学生 {
//          int 学号;
//          int 分数;
//      };                              /* ⚠ 这个分号不能少 */
//
//      int 是优等生(struct 学生 s) {
//          if (s.分数 >= 90) {         /* ⚠ 用 . 取字段 */
//              return 1;
//          }
//          return 0;
//      }
//
//      int main(void) {
//          struct 学生 a = {7, 92};
//          struct 学生 b = {8, 55};
//          printf("%d\n", 是优等生(a));     ⇒ 1
//          printf("%d\n", 是优等生(b));     ⇒ 0
//          return 0;
//      }
//
//  ⚠ 顺带说清楚（这是第 15 课的前菜）：
//    如果你拿到的是**指针**，取字段要用 `->` 而不是 `.`：
//        struct 学生 *p = &a;
//        p->分数       等价于   (*p).分数
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：结构体定义末尾漏了分号 —— 这一课的头号杀手
//
//      错误写法：
//          struct 学生 {
//              int 学号;
//              int 分数;
//          }                               /* ⚠ 少了分号 */
//
//          int main(void) { ... }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:6:1: error: expected ';', identifier or '(' before 'int'
//              6 │ int main(void) {
//                │ ^~~
//
//      为什么：少了分号，编译器就把后面那个 `int main(void)` 当成
//      "定义完 struct 学生 之后，顺便声明一个叫 main 的变量" ——
//      结果看到 `(` 就懵了。
//      ⚠ 注意报错在**第 6 行**，但错在**第 4 行** —— 又是"往上多看一行"。
//      ⇒ 看到 "expected ';', identifier or '(' before"，先找**上面那个 }**。
//
//  ⚠ 坑 2：用类型名的时候省掉了 struct
//
//      错误写法：
//          struct 学生 {
//              int 学号;
//          };
//
//          struct 学生 a;
//          学生 b;                     /* ⚠ 少了 struct */
//
//      你会看到什么（gcc 原文）：
//
//          main.c:6:1: error: unknown type name '\U00005b66\U0000751f'; use 'struct' keyword to refer to the type
//              6 │ 学生 b;
//                │ ^~~~
//                │ struct
//
//      为什么：C 里 `struct 学生` 才是**一个完整的类型名**，
//      `学生` 只是"结构体标签"，不是类型。
//      ⚠ 好消息：gcc 在那行 `struct` 里把答案告诉你了 —— 补上就行。
//      （C++ 里可以直接写 `学生`，C 不行。这是两门语言的一个真实差别。）
//      想省掉 struct 的话要写 `typedef struct 学生 { ... } 学生;`，以后再说。
//
//  ⚠ 坑 3：以为结构体传进函数能被改到
//
//      错误写法：
//          void 清零(struct 学生 s) {
//              s.分数 = 0;             /* ⚠ 改的是拷贝 */
//          }
//
//          struct 学生 a = {7, 92};
//          清零(a);
//          printf("%d\n", a.分数);     ⇒ 还是 92
//
//      你会看到什么：
//          ⚠ **编译零警告、零报错。** 程序安安静静地跑完，打印 92。
//          没有任何提示告诉你"这次修改丢了"。
//
//      为什么：结构体和 int 一样是**按值传递**的 —— 函数收到的是整包拷贝，
//      改拷贝不影响原件。这一点和第 11 课那个 `void 加倍(int x)` 一模一样，
//      只是这次拷贝的是一整包数据，所以更不容易察觉。
//      ⇒ 想让函数改到外面的结构体，传**指针**：
//          void 清零(struct 学生 *s) {
//              s->分数 = 0;            /* ⚠ 用 -> */
//          }
//          清零(&a);                   /* ⚠ 传地址 */
//      ⚠ 顺带一个性能提醒：结构体一大，每次传参都要拷贝一整包。
//        真实项目里几乎都传指针 —— 但本课的函数题按值传就够。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   1. 定义 struct 学生 { int 学号; int 分数; };
//   2. 写函数 int 是优等生(struct 学生 s)
//      分数 >= 90 返回 1，否则返回 0
//
// 提示：不用写 main。

// ⚠ 期望结果：

//      是优等生({7, 92})   ⇒ 1

// ⚠ 检查会分三件事看：

//   ⇒ 所以那个 `};` 的分号，和 `struct 学生 s` 里的 struct，

// 第 13 课：函数声明 —— 写在后面也能用
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么需要"声明"
// ─────────────────────────────────────────────────────
//
// C 编译器是**从上往下**读的。所以这样写会报错：
//
//     int main(void) {
//         printf("%d\n", 三倍(5));     ← 报 implicit declaration of '三倍'
//         return 0;
//     }
//     int 三倍(int x) { return x * 3; }   ← 定义在下面，编译器还没读到
//
// 解决：**在使用之前先"声明"一下**（也叫函数原型）：
//
//     int 三倍(int x);              ← 声明：只有类型，没有函数体，末尾分号
//
//     int main(void) {
//         printf("%d\n", 三倍(5));  ← 现在编译器知道有这么个函数了
//         return 0;
//     }
//
//     int 三倍(int x) {             ← 定义：真正的实现
//         return x * 3;
//     }
//
// ⚠⚠ 这一课要记住的两件事：
//
//   ① **声明 vs 定义**
//        声明：`int 三倍(int x);`     末尾**有分号**，没有 { }
//        定义：`int 三倍(int x) { ... }`  有函数体
//      放分号的地方不同，作用完全不同。
//
//   ② **为什么报错信息里说 implicit declaration**
//      那是编译器在说"我没见过这个函数，就当你返回 int 吧"——
//      这是个**警告级**的问题，但现代 C 已经当错误处理了。
//      看到它，就是"函数定义在使用之后，而且没声明"。
//
// ⚠ 这也解释了 #include 在干嘛：`#include <stdio.h>` 里就是
//   printf 的**声明**。所以你在 main 里能用 printf。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 声明就是"把函数的第一行抄下来，末尾加分号"：
//
//      定义：  int 三倍(int x) { return x * 3; }
//      声明：  int 三倍(int x);
//
//      ⚠ 参数名可以省：`int 三倍(int);` 也对。
//        但**类型必须和定义完全一致**，否则就是另一个函数（坑 3）。
//
//  ② 标准布局：声明在上面，main 在中间，定义在下面。
//
//      #include <stdio.h>
//
//      int 三倍(int x);            /* 声明 */
//
//      int main(void) {
//          printf("%d\n", 三倍(5));    ⇒ 15
//          return 0;
//      }
//
//      int 三倍(int x) {           /* 定义 */
//          return x * 3;
//      }
//
//  ③ 为什么真实项目都这么写：函数多了以后，
//     "谁在谁前面"会变成一团乱麻。有了声明，**顺序就自由了**。
//
//  ④ 最大的那个例子就是头文件：
//     `#include <stdio.h>` 干的事，就是把你用到的那些函数（printf、scanf…）
//     的**声明**一次性抄进你的文件。它里面一个函数体都没有。
//
//      ⚠ 所以"找不到 printf 的声明"和"找不到你自己函数的声明"
//        是**同一件事**，报错措辞也几乎一样。
//
//  ⚠ 声明写在文件开头，定义写在文件末尾 —— 这是 C 项目最经典的排版，
//    以后你读别人的代码会一直见到它。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：函数定义在使用之后，且没有声明
//
//      错误写法：
//          #include <stdio.h>
//
//          int main(void) {
//              printf("%d\n", 三倍(5));     /* ⚠ 三倍 还没出现过 */
//              return 0;
//          }
//
//          int 三倍(int x) { return x * 3; }
//
//      你会看到什么（gcc 原文，中文函数名会被转义）：
//
//          main.c:4:20: error: implicit declaration of function '\U00004e09\U0000500d' [-Wimplicit-function-declaration]
//              4 │     printf("%d\n", 三倍(5));
//                │                    ^~~~
//
//      为什么：编译器**只往下读，不回头**。读到 `三倍(5)` 时它没见过这个名字，
//      只好按"返回 int 的无参函数"去猜。
//      ⚠ 那句 `[-Wimplicit-function-declaration]` 是开关名字 ——
//        它说明这原本是个"警告"，现在被当成错误。看到它，
//        只需要问一句：**这个函数的声明在哪？**
//
//  ⚠ 坑 2：声明末尾忘了分号（写成了定义的样子）
//
//      错误写法：
//          int 三倍(int x)             /* ⚠ 想让它是声明，但少了分号 */
//
//          int main(void) { ... }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:1:16: error: expected ';', identifier or '(' before 'int'
//              1 │ int 三倍(int x)
//                │                ^
//                │                ;
//          main.c:3:1: error: expected ';', identifier or '(' before 'int'
//
//      为什么：没有分号，编译器就以为你在**写定义**，于是接着找 `{`，
//      结果找到了 `int main(void)` ⇒ 崩。
//      ⚠ 它甚至好心地给你显示了该补的东西：`;`。
//      ⇒ 声明和定义的区别就在**一个分号**上：
//          有分号、没函数体  ⇒  声明
//          没分号、有函数体  ⇒  定义
//
//  ⚠ 坑 3：声明和定义的类型对不上
//
//      错误写法（声明说返回 double，定义却返回 int）：
//          double 三倍(int x);             /* 声明 */
//
//          int main(void) {
//              printf("%f\n", 三倍(5));
//              return 0;
//          }
//
//          int 三倍(int x) {               /* ⚠ 定义是 int */
//              return x * 3;
//          }
//
//      你会看到什么：
//
//          main.c:7:5: error: conflicting types for '三倍'; have 'int(int)'
//              7 │ int 三倍(int x) {
//                │     ^~~~
//          main.c:1:8: note: previous declaration of '三倍' with type 'double(int)'
//              1 │ double 三倍(int x);
//                │        ^~~~
//
//      为什么：C 靠"名字 + 参数类型"认函数。声明和定义必须是同一份契约。
//      编译器把两处都列出来了（一处 error、一处 note），
//      意思是"你在第 1 行说是 double，在第 7 行又说是 int"。
//      ⇒ 改的时候**两处一起改**。这也是为什么真实项目把头文件
//        当"契约"来管：改错了编译器立刻拦住你。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   1. 在 main **前面**写 `int 三倍(int x);`（声明）
//   2. 在 main **后面**写 `int 三倍(int x) { return x * 3; }`（定义）
//   3. main 里调用它并打印
//
// ⚠ 期望输出（一行）：
//
//      15
//
// ⚠ 这一课的检查会看**顺序**：声明必须排在定义前面。
//   如果两处调换了，或者少了一处，都算没过。

// 第 14 课：#define 与 const —— 给常量起个名字
//
// ─────────────────────────────────────────────────────
//  先介绍：不希望被改的值，怎么给它起名字
// ─────────────────────────────────────────────────────
//
// 程序里常有"固定不变"的值：圆周率、最大人数、税率……
// 直接写 `3.14159` 散落在各处，改的时候要找遍全文 —— 而且容易漏。
//
// 两种起名字的办法：
//
//   ① **#define**（预处理宏）—— 老办法，用得最广
//
//        #define 圆周率 3.14159
//        ↑ 没有等号！也没有分号！
//
//   ② **const**（真正的常量变量）
//
//        const double 圆周率 = 3.14159;
//
// ⚠⚠ 这一课要记住的坑：**#define 那行没有等号也没有分号。**
//
//     #define 圆周率 = 3.14159      ❌ 那个等号会被当成值的一部分
//     #define 圆周率 3.14159;       ❌ 分号也会被当成值的一部分
//     #define 圆周率 3.14159        ✅
//
//   为什么：`#define` 是**纯粹的文本替换**，不是变量声明。
//   编译器在编译前，把所有 `圆周率` 三个字**原样换成** `3.14159`。
//   所以那个分号会一起被换进去，变成 `printf("%f", 3.14159;);` ⇒ 语法错。
//
//   ⚠ 也正因为是文本替换，`#define` 后面**不写类型** —— 它没有类型。
//
// ⚠ 用哪个：#define 老、快、处处能用；const 有类型、能调试。
//   本课用 #define（读别人的 C 代码时见得最多）。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① #define：`#define 名字 值`，**两个空格之间**就是全部内容。
//
//      #define 圆周率 3.14159
//      #define 最大人数 40
//
//      ⚠ 习惯上名字用全大写（PI、MAX_N），中文也行 —— 这门课用中文。
//
//  ② 用它的地方和用变量一模一样：
//
//      printf("%.2f\n", 圆周率 * 2 * 2);       ⇒ 12.57
//
//  ③ const：像变量一样声明，但加个 const 表示"不许改"。
//
//      const double 圆周率 = 3.14159;
//
//      ⚠ const 那行**要分号、要等号、要类型** —— 和 #define 正好相反。
//        这两个记混是新手常态，所以下面坑 1 专门对比。
//
//  ④ 常量最实用的地方是"一个数字出现在很多地方"：
//
//      #define 每页条数 20
//      ...
//      printf("%d\n", 总数 / 每页条数);        /* 改的时候只改上面那一行 */
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      #define 圆周率 3.14159        /* ⚠ 没有等号，没有分号 */
//
//      int main(void) {
//          printf("%.2f\n", 圆周率 * 2 * 2);
//          return 0;
//      }
//
//  输出：
//
//      12.57
//
//  ⚠ #define 那一行写在 `#include` 后面、函数前面，这是惯例。
//    它跟着**文件**走：这个文件里后面所有用到 圆周率 的地方都会被换掉。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：给 #define 加上了等号或分号
//
//      错误写法：
//          #define 圆周率 3.14159;
//
//          int main(void) {
//              printf("%.2f\n", 圆周率 * 2 * 2);
//              return 0;
//          }
//
//      你会看到什么（gcc 原文，预处理之后分号就跑到表达式里去了）：
//
//          main.c:4:33: error: expected expression before ';' token
//              4 │     printf("%.2f\n", 圆周率 * 2 * 2);
//                │                                 ^
//
//      为什么：预处理阶段，`圆周率` 被**原样替换成** `3.14159;`，
//      那一行就变成了：
//          printf("%.2f\n", 3.14159; * 2 * 2);
//      表达式中间冒出一个分号 ⇒ 编译器当然看不懂。
//      ⚠ 最迷惑的地方：**报错行号指向使用它的那一行，不是 #define 那一行**。
//        所以读到"expected expression before ';' token"、
//        而那一行你左看右看都没有分号时，**往上找 #define**。
//      ⇒ 记住这一课的口诀：**#define 那行，只有名字和值，别的都没有。**
//      同理，写成 `#define 圆周率 = 3.14159` 的话，
//      替换出来是 `= 3.14159 * 2 * 2` ⇒ 同样在这一行报错。
//
//  ⚠ 坑 2：以为 #define 有类型、会做计算
//
//      错误写法：
//          #define 两倍(x) x * 2
//          printf("%d\n", 两倍(1 + 2));        /* 想算 (1+2)*2 = 6 */
//
//      你会看到什么：
//          ⚠ 编译零警告，输出 **5**（而不是 6）。
//
//      为什么：还是文本替换。`两倍(1 + 2)` 被换成：
//          1 + 2 * 2
//      按优先级先算乘法 ⇒ 1 + 4 = 5。
//      ⇒ 想写带参数的宏，每个参数都要加括号：
//          #define 两倍(x) ((x) * 2)
//      ⚠ 这一课不要求你写带参数的宏，但你**必须知道它是文本替换**，
//        否则以后看到别人的宏会完全猜错行为。
//      顺带一句：这也是为什么现代 C 更推荐 `const` 和普通函数 ——
//        它们**真的**有类型、真的会算。
//
//  ⚠ 坑 3：想改 const 常量的值
//
//      错误写法：
//          const double 圆周率 = 3.14159;
//          圆周率 = 3.14;              /* ⚠ 不许改 */
//
//      你会看到什么（gcc 原文）：
//
//          main.c:2:5: error: assignment of read-only variable '圆周率'
//
//      为什么：const 的字面意思就是"只读"。这一条是**编译期**就拦下来的，
//      比"运行时才发现常量被改了"好得多 —— 这正是 const 的价值。
//      ⚠ 顺带对比一下 #define 遇到同样的事：
//          #define 圆周率 3.14159
//          圆周率 = 3.14;
//      替换之后变成 `3.14159 = 3.14;` ⇒
//          error: lvalue required as left operand of assignment
//      （意思是"等号左边不是一个能装东西的容器"）。
//      ⇒ 两种写法的报错**完全不同**，但都在编译期拦住你。
//        这正好说明：#define 是"文本"，const 是"变量"。
//

// 第 15 课：指针与数组 —— 数组名是什么
//
// ─────────────────────────────────────────────────────
//  先介绍：数组名其实是一个地址
// ─────────────────────────────────────────────────────
//
//     int 数们[3] = {1, 2, 3};
//
// `数们` 这个名字，作为表达式的值，等于 **&数们[0]**（第一个元素的地址）。
// 所以下面两种写法**完全等价**：
//
//     数们[i]
//     *(数们 + i)
//
// 搞懂这一点，就明白了三件事：
//
//   ① 为什么数组作为参数传给函数时**会丢掉长度** ——
//      因为传进去的只是"第一个元素的地址"，末尾没有"到此为止"的信息。
//      ⇒ 所以第 09 课那个函数要另外传 `个数`。
//
//   ② 为什么函数里**能改到原数组** ——
//      因为它拿到的是地址，`数们[i] = x` 写的就是原来那块内存。
//      （对比第 11 课：普通 int 参数改不到外面，数组能改到 —— 就在这里。）
//
//   ③ 为什么 `数们[i]` 和 `*(数们 + i)` 一样：
//      `数们 + i` 是"往后数 i 个格子"的地址，`*` 再把里面的值取出来。
//
// ⚠ 参数写成 `int *数们` 或 `int 数们[]` **完全一样** ——
//   编译器把它们当同一件事。看到两种写法都别慌。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 两种下标写法，结果一模一样：
//
//      int 数们[3] = {1, 2, 3};
//      printf("%d\n", 数们[1]);            ⇒ 2
//      printf("%d\n", *(数们 + 1));        ⇒ 2      ⚠ 完全等价
//
//  ② 指针算术是"按格子走"，不是"按字节走"：
//
//      数们 + 1      往后**一个 int**（4 字节），不是 1 字节
//      数们 + 2      再往后一个 ⇒ 指向 数们[2]
//
//      ⚠ 编译器知道 `数们` 指向的是 int，所以它自动乘上 sizeof(int)。
//        这就是为什么"指针要分类型"。
//
//  ③ 参数两种写法等价，随你选：
//
//      void 全部加一(int *数们, int 个数) { ... }
//      void 全部加一(int 数们[], int 个数) { ... }      /* 同一件事 */
//
//  ④ **能改到原数组** —— 这是这一课要你亲手验证的事：
//
//      void 全部加一(int *数们, int 个数) {
//          for (int i = 0; i < 个数; i++) {
//              数们[i] += 1;               /* 改的是原数组 */
//          }
//      }
//
//  一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      void 全部加一(int *数们, int 个数) {
//          for (int i = 0; i < 个数; i++) {
//              数们[i] += 1;
//          }
//      }
//
//      int main(void) {
//          int 数据[] = {1, 2, 3};
//          全部加一(数据, 3);
//          for (int i = 0; i < 3; i++) {
//              printf("%d\n", 数据[i]);
//          }
//          return 0;
//      }
//
//  输出：
//
//      2
//      3
//      4
//
//  ⚠ 注意 main 里打印的是**它自己那个 数据** —— 它真的被改了。
//    对照第 11 课：`void 加倍(int x)` 就改不到。差别只有一个：
//    **这里传的是地址。**
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：以为 `数们 + 1` 是"地址加 1 个字节"
//
//      错误想法：
//          int 数们[3] = {1, 2, 3};
//          printf("%d\n", *(数们 + 1));        /* 有人以为是"第二个字节" */
//
//      你会看到什么：
//          输出 `2` —— 是**第二个元素**，不是某个被拆开的字节。
//
//      为什么会这样（这条专门用来纠正直觉的）：
//      指针算术的单位是"它指向的类型"。`数们` 是 `int *`，
//      所以 `+1` 就是往后一个 int（4 字节）。
//      ⚠ 这也解释了一个吓人的现象：如果你把 int 数组当 char 数组去走：
//
//          char *p = (char *)数们;
//          printf("%d\n", p[1]);           /* 第 1 个**字节** */
//
//      这会打印出整数 1 的某个字节（在小端机器上是 0），
//      而不是元素 2。**同一个地址，换个类型看，内容完全不同。**
//      ⇒ 类型不是装饰，它决定了"走一步有多远"。
//
//  ⚠ 坑 2：在函数里 sizeof 数组参数（第 09 课那个坑的另一面）

//          void 全部加一(int 数们[], int 个数) {

//          }

//
//          main.c:2:32: warning: 'sizeof' on array function parameter '数们' will return size of 'int *' [-Wsizeof-array-argument]

//                │                                ^
//          main.c:1:24: note: declared here
//              1 │ void 全部加一(int 数们[], int 个数) {
//                │                ~~~~^~~~~~
//
//      运行结果：n 恒等于 1（8 字节的指针 除以 4 字节的 int）。
//
//      为什么：`int 数们[]` 这个写法在编译器眼里**就是 `int *数们`** ——
//      参数里的 `[]` 是给你的**提示**，不是真的数组。
//      既然是"一个指针"，sizeof 当然只给你指针的大小。
//      ⚠ 这一条和坑 1 是同一件事的两面：**数组名到了函数里就只剩地址。**
//      ⇒ 所以这一课的函数签名里那个 `个数` 参数，**删不得**。

//          void 全部加一(int *数们, int 个数) {

//                  数们[i] += 1;
//              }
//          }

//          ⚠ **编译零警告。** 程序照跑，但最后一步写到了数组外面。
//          有时候什么都没发生（那块内存刚好没人用），
//          有时候会把你 main 里另一个变量悄悄改掉 —— 而报错的地方离这儿很远。
//
//      为什么：合法下标是 0 到 `个数 - 1`。`i <= 个数` 会访问 `数们[个数]`，
//      那已经是**下一个**地址了。
//      ⚠ 这里有个和"传值"不同的地方值得体会：
//        普通 int 函数改不到外面，所以它写坏了也只是自己倒霉；

// 第 16 课：综合练习 —— 一个小统计程序
//
// ─────────────────────────────────────────────────────
//  先介绍：这一课要把前面学的拼起来
// ─────────────────────────────────────────────────────
//
// 这一课不是新语法 —— 是把前面学的**拼起来**：
//
//     第 06 课  if            比大小
//     第 07 课  for           遍历
//     第 09 课  数组 + 个数参数
//     第 11 课  指针改参数     ← 这一课的重点
//
// 任务：写一个函数，一次算出**最大**和**最小**两个结果。
//
// ⚠ 难点在于：一个函数只能 `return` **一个**值。
//   要交回两个结果，就得用**指针参数** —— 把结果写进调用者给的地址里：
//
//     void 统计(int 数们[], int 个数, int *最大, int *最小) {
//         *最大 = ...;      ← 写进调用者的变量
//         *最小 = ...;
//     }
//
//   调用时：
//     int 大, 小;
//     统计(数据, 5, &大, &小);      ← 传地址
//     printf("%d %d\n", 大, 小);
//
// ⚠⚠ 三个必须注意的点：
//
//   ① **初值要从第一个元素起**，不能写 0：
//        int 大 = 0;                     ❌ 全负数时会返回 0
//        int 大 = 数们[0];               ✅
//
//   ② **个数为 0 要特判** —— 否则 `数们[0]` 就越界读了：
//        if (个数 <= 0) return;
//      这是 C 里最常见的崩溃来源之一。
//
//   ③ 写结果要写 **`*最大`**，不是 `最大`：
//        *最大 = 数们[i];                ✅
//        最大 = &数们[i];                ❌ 那是在改指针本身，外面看不到
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 这个函数有**四个参数**，每个都有明确分工：
//
//      数们   —— 数据（数组名 = 地址）
//      个数   —— 有几个元素（数组自己不知道，必须传）
//      最大   —— 一个 int 的地址，用来"交回"最大值
//      最小   —— 一个 int 的地址，用来"交回"最小值
//
//      void 统计(int 数们[], int 个数, int *最大, int *最小)
//
//  ② 函数体：先特判空数组，再从第一个元素起头，然后遍历比较。
//
//      void 统计(int 数们[], int 个数, int *最大, int *最小) {
//          if (个数 <= 0) {
//              return;                     /* ⚠ 先挡住空数组 */
//          }
//          int 大 = 数们[0];               /* ⚠ 从第一个元素起，不是 0 */
//          int 小 = 数们[0];
//          for (int i = 1; i < 个数; i++) {
//              if (数们[i] > 大) 大 = 数们[i];
//              if (数们[i] < 小) 小 = 数们[i];
//          }
//          *最大 = 大;                     /* ⚠ 星号：写进调用者的变量 */
//          *最小 = 小;
//      }
//
//      ⚠ 循环从 `i = 1` 开始，因为 `i = 0` 那个已经当初始值用过了。
//
//  ③ 调用端（你自己不写 main，但一定要会读这个形状）：
//
//      int 数据[] = {3, 1, 4, 1, 5};
//      int 大, 小;
//      统计(数据, 5, &大, &小);            /* ⚠ 两个 & */
//      printf("%d %d\n", 大, 小);          ⇒ 5 1
//
//  ④ 为什么非得这样绕一圈：因为 C 的 `return` 只能交回**一个**值。
//     想交回两个，就得让函数**往你给的地址里写**。
//     这就是第 11 课那个 `&` 和 `*` 在真实场景里的用途。
//
//  ⚠ 顺带说一个真实项目的做法：参数多了以后，人们常把"结果"打包成结构体
//    再传指针（第 12 课 + 第 11 课的组合）。这一课先用两个 int 指针。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：初值写成 0（全负数就错了）
//
//      错误写法：
//          int 大 = 0;
//          int 小 = 0;
//          for (int i = 0; i < 个数; i++) { ... }
//
//      你会看到什么：
//          ⚠ **编译零警告。** 正数数组跑得好好的，
//          一旦数据全是负数（比如 -5, -1, -9），最大值就变成 **0** ——
//          一个根本不在数组里的数。
//
//      为什么：`0` 比所有负数都大。你把"大"的起点定得比所有候选者还高，
//      当然就没有任何候选者能替换它。
//      ⇒ 唯一正确的起点是**数据里的第一个元素**：`int 大 = 数们[0];`
//        这样"比较"从第二轮开始，而起点一定是真数据。
//      ⚠ 同样的错还有最小值写成 `int 小 = 999999;` —— 数据超过这个数就露馅。
//        用第一个元素当起点，就永远不用猜"够不够大"。
//
//  ⚠ 坑 2：个数为 0 时去读 数们[0]
//
//      错误写法：
//          int 大 = 数们[0];               /* ⚠ 没有特判 */
//          int 小 = 数们[0];
//
//      你会看到什么：
//          ⚠ **编译零警告。** 正常数据下完全没问题，
//          但如果调用者传了 `个数 = 0`（空数组），这一行就在读**数组外面**的内存：
//          运气好读到一个垃圾值，运气不好直接崩（Windows 上闪一下、退出码不是 0）。
//
//      为什么：`数们[0]` 不检查任何范围（第 09 课）。
//      "个数是 0"在 C 里是一个非常容易出现的状态 —— 数据文件是空的、
//      用户什么都没输入、筛选之后一个都没剩下……都会走到这里。
//      ⇒ 函数一开始就挡住它：
//          if (个数 <= 0) {
//              return;                     /* 什么都不写，调用者自己保证 */
//          }
//      ⚠ 注意用 `<= 0` 而不是 `== 0`：负数个数是"更严重的错误"，
//        一并挡住更安全。
//
//  ⚠ 坑 3：写结果时漏了星号，或者漏了 &
//
//      错误写法（函数里漏星号）：
//          void 统计(int 数们[], int 个数, int *最大, int *最小) {
//              ...
//              最大 = &数们[0];            /* ⚠ 改的是局部指针，外面看不到 */
//          }
//
//      你会看到什么：
//          ⚠ **编译零警告**（这是最气人的地方：类型都对得上）。
//          调用者那边的 `大` 从来没被写过，打印出来是**随机垃圾值**。
//
//      为什么：`最大` 是"一个装着地址的局部变量"，`*最大` 才是"那个地址上的东西"。
//      `最大 = ...` 只是让这个局部变量指向别处，函数一返回它就没了。
//      ⇒ 对照记：#define 那句口诀在这里也适用 ——
//        **要改外面，就写 `*`。**
//
//      另一种错法（调用端漏 &）：
//
//          统计(数据, 5, 大, 小);          /* ⚠ 少了两个 & */
//
//      你会看到什么：
//
//          main.c:5:22: error: passing argument 3 of '统计' makes pointer from integer without a cast [-Wint-conversion]
//              5 │     统计(数据, 5, 大, 小);
//                │                   ^~
//          main.c:1:6: note: expected 'int *' but argument is of type 'int'
//
//      运行时多半直接崩溃 —— 因为函数会把"大当前的垃圾值"当地址去写。
//      ⇒ 看到 `makes pointer from integer`，先补 `&`。
//

//

// 第 17 课：switch —— 一个值对上好几个可能
//
// ─────────────────────────────────────────────────────
//  先介绍：和 if 是两种不同的东西
// ─────────────────────────────────────────────────────
//
//     if      —— **判断条件**（可以是很复杂的表达式）
//     switch  —— **把同一个值和一堆候选值比相等**
//
//         switch (月) {
//             case 3:
//                 ...
//                 break;
//             case 4:
//             case 5:
//                 ...
//                 break;
//             default:
//                 ...
//         }
//
// 用哪个？一条实用判据：
//
//     「等于…等于…等于…」        → switch 更清楚
//     「大于、小于、并且、或者」   → 只能用 if
//
// ⚠ switch 里**只能比整数和字符**，不能比字符串、不能比小数。
//   （`case "你好":` 编译不过 —— 字符串比较要用 strcmp，第 10 课讲的那件事。）
//
//  ⚠⚠ 这一课唯一要记住的坑：break
//
// **switch 不会自己停下来。** 一个 case 做完了，它会**继续往下做下一个 case**。
// 这叫「贯穿」（fallthrough），是 C 里最坑人的设计之一。
//
//     switch (2) {
//         case 1: printf("一\n");        // 不执行
//         case 2: printf("二\n");        // 执行 —— 从这里进去
//         case 3: printf("三\n");        // **也执行！** 因为上面没 break
//     }
//
//     实际输出：二、三          ← 不是你以为的"只有二"
//
// ⇒ **每个 case 末尾几乎都要写 break;**，忘了它就等于让程序"漏"下去。
//
// ⚠ 但贯穿**有时候是故意的** —— 而且这是这一课要你用的写法。
//   想表达"3、4、5 都算春天"，可以叠着写：
//
//     case 3:
//     case 4:
//     case 5:
//         return "春";          ← 三个标签共用同一段代码
//
//   这比写逻辑或运算符（月 == 3 或 月 == 4 或 月 == 5）短，也不容易漏掉一个。
//   ⇒ 所以贯穿既是坑、也是工具 —— **关键是你要知道自己有没有用它。**
//
// ⚠ 别忘 default：所有 case 都不匹配时走它。
//   没有 default 又不匹配 —— 什么都不做，而你要自己保证"什么都不做"是对的。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 基本形状：`switch (一个整数表达式)` + 一堆 `case 常量:`。
//
//      switch (月) {
//          case 1:
//              printf("一月\n");
//              break;                  /* ⚠ 停下 */
//          case 2:
//              printf("二月\n");
//              break;
//          default:
//              printf("不认识\n");
//              break;
//      }
//
//  ② case 后面只能跟**编译期常量**：整数、字符字面量。
//
//      case 3:        ✅ 整数
//      case 'A':      ✅ 字符（字符本质上是整数编码）
//      case 变量:     ❌ 变量不是常量
//      case 3.5:      ❌ 小数不行（坑 3）
//      case "春":     ❌ 字符串不行（坑 2）
//
//  ③ **故意贯穿**：几个标签叠在一起，共用同一段代码。
//     这是这一课要你用的写法：
//
//      case 3:
//      case 4:
//      case 5:
//          return "春";
//
//      ⚠ 前两个 case 后面**什么都不写**（不写 break）—— 这是"故意的"。
//        但最后一个（case 5）处理完必须 break 或 return，否则会漏到夏天去。
//
//  ④ 在函数里，`return` 本身就能结束 switch（不需要再补 break）：
//
//      char* 季节(int 月) {
//          switch (月) {
//              case 3: case 4: case 5:
//                  return "春";        /* return 已经终止了整个函数 */
//              ...
//          }
//      }
//
//  一个完整的、能跑的贯穿例子：
//
//      #include <stdio.h>
//
//      int main(void) {
//          int 月 = 2;
//          switch (月) {
//              case 1: printf("一\n");
//              case 2: printf("二\n");
//              case 3: printf("三\n");
//          }
//          return 0;
//      }
//
//  真实输出（⚠ 注意是两行）：
//
//      二
//      三
//
//  ⚠ 这就是贯穿。把 `case 2:` 那行末尾补上 `break;`，输出才会只剩「二」。
//    这个 10 秒钟的实验，比看十遍解释都管用 —— **建议你真的跑一遍。**
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：忘了 break —— 贯穿到你没想要的地方
//
//      错误写法：
//          switch (等级) {
//              case 3: printf("优\n");
//              case 2: printf("良\n");
//              case 1: printf("及格\n");
//          }
//
//      你会看到什么：
//          ⚠ gcc 通常**一声不吭**（除非打开 -Wimplicit-fallthrough）。
//          等级 3 的时候，三行**全都**打印出来：优、良、及格。
//
//      为什么：switch 的真实语义是"**跳到**匹配的那个标签，然后一直往下执行"，
//      不是"只执行那一段"。`break` 才是真正的"到此为止"。
//      ⇒ 规矩：**每个 case 末尾都写 break**，
//        除非你**故意**贯穿 —— 而故意的时候，最好写一行注释说明：
//            case 3:                 /* ⚠ 故意贯穿，3/4/5 同一段 */
//            case 4:
//            case 5:
//        这样读代码的人（包括三个月后的你）才不会以为是漏写。
//
//  ⚠ 坑 2：拿字符串当 case
//
//      错误写法：
//          char* 季节(int 月) {
//              switch (月) {
//                  case "春":              /* ⚠ 字符串 */
//                      return "春";
//              }
//              return "?";
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:3:9: error: pointers are not permitted as case values
//              3 │         case "春":
//                │         ^~~~
//
//      为什么：`"春"` 在 C 里是一个**指针**（字符串第一个字符的地址），
//      而 case 标签要求"编译期就能算出来的整数"。
//      两个字符串即使内容一样，地址也不同 —— 所以"用字符串做 case"这件事
//      在 C 里从根上就不成立。
//      ⇒ 要比字符串，只能用 `strcmp`（第 10 课）配 if：
//          if (strcmp(名字, "春") == 0) { ... }
//

// 第 18 课：while 与 do-while —— 不知道要做几次的时候
//
// ─────────────────────────────────────────────────────
//  先介绍：for 和 while 什么时候用哪个
// ─────────────────────────────────────────────────────
//
//     第 07 课的 for   —— **你知道要做几次**
//                          "从 1 加到 100"、"遍历这个数组"
//
//     这一课的 while  —— **你不知道要做几次**，
//                          只知道"什么时候该停"
//                          "一直取数字，直到取完为止"
//
// 三条循环长得像，各有各的用处：
//
//     while (条件) { ... }        先判断，再做。**可能一次都不做**
//     do { ... } while (条件);    先做一次，再判断。**至少做一次**
//     for (...) { ... }           三段式。次数明确时最清楚
//
//  一、while 的形状
//
//     初始化;
//     while (条件) {
//         做事;
//         **改变量**;        ← ⚠⚠ 这一行忘了就是死循环
//     }
//
// ⚠⚠ **while 最常见的错：忘了在循环体里改变量。**
//
//     int i = 0;
//     while (i < 5) {
//         printf("%d\n", i);
//         /* 忘了 i++ ⇒ i 永远是 0 ⇒ 条件永远成立 ⇒ 死循环 */
//     }
//
//   这条和 for 的区别很值得体会：
//     for 把"改变量"写在**括号里**，想忘都忘不了；
//     while 把"改变量"丢在**循环体里**，忘了也没人拦你，程序就那么卡住。
//   ⇒ 写 while 的时候，先问自己一句：**"哪个变量在变？它在哪里变？"**
//
//  二、do-while 的形状（末尾那个分号不能少）
//
//     do {
//         做事;
//     } while (条件);        ← ⚠ 末尾**必须**有分号
//
//  它和 while 唯一的差别：**先做一次，再判断**。
//  所以"条件一开始就不成立"的时候，while 一次都不做，do-while 会做一次。
//
//      int i = 100;
//      while (i < 5) { printf("while 跑了\n"); }      // 一次都不跑
//      do { printf("do-while 跑了\n"); } while (i < 5); // 跑一次
//
//  什么时候真的需要它？**"至少得做一次"的场合**：
//  菜单（至少显示一次）、读输入（至少读一次才知道对不对）、
//  重试（至少试一次）。这些用 while 写都要在循环外面先抄一遍，很别扭。
//
//  三、这一课的例子：数位和
//
//  算 1234 的各位之和（1+2+3+4 = 10）。你为什么**不知道要做几次**？
//  因为 5 是一位数、12345678 是八位数 —— 循环次数取决于输入。
//
//  两个工具（都是整数运算，正好复习第 03 课）：
//
//     数 % 10    取最后一位      1234 % 10  = 4
//     数 / 10    把最后一位去掉   1234 / 10  = 123   （整数除法，小数被丢掉）
//
//  于是循环体是：
//
//     和 += 数 % 10;        拿走最后一位，加到和里
//     数 /= 10;             把最后一位扔掉
//                            ↑ 这就是"让循环往前走"的那一步
//
//  什么时候停？**数变成 0 的时候**（没位数可取了）。
//
//  ⚠⚠ 这里有个边界要想清楚：**输入是 0 怎么办？**
//
//     while (数 > 0) {...}      ⇒ 0 一次都不进循环 ⇒ 返回 0     ✅ 对
//     do { ... } while (数 > 0); ⇒ 会先做一次，返回 0 也是 0    ✅ 也对
//   这一课要你**两种都写一遍**，然后自己体会：这个题目里它们结果一样，
//   但换个题目（比如"至少问一次用户"）就不一样了。
//
// ⚠ 还有个负数问题：`-123 % 10` 在 C 里是 **-3**（不是 3）。
//   检查只喂正数，所以不用管；但你要知道这件事存在 ——
//   真实项目里输入永远可能带负号。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① while 的标准骨架：**初始化在循环外，改变量在循环内。**
//
//      int i = 0;                  /* ① 初始化 */
//      while (i < 5) {             /* ② 每轮先判断 */
//          printf("%d\n", i);
//          i++;                    /* ③ ⚠ 改变量 —— 忘了就是死循环 */
//      }
//
//  ② do-while：先做，后判断。末尾有分号。
//
//      int i = 0;
//      do {
//          printf("%d\n", i);
//          i++;
//      } while (i < 5);            /* ⚠ 分号在这里 */
//
//  ③ 数位和（这一课的两道题都在算它）：
//
//      1234 ── % 10 ──→ 拿到 4，加进和里
//           ── / 10 ──→ 变成 123，继续
//      一直做到数变成 0
//
//      int 和 = 0;
//      while (数 > 0) {
//          和 += 数 % 10;
//          数 /= 10;               /* ⚠ 让循环往前走的一步 */
//      }
//
//  ④ 一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 数位和(int 数) {
//          int 和 = 0;
//          while (数 > 0) {
//              和 += 数 % 10;
//              数 /= 10;
//          }
//          return 和;
//      }
//
//      int main(void) {
//          printf("%d\n", 数位和(1234));       ⇒ 10
//          printf("%d\n", 数位和(7));          ⇒ 7
//          printf("%d\n", 数位和(0));          ⇒ 0
//          printf("%d\n", 数位和(999));        ⇒ 27
//          return 0;
//      }
//
//  ⚠ 注意 `数 /= 10` 用的是**整数除法**：1234 / 10 = 123（小数被丢掉）。
//    这正是我们要的效果 —— 第 03 课那个"丢小数"的坑，在这里变成了工具。
//
//  ⚠ `数位和(0)` 返回 0：条件是 `数 > 0`，一开始就是假，一次都不进循环。
//    如果这题的语义要求"0 也算一位"，那 while 的写法就得改 ——
//    但按本课的约定（0 → 0），它是对的。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：忘了改变量 —— 死循环
//
//      错误写法：
//          int i = 0;
//          while (i < 3) {
//              printf("%d\n", i);
//              /* ⚠ 忘了 i++ */
//          }
//
//      你会看到什么：
//          ⚠ **编译零警告、零报错。** 程序跑起来之后**停不下来**，
//          屏幕上 0 一行一行飞快地刷下去，界面卡住，
//          只能强制关掉（Ctrl+C 或者关窗口）。
//
//      为什么：`i` 永远是 0，`0 < 3` 永远成立 ⇒ 循环永远进行。

//      ⇒ **写 while 的第一件事**：找出"哪个变量在变"，确认它**真的在变**。
//        在本课的题目里，那个变量是 `数`，改变它的那一行是 `数 /= 10;`。
//      ⚠ 检查这类题时，如果超过几秒钟还没结果，八成就是死循环 ——
//        先去看那一行还在不在。
//
//  ⚠ 坑 2：do-while 末尾漏了分号
//
//      错误写法：
//          int 至少做一次(int 数) {
//              int 和 = 0;
//              do {
//                  和 += 数 % 10;
//                  数 /= 10;
//              } while (数 > 0)         /* ⚠ 少了分号 */
//              return 和;
//          }
//
//      你会看到什么（gcc 原文）：
//
//          main.c:6:21: error: expected ';' before 'return'
//              6 │     } while (数 > 0)
//                │                     ^
//                │                     ;
//              7 │     return 和;
//                │     ~~~~~~
//
//      为什么：`} while (条件)` 之后，这条语句还没结束 —— 它和普通语句一样要分号。
//      少了它，编译器读到 `return` 时才发现不对劲。
//      ⚠ 报错在**第 6 行**（就是那一行本身），而且 gcc 已经把该补的 `;`
//        给你画出来了。这是 C 里最"友好"的一类报错。
//
//  ⚠ 坑 3：拿负数的余数当真
//
//      错误写法（本课不需要处理，但真实项目里一定会遇到）：

//
//      为什么：C 的整数除法是"向零取整"，余数的符号**跟着被除数**。

// 第 19 课：递归 —— 函数调用自己
//
// ─────────────────────────────────────────────────────
//  先介绍：一个函数可以调用它自己
// ─────────────────────────────────────────────────────
//
//     阶乘 n! = 1 × 2 × 3 × ... × n
//
//     用循环写（你已经会了）：
//         int 结果 = 1;
//         for (int i = 2; i <= n; i++) 结果 *= i;
//
//     用递归写：
//         n! = n × (n-1)!        ← 把问题**变小一号**，再问自己
//
//         int 阶乘(int n) {
//             if (n <= 1) return 1;      ← ① 什么时候停
//             return n * 阶乘(n - 1);    ← ② 用"小一号的答案"拼出答案
//         }
//
//  ⚠⚠ 递归必须有的两样东西
//
//   ① **基准情形**（base case）—— 什么时候**不再**调用自己，直接给答案。
//        上面那行 `if (n <= 1) return 1;` 就是它。
//
//   ② **每次都在变小** —— 参数必须朝着基准情形走。
//        `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1。
//
//   ⚠⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看。**
//
//      int 阶乘(int n) {
//          return n * 阶乘(n - 1);      /* 没有基准情形 */
//      }
//
//   它会一直调用下去，每调一次就在内存里压一层（叫"调用栈"），
//   直到把栈用完 ⇒ 崩溃。这个错叫**栈溢出**（stack overflow）。
//
//   ⚠ 在 Windows 上你看到的多半是程序直接消失、退出码不是 0，
//     而不是一句好看的报错。**这就是递归最需要小心的地方。**
//
//  为什么值得学：有些问题用递归写短得多
//
//  阶乘用循环写就挺好，递归没占到便宜。但下面这类问题：
//
//     · 文件夹里还有文件夹，一层套一层 —— 怎么数所有文件？
//     · 一棵树，每个节点还有子树 —— 怎么遍历？
//     · 汉诺塔、走迷宫、表达式求值
//
//  **它们本身就是递归定义的**，用循环写要自己造一个"栈"来记住位置，
//  用递归写则几乎是直译。这一课先在小问题上把套路练熟。
//
//  ⚠ 一个反例：斐波那契**不该**用这种递归写
//
//      fib(n) = fib(n-1) + fib(n-2)
//
//  按这个式子直接写成递归：
//
//      int 斐波那契(int n) {
//          if (n <= 1) return n;
//          return 斐波那契(n - 1) + 斐波那契(n - 2);   ← 能算对，但极慢
//      }
//
//  ⚠⚠ 它**能算出正确答案**，但算 fib(40) 要调用自己上**亿**次。
//     为什么：算 fib(5) 要 fib(4) 和 fib(3)，而 fib(4) 又要 fib(3) ——
//     **同一个 fib(3) 被重复算了无数遍**。这叫"重叠子问题"。
//
//  这一课仍然让你这么写，因为**它最能训练"递归思维"**，
//  而且检查只喂到 n ≤ 20（够快）。但你要记住：
//
//     ⚠ **能写出递归，不等于该用递归。**
//       判断依据是"有没有大量重复计算"，不是"写起来短不短"。
//  （正式的做法叫"动态规划"或"记忆化"：把算过的答案存起来，
//    下次直接查表。那是后面的内容。）
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 递归函数的**四行套路**，抄下来照着填：
//
//      int 函数(int n) {
//          if (n <= 0) {           /* ① 基准情形：什么时候停 */
//              return 0;           /*    直接给答案 */
//          }
//          /* ② 把问题变小一号，用它的答案拼出我的答案 */
//          return ... 函数(n - 1) ...;
//      }
//
//  ② 阶乘：
//
//      int 阶乘(int n) {
//          if (n <= 1) {
//              return 1;                       /* 0! 和 1! 都是 1 */
//          }
//          return n * 阶乘(n - 1);             /* n! = n × (n-1)! */
//      }
//
//      ⚠ 基准情形用 `n <= 1` 而不是 `n == 1`：这样 0 和负数也被挡住了，
//        不会掉进无限递归。
//
//  ③ 斐波那契：
//
//      int 斐波那契(int n) {
//          if (n <= 0) return 0;               /* fib(0) = 0 */
//          if (n == 1) return 1;               /* fib(1) = 1 */
//          return 斐波那契(n - 1) + 斐波那契(n - 2);
//      }
//
//      ⚠ 它**有两个**基准情形（n=0 和 n=1）。少写一个，
//        n=0 时就会去调 `斐波那契(-1)` 和 `斐波那契(-2)` ⇒ 越陷越深 ⇒ 栈溢出。
//
//  ④ 一个完整的、能跑的例子：
//
//      #include <stdio.h>
//
//      int 阶乘(int n) {
//          if (n <= 1) {
//              return 1;
//          }
//          return n * 阶乘(n - 1);
//      }
//
//      int main(void) {
//          printf("%d\n", 阶乘(0));        ⇒ 1
//          printf("%d\n", 阶乘(1));        ⇒ 1
//          printf("%d\n", 阶乘(5));        ⇒ 120
//          printf("%d\n", 阶乘(10));       ⇒ 3628800
//          return 0;
//      }
//
//  ⑤ 心里演算一遍 `阶乘(3)`（这一步做了，递归就懂了）：
//
//      阶乘(3) = 3 × 阶乘(2)
//              = 3 × (2 × 阶乘(1))
//              = 3 × (2 × 1)             ← 碰到基准情形，开始往回算
//              = 3 × 2
//              = 6
//
//      ⚠ 注意顺序：它**一路往下钻到 1**，才开始真正做乘法。
//        递归是"先欠着，最后一起还"。
//
//  ⚠ 递归的深度就是"欠了多少层"。每欠一层都要占一点内存（栈帧），
//    所以递归深度太大就会栈溢出 —— 这是它的硬限制，不是性能问题。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：忘了基准情形 —— 栈溢出，程序直接消失
//
//      错误写法：
//          int 阶乘(int n) {
//              return n * 阶乘(n - 1);         /* ⚠ 没有 if 停住 */
//          }
//
//      你会看到什么：
//          ⚠ **编译完全通过，一个警告都没有**（编译器看不出这里有问题）。
//          运行时程序崩溃，在 Windows 上通常就是**窗口一闪、什么都不打印**，
//          退出码不是 0。你不会看到 "stack overflow" 这样的漂亮提示。
//
//      为什么：每调用一次自己，就在调用栈上压一层（记住"回来之后要乘 n"）。
//      栈的大小是固定的（Windows 默认约 1 MB），压满了就撞墙。
//      撞墙的后果叫**未定义行为** —— 可能是立刻崩，也可能是别的怪事。
//      ⇒ 写递归时**第一行先写基准情形**，别等写完主体再回头补。
//      ⚠ 这也是递归和循环最大的区别：
//        循环忘了改变量是"卡住"（还能 Ctrl+C），
//        递归忘了基准情形是"直接死"。
//
//  ⚠ 坑 2：基准情形写得太窄 —— 漏掉一个边界就掉进负数深渊
//
//      错误写法（斐波那契只写了一个基准情形）：
//          int 斐波那契(int n) {
//              if (n == 1) {
//                  return 1;                   /* ⚠ 只挡住了 1 */
//              }
//              return 斐波那契(n - 1) + 斐波那契(n - 2);
//          }
//
//      你会看到什么：
//          斐波那契(2) 看起来正常（1+1 里两个分支都会走到 1），
//          但 斐波那契(0) 会去算 斐波那契(-1) + 斐波那契(-2)，
//          然后 -2、-3、-4……**永远到不了 1** ⇒ 栈溢出、程序崩掉。
//
//      为什么：`n == 1` 只覆盖了一个点，而参数是会往**两个方向**跑的
//      （-1 和 -2 都往下走）。
//      ⇒ 基准情形要写成**范围**，把所有"不该继续递归"的输入一起挡住：
//          if (n <= 0) return 0;               /* 0 和所有负数 */
//          if (n == 1) return 1;
//      ⚠ 本课的检查会喂 n = 0（斐波那契(0) 应该是 0），
//        所以这个坑一定会被抓到。
//
//  ⚠ 坑 3：参数没有变小（或者变小了又变大）
//
//      错误写法：
//          int 阶乘(int n) {
//              if (n <= 1) {
//                  return 1;
//              }
//              return n * 阶乘(n);             /* ⚠ 传的还是 n */
//          }
//
//      你会看到什么：
//          ⚠ 零警告。程序崩溃（栈溢出），症状和坑 1 一模一样。
//
//      为什么：`阶乘(n)` 调用 `阶乘(n)` —— 参数没变，基准情形永远碰不到。
//      基准情形写得再对也没用，因为**根本走不到那儿**。
//      ⇒ 判据是：**每次调用，参数一定要离基准情形更近一步。**
//        阶乘写 `n - 1`（在减小，靠近 `<= 1`）✅
//        斐波那契写 `n - 1` 和 `n - 2`（都在减小）✅
//      ⚠ 还有一种更隐蔽的错：`阶乘(n - 1)` 写成了 `阶乘(n + 1)`（符号写反）。
//        它"看起来在变"，其实在**远离**基准情形 —— 一样崩。
//        所以别只看"参数变了没有"，要看"**方向对不对**"。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   写两个**递归**函数（不许用循环）：
//
//     1. int 阶乘(int n)          0! 和 1! 都是 1

//

//     少了任何一样，检查会看到程序崩溃。
