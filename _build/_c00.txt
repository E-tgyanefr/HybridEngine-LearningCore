@@@ 00_跑通第一个程序
标题|第 00 课：跑通第一个程序 —— 把工具链装好
要求|1. 确认 gcc 和 dotnet 都装好（本课会真的去调它们）
要求|2. 搞清楚为什么 C 要"先编译、再运行"两步
要求|3. 让 gcc 报一次错，并且学会从第一条 error 读起
模板|// 第 00 课：跑通第一个程序 —— 把工具链装好
模板|// ─────────────────────────────────────────────────────
模板|//  怎么读这一课
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//   先从头读一遍讲解，再照着最后的「轮到你了」写。
模板|//   卡住了看答案（先自己写一遍）—— 命令在「怎么自己测」那一节。
模板|// ─────────────────────────────────────────────────────
模板|//  这一课你会学到
模板|// ─────────────────────────────────────────────────────
模板|//    把编译器装好、跑通第一个程序，以及怎么读编译器的第一条报错
模板|//
模板|//  需要先会
模板|//    没有 —— 这是第一课
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：为什么这一课不教语法
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠⚠ 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
模板|//
模板|//    为什么把它排在第 00 课：
模板|//      C / C++ / Java / C# 四门课都要**先把代码编译成可执行文件**，
模板|//      而这需要外部工具链。调研过的主流教程里，"卡在装工具"是
模板|//      **放弃率最高的一步** —— 比指针、比虚函数都更容易让人走掉。
模板|//      所以它值得单独占一课，而不是塞在第一课的注释里。
模板|//
模板|//  一、需要什么（两样，都是免费的）
模板|//
模板|//  ① .NET SDK  —— 它是"课程运行器"。这门课用它来**编译并运行你的 C 代码**，
模板|//                 所以你不需要自己敲 gcc 命令，它会替你敲。
模板|//
模板|//        winget install Microsoft.DotNet.SDK.8
模板|//
模板|//     或者去 https://dotnet.microsoft.com/download 下。
模板|//     ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
模板|//
模板|//  ② gcc       —— 真正的 C 编译器。
模板|//
模板|//        winget install BrechtSanders.WinLibs.POSIX.UCRT
模板|//
模板|//     装完**重开一个窗口**（让 PATH 生效），然后敲：
模板|//
模板|//        gcc --version
模板|//
模板|//     能看到版本号就成了。
模板|//
模板|//  ⚠ 装完必须重开窗口：PATH 是"进程启动时"读进去的，
模板|//    已经开着的窗口里永远看不到新装的东西 —— 这是最常见的"我明明装了"。
模板|//
模板|//  二、C 为什么要"两步"：先编译、再运行
模板|//
模板|//  Python 里你写 `python 脚本.py`，它**一边读一边执行**。
模板|//  C 不是这样。C 的流程是：
模板|//
模板|//      你写的 hello.c
模板|//          ↓  gcc hello.c -o hello.exe     ← 第一步：编译
模板|//      hello.exe（机器码，人看不懂）
模板|//          ↓  双击 / 敲 hello.exe           ← 第二步：运行
模板|//      屏幕上出现结果
模板|//
模板|//  中间那个 hello.exe 是**真正的程序**：它不再需要 gcc，
模板|//  也不需要你那份 .c 文件，拷给别人就能跑。
模板|//
模板|//  代价是：**你写的代码要先被人（编译器）检查一遍**。
模板|//  语法有错，编译器当场拒绝，连失败的程序都不给你。
模板|//  所以 C 的报错比 Python 多，但**很多错在运行之前就被拦住了** ——
模板|//  这是编译型语言换来"跑得快"所付的钱。
模板|//
模板|//   这门课的流程是：
模板|//
模板|//        写代码  →  检查  →  自动编译 + 自动运行 + 看结果
模板|//
模板|//    "编译"和"运行"两步是**替你做的**，但你必须知道它们在发生 ——
模板|//    不然你读不懂报错，也解释不了"为什么我的程序跑不起来"。
模板|//
模板|//  三、这一课唯一要练的手艺：读第一条 error
模板|//
模板|//  编译器的报错长这样（这是**故意写错**的代码）：
模板|//
模板|//      hello.c:3:1: error: expected ';' before '}' token
模板|//         3 │ }
模板|//           │ ^
模板|//
模板|//  拆开看就四样东西：
模板|//
模板|//      hello.c  :  哪个文件
模板|//      3        :  **第几行**        ← 先看这个
模板|//      1        :  第几列（次要）
模板|//      error    :  严重程度
模板|//
模板|//   **两条铁律**：
模板|//
模板|//   ① **只看第一条 error。** 后面那几十条多数是它引起的连锁反应 ——
模板|//      一个没写对的括号能让编译器抱怨一整屏。改完第一条再重新编译。
模板|//
模板|//   ② **报错行号常常要往上多看一行。** 编译器是在读到"它不认识的
模板|//      东西"时才报错的，而那个东西往往是**上一行漏了分号**造成的。
模板|//      上面那个例子说"第 3 行 } 前面少了分号"，真正该补分号的是第 2 行。
模板|//
模板|//  error 和 warning 是两回事：
模板|//
模板|//      error    —— 编译**停了**，没有可执行文件产生
模板|//      warning  —— 编译**继续**，但它在提醒你"这里很可能是 bug"
模板|//
模板|//  ⚠⚠ **不要忽略 warning。** "能编译"不等于"能跑对"。
模板|//     这门课后面会专门讲几个"只给 warning、但结果一定是错的"的坑
模板|//     （比如 scanf 忘了写 &）。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  最小的 C 程序只有五行，记住它，以后每课都从它开始：
模板|//
模板|//      #include <stdio.h>          /* 头文件：printf 需要它 */
模板|//
模板|//      int main(void) {            /* 程序从这里开始跑 */
模板|//          printf("你好\n");       /* 打印一行 */
模板|//          return 0;               /* 告诉系统"正常结束" */
模板|//      }
模板|//
模板|//  编译它（这条命令你在命令行里敲一次，体会一下"两步"）：
模板|//
模板|//      gcc -std=c11 -Wall hello.c -o hello.exe
模板|//
模板|//   这两个旗标要说一下：
模板|//      -std=c11   用 C11 标准（就是这门课用的标准）
模板|//      -Wall      打开常用警告（打开它，你才能看到 scanf 忘 & 这类提醒）
模板|//
模板|//  运行它：
模板|//
模板|//      .\hello.exe                 （PowerShell 里要写 .\ ，不能只写 hello）
模板|//
模板|//  输出：
模板|//
模板|//      你好
模板|//
模板|//  想知道程序"是不是正常结束"，看退出码：
模板|//
模板|//      echo $LASTEXITCODE          ⇒ 0      0 就是成功
模板|//
模板|//  故意让它失败（比如把 return 0; 改成 return 3;），退出码就变成 3。
模板|//  这一课不要求你背命令，但要知道**界面上那个「检查」按下去时，
模板|//  背后发生的正是上面这三件事**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  ⚠ 坑 1：装完 gcc 不重开窗口 ⇒ 一直报"找不到 gcc"
模板|//
模板|//      错误写法（在**装之前**就打开的那个窗口里）：
模板|//          gcc --version
模板|//
模板|//      你会看到什么：
模板|//          gcc : 无法将"gcc"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
模板|//
模板|//      为什么：PATH 是**进程启动时**读进内存的。你那扇旧窗口里存的是
模板|//      装 gcc 之前的老 PATH，所以它永远看不见新装的东西。
模板|//      ⇒ 关掉窗口，重新开一个。
模板|//
模板|//  ⚠ 坑 2：装的是 .NET **Runtime**，不是 SDK
模板|//
模板|//      症状：gcc --version 有版本号，但一按「检查」就说找不到 dotnet，
模板|//      或者报 "找不到任何已安装的 .NET SDK"。
模板|//
模板|//      为什么：Runtime 只能**运行**已经编好的程序，里面**没有编译器**。
模板|//      这门课要用 dotnet 去调 gcc、还要编译课程本身 ⇒ 必须是 SDK。
模板|//      验一下：dotnet --list-sdks 应该列出版本号；只装 Runtime 时这一行是空的。
模板|//
模板|//  ⚠ 坑 3：把编译器的 error 当成"课程坏了"
模板|//
模板|//      你会看到什么（这是真的报错原文）：
模板|//
模板|//          main.c:5:13: error: expected ';' before '}' token
模板|//              5 │     return 0
模板|//                │             ^
模板|//                │             ;
模板|//
模板|//      为什么：编译器在 `return 0` 后面期待一个分号，却先看到了 `}`。
模板|//      它在**第 5 行**报错，但真正的错就是第 5 行自己少了分号 ——
模板|//      这一条跟前面那个"往上多看一行"的例子正好相反，
模板|//      所以**不要死记行号规则，要读它说的那句话**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  这一课没有算法要写，只有三件事要做：
模板|//
模板|//    1. 确认 gcc 和 dotnet 都装好了
模板|//       （界面首页的「环境自检」会显示；命令行敲 gcc --version 也行）
模板|//
模板|//    2. 让 gcc **报一次错**，并且读懂它
模板|//       下面留了一个空的 main。先故意漏掉那个分号 → 检查 → 看报错 →
模板|//       把分号补上 → 再检查。
模板|//
模板|//       为什么要你故意写错一次：**报错是编译器在跟你说话**。
模板|//       第一次被它骂过的人，第二次才不慌。这一课就是让你先被骂一次，
模板|//       而且是在"没人看、不扣分"的时候被骂。
模板|//
模板|//    3. 让它打印出下面这三行，就算跑通了
模板|//
模板|//          工具链就绪
模板|//          我准备好学 C 了
模板|//          第一步：编译，第二步：运行
模板|//
模板|//  ⚠ 期望输出就是上面这三行，一个字都不能差（检查是逐行比的）。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  怎么自己测
模板|// ─────────────────────────────────────────────────────
模板|//   点界面上的「检查」。
模板|//   命令行：dotnet run --project csharp/c-lessons 检查 00

模板|//     printf("我准备好学 C 了\n");

答案|int main(void) {
答案|    /* ① 先漏掉分号编译一次，读懂第一条 error，再补回来 ——

答案|
答案|       报错大概长这样：
