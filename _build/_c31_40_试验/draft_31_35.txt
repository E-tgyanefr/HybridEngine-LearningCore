模板|//  一、栈：一个数组 + 一个「栈顶在哪」
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int 栈[100];

模板|//
模板|//     push（压栈）：  栈[栈顶] = 值;   栈顶++;
模板|//     pop （弹栈）：  栈顶--;          值 = 栈[栈顶];
模板|//     top （看栈顶）：栈[栈顶 - 1]     ← 只看不弹
模板|//     空栈：          栈顶 == 0

模板|//     pop      →  []           弹出 1

模板|// ─────────────────────────────────────────────────────
模板|//  二、队列：一个数组 + 两个「门」
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int 队[100];

模板|//     入队：  队[队尾] = 值;   队尾++;
模板|//     出队：  值 = 队[队头];   队头++;

模板|// ─────────────────────────────────────────────────────

模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 一个班 30 个人，用数组存，好得很：
模板|//
模板|//     int 学号[30];
模板|//
模板|// 可插进来一个转学生，要按学号排在第 3 位：
模板|//
模板|//     [10][20][30][40][50] ...
模板|//               ↑ 要插 25 在这里
模板|//
模板|// 数组里**没地方塞** —— 只能把 30 之后的每一个人**统统往右挪一格**，

模板|// 你不知道会来多少人 —— 写 100 怕不够，写 1000000 又浪费。
模板|//
模板|// 链表就是来解决这两件事的：**要一个就申请一个，插进去不用挪别人。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、节点：值 + 「下一个在哪」
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     struct 节点 {
模板|//         int 值;
模板|//         struct 节点 *下一个;        ← 指向同一种结构体的指针
模板|//     };

模板|//
模板|// 一条链就是这样连起来的（最后一个的「下一个」是 NULL）：
模板|//
模板|//     [10| •] → [20| •] → [30| NULL]
模板|//      头                    尾
模板|//
模板|// ⚠ 数组和链表的区别一句话：**数组的元素是挨着的，链表的元素谁在哪都行**，
模板|//   它们靠指针互相认得。所以链表里没有「第 3 个元素在哪」的公式，
模板|//   想找第 3 个，只能从**头**一个一个走过去。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、造一个节点：malloc + 填空
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     节点 *新 = malloc(sizeof(节点));
模板|//     新->值 = 42;
模板|//     新->下一个 = NULL;
模板|//
模板|// ⚠ sizeof(节点) 是**整个结构体多大**（int + 指针，通常 16 字节），
模板|//   不是 4。写成 malloc(4) 会只给你 4 字节 —— 编译不报错，
模板|//   程序**跑着跑着**才崩，而且崩的位置和出错的位置隔得很远。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  三、遍历：一定要有「会走路的指针」
模板|// ─────────────────────────────────────────────────────
模板|//

模板|//         printf("%d ", 走->值);
模板|//     }
模板|//
模板|// ⚠⚠ **绝对不能拿「头」本身去走**：
模板|//
模板|//     while (头 != NULL) { printf("%d ", 头->值); 头 = 头->下一个; }    ✗
模板|//
模板|//   走完一遍，头就变成 NULL 了 —— 你**永远找不回这条链了**，
模板|//   而且那几十个节点也**再也没法 free**（内存泄漏）。
模板|//   ⇒ 遍历永远用一个临时指针，头原地不动。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  四、头部插入：三步，顺序会咬人
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     新->下一个 = 头;        ① 新节点先拉住原来那条链
模板|//     头 = 新;                ② 再把「头」挪到新节点上
模板|//
模板|// ⚠ ①②**不能换顺序**。先写「头 = 新」的话，原来那条链的地址
模板|//   就丢了（新->下一个 还是 NULL）—— 结果链表里永远只剩一个节点。
模板|//
模板|//   这个错误特别典型：**程序不崩、编译不报，就是打印出来只剩一个数。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  五、删除：先接上，再放手
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 要删「值 == 20」的那个节点：
模板|//
模板|//     前一个->下一个 = 要删->下一个;      ← 先让链条跨过去
模板|//     free(要删);                        ← 再放掉内存
模板|//
模板|// 两种位置要分开处理：
模板|//
模板|//     要删的是**头**   →  头 = 头->下一个; 再 free
模板|//     要删的在**中间** →  用一个「前一个」指针追在后面
模板|//
模板|// ⚠ 「前一个」的意义就是「我要删的那个的**前一个**」——
模板|//   因为改链条要改**前一个**的下一个，不是改自己的。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 这一课唯一要记住的坑：free 完还去用那个指针
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     free(前一个->下一个);
模板|//     printf("%d\n", 前一个->下一个->值);       ← 那块内存已经不是你的了
模板|//
模板|// gcc 会给你一句（我在本机 gcc 16.1.0 真编译出来的）：
模板|//
模板|//     warning: pointer 'p' used after 'free' [-Wuse-after-free]
模板|//         8 |     printf("%d\n", p->值);
模板|//           |     ^~~~~~~~~~~~~~~~~~~~~
模板|//         7 |     free(p);
模板|//           |     ^~~~~~~
模板|//         note: call to 'free' here
模板|//
模板|// ⚠ 注意这只是 **warning**，不是 error —— 程序照样编译出来、照样跑。
模板|//   跑出来你可能看到 42（内存还没被人踩），
模板|//   也可能看到 6029409 这种莫名其妙的数字（**我实测跑出来就是 6029409**）。
模板|//   ⇒ 这叫「用已经还给系统的内存」，结果完全看运气。

模板|//  这一课不碰什么

模板|//   链表排序、链表反转 → 不涉及（那是八级的题）。
模板|//   用 struct 把「头指针 + 长度」打包 → 不涉及。
模板|//

模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：链表分了个岔
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 链表是**一条线**：每个节点只知道下一个是谁。
模板|//
模板|//     [10] → [20] → [30] → NULL
模板|//
模板|// 如果让每个节点能指**两个**呢？
模板|//
模板|//            [1]
模板|//           /   \
模板|//        [2]     [3]
模板|//       /   \       \
模板|//    [4]    [5]      [6]
模板|//
模板|// 这就叫**二叉树**：每个节点最多两个孩子，一个叫左孩子、一个叫右孩子。
模板|//
模板|// ⚠ 「树」这个词在生活里是**根在下、叶在上**，在计算机里**反过来**：
模板|//   最上面那个节点叫**根（root）**，往下分叉，最下面没有孩子的叫**叶子**。
模板|//

模板|//   而一棵排好序的二叉树找一个数只要**一层一层往下**走 ——
模板|//   100 万个节点最多走 20 步。这就是「有序」的威力。

模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、怎么定义一个二叉树的节点
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     struct 树节点 {
模板|//         int 值;
模板|//         struct 树节点 *左;

模板|// DFS 的规矩简单到一句话：**能往前就往前，走不动就退回来换一条。**
模板|//
