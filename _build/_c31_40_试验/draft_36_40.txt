模板|// 第 37 课：二维 DP —— 表格上填数字
模板|// ─────────────────────────────────────────────────────
模板|//  怎么读这一课
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//   先从头读一遍讲解，再照着最后的「轮到你了」写。
模板|//   卡住了看答案（先自己写一遍）—— 命令在「怎么自己测」那一节。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  这一课你会学到
模板|// ─────────────────────────────────────────────────────
模板|//    二维动态规划：dp 不是一排格子，而是**一张表**
模板|//
模板|//  需要先会
模板|//    第 35 课：一维 DP —— 三步套路（定义 / 递推 / 初值）完全一样
模板|//    第 20 课：二维数组 —— dp 表就是它
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：一维不够记的时候
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 第 35 课的 dp 是一排格子：dp[1] dp[2] dp[3] ……
模板|// 因为那时候「状态」只有一个数（走到第几级、容量多大）。
模板|//
模板|// 可有些问题的状态是**两个数**：
模板|//
模板|//     「从左上角走到第 i 行第 j 列，有几条路？」
模板|//                          └─ 两个数 ─┘
模板|//
模板|// 一个数记不下，那就用**一张表**：dp[i][j]。
模板|//
模板|// ⚠ 套路一点没变，还是那三步，只是把 dp[i] 换成 dp[i][j]：
模板|//
模板|//     ① 定义  dp[i][j] 是什么
模板|//     ② 递推  dp[i][j] 从它的**上面**和**左边**来
模板|//     ③ 初值  最上面一行、最左边一列
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、网格路径数：只能往右或往下
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 一个 行×列 的格子，从 (0,0) 出发，每步只能**往右**或**往下**，
模板|// 走到 (行-1, 列-1) 一共有多少条不同的路？
模板|//
模板|//     ① dp[i][j] = 走到 (i, j) 的路的条数
模板|//     ② 要到 (i,j)，只能从**上面** (i-1,j) 或**左边** (i,j-1) 过来：
模板|//            dp[i][j] = dp[i-1][j] + dp[i][j-1]
模板|//     ③ 第一行只能一路往右（只有 1 条路）→ dp[0][j] = 1
模板|//        第一列只能一路往下（只有 1 条路）→ dp[i][0] = 1
模板|//
模板|// 3 行 7 列填出来长这样：
模板|//
模板|//            j=0  j=1  j=2  j=3  j=4  j=5  j=6
模板|//     i=0     1    1    1    1    1    1    1
模板|//     i=1     1    2    3    4    5    6    7
模板|//     i=2     1    3    6   10   15   21   28
模板|//
模板|// 答案 28。⚠ 每个格子都是「上面 + 左边」，你可以在纸上核对几个：
模板|//   10 = 4 + 6，21 = 6 + 15，28 = 7 + 21。
模板|//
模板|// ⚠ 第一行 / 第一列**必须**单独填成 1，不能让递推式去算 ——
模板|//   dp[0][0] 的上面和左边都越界了。这类「边界单独处理」是二维 DP 的固定动作。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、最长公共子序列（LCS）：两个字符串比一比
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 「子序列」= 从原串里**挑若干个字符出来、保持原来的先后顺序**（可以不连续）。
模板|//
模板|//     串 A = 1 2 3 4 5
模板|//     串 B = 1 3 5
模板|//     公共子序列有：1、3、5、13、15、35、135 ……
模板|//     最长的那个是 135，长度 3
模板|//
模板|// ⚠ 别和「子串」搞混：**子串必须连着**，子序列可以不连着。
模板|//   135 是 A 的子序列，但不是 A 的子串。
模板|//
模板|// 怎么用 DP 求最长长度：
模板|//
模板|//     ① dp[i][j] = A 的**前 i 个**字符 和 B 的**前 j 个**字符 的最长公共子序列长度
模板|//     ② 看 A[i-1] 和 B[j-1] 这两个字符（注意下标差 1！）：
模板|//
模板|//          一样 → dp[i][j] = dp[i-1][j-1] + 1        这个字符能用上
模板|//          不同 → dp[i][j] = max(dp[i-1][j], dp[i][j-1])   只能丢掉一边
模板|//
模板|//     ③ 第 0 行、第 0 列全是 0（「前 0 个字符」当然没有公共子序列）
模板|//
模板|// ⚠ 第 ② 步的 dp[i-1][j-1] + 1 里，那个 **+1 就是「这两个字符配上了」**。
模板|//   很多人会写成 dp[i-1][j-1]（忘了 +1）—— 结果永远是 0。
模板|//
模板|// 拿 A = 1 2 3 4 5、B = 1 3 5 填一遍（整张表）：
模板|//
模板|//            ""   1    3    5
模板|//     ""     0   0    0    0
模板|//     1      0   1    1    1
模板|//     2      0   1    1    1
模板|//     3      0   1    2    2
模板|//     4      0   1    2    2
模板|//     5      0   1    2    3      ← 答案 3
模板|//
模板|// ⚠ 下标差 1 这件事**必须自己盯住**：
模板|//   dp 的第 i 行说的是「前 i 个字符」，而字符串的下标是从 0 开始的。
模板|//   所以第 i 个字符是 A[i-1]，dp 表要比字符串**多一行一列**。
模板|//   这是二维 DP 最常见的「差一格」bug 来源。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 这一课唯一要记住的坑：dp 表忘了清零
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int dp[100][100];                     ← 没初始化
模板|//     for (int i = 1; i <= n; i++)
模板|//         for (int j = 1; j <= m; j++)
模板|//             dp[i][j] = dp[i-1][j] + dp[i][j-1];      ← 读了垃圾值
模板|//
模板|// 你会看到：数字大得离谱，而且是**负数** —— 大概是这种：
模板|//
模板|//     dp[0][0] = -858993460
模板|//
模板|// ⚠ -858993460 这个数记住它：**它就是 0xCCCCCCCC**。
模板|//   没初始化的栈内存被填成的「有毒的初值」，特征就是它。
模板|//   以后再看见这个数字，不用往下查了，直接去找哪里忘了初始化。
模板|//
模板|// ⚠⚠ 二维数组要注意：int dp[100][100] = {0}; 能把**整个表**清零，
模板|//   但 int dp[100][100]; 然后只写 dp[0][0] = 0; **不行** ——
模板|//   那只清了一个格子。
模板|//
模板|// ⇒ 铁律：二维 dp 表一律写 = {0}。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  这一课不碰什么
模板|// ─────────────────────────────────────────────────────
