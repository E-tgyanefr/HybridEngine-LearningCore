# 反面测试台账（第 16~25 课）

这些是**故意写错/偷懒但输出可能对**的解法，用来确认每一课的核心检查点真的拦得住。
文件本身在清理临时产物时删掉了，这里留下代码形状、实测结果和当时的输出。

**结论：十课全部至少被拦掉一条检查，其中九课的核心检查点直接不过。**

| 课 | 偷懒解法 | 实测结果 | 被哪一条拦住 |
|---|---|---|---|
| 16 | 把三行、四列、最大值全**写死** | `== 0/6 ==` | ★按列打印、★主对角线和、★矩阵最大、真的是两层的循环 |
| 17 | 三个排序都调 `std::sort` | `== 5/7 ==` | ★不许拿 std::sort 交差、★三个函数体里各自都要有循环 |
| 18 | `按分排序_不稳定` 也写成 `stable_sort` | `== 3/5 ==` | ★按分排序_不稳定：真的用 std::sort |
| 19 | `平方和` 直接 `return 公式(n);` | `== 1/4 ==` | ★平方和里要真的有两层循环，而且不许去调用 公式/一重和 |
| 20 | 四个函数全用第 11 课那种**递归** | `== 0/6 ==` | ★四个都必须是从前往后填表（数组+循环），不许用递归；另有超时 |
| 21 | 不读文件，直接写死答案 2 | `== 1/3 ==` | ★真的从 data.in 里读：换三份不同的输入，答案要跟着变 |
| 22 | `是质数` 一个个试到 n | `== 4/6 ==` | ★是质数：大质数不能慢 —— **实测 6221 毫秒 > 上限 2000 毫秒**；文本检查也拦 |
| 23 | 用 `std::gcd` 拼出来 | `== 0/6 ==` | ★不许用 std::gcd；★最大公约数里要用到 % |
| 24 | `素数个数` 对每个数单独试除 | `== 2/5 ==` | ★素数个数(1000000) 必须在时限内算完（约 50 秒 ⇒ 超时） |
| 25 | 从头到尾**线性扫** | `== 5/6 ==` | ★必须是真二分：函数体里要有「折半」的写法 |

## 典型的实测输出

**第 22 课（计时拦住的）**：

```
  OK  因数个数：1、2、12、36、100 都要对（36 是完全平方数）
  XX  ★ 是质数：小数字、大质数都要对，而且大质数不能慢
        答案是对的，但**太慢了**：判断两个大质数一共花了 6221 毫秒（上限 2000 毫秒）。
              本机实测（判 999999937）：试到 √n 是 **0 毫秒**，试到 n 是 **2527 毫秒**。
  XX  ★ 是质数不许一个个试到 n（试到 √n 就够）
              for (int i = 2; i < n; i++) { if (n % i == 0) { return false; } }
== 4/6 ==
```

**第 25 课（线性扫：前 17 组用例答案全对，但核心检查点拦住了）**：

```
  OK  二分查找：第一格、最后一格、找不到、重复元素都要对
  OK  下界：比所有数都小/都大、命中、重复元素
  OK  ★ 大数组也要对（10 万个元素，二分只要约 17 次）
  XX  ★ 必须是真二分：函数体里要有「折半」的写法
  OK  ★ 不许用 std::lower_bound / binary_search 交差
== 5/6 ==
```

⚠ **第 25 课这条最值得记住**：线性扫和二分在"答案对不对"上**完全一样**，
计时也分不出来（10 万个元素线性扫也就几百微秒）——
只能靠源码形状（函数体里有没有 `/ 2`）来判。所以那条检查的提示语写得特别小心，
说清楚"答案对不算过，这一课要的是砍一半"。

⚠ **第 22 课那条改过一次**：我原以为"试到 n"会撞上运行器的 60 秒超时，
实测发现**不会**（一个大质数才 2.5 秒），于是改成在调用点里用 `std::chrono`
自己量时间、超过 2000 毫秒判不过。
