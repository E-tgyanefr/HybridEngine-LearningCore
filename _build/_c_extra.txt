模板|// 三条循环长得像，各有各的用处：
模板|//

标题|第 19 课：递归 —— 函数调用自己
要求|写两个递归函数：int 阶乘(int n) 和 int 斐波那契(int n)
模板|// 第 19 课：递归 —— 函数调用自己
模板|//
模板|// 先介绍：一个函数可以调用它自己
模板|//
模板|//     阶乘 n! = 1 × 2 × 3 × ... × n
模板|//
模板|//     用循环写（你已经会了）：
模板|//         int 结果 = 1;
模板|//         for (int i = 2; i <= n; i++) 结果 *= i;
模板|//
模板|//     用递归写：
模板|//         n! = n × (n-1)!        ← 把问题**变小一号**，再问自己
模板|//
模板|//         int 阶乘(int n) {
模板|//             if (n <= 1) return 1;      ← ① 什么时候停
模板|//             return n * 阶乘(n - 1);    ← ② 用"小一号的答案"拼出答案
模板|//         }
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠⚠ 递归必须有的两样东西
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//   ① **基准情形**（base case）—— 什么时候**不再**调用自己，直接给答案。
模板|//        上面那行 `if (n <= 1) return 1;` 就是它。
模板|//
模板|//   ② **每次都在变小** —— 参数必须朝着基准情形走。
模板|//        `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1。
模板|//
模板|//   ⚠⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看。**
模板|//
模板|//      int 阶乘(int n) {
模板|//          return n * 阶乘(n - 1);      /* 没有基准情形 */
模板|//      }
模板|//
模板|//   它会一直调用下去，每调一次就在内存里压一层（叫"调用栈"），
模板|//   直到把栈用完 ⇒ 崩溃。这个错叫**栈溢出**（stack overflow）。
模板|//
模板|//   ⚠ 在 Windows 上你看到的多半是程序直接消失、退出码不是 0，
模板|//     而不是一句好看的报错。**这就是递归最需要小心的地方。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  为什么值得学：有些问题用递归写短得多
模板|// ─────────────────────────────────────────────────────
模板|//

模板|//
模板|//     · 文件夹里还有文件夹，一层套一层 —— 怎么数所有文件？
模板|//     · 一棵树，每个节点还有子树 —— 怎么遍历？
模板|//     · 汉诺塔、走迷宫、表达式求值
模板|//

模板|//  用递归写则几乎是直译。这一课先在小问题上把套路练熟。
模板|//
模板|// ─────────────────────────────────────────────────────

模板|// ─────────────────────────────────────────────────────
模板|//
模板|//      fib(n) = fib(n-1) + fib(n-2)
模板|//

模板|//
模板|//      int 斐波那契(int n) {
模板|//          if (n <= 1) return n;

模板|//      }
模板|//
模板|//  ⚠⚠ 它**能算出正确答案**，但算 fib(40) 要调用自己上**亿**次。
