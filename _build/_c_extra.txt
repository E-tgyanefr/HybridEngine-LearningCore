模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：和 if 是两种不同的东西
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     if      —— **判断条件**（可以是很复杂的表达式）
模板|//     switch  —— **把同一个值和一堆候选值比相等**
模板|//
模板|//         switch (月) {
模板|//             case 3:
模板|//                 ...
模板|//                 break;
模板|//             case 4:
模板|//             case 5:
模板|//                 ...
模板|//                 break;
模板|//             default:
模板|//                 ...
模板|//         }
模板|//
模板|// 用哪个？一条实用判据：
模板|//
模板|//     「等于…等于…等于…」        → switch 更清楚
模板|//     「大于、小于、并且、或者」   → 只能用 if
模板|//
模板|// ⚠ switch 里**只能比整数和字符**，不能比字符串、不能比小数。
模板|//   （`case "你好":` 编译不过 —— 字符串比较要用 strcmp，第 10 课讲的那件事。）
模板|//
模板|//  ⚠⚠ 这一课唯一要记住的坑：break
模板|//
模板|// **switch 不会自己停下来。** 一个 case 做完了，它会**继续往下做下一个 case**。
模板|// 这叫「贯穿」（fallthrough），是 C 里最坑人的设计之一。
模板|//
模板|//     switch (2) {
模板|//         case 1: printf("一\n");        // 不执行
模板|//         case 2: printf("二\n");        // 执行 —— 从这里进去
模板|//         case 3: printf("三\n");        // **也执行！** 因为上面没 break
模板|//     }
模板|//
模板|//     实际输出：二、三          ← 不是你以为的"只有二"
模板|//
模板|// ⇒ **每个 case 末尾几乎都要写 break;**，忘了它就等于让程序"漏"下去。
模板|//
模板|// ⚠ 但贯穿**有时候是故意的** —— 而且这是这一课要你用的写法。
模板|//   想表达"3、4、5 都算春天"，可以叠着写：
模板|//
模板|//     case 3:
模板|//     case 4:
模板|//     case 5:
模板|//         return "春";          ← 三个标签共用同一段代码
模板|//
模板|//   这比写逻辑或运算符（月 == 3 或 月 == 4 或 月 == 5）短，也不容易漏掉一个。
模板|//   ⇒ 所以贯穿既是坑、也是工具 —— **关键是你要知道自己有没有用它。**
模板|//

模板|//   没有 default 又不匹配 —— 什么都不做，而你要自己保证"什么都不做"是对的。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  ① 基本形状：`switch (一个整数表达式)` + 一堆 `case 常量:`。
模板|//
模板|//      switch (月) {
模板|//          case 1:
模板|//              printf("一月\n");
模板|//              break;                  /* ⚠ 停下 */
模板|//          case 2:
模板|//              printf("二月\n");
模板|//              break;

模板|//              printf("不认识\n");
模板|//              break;
模板|//      }
模板|//
模板|//  ② case 后面只能跟**编译期常量**：整数、字符字面量。
模板|//
模板|//      case 3:        ✅ 整数
模板|//      case 'A':      ✅ 字符（字符本质上是整数编码）
模板|//      case 变量:     ❌ 变量不是常量
模板|//      case 3.5:      ❌ 小数不行（坑 3）
模板|//      case "春":     ❌ 字符串不行（坑 2）
模板|//

模板|//
模板|//      二

标题|第 18 课：while 与 do-while —— 不知道要做几次的时候
要求|1. 用 while 写 数位和(数)：返回一个正整数的各位数字之和
要求|2. 用 do-while 写 至少做一次(数)：同一个计算，但用后判断的循环
模板|// 第 18 课：while 与 do-while —— 不知道要做几次的时候
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：for 和 while 什么时候用哪个
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     第 07 课的 for   —— **你知道要做几次**
模板|//                          "从 1 加到 100"、"遍历这个数组"
模板|//
模板|//     这一课的 while  —— **你不知道要做几次**，
模板|//                          只知道"什么时候该停"
模板|//                          "一直取数字，直到取完为止"
模板|//
模板|// 三条循环长得像，各有各的用处：
模板|//
模板|//     while (条件) { ... }        先判断，再做。**可能一次都不做**
模板|//     do { ... } while (条件);    先做一次，再判断。**至少做一次**
模板|//     for (...) { ... }           三段式。次数明确时最清楚
模板|//
模板|//  一、while 的形状
模板|//
模板|//     初始化;
模板|//     while (条件) {
模板|//         做事;
模板|//         **改变量**;        ← ⚠⚠ 这一行忘了就是死循环
模板|//     }
模板|//
模板|// ⚠⚠ **while 最常见的错：忘了在循环体里改变量。**
模板|//
模板|//     int i = 0;
模板|//     while (i < 5) {
模板|//         printf("%d\n", i);
模板|//         /* 忘了 i++ ⇒ i 永远是 0 ⇒ 条件永远成立 ⇒ 死循环 */
模板|//     }
模板|//
模板|//   这条和 for 的区别很值得体会：
模板|//     for 把"改变量"写在**括号里**，想忘都忘不了；
模板|//     while 把"改变量"丢在**循环体里**，忘了也没人拦你，程序就那么卡住。
模板|//   ⇒ 写 while 的时候，先问自己一句：**"哪个变量在变？它在哪里变？"**
模板|//
模板|//  二、do-while 的形状（末尾那个分号不能少）
模板|//
模板|//     do {
模板|//         做事;
模板|//     } while (条件);        ← ⚠ 末尾**必须**有分号
模板|//
模板|//  它和 while 唯一的差别：**先做一次，再判断**。
模板|//  所以"条件一开始就不成立"的时候，while 一次都不做，do-while 会做一次。
模板|//
模板|//      int i = 100;
模板|//      while (i < 5) { printf("while 跑了\n"); }      // 一次都不跑
模板|//      do { printf("do-while 跑了\n"); } while (i < 5); // 跑一次
模板|//
模板|//  什么时候真的需要它？**"至少得做一次"的场合**：
模板|//  菜单（至少显示一次）、读输入（至少读一次才知道对不对）、
模板|//  重试（至少试一次）。这些用 while 写都要在循环外面先抄一遍，很别扭。
模板|//
模板|//  三、这一课的例子：数位和
模板|//
模板|//  算 1234 的各位之和（1+2+3+4 = 10）。你为什么**不知道要做几次**？
模板|//  因为 5 是一位数、12345678 是八位数 —— 循环次数取决于输入。
模板|//
模板|//  两个工具（都是整数运算，正好复习第 03 课）：
模板|//
模板|//     数 % 10    取最后一位      1234 % 10  = 4
模板|//     数 / 10    把最后一位去掉   1234 / 10  = 123   （整数除法，小数被丢掉）
模板|//
模板|//  于是循环体是：
模板|//
模板|//     和 += 数 % 10;        拿走最后一位，加到和里
模板|//     数 /= 10;             把最后一位扔掉
模板|//                            ↑ 这就是"让循环往前走"的那一步
模板|//
模板|//  什么时候停？**数变成 0 的时候**（没位数可取了）。
模板|//
模板|//  ⚠⚠ 这里有个边界要想清楚：**输入是 0 怎么办？**
模板|//
模板|//     while (数 > 0) {...}      ⇒ 0 一次都不进循环 ⇒ 返回 0     ✅ 对
模板|//     do { ... } while (数 > 0); ⇒ 会先做一次，返回 0 也是 0    ✅ 也对
模板|//   这一课要你**两种都写一遍**，然后自己体会：这个题目里它们结果一样，
模板|//   但换个题目（比如"至少问一次用户"）就不一样了。
模板|//
模板|// ⚠ 还有个负数问题：`-123 % 10` 在 C 里是 **-3**（不是 3）。
模板|//   检查只喂正数，所以不用管；但你要知道这件事存在 ——
模板|//   真实项目里输入永远可能带负号。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  ① while 的标准骨架：**初始化在循环外，改变量在循环内。**
模板|//
模板|//      int i = 0;                  /* ① 初始化 */
模板|//      while (i < 5) {             /* ② 每轮先判断 */

要求|写两个递归函数：int 阶乘(int n) 和 int 斐波那契(int n)
模板|// 第 19 课：递归 —— 函数调用自己
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：一个函数可以调用它自己
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     阶乘 n! = 1 × 2 × 3 × ... × n
模板|//
模板|//     用循环写（你已经会了）：
模板|//         int 结果 = 1;
模板|//         for (int i = 2; i <= n; i++) 结果 *= i;
模板|//
模板|//     用递归写：
模板|//         n! = n × (n-1)!        ← 把问题**变小一号**，再问自己
模板|//
模板|//         int 阶乘(int n) {
模板|//             if (n <= 1) return 1;      ← ① 什么时候停
模板|//             return n * 阶乘(n - 1);    ← ② 用"小一号的答案"拼出答案
模板|//         }
模板|//
模板|//  ⚠⚠ 递归必须有的两样东西
模板|//
模板|//   ① **基准情形**（base case）—— 什么时候**不再**调用自己，直接给答案。
模板|//        上面那行 `if (n <= 1) return 1;` 就是它。
模板|//
模板|//   ② **每次都在变小** —— 参数必须朝着基准情形走。
模板|//        `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1。
模板|//
模板|//   ⚠⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看。**
模板|//
模板|//      int 阶乘(int n) {
模板|//          return n * 阶乘(n - 1);      /* 没有基准情形 */
模板|//      }
模板|//
模板|//   它会一直调用下去，每调一次就在内存里压一层（叫"调用栈"），
模板|//   直到把栈用完 ⇒ 崩溃。这个错叫**栈溢出**（stack overflow）。
模板|//
模板|//   ⚠ 在 Windows 上你看到的多半是程序直接消失、退出码不是 0，
模板|//     而不是一句好看的报错。**这就是递归最需要小心的地方。**
模板|//
模板|//  为什么值得学：有些问题用递归写短得多
模板|//
模板|//  阶乘用循环写就挺好，递归没占到便宜。但下面这类问题：
模板|//
模板|//     · 文件夹里还有文件夹，一层套一层 —— 怎么数所有文件？
模板|//     · 一棵树，每个节点还有子树 —— 怎么遍历？
模板|//     · 汉诺塔、走迷宫、表达式求值
模板|//
模板|//  **它们本身就是递归定义的**，用循环写要自己造一个"栈"来记住位置，
模板|//  用递归写则几乎是直译。这一课先在小问题上把套路练熟。
模板|//
模板|//  ⚠ 一个反例：斐波那契**不该**用这种递归写
模板|//
模板|//      fib(n) = fib(n-1) + fib(n-2)
模板|//
模板|//  按这个式子直接写成递归：
模板|//
模板|//      int 斐波那契(int n) {
模板|//          if (n <= 1) return n;
模板|//          return 斐波那契(n - 1) + 斐波那契(n - 2);   ← 能算对，但极慢
模板|//      }
模板|//
模板|//  ⚠⚠ 它**能算出正确答案**，但算 fib(40) 要调用自己上**亿**次。
模板|//     为什么：算 fib(5) 要 fib(4) 和 fib(3)，而 fib(4) 又要 fib(3) ——
模板|//     **同一个 fib(3) 被重复算了无数遍**。这叫"重叠子问题"。

模板|//  这一课仍然让你这么写，因为**它最能训练"递归思维"**，
