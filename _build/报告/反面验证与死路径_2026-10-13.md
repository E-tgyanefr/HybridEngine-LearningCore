## 四、两条弱检查：**都坐实了**（课程文件只读，一个字没动）

新增探针 `_build/_probe_weakchecks.py`（**退出码 0** · 没跑到 0 · 正对照都过）。
每条探针跑**两次**：**正对照**（喂该课自己的参考答案 ⇒ 必须全部通过）+ **反探针**（喂**能编译**的错答案）。

### ① 第 19 课「★ 比较器是两级比较」—— 比预想的严重

反探针：`按长度再按字典()` 只 `return a.length() - b.length();`

```
目标检查：✓ ★ 比较器是两级比较：长度相同的还要按字典序排
整轮：5✓ 0✗   ！全部通过
```

⇒ **不是"这条检查漏了"，而是这一课 5/5 全部通过 —— 错答案被判成完全正确。**

**机制**（已在源码逐字核实）：检查喂的数据是
`new ArrayList<>(Arrays.asList("java", "c", "abc", "ab", "zz"))`（`第19课*.cs:386`），
里面**等长的只有 `ab` / `zz`**，而它们在输入里**本来就是字典序**；
`List.sort` 是**稳定排序** ⇒ 「只比长度」和「先长度再字典序」**输出完全相同**。

⚠ **为什么"`return 0` 全过"那个说法复现不出来**：`return 0` 在 Java 里**编译不过**
（`int` 不是 `Comparator<String>`），它被**编译阶段**拦住、**那条检查根本没执行**。
⇒ 这恰好证明「**没跑到**必须判失败」那条规矩的必要性 —— 否则会把
  "编译没过"当成"这条检查有效"。

### ② 第 22 课「★ 数行数 用的是 try-with-resources」—— 判据确实太松，但危害轻一档

反探针：资源 `new` 在 try **外面**、进了 try 从不 close（只留空 `finally`）—— 能编译。

```
目标检查：✓ ★ 数行数 用的是 try-with-resources（资源写在 try 后面的圆括号里）
整轮：4✓ 1✗
```

⇒ 这条检查放过了；**但整轮还是被别的检查拒了**（另有 1 条 ✗），
   学员蒙混不过去 —— 是"**少了一道防线**"，不是"开了个洞"。

**判据原文**（`第22课*.cs:318` + `:330`）：`体.Contains("try") || 体.Contains("(")` ，
再加 `体.Contains("readLine")` —— **只问"这三个词出现过吗"**，
**没有核对资源是不是真的写在 `try (` 的圆括号里**，也不要求 close。

### ③ 建议（**等作者定**，本轮不改）

- 第 19 课：把检查数据换成**等长但输入里逆序**的一组
  （例如 `["java","c","abc","zz","ab"]` ⇒ 正确输出 `[c, ab, zz, abc, java]`，
  只比长度会得到 `[c, zz, ab, abc, java]`），这一条立刻有区分度。
- 第 22 课：用正则确认资源出现在 `try (` 的圆括号里，而不是只看两个词出现过。

## 六、⚠ 意外发现：修好 `tests/验收.py` 之后，它会把 `run_tests.py` 搞挂

**这是本轮最重要的一条**，因为它**只在路径被修好之后才出现**。

### 现象

修完路径后跑 `python _build\run_tests.py` ⇒ **退出码 1**：

```
FAIL: test_每条线都能生成非空的答题模板
AssertionError: Lists differ: ['python：模板只有 9 行非空（像没生成）'] != []
```

### 根因（实测，不是推理）

`tests/验收.py` 会把 `lessons/solutions/` 复制进 `lessons/answers/`。
而 `*-answers/` 是**运行期答题区**：`learnmodel.读答案()` **只要看到文件就直接返回它**，
不再生成模板。⇒ 测试读到的"模板"其实是**参考答案**。
第 00 课的参考答案**只有 9 行非空**（它是答案，不是模板）—— 所以报"像没生成"。

**它不是本来就这样**：修路径**之前** `tests/验收.py` 的 `ROOT` 指向不存在的目录，
`os.path.isdir(s)` 为假 ⇒ **整个脚本是个静默空转**。路径一修好，它**真的开始干活**，
于是这个副作用才浮出来。

### 验证因果（两条命令）

```
把 lessons/answers 移开 ⇒ python _build\run_tests.py ⇒ 退出码 0
放回去（里面是参考答案）⇒ python _build\run_tests.py ⇒ 退出码 1
```

### 处理

给 `tests/验收.py` 加了**备份 → 跑 → 还原**（`atexit` 兜底，中途崩了也会还回去）：
旧的是 `shutil.move` **搬走**而不是删（学员真写过的东西，脚本没权力替他决定）。

实测：

```
跑 验收.py 之前：lessons/answers = 1 个文件（6223 B 模板）
跑 验收.py 之后：lessons/answers = 1 个文件（6223 B 模板）   ← 一模一样
紧接 python _build\run_tests.py ⇒ 退出码 0 · Ran 320 OK + Ran 7 OK
```

原始输出：`_build/_yanshou_restore.txt` · `_build/_runtests_after_fix.txt`
