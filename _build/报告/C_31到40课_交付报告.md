逻辑错误，作用只是防「根本没用 malloc」这种偷懒）。

### 两个**故意做过的加固**（都是我自己的课，发现弱就改了）

1. **第 34 课**：我先用一个「栈 + 入栈即标记」的假 BFS 打样，结果发现它**恰好也能走出 6 步**
   ⇒ 输出检查拦不住它。于是我用穷举（`maze.py`）确认了真正会出错的是
   **「出栈才标记」**那种写法：在题目这个迷宫上它会答 **8**（真最短 6）
   ⇒ 检查2 的 `BFS 最少步数 = 6` 确实是一条有效防线。
2. **第 40 课**：原来的边表顺序 `(0,1)(0,2)(2,1)…` **只松一遍也恰好全对**（我实测过：
   7 条边一遍就出 [0,2,1,6,7]，拦不住偷懒的实现）。于是把边表的**顺序**换成
   `0→1, 2→1, 2→3, 1→4, 0→2, 1→3, 3→4`（**数字一个没改**，只换位置）：
    - 松一遍 → `[0, 4, 1, 8, 9]`（错）
    - 松四遍 → `[0, 2, 1, 6, 7]`（对）
   ⇒ 从此「只松一遍」当场露馅。课里的手算示例也照着这个顺序重写了。

### 3. 第 36 课的 `-lm`：**真编译验证过才写的**

- MinGW 16.1.0（本机）：`gcc -std=c11 -O1 -Wall -o m.exe m.c` → 退出码 0，输出 4；
  加 `-lm` 也一样 ⇒ **MinGW 上不需要 `-lm`**（课里就是这么写的）。
- Linux 需要 `-lm`、且 `-lm` 必须写在源文件**后面** ⇒ 课里写了这一点，
  但**明确标注那是 Linux 上的行为**，没有谎称在本机实测。
- 顺带一个好用的真实报错（本机 gcc 实跑）：少 `#include <math.h>` 时
  ```
  error: implicit declaration of function 'sqrt' [-Wimplicit-function-declaration]
  note: include '<math.h>' or provide a declaration of 'sqrt'
  ```
  这句 note 连 `+++ |+#include <math.h>` 都替学生写好了。

### 4. ⚠ 结构性限制（值得记一笔）：`函数用例` 撑不住多参数函数

- `形_函数用例` 生成的是 `printf("%d\n", f(参))` —— **参数是原样拼进去的**，
  所以 `f(3, 7)` 能行、`f("abc", "def")` 能行，但 `背包(重量, 价值, 件数, 容量)`
  **没法这样调**。`形_数组合用例` 只支持**一个**数组参数。
- 因此我**改了两课的学生签名**去适配（而不是放宽检查）：
  - **第 35 课**：改成「只写三个函数、不用写 main」（`爬楼梯` 走 `函数用例`、
    `打家劫舍` 走 `数组合用例` 喂 5 组、`背包` 用 `代码包含` 盯「内层从大到小」那一行）。
  - **第 37 课**：改成「只写两个函数」——`路径数` 和 `最长公共子序列`
    都走 `函数用例`，各喂 **6 组**数据（含 1×1、空串、完全不沾边）。
  - 两课的「轮到你了」里都写明了：**签名一个字别改、不要自己加 main**
    （检查会补一个 main，两个 main 会 `redefinition of 'main'`）。
- 第 35 课的 `背包` 是这一批里**唯一没有跑函数用例**的：它的 4 个参数喂不进去，
  只能靠 `代码包含` + 我本地参照实现核对（重量 2,3,4,5 / 价值 3,4,5,8 / 容量 8 → 12，
  容量 3 → 4，容量 5 → 11，都用参照实现算过）。**这是已知的覆盖缺口，不是"验过了"。**
