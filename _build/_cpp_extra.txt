模板|// 第 11 课：递归 —— 函数调用自己
模板|//
模板|// 这一课讲一件事：**把一个问题的答案，说成「小一号的同一个问题」的答案**。
模板|// ─────────────────────────────────────────────────────
模板|//  这一课你会学到
模板|// ─────────────────────────────────────────────────────
模板|//    递归：函数调用自己
模板|//
模板|//  需要先会
模板|//    第 05 课：函数
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：换个说法
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 阶乘 n! = 1 × 2 × 3 × … × n。用循环写你已经会了。
模板|// 换个说法：**n! = n × (n-1)!** —— 「n 的阶乘 = n 乘上 n-1 的阶乘」。
模板|// 这个说法里出现了自己，于是就能写成函数调用自己：
模板|//
模板|//     int 阶乘(int n) {
模板|//         if (n <= 1) { return 1; }      ① 什么时候停
模板|//         return n * 阶乘(n - 1);        ② 用「小一号的答案」拼出答案
模板|//     }
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、递归必须有的两样东西
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     ① **基准情形**：什么时候**不再**调用自己，直接给答案
模板|//        就是上面那行 `if (n <= 1) { return 1; }`
模板|//     ② **每次都在变小**：参数必须朝着基准情形走
模板|//        `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1
模板|//
模板|// ⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看**（见下面那个坑）。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、一层层展开着看（写递归时脑子里要能这样展开）
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     阶乘(4) = 4 × 阶乘(3)
模板|//             = 4 × (3 × 阶乘(2))
模板|//             = 4 × (3 × (2 × 阶乘(1)))
模板|//             = 4 × (3 × (2 × 1))        ← 到基准情形了，开始一层层往回算
模板|//             = 24
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  三、斐波那契：基准情形**有两个**
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int 斐波那契(int n) {
模板|//         if (n <= 0) { return 0; }      基准情形 ①
模板|//         if (n == 1) { return 1; }      基准情形 ②
模板|//         return 斐波那契(n - 1) + 斐波那契(n - 2);
模板|//     }
模板|//
模板|//     fib(0)=0   fib(1)=1   fib(2)=1   fib(3)=2   fib(4)=3   fib(5)=5
模板|//
模板|// ⚠ 为什么两个都要：n 每次减 1 或减 2，只写 `n == 0` 的话，
模板|//   n = 1 时会掉到 斐波那契(-1)、斐波那契(-2) 去。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  四、怎么读一个递归函数
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     第一步：哪一行**没有**调用自己？      → 那就是出口
模板|//     第二步：参数每次怎么变？变小了吗？  → 那决定它会不会走到出口
模板|//
模板|// ⚠ 一个反例：斐波那契**不该**用这种递归写。
模板|//   算 fib(40) 要调用自己上**亿**次 —— 同一个 fib(3) 被重复算了无数遍
模板|//   （这叫「重叠子问题」）。这一课仍然让你这么写，因为它最能训练递归思维，
模板|//   而且检查只喂到 n <= 20。但请记住：**能写出递归，不等于该用递归。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 这一课唯一要记住的坑：没有基准情形（栈溢出）
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int 阶乘(int n) { return n * 阶乘(n - 1); }      ← 永远不停
模板|//
模板|// 你会看到：**编译完全通过**（语法没问题），一跑起来 ——
模板|//   程序**直接消失**，屏幕上什么输出都没有。实测退出码 **-1073741571**
模板|//   （0xC00000FD，栈溢出），大约两秒后进程就没了。
模板|//
模板|// 为什么：每调一次自己就要在调用栈上压一层（返回地址、参数、局部变量）。
模板|//   栈是有限的（通常几 MB），压满了就崩 —— 这不是「报错」，是进程被系统干掉。
模板|//
模板|// ⚠ 参数不缩小（`return n * 阶乘(n);`）**也是同一个下场**。
模板|//   基准情形管「什么时候停」，参数变小管「能不能走到那里」，两样缺一不可。
模板|//
模板|// ⇒ 写递归时，**第一件事就是写下基准情形**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  这一课不碰什么
模板|// ─────────────────────────────────────────────────────
模板|//   循环和递归哪个更好 —— 没有定论，看问题。这一课只练递归的手感。
模板|//
