要求|1. 写函数 int 影子()：在函数里声明一个和全局同名的局部变量，返回局部变量的值（体会"名字遮蔽"）
要求|2. 写函数 int 计数器()：用一个 static 局部变量，让它每调一次加一并返回（体会"活得更久"）
模板|// 第 10 课：作用域与生命周期 —— 变量从哪儿来、什么时候死
模板|//
模板|// 先介绍：两个经常被混在一起的问题
模板|//
模板|//     **作用域**（scope）    —— 这个名字在**哪几行代码**里能用？
模板|//     **生命周期**（lifetime）—— 这个变量在**什么时候**存在？
模板|//
模板|//  它们相关，但不是一回事。这一课的两个例子正好把它俩分开：
模板|//
模板|//     · 局部变量：作用域是那个 `{}`，生命周期也是那个 `{}`
模板|//     · static 局部变量：作用域**还是**那个 `{}`，但生命周期是**整个程序**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  一、作用域：花括号就是边界
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     #include <iostream>
模板|//
模板|//     int 数 = 100;                    // ← 全局：这个文件里到处都能用
模板|//
模板|//     int main() {
模板|//         std::cout << 数 << "\n";     // 100
模板|//         int 数 = 5;                  // ← 局部：**遮蔽**了全局那个
模板|//         std::cout << 数 << "\n";     // 5    ← 现在这个名字指局部的
模板|//         {
模板|//             int 数 = 7;              // ← 再遮蔽一层
模板|//             std::cout << 数 << "\n"; // 7
模板|//         }
模板|//         std::cout << 数 << "\n";     // 5    ← 内层那个已经死了
模板|//     }
模板|//
模板|// ⚠⚠ **名字遮蔽（shadowing）是 C++ 里一个安静的坑**：
模板|//   编译器**不会警告**（除非开了特定选项），
模板|//   于是你以为在改全局那个，其实改的是局部那个。
模板|//
模板|//   典型症状："我在函数里把它改了，出来怎么没变？"
模板|//   ⇒ 先看一眼**函数里是不是重新声明了一个同名的变量**。
模板|//
模板|// ⚠ 再强调一次第 11 课会正式讲的事：
模板|//   C++ 的参数是**按值传递** —— 函数里的形参是**另一个**变量，
模板|//   改它不会影响调用方。这和"遮蔽"是两种不同的"改了没生效"。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  二、生命周期：`{}` 一结束，局部变量就死了
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int* 造一个() {
模板|//         int 数 = 42;
模板|//         return &数;          // ⚠⚠ 返回局部变量的地址
模板|//     }
模板|//
模板|//  函数一返回，`数` 待的那块内存就被回收了。
模板|//  你拿到的地址**还在**，但它指向的东西已经没了 —— 这叫**悬垂指针**。
模板|//  用它读出来的值是**随机的**，写进去可能破坏别的数据。
模板|//
模板|//  ⚠⚠ 这是 C++ 里最难查的一类 bug：**它常常"看起来是对的"**。
模板|//    程序可能正常跑完、输出也对，只是偶尔崩在别的地方。
模板|//    （这门课不会让你写这种代码，但你必须认识它。）
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  三、`static` 局部变量：作用域不变，但活得更久
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//     int 计数器() {
模板|//         static int 次数 = 0;      // ← 注意这个 static
模板|//         次数++;
模板|//         return 次数;
模板|//     }
模板|//
模板|//  普通局部变量每次调用都**重新出生**（值回到初值）。
模板|//  加了 `static` 之后：
模板|//
模板|//     · **只初始化一次**（整个程序运行期间就那一次）
模板|//     · 函数返回之后它**不消失**，下次调用还是上次那个值
模板|//     · 但**名字还是只有函数里能看见**（作用域没变）
模板|//
模板|//     计数器()  → 1
模板|//     计数器()  → 2      ← 记住上一次了
模板|//     计数器()  → 3
模板|//
模板|// ⚠ 和全局变量比：`static` 局部变量**不会污染全局名字空间** ——
模板|//   别的文件、别的函数看不到它。这是它比全局变量好的地方。
模板|//
模板|// ⚠ 和全局变量共有的坑：**它让函数有了"记忆"**，
模板|//   于是同一个函数调两次结果不一样 —— 测起来、读起来都更麻烦。
模板|//   真实项目里它常用于：调用计数、只初始化一次的资源、随机数种子。
模板|//   但**能不用就不用**，因为它是一种隐藏状态。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//   ① int 影子()
模板|//      在函数**里面**声明一个叫 `数` 的局部变量并赋值为 5，返回它。
模板|//      （文件顶部已经有一个全局 `数 = 100`，你会亲眼看到名字被遮蔽。）
模板|//
模板|//   ② int 计数器()
模板|//      用一个 `static int` 局部变量，每调一次加一，返回当前值。
模板|//      第一次返回 1，第二次返回 2，依此类推。
模板|//
模板|// 提示：不用写 main。
模板|
模板|// ── 在下面写你的两个函数 ──
模板|
答案|/* ⚠ 全局变量：文件里到处都能用（这一课用它演示"遮蔽"） */
答案|int 数 = 100;
答案|
答案|int 影子() {
答案|    /* ⚠ 这里**重新声明**了一个同名的 数 —— 它遮蔽了全局那个。
答案|       函数里所有 `数` 指的都是这一个（值是 5）。
答案|       全局那个 100 **一点没变**。 */
答案|    int 数 = 5;
答案|    return 数;
答案|}
答案|
答案|int 计数器() {
答案|    /* ⚠ static 的两层意思：
答案|         ① 只初始化一次（不是每次调用都变回 0）
答案|         ② 函数返回之后它**不消失**
答案|       但它的名字仍然只有这个函数里能看见 —— 作用域没变。 */
答案|    static int 次数 = 0;
答案|    次数++;
答案|    return 次数;
答案|}

@@@ 11_递归
标题|第 11 课：递归 —— 函数调用自己
要求|写两个递归函数：int 阶乘(int n) 和 int 斐波那契(int n)
模板|// 第 11 课：递归 —— 函数调用自己
模板|//
模板|// 先介绍：把一个问题的答案，说成"小一号的同一个问题"的答案
模板|//
模板|//     阶乘 n! = 1 × 2 × 3 × ... × n
模板|//
模板|//     用循环写（你已经会了）：
模板|//         int 结果 = 1;
模板|//         for (int i = 2; i <= n; i++) 结果 *= i;
模板|//
模板|//     用递归写 —— 换个说法：
模板|//         n! = n × (n-1)!
模板|//         "n 的阶乘 = n 乘上「n-1 的阶乘」"
模板|//
模板|//     int 阶乘(int n) {
模板|//         if (n <= 1) return 1;      ← ① 什么时候停
模板|//         return n * 阶乘(n - 1);    ← ② 用"小一号的答案"拼出答案
模板|//     }
模板|//
模板|//  这个函数里出现了自己的名字 —— 这就是递归。
模板|//  它不会无限循环下去，因为每一层的 n 都比上一层**小一号**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠⚠ 递归必须有的两样东西
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//   ① **基准情形**（base case）—— 什么时候**不再**调用自己，直接给答案。
模板|//        上面那行 `if (n <= 1) return 1;` 就是它。
模板|//
模板|//   ② **每次都在变小** —— 参数必须朝着基准情形走。
模板|//        `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1。
模板|//
模板|//   ⚠⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看。**
模板|//
模板|//      int 阶乘(int n) {
模板|//          return n * 阶乘(n - 1);      /* 没有基准情形 */
模板|//      }
模板|//
模板|//   它会一直调用下去，每调一次就在内存里压一层（叫"调用栈"），
模板|//   直到把栈用完 ⇒ 崩溃。这个错叫**栈溢出**（stack overflow）。
模板|//
模板|//   ⚠ 在 Windows 上你看到的多半是程序直接消失、退出码不是 0，
模板|//     而不是一句好看的报错。
模板|//     **这就是递归最需要小心的地方：它不会好好告诉你哪里错了。**
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  为什么值得学：有些问题用递归写短得多
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  阶乘用循环写就挺好，递归没占到便宜。但下面这类问题：
模板|//
模板|//     · 文件夹里还有文件夹，一层套一层 —— 怎么数所有文件？
模板|//     · 一棵树，每个节点还有子树 —— 怎么遍历？
模板|//     · 汉诺塔、走迷宫、表达式求值
模板|//
模板|//  **它们本身就是递归定义的**，用循环写要自己造一个"栈"来记住位置，
模板|//  用递归写则几乎是直译。这一课先在小问题上把套路练熟。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 一个反例：斐波那契**不该**用这种递归写
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//      fib(n) = fib(n-1) + fib(n-2)
模板|//
模板|//  按这个式子直接写成递归：
模板|//
模板|//      int 斐波那契(int n) {
模板|//          if (n <= 1) return n;
模板|//          return 斐波那契(n - 1) + 斐波那契(n - 2);   ← 能算对，但极慢
模板|//      }
模板|//
模板|//  ⚠⚠ 它**能算出正确答案**，但算 fib(40) 要调用自己上**亿**次。
模板|//     为什么：算 fib(5) 要 fib(4) 和 fib(3)，而 fib(4) 又要 fib(3) ——
模板|//     **同一个 fib(3) 被重复算了无数遍**。这叫"重叠子问题"。
模板|//
模板|//  这一课仍然让你这么写，因为**它最能训练"递归思维"**，
模板|//  而且检查只喂到 n ≤ 20（够快）。但你要记住：
模板|//
模板|//     ⚠ **能写出递归，不等于该用递归。**
模板|//       判断依据是"有没有大量重复计算"，不是"写起来短不短"。
模板|//
模板|//  （正式的做法叫"记忆化"：把算过的答案存起来，下次直接查表。）
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  ⚠ 顺便认识一个 C++ 特有的坑：递归深度
模板|// ─────────────────────────────────────────────────────
模板|//
模板|//  就算基准情形写对了，递归**太深**照样崩 ——
模板|//  因为每层都要占一块栈内存，栈是**有限**的（通常几 MB）。
模板|//
模板|//     阶乘(10)      10 层，没问题
模板|//     阶乘(100000)  十万层 ⇒ **栈溢出**
模板|//
模板|//  ⇒ 递归适合"层数不深"的问题。要处理很深的层级时，
模板|//    要么改成循环，要么显式用一个容器当栈。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了 —— 在下面写
模板|// ─────────────────────────────────────────────────────
模板|//   写两个**递归**函数（不许用循环）：
模板|//
模板|//     1. int 阶乘(int n)          0! 和 1! 都是 1
模板|//     2. int 斐波那契(int n)       fib(0)=0, fib(1)=1, fib(2)=1, fib(3)=2 …
模板|//
模板|//   ⚠ 两个都必须有**基准情形**，而且参数要**每次变小** ——
模板|//     少了任何一样，检查会看到程序崩溃。
模板|//
模板|//   ⚠ `阶乘(13)` 就已经超出 int 的范围了（13! ≈ 62 亿 > 21 亿），

模板|//
模板|// 提示：不用写 main。
模板|
模板|// ── 在下面写你的两个函数 ──
