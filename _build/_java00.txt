@@@ 00_跑通第一个程序
标题|第 00 课：跑通第一个程序 —— 把 JDK 装好
要求|1. 确认 javac / java / dotnet 都在（本课会真的去调它们）
要求|2. 搞清楚 Java 的程序结构和别的语言哪里不一样
要求|3. 让编译器报一次错，并且学会从第一条 error 读起
模板|// 第 00 课：跑通第一个程序 —— 把 JDK 装好
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  先介绍：本课的唯一目标
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠⚠ 这一课**不教语法**，只干一件事：让你这台机器真的能编译、能运行。
模板|//
模板|//    为什么把它排在第 00 课：
模板|//      Java **不是"装上就能跑"的语言** —— 它要 JDK，而网上大量教程
模板|//      让人装的是 JRE。**JRE 里没有 javac**，于是他永远编不过，
模板|//      还找不到原因。这一步值得单独占一课。
模板|//
模板|//    还有一个理由：所有教程里，**"卡在装工具"是放弃率最高的一步**。
模板|//      大多数人不是学不会编程，而是在"第一步就跑不起来"那里放弃了。
模板|//
模板|//    跑通之后你拿到的是**信心**：后面每一课的报错才都是"我写错了"，
模板|//      而不是"环境又怎么了"。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  用法与例子：需要什么、Java 程序长什么样
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// 一、需要什么（两样，都是免费的）
模板|//
模板|// ① .NET SDK —— 课程运行器。它替你调 javac 和 java，并跑起来看结果。
模板|//
模板|//      winget install Microsoft.DotNet.SDK.8
模板|//
模板|//    ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
模板|//
模板|// ② JDK —— Java 的开发包。**不是 JRE。**
模板|//
模板|//      winget install Microsoft.OpenJDK.21     （或去 adoptium.net 下 Temurin）
模板|//
模板|//  ⚠⚠ **JDK ≠ JRE** —— 这是这一课最重要的一句话：
模板|//
模板|//        JRE = Java Runtime Environment    只能**运行**别人编好的程序
模板|//        JDK = Java Development Kit        = JRE + **javac 编译器** + 工具
模板|//
模板|//    只装 JRE 的话，`java` 有、`javac` 没有 —— 而你要**自己写代码**，
模板|//    就必须要 javac。报错会是「找不到 javac」或「不是内部或外部命令」。
模板|//
模板|//  装完**重开一个窗口**（让 PATH 生效），敲这两条，都能看到版本号才算成：
模板|//
模板|//      javac -version
模板|//      java  -version
模板|//
模板|// 二、Java 的程序结构：和 C 完全不同的三点
模板|//
模板|// ① **不能有游离的代码。** 每一样东西都必须装在一个**类**里面。
模板|//
模板|//      Python 可以:   print("hi")                    ← 文件顶层直接写
模板|//      C 可以:        int main() { printf(...); }    ← 函数里直接写
模板|//      Java 不行:     必须 类 → 方法 → 语句，一层套一层
模板|//
模板|//   在文件顶层直接写一句 System.out.println("hi"); 会报：
模板|//      Main.java:1: 错误: 需要类、接口、批注类型、枚举、记录、方法或字段
模板|//
模板|// ② **入口方法长这样**，一个字都不能错：
模板|//
模板|//      public static void main(String[] args) { ... }
模板|//      ↑      ↑      ↑    ↑      ↑
模板|//      公开   静态   无返回 方法名  参数（一个字符串数组）
模板|//
模板|//   少了 static ⇒ 老版本 JDK 上程序起不来 —— Java 新手最常卡的第一处。
模板|//   ⚠ 但 **JDK 25 放宽了这条**：漏 static、漏 public、甚至没参数，
模板|//     实测都能编译能跑。所以「在我机器上能跑」不等于写对了。
模板|//
模板|// ③ **public 的类名必须和文件名一致**（区分大小写）：文件叫 Main.java，
模板|//   类就必须叫 `public class Main`；写成 public class main 会编译报错。
模板|//   这一条**别的语言都没有**。C 的 main 是小写的函数，而 Java 的 main 是
模板|//   方法、类才是外壳 —— 别把两件事混起来。
模板|//
模板|// ④ 它还多一层：字节码（不是机器码）
模板|//
模板|//      Main.java  --(javac)-->  Main.class  --(java Main)-->  结果
模板|//                                 ↑ 字节码，由 JVM 在运行时翻译
模板|//
模板|//   ⚠ 所以运行的时候写的是 **java Main**（一个**类名**，不带后缀）：
模板|//        java Main.class     ✗ 错误: 找不到或无法加载主类 Main.class
模板|//        java Main.java      ⚠ 新版 JDK（11 起）碰巧也能跑 —— 它把源码
模板|//                              直接编译再运行，另一套机制。别依赖它。
模板|//
模板|// 三、这一课唯一要练的手艺：读第一条 error
模板|//
模板|//  Java 的报错长这样（这是**故意写错**的代码）：
模板|//
模板|//      Main.java:5: 错误: 需要';'
模板|//          System.out.println("你好")
模板|//                                 ^
模板|//      1 个错误
模板|//
模板|//  拆开看：**哪个文件、第几行、什么错**。先看行号。
模板|//
模板|//  ⚠⚠ **两条铁律**：① **只看第一条 error** —— 后面那几十条多数是它引起的
模板|//   连锁反应；② **报错行号常常要往上多看一行** —— 编译器是读到"它不认识的
模板|//   东西"才报的错，而那个东西往往是**上一行**漏了什么造成的。
模板|//
模板|//  ⚠ 本机是中文环境，javac 的报错就是中文的。换一台英文环境的机器，
模板|//    同样的错会写成 `error: ';' expected` —— **是同一件事**。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  常见坑
模板|// ─────────────────────────────────────────────────────
模板|//
模板|// ⚠ 坑 1：装的是 JRE，不是 JDK
模板|//
模板|//     winget install Microsoft.OpenJDK.21     ← 对的
模板|//     （网上很多教程让人装"Java 运行时 / JRE"—— 那个**没有 javac**）
模板|//
模板|// 你会看到：敲 `javac -version` 说「不是内部或外部命令」，或者课程检查
模板|//   一上来就红，写着「工具链还没装好」。
模板|// 为什么：**编译器 javac 只在 JDK 里**；JRE 是给"只想运行别人程序"的人用的。
模板|// ⇒ 再装一次 JDK 就好，两个可以共存，不用先卸。
模板|//   ⚠ 这条**不是你代码的问题** —— 第一项检查专门在说这件事。
模板|//
模板|// ⚠ 坑 2：装完不重开窗口
模板|//
模板|// 你会看到：`javac` 还是"不是内部或外部命令"—— 明明刚才装的时候提示成功了。
模板|// 为什么：安装程序改的是 **PATH 环境变量**，而已经打开的窗口用的是
模板|//   **打开那一刻**的 PATH 副本。
模板|// ⇒ 关掉窗口重新开一个（或者干脆注销一次）。
模板|//   ⚠ 这个坑在 C 线（装 gcc）和 C# 线（装 .NET SDK）**一模一样**，
模板|//     凡是"装完说找不到命令"，先想这一条。
模板|//
模板|// ⚠ 坑 3：运行的时候把 .class / .java 也写上去
模板|//
模板|//     java Main.class
模板|//
模板|// 你会看到：错误: 找不到或无法加载主类 Main.class
模板|//   原因: java.lang.ClassNotFoundException: Main.class
模板|// 为什么：`java` 收的是**类名**，它自己去 classpath 上找 Main.class；
模板|//   你多写的那截后缀被当成了类名的一部分，自然找不到。
模板|//   ⚠ 这条**不是编译错误** —— 编译早就成功了，是"运行"那一步的命令写错了。
模板|//
模板|// ⚠ 坑 4：类名和文件名不一致
模板|//
模板|//     public class main { ... }        ← 文件叫 Main.java，类却叫 main
模板|//
模板|// 你会看到：Main.java:1: 错误: 类 main 是公共的, 应在名为 main.java 的文件中声明
模板|// 为什么：**一个 .java 文件里的 public 类，名字必须和文件名一模一样**
模板|//   （连大小写都要一样）。这是 Java 独有的规矩。
模板|// ⇒ 这个文件叫 Main.java，所以类只能叫 `public class Main`。
模板|//
模板|// ─────────────────────────────────────────────────────
模板|//  轮到你了
模板|// ─────────────────────────────────────────────────────

模板|//    1. 确认 javac、java、dotnet 都在

答案|       Main.java:5: error: ';' expected
答案|   意思是「第 5 行这里我以为该有个分号」。
答案|
答案|   ⚠ 如果报错是「类 Main 是公共的, 应在名为 Main.java 的文件中声明」，
答案|     那是**类名和文件名不一致** —— Java 特有的规矩。
答案|
答案|   程序结构是三层：类 → 方法 → 语句。
答案|   Java 里没有「游离的代码」，任何一行都必须待在这三层里面。 */
答案|public class Main {
答案|    public static void main(String[] args) {

答案|        System.out.println("类 → main → 语句");
