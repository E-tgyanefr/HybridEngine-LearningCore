// 第 02 课：输入与计算 —— 让程序接收数据
//
// ─────────────────────────────────────────────────────
//  先介绍：程序得能"听"
// ─────────────────────────────────────────────────────
//
// 第 01 课的程序只会自己说话，不会听 —— 想换一组数据，只能改代码再跑。
// 这一课让程序**接收输入**：从此同一个程序能处理不同的数据。
//
// 但"输入 + 计算"在 Java 里带来两个**不报错的坑**，这一课的重点全在这里：
//
//   ① **两个 int 相除，结果还是 int**：7 / 2 得 3，不是 3.5。
//      编译不报错、运行不警告 —— 它就这么安安静静地把小数丢掉了。
//
//   ② **nextInt() 读到不是整数的东西会抛异常**：InputMismatchException，
//      不处理的话程序**当场结束**。
//      ⚠ 这一点和 C++ **相反**：C++ 的 cin 是"静默失败"（不抛异常、把变量
//      写成 0、后面的读入全部失效，程序照跑）；Java 是"当场抛异常"，
//      把问题立刻摆出来。两种设计各有代价，你必须知道自己这门是哪种。
//
// 为什么这两件事值得单占一课：因为它们都是"**看起来成功了，其实错了**"的
//   类型 —— 初学者最怕这种。报错反而好办，不报错才难查。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
// ① Scanner：Java 读输入的标准工具
//
//     import java.util.Scanner;                        ← 写在文件**最上面**
//
//     public class Main {
//         public static void main(String[] args) {
//             Scanner 输入 = new Scanner(System.in);    ← 建一个读数器
//             String 姓名 = 输入.nextLine();            ← 读一整行
//             int 甲 = 输入.nextInt();                  ← 读一个整数
//         }
//     }
//
//   ⚠ import 必须写在 **class 外面**（文件最上面）。写在 class 的 { } 里面，
//     javac 会报「非法的类型开始」；忘了 import 则报「找不到符号：类 Scanner」。
//     java.lang 里的东西（String、System）不用 import，别的东西都要。
//
// ② 三个最常用的读法
//
//     输入.nextLine()       读**一整行**（读到回车为止），结果是 String
//     输入.nextInt()        读一个**整数**，结果是 int
//     输入.hasNextInt()     问一句："下一个东西是整数吗？" 结果是 boolean
//
//   nextInt 读的是"一个词"，nextLine 读的是"一整行" —— 分工不同。
//
// ③ 整数除法：小数会被丢掉（不是四舍五入）
//
//     int 甲 = 7, 乙 = 2;
//     甲 / 乙              ⇒ 3      ← 丢掉小数，**不是**四舍五入
//     9 / 2                ⇒ 4
//     (甲 + 乙) / 2        ⇒ 4      ← 先按整数算出 4，再存进哪里都还是 4
//
//   想要小数，得让除号两边**至少有一个是小数**：
//
//     (甲 + 乙) / 2.0      ⇒ 4.5    ← 最省事
//     (double)(甲 + 乙) / 2 ⇒ 4.5   ← 或者把其中一个转成 double
//
//   ⚠ 特别注意这一种写法**也是错的**：
//         double 平均 = (甲 + 乙) / 2;
//     右边先按整数算出 4，**然后**才变成 4.0 存进去。类型写成 double 只能
//     决定"结果装在哪"，决定不了"怎么算"。一句话：**除号两边至少要有一个
//     是小数，除法才按小数算。**
//
// ④ 读之前先问一句，能躲开异常
//
//     if (!输入.hasNextInt()) {              ← 不是整数就别读了
//         System.out.println("输入无效");
//         return;                           ← 这个 return 不能少：不往下算
//     }
//     int 甲 = 输入.nextInt();
//
//   不 return 的话，程序会拿着没读到东西的变量继续算，然后在下一次读入
//   或者除法那里抛一个**更难懂**的异常。
//
// ⑤ 顺序很重要：先 nextLine，再 nextInt
//
//     输入.nextLine()      ← 先读一整行（姓名）
//     输入.nextInt()       ← 再读数字
//
//   本课要求的顺序正好绕开了那个经典坑（见坑 4），**别调换**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
// ⚠ 坑 1：整数除法把小数丢了（本课第一个大坑）
//
//     int 甲 = 7, 乙 = 2;
//     double 平均 = (甲 + 乙) / 2;
//     System.out.println("平均数=" + 平均);        ⇒ 平均数=4.0    ✗ 应该 4.5
//
// 你会看到：**什么都不报**。编译通过、运行正常，只是值是错的 ——
//   连类型都是 double，看上去"我用了小数"，其实没有。
// 为什么：两个 int 相除，Java 先按**整数**算出 4，再把 4 变成 4.0 存进
//   double。算的时候就已经丢了小数，存的时候救不回来。
// ⇒ 除号两边至少有一个写成小数：
//       double 平均 = (甲 + 乙) / 2.0;              ✓
//       double 平均 = (double)(甲 + 乙) / 2;         ✓
//   ⚠ 对照着记：7 / 2 得 3（整数商），7 / 2.0 得 3.5（小数商）。
//
// ⚠ 坑 2：import 忘了写，或者写错了位置
//
//     public class Main {
//         import java.util.Scanner;          ← ✗ 写在 class 里面了
//     }
//
// 你会看到：错误: 非法的类型开始
//   （跟着还有一条：错误: 需要<标识符>）
// 为什么：**import 只能出现在文件最上面、class 外面**。class 的花括号里
//   只允许放"成员"（字段、方法），import 不是成员。
// ⇒ 把它挪到第 1 行：
//       import java.util.Scanner;
//
//       public class Main { ... }
//
//   ⚠ 另一种写法是**根本没写 import**：
//       Scanner 输入 = new Scanner(System.in);
//     你会看到：错误: 找不到符号   符号: 类 Scanner   位置: 类 Main
//     为什么：Java 不知道 Scanner 是哪来的 —— java.lang 里没有它。
//
// ⚠ 坑 3：nextInt() 读到不是整数的东西 —— 程序当场结束
//
//     int 甲 = 输入.nextInt();        ← 输入是 abc 的时候
//
// 你会看到：
//     Exception in thread "main" java.util.InputMismatchException
//         at java.base/java.util.Scanner.nextInt(Scanner.java:2297)
//         at Main.main(Main.java:8)
//   程序在这里就停了，后面的活一行都干不了。
// 为什么：Scanner 的 nextInt 读不到整数就**抛异常**。
//   ⚠ 这和 C++ **正好相反**：C++ 的 cin 读失败是**一声不吭**的 ——
//     不抛异常、把变量写成 0、后面的读入全部失效，程序继续跑。
//     Java 的选择是当场抛异常。这是好意（错误不会被藏起来），
//     代价是你不处理就全停。
// ⇒ 读之前先问一句（推荐，最干净）：
//       if (!输入.hasNextInt()) {
//           System.out.println("输入无效");
//           return;
//       }
//       int 甲 = 输入.nextInt();
//
// ⚠ 坑 4：先 nextInt() 再 nextLine()，那个 nextLine 读到的是"剩下的东西"
//
//     int 甲 = 输入.nextInt();          ← 输入这一行是 "7 2"
//     String 姓名 = 输入.nextLine();    ← 读到的**不是下一行**
//
// 你会看到：姓名 里装的是 " 2"（这一行**剩下**的部分）；如果数字后面就是
//   回车，那它读到的是**空串**。程序不报错，只是名字是空的。
// 为什么：nextInt() 只吃掉**数字本身**，把这一行剩下的东西（空格、以及
//   结尾那个回车）**留在原地**。紧跟其后的 nextLine() 读到的是"这一行剩下
//   的部分"，而不是下一行。这是分工不同，不是 bug。
// ⇒ 本课要求的顺序（先读姓名、再读数字）正好绕开它，**别调换**：
//       ① 先  String 姓名 = 输入.nextLine();      读整行
//       ② 再  int 甲 = 输入.nextInt();            读数字
//
// ⚠ 坑 5：整数除以 0 —— 直接抛异常（不是 Infinity）
//
//     int 甲 = 0;
//     System.out.println(10 / 甲);
//
// 你会看到：Exception in thread "main" java.lang.ArithmeticException: / by zero
// 为什么：**整数除法除以 0 会抛异常**。
//   ⚠ 小数不一样：10.0 / 0 得到的是 Infinity，**不抛异常**。别记混。
// ⇒ 分母是用户给的数时，先判断一下它是 0 吗。
//   ⚠ 顺带一条编译期的坑：写成 int 甲;（不给初值）再在 try 里赋值，
//     后面用到 甲 的地方会**编译不过**：错误: 可能尚未初始化变量甲。
//     Java 要求"每一条能走到使用点的路径上都赋过值"。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
// ⚠ 写一个**完整的程序**（import + public class Main + main 方法）。
//
//   1. 用 Scanner 读入：
//        · 先读**一行**姓名    →  输入.nextLine()
//        · 再读两个整数        →  输入.nextInt() 两次，存进 int 甲、int 乙
//
//   2. 打印一行    你好，<姓名>
//   3. 打印一行    商=...        （甲 除以 乙 的整数商；输入 7 2 → 商=3）
//   4. 打印一行    平均数=...    （必须带小数；输入 7 2 → 平均数=4.5）
//   5. 两个数里只要有一个不是整数，就打印「输入无效」，并且**不要再往下算**
//
// 检查时程序会自动拿到一组固定输入（就像有人替你敲了键盘），
// 你不需要自己敲，直接跑检查就行：
//     第一组  小明 / 7 / 2      期望  你好，小明 / 商=3 / 平均数=4.5
//     第二组  小明 / 10 / 4     期望  你好，小明 / 商=2 / 平均数=7.0
//     第三组  小明 / abc        期望  输入无效
//
// ⚠ 两组**不同**的输入是有意的：把答案写死的人，第二组就会露馅。
// ⚠ 「输入无效」打印完一定要 return（或者把计算放进 else 里）——
//   光打印不停下来，程序会接着拿 0 去算，然后抛一个不相干的除零异常。
//
