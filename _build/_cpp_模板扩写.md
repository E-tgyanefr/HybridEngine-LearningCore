// 第 00 课：跑通第一个程序 —— 把工具链装好
//
// ─────────────────────────────────────────────────────
//  先介绍：为什么第 00 课不教语法，只教"装工具 + 读报错"
// ─────────────────────────────────────────────────────
//
//  C++ 要先把源码**编译**成可执行文件，而这需要一个**单独安装的编译器**。
//  调研过的权威教程里，"卡在装工具"是放弃率最高的一步 ——
//  所以它值得单独占一课，而不是塞在第一课的注释里。
//
//  这一课只干三件事：
//
//     ① 让你这台机器真的能编译、能运行
//     ② 搞清楚 C++ 比 C 还多出来的那一步：**编译 → 链接 → 运行**
//     ③ 让编译器报一次错，并且学会从**第一条 error** 读起
//
//  ⚠ 第 ③ 件最容易被跳过，但它最值钱：**报错是编译器在跟你说话**。
//    第一次被它骂过的人，第二次才不慌 —— 而且是在"没人看、不扣分"的时候被骂。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  一、需要什么（两样，都是免费的）
//
//   ① .NET SDK  —— "课程运行器"。它替你敲 g++ 命令，并跑起来看结果。
//
//        winget install Microsoft.DotNet.SDK.8
//
//     ⚠ 要的是 **SDK**，不是 Runtime —— Runtime 里没有编译器。
//
//   ② g++       —— 真正的 C++ 编译器。
//
//        winget install BrechtSanders.WinLibs.POSIX.UCRT
//
//     装完**重开一个窗口**（让 PATH 生效），然后敲：
//
//        g++ --version
//
//     能看到版本号就成了（本机实测是 g++ 16.1.0）。
//
//  ⚠ 装完必须重开窗口：PATH 是"进程启动时"读进去的，
//    已经开着的窗口里永远看不到新装的东西 —— 这是最常见的"我明明装了"。
//
//  二、C++ 比 C 还多一步：编译、**链接**、运行
//
//  C 和 C++ 都是"先编译、再运行"两步。C++ 内部其实还有第三步：
//
//      main.cpp
//         ↓  编译（compile）     每个 .cpp 单独变成"目标文件"
//      main.o
//         ↓  链接（link）        把目标文件和标准库拼成一个可执行文件
//      main.exe
//         ↓  运行                    结果
//
//  为什么值得知道"链接"这一步：**链接错误和编译错误长得不一样，说的是不同的事。**
//
//      编译错误  →  "你这行代码语法不对"        例如漏了分号
//      链接错误  →  "你用了某个东西，但我找不到它"  例如函数只有声明没定义
//
//    `undefined reference to ...` 就是典型的**链接**错误（坑 3 有实测原文）——
//    看到它别去改语法，去查"那个函数/变量到底定义了没有"（多文件编译时最常见，第 16 课会再遇到）。
//
//  三、这一课唯一要练的手艺：读第一条 error
//
//  报错长这样（这是**故意写错**的代码：漏了分号）：
//
//      main.cpp:4:28: error: expected ';' before 'std'
//          4 │     std::cout << "你好" << std::endl
//            │                                ^
//
//  （⚠ 上面那条竖线是编译器画给你看的，原文里是半角的，这里换成了全角。）
//
//  拆开看四样东西：
//
//      main.cpp  :  哪个文件
//      4         :  **第几行**        ← 先看这个
//      28        :  第几列（次要）
//      error     :  严重程度
//
//  ⚠⚠ **两条铁律**：
//
//   ① **只看第一条 error。** 后面那几十条多数是它引起的连锁反应。
//      C++ 的模板报错尤其能滚出一屏 —— 全都不是你要修的。
//
//   ② **报错行号常常要往上多看一行。** 编译器是读到"它不认识的东西"
//      才报的错，而那个东西往往是**上一行**漏了什么造成的。
//
//  error 和 warning：
//
//      error    —— 编译**停了**，不会产生可执行文件（链接也不会发生）
//      warning  —— 编译**继续**，但它在提醒你"这里很可能是 bug"
//
//  ⚠⚠ **不要忽略 warning。** "能编译"不等于"能跑对"。
//     这门课后面会专门讲几个"只给 warning、但结果一定是错的"的坑。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：装完了，但当前这个窗口还看不见它
//
//  你会看到：检查时说「工具链还没装好 —— **这不是你代码的问题**。现在缺：g++」，
//      接着是「没有找到 C++ 编译器。… winget install BrechtSanders.WinLibs.POSIX.UCRT」
//    去命令行敲 g++ --version，终端会说它不认识这个命令（PowerShell 原文：
//      The term 'g++' is not recognized as the name of a cmdlet, function…）
//  为什么：PATH 是**进程启动时**读进去的。装完 g++ 之后，
//  已经开着的窗口、已经开着的编辑器，看到的还是老 PATH。
//  ⇒ **重开一个终端 / 重开这个程序**再试一次。这是"我明明装了"的头号原因。
//
//  ⚠ 坑 2：忘了 #include <iostream>
//
//      int main() {
//          std::cout << "你好" << std::endl;
//          return 0;
//      }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:2:10: error: 'cout' is not a member of 'std'
//      main.cpp:1:1: note: 'std::cout' is defined in header '<iostream>'; this is probably fixable by adding '#include <iostream>'
//  为什么：cout 不是语言关键字，它只是 iostream 这个头文件里**声明**的东西。
//  编译器从上往下读，读到 cout 时没见过它 —— 于是说"std 里没这个名字"。
//  ⚠ note 那一行已经把改法写给你了：加上 #include <iostream>。
//
//  ⚠ 坑 3：函数只有声明、没有定义（这是**链接**错误，不是语法错误）
//
//      int 加一(int n);            ← 只说了"有这么个函数"
//      int main() { std::cout << 加一(4); return 0; }   ← 但谁都没实现它
//
//  你会看到（g++ 原文，实测；中间那一长串是临时文件路径，略掉了）：
//      ld.exe: C:\...\xxxx.o:main.cpp:(.text+0xf): undefined reference to `加一(int)'
//      collect2.exe: error: ld returned 1 exit status
//  为什么：编译这一关过了（"加一"这个名字确实被声明过），
//  但**链接**那一关找不到它的实现 —— 于是整个程序拼不起来。
//  ⚠ 这正是"编译错误和链接错误不是一回事"的现场：
//    `error:` 说的是"你这行语法不对"，`undefined reference` 说的是"你用了它，找不到它"。
//  （顺便注意：链接错误里中文函数名**没有**被转义，直接就是「加一(int)」。）
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//
//  这一课没有算法要写，只有三件事：
//
//    1. 确认 g++ 和 dotnet 都装好了（界面首页的「环境自检」会显示；敲 g++ --version 也行）
//
//    2. 让编译器**报一次错**，并且读懂它
//       下面留了一个 main。先故意漏掉一个分号 → 检查 → 看报错 → 把分号补上 → 再检查。
//
//    3. 让它打印出下面这三行，就算跑通了
//
//          工具链就绪
//          我准备好学 C++ 了
//          编译 → 链接 → 运行
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────
//  这一课在界面上点「检查」就行。
//  命令行（在源码目录里）：
//
//      dotnet run --project csharp/cpp-lessons 检查 00
//
//  看这一课要干什么：dotnet run --project csharp/cpp-lessons 00
//  看答案（先自己写一遍）：dotnet run --project csharp/cpp-lessons 答案 00
//
//  卡住了？把报错连同你的代码发出去问，比空想快得多。

// ── 在下面写你的代码 ──

#include <iostream>

int main() {
    std::cout << "工具链就绪" << std::endl;
    /* ⚠ 先故意把下面这一行的分号删掉，检查一次，看看编译器怎么说。
       读完报错再把分号补回来。 */
    std::cout << "我准备好学 C++ 了" << std::endl;
    std::cout << "编译 → 链接 → 运行" << std::endl;
    return 0;
}

// 第 01 课：输出 —— 让程序开口说话
//
// ─────────────────────────────────────────────────────
//  先介绍：程序的第一件事是"会说话"
// ─────────────────────────────────────────────────────
//
//  一个程序如果什么都不显示，你就无从知道它到底算了个啥。
//
//      没有输出 → 你只能"猜"自己对不对
//      有输出   → 你能看见结果，也就有了自己排查问题的能力
//
//  所以这一课先学**打印**，再学**变量** —— 这两件事之后每一课都要用：
//
//      打印   std::cout << "你好，C++" << std::endl;
//      变量   int 甲 = 6;
//
//  一个是"能看见"，一个是"能记住"。缺一个，后面的课都做不下去。
//
//  C++ 的程序长这样（和第 00 课见过的一样，多了一个变量）：
//
//      #include <iostream>          ← 让程序认识 std::cout
//
//      int main() {                 ← 程序从这里开始跑
//          int 甲 = 6;              ← 定义一个整数变量
//          std::cout << 甲 << std::endl;
//          return 0;                ← 告诉系统"正常结束"
//      }
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 打印一行字
//
//      std::cout << "你好，C++" << std::endl;
//
//  从左往右读：
//
//      std::cout       标准输出（屏幕）
//      <<              把右边的东西送进去
//      "你好，C++"     要打印的文字，**必须放在双引号里**
//      std::endl       换行（顺便把输出刷出去）
//      ;               每条语句末尾的**分号，必须有**
//
//  ② 变量：给一个值起个名字
//
//      int 甲 = 6;
//      int 乙 = 7;
//
//          int    甲    =   6   ;
//          ↑      ↑    ↑   ↑   ↑
//        类型    名字 赋值 值  分号
//
//  ⚠ **类型必须写**。这一点和 Python 很不一样：
//
//      Python:   甲 = 6            ← 不写类型
//      C++:      int 甲 = 6;       ← 必须写（告诉编译器它装的是整数）
//
//  ③ 把变量打出来
//
//      std::cout << 甲 << std::endl;                 ⇒ 6
//      std::cout << 甲 + 乙 << std::endl;            ⇒ 13
//      std::cout << "和是" << 甲 + 乙 << std::endl;   ⇒ 和是13
//
//  第三种最常用：一眼就能看懂打印的是什么，以后查问题全靠它。
//
//  ④ 换行有两种写法，效果一样
//
//      std::cout << "第一行" << std::endl;     ← endl：换行 + 刷新缓冲
//      std::cout << "第二行" << "\n";          ← "\n"：只换行（更快）
//
//  ⚠ 不写换行会怎样：两次打印会**挤在同一行**（见坑 3）。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：漏了分号
//
//      std::cout << "你好，C++" << std::endl
//      return 0;
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:4:42: error: expected ';' before 'return'
//  为什么：编译器一路读到 `return`，才发现上一句没说"结束"。
//  ⚠ 报的是第 4 行，可该补分号的是**第 3 行** —— 往上多看一行。
//
//  ⚠ 坑 2：用了中文标点
//
//      std::cout << "你好，C++" << std::endl；      ← 末尾是全角分号
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:4:38: error: 'endl\U0000ff1b' is not a member of 'std'; did you mean 'endl'?
//  为什么：全角分号 **；** 不是分号，它被当成了标识符的一部分 ——
//  报错里那串 \U0000ff1b 就是它的"学名"（字符 U+FF1B）。
//  ⚠ "明明看着有分号"却报错，多半就是中文标点。
//    同理还有引号 “ ” 、括号 （ ） 、逗号 ，和冒号 ：。
//
//  ⚠ 坑 3：忘了换行
//
//      std::cout << "你好，C++";
//      std::cout << 13;
//
//  你会看到：**编译通过**，可输出只有一行：
//      你好，C++13
//  为什么：cout 只管把东西"接着"送出去，换不换行由你决定 ——
//  不写 std::endl 也不写 "\n"，两句话就粘在一起了。
//
//  ⚠ 坑 4：漏了 #include <iostream>，或者漏了 std::
//
//      int main() { std::cout << "你好" << std::endl; return 0; }     ← 少了 #include
//      int main() { cout << "你好" << endl; return 0; }               ← 少了 std::
//
//  你会看到（两种写法的 g++ 原文，实测）：
//      main.cpp:2:10: error: 'cout' is not a member of 'std'
//      main.cpp:1:1: note: 'std::cout' is defined in header '<iostream>'; this is probably fixable by adding '#include <iostream>'
//      main.cpp:4:5: error: 'cout' was not declared in this scope; did you mean 'std::cout'?
//  为什么：cout 不是关键字，它住在 std 命名空间里、声明在 iostream 里。
//  两样都得对：**头文件**要有、**std::** 要有。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//  本课的作业是一个**完整的程序**（要自己写 #include 和 main）：
//
//    1. 打印一行文字：你好，C++
//    2. 定义 int 变量 甲 = 6、int 变量 乙 = 7
//    3. 打印它们的和
//
//  ⚠ 第 3 步要**真的用变量相加**（std::cout << 甲 + 乙），
//    不要写死 std::cout << 13; ——
//    检查会把变量的初值改掉再跑一遍：真用变量，输出就跟着变；
//    写死答案，输出纹丝不动。骗不过去，而且那样你也学不到"变量"是什么。
//
//  期望输出两行：
//
//      你好，C++
//      13
//
// ─────────────────────────────────────────────────────
//  怎么自己测
// ─────────────────────────────────────────────────────

// 第 02 课：输入与计算
//
// ─────────────────────────────────────────────────────
//  先介绍：让程序学会"听"
// ─────────────────────────────────────────────────────
//
//  第 01 课的程序只会自己说话，不会听。
//  于是每换一组数据，你都得回去改代码 —— 那不是程序，那是一张写死的纸条。
//
//      01 课：  int 甲 = 6;        数字写在代码里，换数据就得重新编译
//      02 课：  std::cin >> 甲;    数字由使用者给，同一个程序处理不同数据
//
//  这一课学两件事：**读输入** 和 **算除法**。
//  而它们各带一个"不会报错"的坑，这一课的重点全在这里：
//
//      · std::cin 读到非数字时**静默失败** —— 不抛异常、不停下，程序拿着错数据继续跑
//      · 两个 int 相除，结果还是 int：7 / 2 得 3，不是 3.5
//
//  编译器对这两件事一声不吭。所以下面每个坑都值得单独看一眼。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 读一个整数
//
//      int 甲 = 0;             ← C++ 的变量必须先写类型
//      std::cin >> 甲;         ← >> 的方向是"从 cin 流进 甲"
//
//  ② 连着读两个
//
//      int 甲 = 0;
//      int 乙 = 0;
//      std::cin >> 甲 >> 乙;   ← 从输入里依次取两个数
//
//  ③ 读完**立刻检查**成功了没有（本课第一个重点）
//
//      if (!(std::cin >> 甲 >> 乙)) {
//          std::cout << "输入无效" << std::endl;
//          return 0;                     ← 不往下算
//      }
//
//  为什么必须查：输入 abc 时 cin **不报错**，只是把 甲 写成 0，
//  然后让程序继续跑 —— 你就拿着 0 去做除法了。
//  等价写法：std::cin.fail()（它和上面那句问的是同一件事）。
//
//  ⚠ 一旦读失败，后面的 >> 会**全部什么都不做**：
//    「7 abc」这种"一半对一半错"的输入，第一个数进去了，第二个还是 0。
//
//  ④ 整数除法 vs 小数除法（本课第二个重点）
//
//      7 / 2      ⇒ 3      ← 两个 int 相除，**小数部分直接丢掉**（不是四舍五入）
//      9 / 2      ⇒ 4
//      7 / 2.0    ⇒ 3.5    ← 除号两边只要有一个是小数，就按小数算
//
//  ⚠ 下面这种写法**也是错的**（实测打印 4，不是 4.5）：
//
//      double 平均数 = (甲 + 乙) / 2;     ← 右边先按整数算出 4，再存进 double
//
//  要写成 2.0，或者先把一边转成小数：
//
//      double 平均数 = (甲 + 乙) / 2.0;
//      double 平均数 = (double)(甲 + 乙) / 2;
//
//  ⑤ 打印结果：把标签和值一起打出来
//
//      std::cout << "商=" << 甲 / 乙 << std::endl;        ⇒ 商=3
//      std::cout << "平均数=" << 平均数 << std::endl;    ⇒ 平均数=4.5
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：以为 7 / 2 会给你 3.5
//
//      double 平均数 = (甲 + 乙) / 2;      ← 甲=7、乙=2
//
//  你会看到：**什么报错都没有** —— 编译通过，-Wall 也一声不吭（实测），
//  打印出来是 平均数=4。因为除号两边都是 int，小数在赋值**之前**就被丢掉了。
//  ⚠ 它的可怕之处是"看起来像个正常答案"：4 不刺眼，你很可能就这么交了。
//
//  ⚠ 坑 2：不检查就往下算 —— 拿 0 去除
//
//      std::cin >> 甲 >> 乙;
//      std::cout << "商=" << 甲 / 乙 << std::endl;      ← 输入 abc 时 乙 是 0
//
//  你会看到（实测，输入 abc 时）：程序**直接崩**，退出码 -1073741676
//  （也就是 0xC0000094，"整数除以 0"）。屏幕上什么解释都没有。

// ─────────────────────────────────────────────────────
//  先介绍：让程序会"做选择"
// ─────────────────────────────────────────────────────
//
//  到上一课为止，程序只会一条道走到黑：读两个数、算、打印。可真实的问题几乎都带"如果"：
//
//      如果 猜的数 等于 42  → 说"对了"

//
//  if 就是干这个的：**同一个函数，不同的输入走不同的路**。
//
//      if (条件) {
//          // 条件为真时做这里
//      } else {
//          // 条件为假时做这里
//      }
//
//  ⚠ 这一课的作业是**写函数**：结果用 `return` 交出去，而不是在函数里打印 ——
//    检查会替你调用这些函数，再拿返回值去比。
//

//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 三个分支：if / else if / else
//
//      std::string 猜数字(int 猜) {
//          if (猜 == 42) {
//              return "对了";
//          } else if (猜 < 42) {
//              return "小了";
//          } else {
//              return "大了";
//          }
//      }
//
//  读作"等于 42 就……否则如果小于 42 就……否则……"。

//

//      >    大于          >=   大于或等于
//
//  ⚠ `==` 是**两个**等号。一个 `=` 是赋值（见坑 1）。
//
//  ③ 逻辑运算符：把条件连起来
//

//      ||   有一个为真就为真   （或者）
//      !    取反
//
//  闰年那一题正好两个都要用：
//
//      if ((年 % 4 == 0 && 年 % 100 != 0) || 年 % 400 == 0) { ... }
//
//  读作：「能被 4 整除 **且** 不能被 100 整除」**或者**「能被 400 整除」。

// 第 04 课：循环
//
// ─────────────────────────────────────────────────────
//  先介绍：让程序重复做事，而且重复得**正好**
// ─────────────────────────────────────────────────────
//
//  求和、计数、查找 —— 都要把同一件事做很多遍。循环就是干这个的。
//  但循环的错法和前面几课都不一样：
//
//      **它不报错，也不崩，只是把结果算错一点点。**
//
//      差一错误（off-by-one）：for (int i = 1; i < n; i++) 少跑一次
//          算 1..10 的和，它给你 45 —— 看上去像个正常答案
//      累加变量没给初值：int 和; 里面装的是内存里的残留值
//          这次碰巧是 0，结果"对了" —— 但它随时可能变成别的数
//
//  第一件编译器完全不提，第二件只给一句 warning。所以这两件事都得你自己盯。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① for：次数已知时最好用
//
//      int 和 = 0;                        ← 初值不能少
//      for (int i = 1; i <= n; i++) {     ← 初始化; 继续的条件; 每轮之后做什么
//          和 += i;
//      }
//      ⇒ 求和(5) 得 15
//
//  ⚠ 三个部分之间是**分号**，不是逗号。
//
//  ② while + continue：以条件为主
//
//      int 个数 = 0;
//      int i = 0;
//      while (i < n) {
//          i++;                           ← 先让 i 前进
//          if (i % 2 != 0) continue;      ← 奇数跳过这一轮剩下的部分
//          个数++;
//      }
//
//  ③ for + break：找到就停
//
//      for (int i = 2; i < n; i++) {
//          if (n % i == 0) { 结果 = i; break; }     ← 跳出整个循环
//      }
//
//  ④ 三种循环的分工
//
//      for        次数已知（从 1 走到 n）—— 最常用
//      while      以条件为主（不知道要跑几次）
//      do-while   **至少执行一次**（先做一遍再看条件）
//
//      break      立刻跳出整个循环
//      continue   跳过这一轮的剩余部分，直接进入下一轮
//
//  ⑤ 写完循环，先问自己两句
//
//      n = 1 时，循环该跑几次？      n = 0 时，该不该跑？
//
//  这两问能拦住绝大多数差一错误，比事后盯着 45 和 55 发呆有用得多。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：累加变量没给初值
//
//      int 和;                                  ← 里面是内存里的残留值
//      for (int i = 1; i <= n; i++) { 和 += i; }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:6:12: warning: '\U0000548c' may be used uninitialized [-Wmaybe-uninitialized]
//      main.cpp:4:9: note: '\U0000548c' was declared here
//  ⚠ 只给一句 warning，而且实测这个程序**还碰巧算对了**（打印 15）——
//    这才是它最坏的地方：你看到"结果对了"，就以为没事了。
//  为什么：C++ 的局部变量**不会自动清零**，int 和; 里是这块栈内存上剩下的东西。
//    这一点和 Python、C# 都不同（那两边的变量一定有个确定的值）。
//  改法：声明的时候就给初值 —— 累加用 0，累乘用 1，找最大值用第一个元素。
//
//  ⚠ 坑 2：for 里的分号写成了逗号
//
//      for (int i = 1, i <= n, i++) { 和 += i; }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:22: error: expected ';' before '<=' token
//      main.cpp:5:23: error: expected primary-expression before '<=' token
//      main.cpp:5:32: error: expected ';' before ')' token
//  为什么：逗号在声明里的意思是"再声明一个同类型的变量"（int i = 1, j = 2 那种），
//  于是编译器以为 `i <= n` 也是声明的一部分，读到 <= 就懵了。
//  ⚠ 后两条是第一条引起的**连锁反应** —— 补上分号它们就一起消失了。
//
//  ⚠ 坑 3：continue 之前忘了让循环变量前进
//
//      while (i < n) {
//          if (i % 2 != 0) continue;      ← 奇数直接跳回条件判断
//          i++;                           ← 永远轮不到它
//      }
//
//  你会看到：**没有任何报错**，程序就那么一直转 ——
//  检查会在 60 秒后说「程序运行超时（超过 60 秒）—— 检查有没有死循环」。

//  改法：把 i++ 放到 continue **前面**（见上面 ② 的写法）。
//
//  ⚠ 坑 4：差一错误：<= 写成了 <
//
//      for (int i = 1; i < n; i++) { 和 += i; }     ← 少加了最后一个 n
//
//  你会看到：什么都不报。求和(1) 给你 0（应该是 1），求和(10) 给你 45（应该是 55）。
//  为什么：i < n 在 i == n 时就停了，最后一轮根本没跑。
//  ⚠ 光看大数很难发现（45 也像个正常答案）—— 检查里专门放了 n = 0 和 n = 1，
//    就是为了让"少跑一次"这件事一眼现形。

//
// ─────────────────────────────────────────────────────
//  先介绍：给一段计算起个名字
// ─────────────────────────────────────────────────────
//
//  有了函数，同一个计算就不用抄第二遍；而且一段代码能**对不同输入给出不同结果**。
//
//  写一个函数，要交代清楚两件事：
//
//      返回类型 —— 这个函数交出什么？   int 交出整数，void 什么都不交
//      参数类型 —— 这个函数要什么？     int n 表示"要一个整数"
//
//  这就是 C++ 和 Python 最直接的区别：
//
//      Python:   def 双倍(n):  return n * 2          ← 不写类型
//      C++:      int 双倍(int n) { return n * 2; }    ← 返回类型、参数类型都必须写
//
//  ⚠ 判断一个函数写对没有，办法只有一个：**换几组输入多试几次**。
//    一组对了不代表函数对了 —— 检查里每一条都是这么干的。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 一个函数长这样，四个部分缺一不可
//
//      返回类型  函数名 (参数类型 参数名) {
//          函数体
//          return 结果;          ← 有返回类型的函数，最后要把结果交出来
//      }
//
//  ② 有参数、有返回值
//
//      int 双倍(int n) {
//          return n * 2;         ← n 是"这一次的输入"，拿它去算
//      }
//
//  ③ 两个参数、用 if 比一比
//
//      int 最大值(int a, int b) {
//          if (a > b) { return a; }
//          return b;             ← 走到这儿说明 a 没比 b 大
//      }
//
//  ④ void：只做事，不交出值
//
//      void 打印星星(int n) {
//          for (int i = 0; i < n; i++) {
//              std::cout << "*";
//          }
//      }
//
//  ⑤ 怎么用：把调用当成一个"值"
//
//      std::cout << 双倍(4) << "\n";      ⇒ 8
//      打印星星(3);                       ⇒ ***（它不交值，只能当语句用）
//
//  ⑥ 返回类型怎么选
//
//      int     交出整数        （双倍、最大值）
//      double  交出小数
//      void    什么都不交出    （打印星星：它只负责打印）
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：漏写返回类型
//
//      双倍(int n) { return n * 2; }        ← 前面没有 int
//
//  你会看到：**什么都没有** —— 实测 g++ 16.1.0 既不报错也不警告，
//  它默默把这个函数当成 int，程序照跑、结果还对。
//  为什么：这是 C++ 留给老代码的一个口子（隐式 int）。编译器不提醒，
//  就只能靠你自己记住：**返回类型一定要写出来**。
//  ⚠ "编译器不报错"不等于"这样写没问题"—— 这是这一课唯一一个
//    只能靠纪律守住的错误。
//
//  ⚠ 坑 2：声明了 int，函数体里却没有 return（改成在函数里打印了）
//
//      int 双倍(int n) {
//          std::cout << n * 2;              ← 打印了，但没有交出去
//      }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:1: warning: no return statement in function returning non-void [-Wreturn-type]
//  ⚠ 它**能编译**，但实测一用到函数的返回值程序就崩（退出码 -1073741819）。
//  为什么：函数答应了要交出一个 int，实际什么都没交 —— 调用方拿到的是垃圾。
//  ⇒ 分清这两句做的是完全不同的事：
//      std::cout << n * 2;     打到屏幕上，函数本身什么都没交出
//      return n * 2;           把结果交给调用它的人
//
//  ⚠ 坑 3：把 void 函数塞进 cout
//
//      void 双倍(int n) { std::cout << n * 2; }
//      std::cout << 双倍(4) << "\n";        ← 想拿它的"返回值"
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:11:15: error: no match for 'operator<<' (operand types are 'std::ostream' {aka 'std::basic_ostream<char>'} and 'void')
//  为什么：void 的意思是"我什么都不交"，而 cout 需要一个**值**才能打印。
//  改法：要交值就把返回类型改成 int；只打印就别往 cout 里塞。
//
//  ⚠ 坑 4：函数写在后面，前面就调用它
//
//      int main() { std::cout << 双倍(3); return 0; }
//      int 双倍(int n) { return n * 2; }      ← 定义在下面
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:3:27: error: '\U000053cc\U0000500d' was not declared in this scope
//  为什么：C++ **从上往下**读代码，读到 双倍(3) 时它还没见过这个函数。
//  （Python 可以"先调用后定义"，C++ 不行。）
//  改法：把函数定义放到调用之前，或者在前面写一行声明：int 双倍(int n);
//  ⚠ 那串 \U000053cc\U0000500d 就是「双倍」被转义之后的样子。
//
// ─────────────────────────────────────────────────────

// 第 06 课：数组与向量 —— 一排格子和会变长的格子
//
// ─────────────────────────────────────────────────────
//  先介绍：一次装很多个数
// ─────────────────────────────────────────────────────
//
//  前面每课都是"一个变量装一个数"。可"一个班的成绩""一串数字"怎么办？
//  那就要有一**排**格子 —— 这就是数组。
//
//      int 甲[3] = {1, 2, 3};      ← 三格，下标是 0、1、2（不是 1、2、3）
//      std::cout << 甲[0];         ← 第一格 → 1
//      std::cout << 甲[2];         ← 最后一格 → 3
//
//  而 C++ 的数组有一个**和别的语言都不一样**的脾气，必须一开始就说清楚：
//
//      **下标越界，C++ 不一定会崩。**
//
//  实测（本机 g++ 16.1.0，就是检查用的那个编译器）：
//
//      int a[3] = {1, 2, 3};
//      std::cout << a[10];        ← 程序**正常退出**，只是打印出一个垃圾值
//
//  Python 会抛 IndexError、C# 会抛异常，C++ **什么都不做** ——
//  它安静地读到了别人的内存，于是结果莫名其妙地不对。这是最难查的一类 bug。
//
//  所以 C++ 还提供了一个"会变长、而且自己知道长度"的替代品：std::vector。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 数组：固定几格
//
//      int 甲[3] = {1, 2, 3};           ← 声明时就把格数定死
//      std::cout << 甲[0] << "\n";      ← 下标从 0 开始
//
//  ⚠ 合法下标只有 0 到 长度-1。守住这条线是**你的责任**（C++ 不替你查）。
//
//  ② 数组的长度从哪来
//
//  数组**自己不知道**自己有多长，所以传进函数时要**另外**给一个长度：
//
//      int 求和(int 数[], int 长度) {        ← 长度是第二个参数，少不了
//          int 和 = 0;
//          for (int i = 0; i < 长度; i++) { 和 += 数[i]; }
//          return 和;
//      }
//
//  在"数组还在眼前"的地方（比如 main 里）可以这样量长度：
//
//      int 长度 = sizeof(甲) / sizeof(甲[0]);       ⇒ 3
//
//  ⚠ 但这一招**进了函数就不管用**了（见坑 1）。
//
//  ③ vector：会变长，而且自己知道长度
//
//      std::vector<int> 数 = {1, 2, 3};
//      数.size()          // 元素个数（C# 里的 数.Length、Python 的 len(数)）
//      数.push_back(4)    // 末尾追加一个
//      数[0]              // 也能用下标 —— 但**同样不检查越界**
//      数.at(0)           // 用 at 才会检查：越界会抛异常，而不是悄悄读垃圾
//
//  ⇒ **能用 vector 就用 vector**：长度信息跟着它走，不用你额外传，也就不会传错。
//
//  ④ 遍历
//
//      for (int i = 0; i < 长度; i++) { ... }              ← 数组版（长度是参数）
//      for (int i = 0; i < (int)数.size(); i++) { ... }    ← 向量版
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：在函数里用 sizeof 算数组长度
//
//      int 求和(int 数[], int 长度) {
//          int 算出来的 = sizeof(数) / sizeof(数[0]);
//      }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:4:29: warning: 'sizeof' on array function parameter '\U00006570' will return size of 'int*' [-Wsizeof-array-argument]
//      main.cpp:3:14: note: declared here
//  而且算出来的数是 **2**（实测）：函数里 sizeof(数) 是"一个指针的大小"8，8 除以 4 得 2 ——
//  不管你的数组真实有多长。它不报错，只是错得很安静。
//  为什么：数组当参数会"退化"成指针，长度信息在那一刻就丢了。
//  ⇒ 用**另外传进来的那个长度参数**。
//
//  ⚠ 坑 2：数组下标越界
//
//      int a[3] = {1, 2, 3};
//      std::cout << a[10] << "\n";        ← 越界读
//
//  你会看到：**编译通过，程序正常退出**，只是打印出一个每次都可能不一样的垃圾值
//  （实测两次分别见到 51 和 32758）。不报错、不崩溃、结果悄悄错掉。
//  为什么：C++ 不做下标检查。a[10] 就是"从 a 的地址往后数第 10 格"，
//  那里可能是别的变量、可能是别的函数的栈，读到什么全看运气。
//  ⚠ 越界**写**（a[10] = 5）更危险：它可能改掉别的变量的值，
//    于是你会在离这一行很远的地方看到莫名其妙的错误。
//
//  ⚠ 坑 3：拿 int 和 数.size() 直接比
//
//      for (int i = 0; i < 数.size(); i++) { ... }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:6:23: warning: comparison of integer expressions of different signedness: 'int' and 'std::vector<int>::size_type' {aka 'long long unsigned int'} [-Wsign-compare]
//  为什么：size() 给的是**无符号**的整数类型，而 i 是 int（有符号）。
//  编译器怕你在负数上出错，所以提醒一句。
//  改法：写成 (int)数.size()，或者干脆把循环变量声明成 std::size_t。
//
//  ⚠ 坑 4：长度是 0 的时候先把 数[0] 塞进结果
//
//      int 和 = 数[0];                       ← 长度 0 时，这一步已经越界了
//      for (int i = 1; i < 长度; i++) { 和 += 数[i]; }
//
//  你会看到：**没有报错**（越界不一定崩），只是答案悄悄错了 ——
//  求和(甲, 0) 本该是 0，它却给你那一格里的垃圾值。
//  为什么：见坑 2，越界读不会拦住你。
//  ⇒ 正确写法是从 0 开始、从 0 累加：
//      int 和 = 0;
//      for (int i = 0; i < 长度; i++) { 和 += 数[i]; }
//  ⚠ 边界（0 个、1 个、最后一个）是循环最容易错的地方。
//    写完先想一遍"长度是 0 会怎样"，这一课有两组用例专门等在那里。
//
// ─────────────────────────────────────────────────────

// 第 07 课：字符串 —— 'A' 和 "A" 不是一回事
//
// ─────────────────────────────────────────────────────
//  先介绍：一串字符，和一个字符
// ─────────────────────────────────────────────────────
//
//  名字、地名、提示语 —— 程序里到处是"一串字符"。C++ 里最常用的是 std::string。
//  但在用它之前，必须先分清一对**看起来只差一对引号**的东西：
//
//      'A'   单引号 → **char**，一个字符，sizeof 是 1
//      "A"   双引号 → **字符串字面量**，sizeof 是 2
//
//  多出来的那 1 个字节，是末尾隐藏的结束符 '\0'（C++ 用它标记"字符串到此结束"）。
//
//  这个区别在 C++ 里是**硬性**的，两边的类型不一样，不能互相替换：
//
//      char c = 'A';          ✓
//      char c = "A";          ✗ 类型不对（"A" 是一串字符，不是一个字符）
//      std::string s = "A";   ✓
//      std::string s = 'A';   ✗ 类型不对
//
//  另一件必须早知道的事：**std::string 存的是字节，不是"字"**。
//  实测（本机 g++ 16.1.0，源文件 UTF-8）：
//
//      std::string s = "中文";    s.size()  →  6      ← 不是 2！
//      std::string t = "中";      t.size()  →  3
//
//  UTF-8 里一个汉字要 3 个字节 ⇒ 中文的 size() 不是"几个字"，
//  而 s[0] 也不是"第一个字"，只是那个字的第一个字节。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 常用操作（这一课的六个函数全在这里面）
//
//      std::string s = "hello";
//      s.size()             5          // 有几个字节（s.length() 一样，两个名字都对）
//      s[0]                 'h'        // 下标从 0 开始，取到的是 **char**
//      s + " world"         "hello world"    // 用 + 拼接
//      s.substr(0, 3)       "hel"      // 从下标 0 开始取 3 个
//      s.find("llo")        2          // 子串第一次出现的下标
//      s.find("z")          std::string::npos    // 找不到时返回一个"不可能的下标"
//
//  ② 用 sizeof 量一量（本课要你亲手量一遍）
//
//      sizeof('A')     ⇒ 1      单引号就是一个 char，1 个字节
//      sizeof("A")     ⇒ 2      'A' 后面还藏着一个 '\0'
//
//  sizeof 是**编译期**就得出结果的，不花运行时间。它的用处不是"记住 1 和 2"，
//  而是"以后换个类型也知道怎么问编译器"。
//
//  ③ find 找不到时**不是 -1**，要自己转
//
//      std::size_t 位置 = s.find(子);
//      if (位置 == std::string::npos) { return -1; }     ← 题目约定用 -1 表示找不到
//      return (int)位置;
//
//  npos 是一个非常大的无符号数（实测打印出来是 18446744073709551615），不是 -1 ——
//  直接当 -1 用，你会得到一个"大得离谱的下标"，而不是"没找到"。
//
//  ④ 空串要单独处理
//
//      char 首字符(std::string s) {
//          if (s.empty()) { return '\0'; }      ← 单引号：一个空字符
//          return s[0];
//      }
//
//  ⚠ 空的时候要返回的是 '\0'（一个字符），不是 ""（一个空字符串）—— 类型不一样。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：把双引号的东西塞进 char
//
//      char c = "A";
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:14: error: invalid conversion from 'const char*' to 'char' [-fpermissive]
//  为什么："A" 的类型不是"一个字符"，而是"指向字符的指针"（const char*）—— 它其实是
//  "A 这个字符串住在哪"，一个字节装不下一个地址 ⇒ 一个字符要用单引号。
//
//  ⚠ 坑 2：把单引号的东西塞进 std::string
//
//      std::string s = 'A';
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:21: error: conversion from 'char' to non-scalar type 'std::string' {aka 'std::__cxx11::basic_string<char>'} requested
//  为什么：'A' 是一个 char（一个字节），std::string 是一个"管着一串字符"的对象，
//  两者之间没有现成的转换 ⇒ 一串字符要用双引号：std::string s = "A";
//
//  ⚠ 坑 3：返回类型写 char，却 return 一个 substr
//
//      char 首字符(std::string s) {
//          return s.substr(0, 1);            ← substr 给的是一串字符
//      }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:20: error: cannot convert 'std::__cxx11::basic_string<char>' to 'char' in return
//  ⚠ 这个错最阴的地方是：它打印出来也是 h，看着一模一样 —— 所以检查不看打印结果，
//    而是**量类型**（sizeof(首字符("h")) 必须是 1）。
//  为什么：substr 无论取几个，返回的都是 std::string；要一个 char 得用下标取：s[0]。
//
//  ⚠ 坑 4：以为 find 找不到会返回 -1
//
//      int 找位置(std::string s, std::string 子) {
//          return s.find(子);                ← 类型就已经不对了
//      }
//
//  你会看到：找不到时打印 **18446744073709551615**（实测就是 npos 的值），而不是 -1。
//  程序不报错，只是答案荒谬。
//  为什么：npos 是"一个不可能的下标"（无符号类型），所以是个天文数字 ⇒ 判断 `位置 == std::string::npos` 之后再 return -1; 才对。
//
//  ⚠ 坑 5：以为 size() 是"几个字"
//
//      std::string s = "中文";
//      std::cout << s.size();               ⇒ 6（实测）
//
//  你会看到：6，而不是 2。**这不是 bug，这就是 C++ 的真相**：
//  std::string 存的是**字节**，UTF-8 里一个汉字占 3 个字节。
//  对比一下：Python 的 len("中文") 是 2，C# 的 "中文".Length 也是 2。
//  ⇒ 想让 s.size() 等于"字数"，得换别的工具（这一课不涉及），但你必须知道它数的是字节。
//
// ─────────────────────────────────────────────────────

// 第 08 课：指针与引用 —— 改了参数，外面会不会变
//
// ─────────────────────────────────────────────────────
//  先介绍：这一课只回答一个问题
// ─────────────────────────────────────────────────────
//
//      **函数里改了参数，外面到底会不会变？**
//
//  答案完全取决于**参数类型**，和函数体怎么写没关系：
//
//      void f(int  n)   值传递   —— 外面**不变**（函数拿到的是复制品）
//      void f(int& n)   引用     —— 外面**会变**（n 就是外面那个变量）
//      void f(int* p)   指针     —— 要用 *p 才会变（p 装的是地址）
//
//  人的直觉通常是"传进去了，改了当然会变" ——
//  这一课就是要你**亲手把三个版本都跑一遍**，亲眼看到值传递改了等于没改。
//
//  顺带讲清野指针：`int* p;` 里装的是随机地址，`*p` 可能读到任何地方；
//  `int* p = nullptr;` 才是"明确地什么都没指"，用之前还能判断一下。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 四个符号，先记住它们各自在说什么
//
//      &甲       取地址     "甲 住在哪"（类型是 int*）
//      *p        解引用     "p 指向的那个变量"（把地址变回变量）
//      int& n    引用       n 就是外面那个变量本身，只是换了个名字
//      int* p    指针       p 装的是一个地址，要用 *p 才拿到那个变量
//
//  ② 三个版本并排看（本课的全部内容）
//
//      void 翻倍_值(int n)    { n = n * 2; }       外面 **不变**
//      void 翻倍_引用(int& n) { n = n * 2; }       外面 **会变**
//      void 翻倍_指针(int* p) { *p = *p * 2; }     外面 **会变**
//
//  ③ 为什么值传递改不动外面
//
//  调用 翻倍_值(甲) 的时候，C++ 把 甲 的值**复制**一份给 n；
//  函数里改的是那份复制品，函数一结束它就没了 —— 甲 从头到尾没被碰过。
//  引用则是"给外面那个变量起个别名"：n 和 甲 是同一个东西的两个名字。
//  指针拿到的是**地址**：p 是"甲 住在哪"，*p 才是"住在那儿的甲"。
//
//  ④ 调用时的写法不一样（最容易混的地方）
//
//      int 甲 = 5;
//      翻倍_引用(甲);      // 引用：直接传变量
//      翻倍_指针(&甲);     // 指针：要取地址，多一个 &
//
//  ⑤ 指针用之前先判断
//
//      int* p;                    ✗ **野指针**：里面是随机地址，指向哪全看运气
//      int* p = nullptr;          ✓ 空指针："明确地什么都没指"
//      if (p == nullptr) { ... }  // 用之前能判断，程序不会崩
//
//  ⇒ 规则很简单：**指针变量一定要初始化**。还不知道指哪，就先写 nullptr。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：引用参数漏写 & —— 函数就变成"改了等于没改"
//
//      void 翻倍_引用(int n) { n = n * 2; }        ← 少了 &
//
//  你会看到：**编译通过、什么都不报**，可外面的变量一点没变（实测）。
//  为什么：少了 & 就成了值传递 —— 会不会变，**只看参数类型**。
//  ⚠ 这一类错误没有任何提示，只能靠"改完再看一眼外面那个变量"的习惯抓住。
//
//  ⚠ 坑 2：传指针时忘了取地址 &
//
//      int 乙 = 5;
//      翻倍_指针(乙);              ← 传的是 5，不是"5 住在哪"
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:7:15: error: invalid conversion from 'int' to 'int*' [-fpermissive]
//      main.cpp:7:15: note: possible fix: take the address with '&'
//  为什么：int* 参数要的是地址，你给的是值 —— 类型对不上。
//  ⚠ 编译器这次特别贴心，note 里直接把改法写出来了：加一个 &。
//
//  ⚠ 坑 3：给"引用参数"传一个常量或者算式
//
//      void 翻倍_引用(int& n) { n = n * 2; }
//      翻倍_引用(5);               ← 5 不是一个变量，没有"外面"可以改
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:6:15: error: cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'
//  为什么：引用的意思是"另一个变量本身"，而 5 不是一个变量（叫右值）——
//  你让它去改谁呢？编译器不答应。
//  ⇒ 引用只能接变量：先 int 甲 = 5; 再 翻倍_引用(甲);
//    （如果函数本来就不打算改它，参数写 const int& 就能接常量 —— 那是第 09 课的事。）
//
//  ⚠ 坑 4：野指针 —— 声明了指针，却没让它指任何地方
//
//      int* p;                     ← 里面是随机地址
//      std::cout << *p << "\n";
//
//  你会看到（g++ 原文，实测）：

//
//  ⚠ 坑 5：解引用空指针
//
//      int* p = nullptr;
//      std::cout << *p << "\n";    ← 空指针**绝对不能**读
//
//  你会看到：程序立刻崩（实测退出码 -1073741819，0xC0000005）——

// 第 09 课：const 与 constexpr —— 承诺不改，和编译时就算好
//
// ─────────────────────────────────────────────────────
//  先介绍：`const` 和 `constexpr` 长得很像，但不能互换
// ─────────────────────────────────────────────────────
//
//      const       **我承诺不改它**（运行时的常量）
//      constexpr   **编译的时候它就已经是一个确定的数了**（编译期常量）
//
//  每个 constexpr 都是 const，但**反过来不成立**：
//
//      int 读一个数();                        // 运行时才知道
//      const int a = 读一个数();               // 合法：承诺不改
//      constexpr int b = 读一个数();           // 编译不过：编译时算不出来
//
//  判据很简单：**这个值在编译的时候能不能算出来？**
//
//  一、`const`：把"不该改"写进代码里
//
//      const double 圆周率 = 3.14159;
//      圆周率 = 3.14;              // 编译报错：assignment of read-only variable
//
//  它挡住的是一类具体的事故：**手滑改了一个本该固定的值**。
//  比如税率、圆周率、最大人数 —— 改错了程序照样跑，只是结果全错。
//  让编译器替你记住"这个不许改"，比靠人记住可靠得多。
//
//  ⚠⚠ **`const` 到底锁住了什么（这一课最容易搞错的一处）：**
//
//        const int* p;               // p **指向的 int** 不能改；p 自己能改（换指向）
//        int* const p = &x;          // p **自己**不能改（不能换指向）；指向的能改
//        const int* const p = &x;    // 两个都不能改
//
//     读法：**从右往左读** —— `const int* p` 读作"p 是一个指针，指向 const int"。
//     这不是"指向的东西和指针本身都不能改"，很多人第一反应会读错。
//
//  ⚠ 和 `#define`（C 那边的做法）比：`const` **有类型**，
//    所以编译器能帮你检查类型、调试器里也能看见它。
//    C++ 里**优先用 const / constexpr，不要用 #define 定义常量**。
//
//  二、`constexpr`：让编译器替你算
//
//      constexpr int 边长 = 4;
//      constexpr int 面积 = 边长 * 边长;      // 编译器**当场算出 16**
//
//  好处有两个：
//      ① 这个计算**不用等程序跑起来**，编译时就做完了（快一点）
//      ② 它能用在**必须编译时确定**的地方 —— 比如数组长度：
//
//             constexpr int 边长 = 4;
//             int 格子[边长 * 边长];          // 可以
//             const int n = 读一个数();
//             int 格子[n];                    // 标准 C++ 里不行（那是运行时才知道的）
//
//  ⚠⚠ **这就是 const 和 constexpr 最实用的一条分界线。**
//     需要"用它来定数组长度"的时候，就用编译期常量。
//
//  ⚠ 顺便说清一件常被说错的事：**`const` 也可能是编译期常量**。
//    初值是字面量时，`const int 格子数 = 12;` 一样能拿来定数组长度
//    （这是语言保证的，实测 `int 格子[格子数];` 能编过）。
//    那 `constexpr` 多出来的是什么？是**硬性要求**：
//    初值算不出来时它**当场报错**（见坑 2），而 const 只会在用它的地方才发现不行。
//
//  三、什么时候用哪个（一条实用判据）
//
//      初值是字面量、而且我要拿它定数组长度或做别的编译期计算  → constexpr
//      初值要运行时才知道（读文件、读传感器、算出来）           → const
//      只是函数参数，保证函数里不改它                          → const（放在参数上）
//
//  ⚠ 一个常见误解："用了 const 程序会变快。" 不会 —— const 是**给编译器和给人看**的约束，
//    不是性能开关。真正省时间的是 constexpr（把计算挪到编译期）。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 局部常量：把"不许改"写下来
//
//      int 圆周长的百倍(int 半径) {
//          const int 圆周率的百倍 = 314;
//          return 2 * 圆周率的百倍 * 半径 / 100;
//      }
//
//  ② constexpr 定数组长度
//
//      constexpr int 格子数 = 12;
//      int 格子[格子数];                    ← 编译期就知道要开 12 格
//
//  ③ 参数写 `const T&`：只借来看，不拿走
//
//      void 打印(const std::string& 名字) { std::cout << 名字 << "\n"; }
//
//      T         值传递    复制一份（有成本）
//      T&        引用      不复制，但函数里能改到外面
//      const T&  只读引用  不复制、也不能改 —— 所以它连常量都能接
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：给 const 变量赋值
//
//      const int 圆周率的百倍 = 314;
//      圆周率的百倍 = 315;               ← 想改它
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:18: error: assignment of read-only variable '\U00005706\U00005468\U00007387\U00007684\U0000767e\U0000500d'
//  为什么：const 就是"只读"的意思，赋值直接编译不过。
//  ⚠ 那一长串转义就是「圆周率的百倍」（g++ 会把中文标识符转义）。
//    这**正是 const 的价值**：把"手滑"从"结果悄悄错"变成"编译不过"。
//
//  ⚠ 坑 2：用 constexpr 装一个"运行时才知道"的值
//
//      int 读一个数() { return 5; }
//      constexpr int b = 读一个数();
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:4:27: error: call to non-'constexpr' function 'int \U00008bfb\U00004e00\U00004e2a\U00006570()'
//  为什么：constexpr 的初值必须是**编译期就能算出来**的，而调用一个普通函数
//  要等程序跑起来才知道结果（哪怕它永远返回 5）⇒ 这种值用 `const int b = 读一个数();`。
//
//  ⚠ 坑 3：拿"运行时才知道的 const"去定数组长度
//
//      const int n = 读一个数();
//      int 格子[n];
//
//  你会看到：**g++ 居然不报错** —— 实测它能编过、还能跑

//  为什么：g++ 把这种数组当成"变长数组"的**扩展**放过去了 ——
//  但标准 C++ 里数组长度必须是编译期常量，换别的编译器就直接编译不过。
//  ⚠ 这一条最误导人：编译器不拦你，不代表写法是对的 ⇒ 要定数组长度就用编译期常量。

//  为什么：`const int* p` 和 `int* const p` 锁的是**不同的东西**，从右往左读一遍就清楚：
//      const int* p        锁的是"指向的那个 int"   ⇒ p = &别的 可以，*p = 1 不行
//      int* const p        锁的是"p 这个指针自己"   ⇒ *p = 1 可以，p = &别的 不行
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────

// 第 10 课：作用域与生命周期 —— 变量从哪儿来、什么时候死
//
// ─────────────────────────────────────────────────────
//  先介绍：两个经常被混在一起的问题
// ─────────────────────────────────────────────────────
//
//      **作用域**（scope）    —— 这个名字在**哪几行代码**里能用？
//      **生命周期**（lifetime）—— 这个变量在**什么时候**存在？
//
//  它们相关，但不是一回事。这一课的两个例子正好把它俩分开：
//      · 局部变量：作用域是那个 `{}`，生命周期也是那个 `{}`
//      · static 局部变量：作用域**还是**那个 `{}`，但生命周期是**整个程序**
//
//  一、作用域：花括号就是边界
//
//      #include <iostream>
//
//      int 数 = 100;                    // ← 全局：这个文件里到处都能用
//
//      int main() {
//          std::cout << 数 << "\n";     // 100
//          int 数 = 5;                  // ← 局部：**遮蔽**了全局那个
//          std::cout << 数 << "\n";     // 5    ← 现在这个名字指局部的
//          {
//              int 数 = 7;              // ← 再遮蔽一层
//              std::cout << 数 << "\n"; // 7
//          }
//          std::cout << 数 << "\n";     // 5    ← 内层那个已经死了
//      }
//
//  ⚠⚠ **名字遮蔽（shadowing）是 C++ 里一个安静的坑**：
//    编译器**不会警告**（实测：-Wall 也一声不吭），
//    于是你以为在改全局那个，其实改的是局部那个。
//    典型症状："我在函数里把它改了，出来怎么没变？"
//    ⇒ 先看一眼**函数里是不是重新声明了一个同名的变量**。
//  ⚠ 再强调一次第 **08** 课讲过的事：C++ 的参数是**按值传递** ——
//    函数里的形参是**另一个**变量，改它不会影响调用方。这和"遮蔽"是两种不同的"改了没生效"。
//
//  二、生命周期：`{}` 一结束，局部变量就死了
//
//      int* 造一个() {
//          int 数 = 42;
//          return &数;          // ⚠⚠ 返回局部变量的地址
//      }
//
//  函数一返回，`数` 待的那块内存就被回收了。
//  你拿到的地址**还在**，但它指向的东西已经没了 —— 这叫**悬垂指针**。
//  用它读出来的值是**随机的**，写进去可能破坏别的数据。
//
//  ⚠⚠ 这是 C++ 里最难查的一类 bug：**它常常"看起来是对的"**。
//    程序可能正常跑完、输出也对，只是偶尔崩在别的地方。
//    （这门课不会让你写这种代码，但你必须认识它。）
//
//  三、`static` 局部变量：作用域不变，但活得更久
//
//      int 计数器() {
//          static int 次数 = 0;      // ← 注意这个 static
//          次数++;
//          return 次数;
//      }
//
//  普通局部变量每次调用都**重新出生**（值回到初值）。加了 `static` 之后：
//      · **只初始化一次**（整个程序运行期间就那一次）
//      · 函数返回之后它**不消失**，下次调用还是上次那个值
//      · 但**名字还是只有函数里能看见**（作用域没变）
//
//      计数器()  → 1
//      计数器()  → 2      ← 记住上一次了
//      计数器()  → 3
//
//  ⚠ 和全局变量比：`static` 局部变量**不会污染全局名字空间**（别的文件、别的函数看不到它）。
//    但它和全局变量共有一个坑：**它让函数有了"记忆"**，于是同一个函数调两次结果不一样，
//    测起来、读起来都更麻烦。真实项目里它常用于：调用计数、只初始化一次的资源、随机数种子。
//    但**能不用就不用**，因为它是一种隐藏状态。
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 把上面那段遮蔽的例子跑一遍：实测输出就是 100 / 5 / 7 / 5 ——
//     注意最后一行还是 5：内层的 7 出了花括号就死了，全局那个 100 **从头到尾没被改过**。
//
//  ② static 局部变量：函数自己的"记忆"
//
//      int 计数器() { static int 次数 = 0; 次数++; return 次数; }
//      std::cout << 计数器() << 计数器() << 计数器();   ⇒ 1 2 3
//
//  ③ 四类变量对照表（这一课的核心）
//
//      变量          作用域（名字能在哪用）    生命周期（什么时候存在）
//      全局         整个文件                 整个程序
//      static 局部  只有那个函数里            整个程序（只初始化一次）
//      普通局部     那个 {} 里面              那个 {} 期间
//      函数参数     那个函数体里              这次调用期间
//
//  ④ static 局部变量不写初值时是 0
//
//      int 计数器() { static int 次数; 次数++; return 次数; }
//
//  实测：它从 0 开始（连着调 3 次得到 1、2、3），**不是**垃圾值 ——
//  因为 static 变量和全局变量一样，程序启动时会被清零，
//  这一点和普通局部变量（`int 和;` 里面是残留值）**正好相反**。
//  ⚠ 别以为它每次调用都会重置：那行 `static int 次数 = 0;` 整个程序只执行**一次**。
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：返回局部变量的地址
//
//      int* 造一个() {
//          int 数 = 42;
//          return &数;                  ← 数 在函数返回时就死了
//      }
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:12: warning: address of local variable '\U00006570' returned [-Wreturn-local-addr]
//      main.cpp:4:9: note: declared here
//  ⚠ 只给一句 warning，可后果很重：实测这个程序**直接崩**（退出码 -1073741819），
//    也可能碰巧打印出 42 —— 让你以为它是对的。**两种结果都不代表写对了。**
//  为什么：函数一返回，那块栈内存就被回收了；你手里的地址成了**悬垂指针**。
//  ⇒ 要交出一个"值"，就 return 那个值本身（值会被复制出来，是安全的）；
//    要交出一块更长久的内存，得用堆（new / std::vector）—— 那是后面的事。
//
//  ⚠ 坑 2：花括号里声明的变量，拿到外面用
//
//      { int 数 = 7; }
//      std::cout << 数 << "\n";         ← 数 已经不在了
//
//  你会看到（g++ 原文，实测）：
//      main.cpp:5:13: warning: unused variable '\U00006570' [-Wunused-variable]
//      main.cpp:7:20: error: '\U00006570' was not declared in this scope
//  为什么：作用域就是"名字能用的范围"，出了花括号这个名字就不存在了 ——
//  编译器根本不认识它（前面那句 unused variable 也在提醒你"这个 数 白定义了"）。
//
//  ⚠ 坑 3：名字遮蔽 —— 编译器一声不吭
//
//      int 数 = 100;                              ← 全局
//      int 影子() { int 数 = 5; return 数; }        ← 这个 数 是另一个变量
//
//  你会看到：**什么都没有**。实测 -Wall 也不警告，程序照跑，
//  影子() 返回 5，全局那个 100 一点没变（实测）。
//  为什么：C++ 允许内层同名遮蔽外层，而且默认不提醒。
//  ⚠ 症状是"我明明在函数里改了它" —— 其实你改的是另一个变量。
//    防身：起名时别让里外重名；真要用全局那个，就换个名字。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   ① int 影子()
//      在函数**里面**声明一个叫 `数` 的局部变量并赋值为 5，返回它。

//
//   ② int 计数器()
//      用一个 `static int` 局部变量，每调一次加一，返回当前值。
//      第一次返回 1，第二次返回 2，依此类推。

//     少一次 static，得到的就全是 1。
//

// 第 11 课：递归 —— 函数调用自己
//
// ─────────────────────────────────────────────────────
//  先介绍：把一个问题的答案，说成"小一号的同一个问题"的答案
// ─────────────────────────────────────────────────────
//
//      阶乘 n! = 1 × 2 × 3 × ... × n
//
//  用循环写（你已经会了）：
//
//      int 结果 = 1;
//      for (int i = 2; i <= n; i++) { 结果 *= i; }
//
//  用递归写 —— 换个说法：n! = n × (n-1)!，即"n 的阶乘 = n 乘上「n-1 的阶乘」"
//
//      int 阶乘(int n) {
//          if (n <= 1) { return 1; }      ← ① 什么时候停
//          return n * 阶乘(n - 1);        ← ② 用"小一号的答案"拼出答案
//      }
//
//  这个函数里出现了自己的名字 —— 这就是递归。
//  它不会无限跑下去，因为每一层的 n 都比上一层**小一号**。
//
//  ⚠⚠ 递归必须有的两样东西：
//    ① **基准情形**（base case）—— 什么时候**不再**调用自己，直接给答案。
//       上面那行 `if (n <= 1) { return 1; }` 就是它。
//    ② **每次都在变小** —— 参数必须朝着基准情形走。
//       `阶乘(n - 1)` 比 `阶乘(n)` 小一号 ⇒ 早晚会到 1。
//
//  ⚠⚠⚠ **缺了任何一样，程序会崩 —— 而且崩法很难看。**
//
//      int 阶乘(int n) {
//          return n * 阶乘(n - 1);        /* 没有基准情形 */
//      }
//
//  它会一直调用下去，每调一次就在内存里压一层（叫"调用栈"），
//  直到把栈用完 ⇒ 崩溃。这个错叫**栈溢出**（stack overflow）。
//
//  ⚠ 在 Windows 上你看到的多半是程序直接消失、退出码不是 0（坑 1 有实测数字），
//    而不是一句好看的报错。
//    **这就是递归最需要小心的地方：它不会好好告诉你哪里错了。**
//
// ─────────────────────────────────────────────────────
//  用法与例子
// ─────────────────────────────────────────────────────
//
//  ① 阶乘：一层层展开着看
//
//      阶乘(4) = 4 × 阶乘(3) = 4 × (3 × 阶乘(2)) = 4 × (3 × (2 × 阶乘(1)))
//              = 4 × (3 × (2 × 1))          ← 到基准情形了，开始一层层往回算
//              = 24
//
//  写递归的时候，脑子里要能这样展开；不然很容易漏掉基准情形。
//
//  ② 斐波那契：基准情形**有两个**
//
//      int 斐波那契(int n) {
//          if (n <= 0) { return 0; }      ← 基准情形 ①
//          if (n == 1) { return 1; }      ← 基准情形 ②
//          return 斐波那契(n - 1) + 斐波那契(n - 2);
//      }
//
//      fib(0)=0   fib(1)=1   fib(2)=1   fib(3)=2   fib(4)=3   fib(5)=5
//
//  ⚠ 为什么两个都要：n 每次减 1 或减 2，如果只写 `n == 0`，
//    那 n = 1 时就会掉到 `斐波那契(-1)`、`斐波那契(-2)` 去（见坑 2）。
//
//  ③ 同一个问题，两种写法
//
//      循环版：int 结果 = 1; for (int i = 2; i <= n; i++) 结果 *= i;
//      递归版：if (n <= 1) return 1; return n * 阶乘(n - 1);
//
//  阶乘用循环写就挺好，递归没占到便宜。递归的长处是下面这类问题：
//      · 文件夹里还有文件夹，一层套一层 —— 怎么数所有文件？
//      · 一棵树，每个节点还有子树 —— 怎么遍历？
//      · 汉诺塔、走迷宫、表达式求值
//  它们**本身就是递归定义的**，用循环写要自己造一个"栈"来记住位置，
//  用递归写则几乎是直译。这一课先在小问题上把套路练熟。
//
//  ④ 怎么读一个递归函数：先找基准情形
//
//      第一步：哪一行**没有**调用自己？   → 那就是出口
//      第二步：参数每一次怎么变？变小了吗？ → 那决定它会不会走到出口
//
//  ⚠ 一个反例：斐波那契**不该**用这种递归写。
//    它能算对，但算 fib(40) 要调用自己上**亿**次 ——
//    因为 fib(5) 要 fib(4) 和 fib(3)，而 fib(4) 又要 fib(3)：
//    **同一个 fib(3) 被重复算了无数遍**（这叫"重叠子问题"）。
//    这一课仍然让你这么写，因为它最能训练递归思维，而且检查只喂到 n <= 20。
//    但请记住：**能写出递归，不等于该用递归。**
//    （正式的做法叫"记忆化"：把算过的答案存起来，下次直接查表。）
//
// ─────────────────────────────────────────────────────
//  常见坑
// ─────────────────────────────────────────────────────
//
//  ⚠ 坑 1：没有基准情形
//
//      int 阶乘(int n) { return n * 阶乘(n - 1); }      ← 永远不停
//
//  你会看到：**编译完全通过**（语法没问题），一跑起来 ——
//  程序**直接消失**，屏幕上什么输出都没有。实测退出码是 **-1073741571**
//  （也就是 0xC00000FD，"栈溢出"），大约两秒后进程就没了。
//  为什么：每调一次自己就要在调用栈上压一层（返回地址、参数、局部变量）。
//  栈是有限的（通常几 MB），压满了就崩 —— 这不是"报错"，是进程被系统干掉。
//  ⇒ 写递归时，**第一件事就是写下基准情形**。
//
//  ⚠ 坑 2：基准情形少写一个（斐波那契只写了 n <= 0）
//
//      int 斐波那契(int n) {
//          if (n <= 0) { return 0; }
//          return 斐波那契(n - 1) + 斐波那契(n - 2);      ← n=1 时没有出口
//      }
//
//  你会看到：和坑 1 一模一样 —— 程序消失，退出码 -1073741571（实测同一个码）。
//  为什么：n = 1 时走的是 `n - 1 = 0`（这个能停）和 `n - 2 = -1`（停不下来）——
//  负数越走越小，碰不到别的出口，就这么一路压到栈满。
//  ⇒ 两个基准情形都要写：`n <= 0` 和 `n == 1`。
//
//  ⚠ 坑 3：参数没有变小
//
//      int 阶乘(int n) {
//          if (n <= 1) { return 1; }
//          return n * 阶乘(n);            ← 传进去的还是 n
//      }
//
//  你会看到：基准情形明明写了，程序照样消失，退出码还是 -1073741571（实测）。
//  为什么：基准情形管的是"什么时候停"，**参数变小**管的是"能不能走到那里"。
//  两样缺一不可 —— n 一直不变，那个 if 永远等不到 n <= 1。
//  ⇒ 每次调用都必须朝着基准情形**迈一步**（n - 1、n / 2 都行，就是不能原地踏步）。
//
//  ⚠ 坑 4：以为递归能装下任意大的结果
//
//      阶乘(12)  ⇒ 479001600     ← 刚好还装得下
//      阶乘(13)  ⇒ 1932053504    ← 实测就是这个数，可真实值是 6227020800
//
//  你会看到：**没有任何警告**，只有一个"看着挺正常"的正数（实测 1932053504）。
//  为什么：int 最大只到 2147483647，13! 早就超了，多出来的位被丢掉 ——
//  这叫溢出，C++ 不会替你检查。
//  ⇒ 检查只喂到 n <= 10，就是为了避开这件事；
//    真需要大结果时得换更大的类型（long long 也有上限，那是后面的话题）。
//
// ─────────────────────────────────────────────────────
//  轮到你了 —— 在下面写
// ─────────────────────────────────────────────────────
//   写两个**递归**函数（不许用循环）：

//      2. int 斐波那契(int n)       fib(0)=0, fib(1)=1, fib(2)=1, fib(3)=2 …
//
//    ⚠ 两个都必须有**基准情形**，而且参数要**每次变小** ——
//      少了任何一样，检查会看到程序崩溃（就是坑 1、2、3 那三种）。
//
//    ⚠ `阶乘(13)` 就已经超出 int 的范围了（13! ≈ 62 亿 > 21 亿），

//
//   提示：不用写 main。
