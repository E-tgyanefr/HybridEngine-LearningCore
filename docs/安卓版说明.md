## 〇、⚠⚠ 先看这一节：那次"判分做不到"是怎么来的（最值钱的一课）

### 症状与它骗人的地方

前 5 轮排查看到的**唯一**线索是这一行：

```
F libc : FORTIFY: pthread_mutex_lock called on a destroyed mutex (0x711b60eaf8)
```

它看起来指向"锁被销毁了"，于是 5 轮都在查线程、HttpListener、WebView、扩展模块。
**但它是收尸时的噪音，不是死因。** 证据：把那个地址交给 `dladdr`：

```
0x711b60eaf8 → /system/lib64/libhwui.so        ← 安卓的 UI 渲染库
0x711b611268 → /system/lib64/libhwui.so
```

**`libhwui` 跟 libpython 一行关系都没有** —— 是进程开始退出时，
.NET / HWUI 的渲染线程撞上自己刚拆掉的锁。

### 真死因（第一次真的看到）

CPython 的报错**一直写在 stderr**，而安卓应用的 `fd 2` 指向 `/dev/null`
⇒ **写进去就没了**。把 `fd 1/2` 用 `dup2` 接到应用私有目录的文件上，
崩完再启动一次读回来（`Diag.读输出`），原文终于露出来：

```
Could not find platform independent libraries <prefix>
Python path configuration:
  PYTHONHOME = (not set)
  PYTHONPATH = (not set)
  sys.path = [
    '/usr/local/lib/python312.zip',
    '/usr/local/lib/python3.12',
    '/usr/local/lib/python3.12/lib-dynload',
  ]
Fatal Python error: init_fs_encoding: failed to get the Python codec of the filesystem encoding
Python runtime state: core initialized
ModuleNotFoundError: No module named 'encodings'
```

⇒ **`Py_Initialize()` 在初始化过程中就要 `import encodings`**，
而旧代码把 `PYTHONPATH` 只设成 `python-app`（我们自己的引擎），
标准库却在 `python-stdlib` ⇒ 找不到 ⇒ `Py_FatalError` ⇒ 进程退。
**"初始化之后再 `sys.path.insert`"是无效的 —— 那一步已经太晚了。**
（`PyRun_SimpleStringFlags` 在 `Py_Initialize()` 之后才跑得上。）

### 第二个坑：环境变量"设了等于没设"

只把 `PYTHONPATH` 改对**还不够**。实测：

```
托管读回：/data/.../python-stdlib:/data/.../python-app:/data/.../lib-dynload/arm64-v8a
原生读回：/data/.../python-stdlib:…            ← 两边一模一样
```
——那是在 `setenv` 之后。而在只用
`Environment.SetEnvironmentVariable` 的那一版里，CPython 的诊断原文是
**`PYTHONPATH = (not set)`**：

```
托管侧：设好了（GetEnvironmentVariable 读得到）
原生侧：libpython 的 getenv("PYTHONPATH") 是 NULL
```

⇒ **`.NET` 的 `Environment.SetEnvironmentVariable` 在安卓上到不了原生 environ。**
⇒ 改成 P/Invoke libc 的 `setenv` 才真的生效（`Diag.本地设环境`）。

⚠ 这条也解释了当年第 3 轮"排除环境变量"为什么是
**结论对、原因错** —— 那些变量从头到尾**一次都没生效过**。

### 修好之后（实测 logcat）

```
I/HybridEngineLight: setenv(PYTHONPATH) 返回 0，原生 getenv 读回 /data/user/0/…
I/HybridEngineLight: 准备调 Py_Initialize()…
I/HybridEngineLight: Py_Initialize 返回了
I/HybridEngineLight: Python 起来了：3.12.7 (main, May  7 2025, 15:50:22) [Clang 18.0.3 …，用时 20 ms
```

### ⚠ 被证伪的假设（都做过实验，不是"觉得不对"）

| 假设 | 实验 | 结果 |
|---|---|---|
| **RTLD_GLOBAL**：`DllImport` 以 `RTLD_LOCAL` 载入 libpython ⇒ 扩展模块解析不到 `Py*` | ① `readelf -d` 看扩展模块 ② 实验 `global`/`dlglobal`/`dllocal` | **证伪**。扩展模块自带 `DT_NEEDED: libpython3.12.so`（`_io` 是 builtin，init 期根本不需要 dlopen 扩展）。libpython **确实**是 RTLD_LOCAL 加载的（dlsym 全局=0x0），但那不是崩因 |
| 线程（`Task.Run` / 同线程） | 前 5 轮已做 | 与本死因无关 |
| 环境变量 | 前 5 轮已做 | **结论对、原因错**（见上） |
| 扩展模块找不到 libpython | 前 5 轮已做 | 与本死因无关（`_io`/`_locale` 在本产物里是 builtin，`lib-dynload` 里没有它们） |
| 那行 FORTIFY mutex 是死因 | `dladdr` + 抓 stderr | **证伪**：它在 `libhwui`，是退出时的噪音 |

## 三、⚠⚠ 真机怎么验：**用 CDP，不要用 `input tap`**

这是本项目在安卓侧**最重要的经验**。

### 别这么干

```powershell
adb shell input tap 540 825     # ← 我在这上面烧了好几轮
```

问题在于**你得把坐标算准**：

* 截图的预览尺寸是 838×1862，而屏幕是 1080×2400 ⇒ 得乘 1.289
* 页面一滚动，元素的 y 就变了 ⇒ 得重新截图、重新量
* 点了没反应时，**分不清「没点中」还是「点中了但逻辑没跑」**
  —— 我为此误判过一次"功能坏了"，实际只是坐标错

### 这么干

```powershell
python _build/_cdp.py --看                                  # 读页面状态
python _build/_cdp.py --点 "[data-做=分享]"                  # 点（不碰坐标）
python _build/_cdp.py "localStorage.getItem('hel-草稿')"      # 任意 JS
```

从"看截图猜"变成"读返回值"。

### 前提（踩过才知道）

`.NET Android` **没有** `WebViewDebuggingEnabled` 这个 MSBuild 属性 ——
全盘搜 `Microsoft.Android.Sdk.Windows` 的 targets/props/cs，
`WebViewDebugging` 这个词**一次都没出现**（我加过，是空操作，白花一轮）。

必须显式调：

```csharp
Android.Webkit.WebView.SetWebContentsDebuggingEnabled(true);
```

代码里是 `MainActivity` 的 `调试WebView` 开关（**发布前要关**）。

### 页面里的自检通道

`?自检=1` 时，页面每秒把 DOM 状态写进 `document.title`，
宿主用 `WebChromeClient.OnReceivedTitle` 落进 logcat：

```
#28 行=55 进度=有 宽=0% 记=0 视图=列表 线=Python 错=无
```

⚠ 标题里**必须带一个每帧都变的值**（帧计数）—— 实测
`OnReceivedTitle` **只在标题真的变了时才回调**，不加计数器
看到的一直是**卡住的旧值**。

## 四、能力边界（哪些是平台硬限制，哪些是我们还没做）

三条都出自 CPython 官方 [PEP 738](https://peps.python.org/pep-0738/)：

| 限制 | 原文依据 | 后果 |
|---|---|---|
| **没有 tkinter** | "would require an Android build of Tk itself, which is **not officially supported**" | ⚠ **判分不受影响**（`check`/`examrun` 不碰 tkinter）；但界面只能是网页，而且 `ctl.lesson.check` 的 python 线要 `from . import run`、**`run.py` 顶层引 tkinter** ⇒ 那条命令在手机上是死的，改用 `桥.Pan`（直接调 `check.run_checks`） |
| **不能跑自己的可执行文件** | "apps may only run executables in certain locations, **none of which are writable at runtime**" | C / C++ / Java / C# 那四条线**判不了分**（它们必须起编译器子进程）。⚠ **Python 线不受影响** —— 它是**进程内**跑的（libpython 载进主进程） |
| **没有 Python 可执行文件** | "A `python3.x` executable will **not** be officially supported" | 只能把 `libpython.so` 载进主进程 —— 这也正是我们做的 |

### ⚠ 纠正一条**我自己写错过的**结论

2026-10-13 之前，本文档在这里写着"`Py_Initialize()` 一调就原生崩 ⇒ 手机版
不需要 Python、判分做不到"。**那是错的**，死因是路径配置（见第〇节），
已修好：真机上 `Py_Initialize 返回了`、判分 ✗/✓ 都在界面里验过。

⚠ 教训值得留在这里：当时那行
`FORTIFY: pthread_mutex_lock called on a destroyed mutex`
**看着像根因**，实际是退出时的噪音（`dladdr` 指到 `/system/lib64/libhwui.so`）。
**"看起来像根因的报错"要先问"谁打的、什么时候打的"。**

### 仍然没做的（不是平台限制，是我们没做）

| 缺口 | 现状 | 要接上需要什么 |
|---|---|---|
| 判分**只接了 Python 线** | `桥.Pan` 判 `lessons/answers/` 那一线（真机验过） | 另外三条线（embedded / raspi / ai）也用同一形状，但**没验过** |
| `ctl` 协议**只接了入口** | `桥.ctl(一行 JSON)` 真能通（`code.run`/`code.check`/`lesson.list`/`exam.list` 都验过） | 界面还没有调它的按钮；`lesson.check`（python 线）在手机上跑不通，见上 |
| 判分**没有超时** | ✅ **已解决**（2026-10-13，真机验过） | `hybridengine_light/watchdog.py` 走 **`signal.setitimer` + `SIGALRM`**（安卓有！）—— 真机实测 `**INTERRUPTED 2.00 秒** 走了 signal`。⚠ `sys.settrace` **在这份构建上不生效**（tracer 一次都不回调），所以是**按能力选**的两条路，不是按平台写死 |
| 编译型四线不能用 | 无 | 安卓上不可能（PEP 738），只能在电脑版做 |

## 五、构建期的硬约束（与设备无关）

### ① AAPT2 处理不了含中文的工程路径

```
error APT2265: ... non-ASCII characters in its filename or path.
```

而本项目根目录就是 `引擎` ⇒ `build_android.py` 先拷到 `C:\lc_android`（纯 ASCII）。

⚠ 这个拷贝**不只是绕过限制** —— 中文路径下 APT2265 会把**后面所有错误挡住**。
解决后连续露出两个：`APT2260 缺图标`、`APT2098 资产文件名含中文`。

### ② AAPT2 也处理不了非 ASCII 的**资产文件名**

课程文件名 79/667 个含中文，而那些名字**不能改**（学员在界面上看到的就是它们）
⇒ 把 Python 侧全部内容打成一个 `python.zip`，APK 里只有这一个 ASCII 名字。

### ③ ⚠⚠ 中文标识符 + JNI 包装会挂构建

这个项目**通篇用中文标识符**（刻意风格）。而 .NET Android 会把
Java↔C# 的调用包装编成 **native assembly**（即使 AOT 全关），
生成的 LLVM IR 里**带中文参数名**：

```llvm
define i1 @Java_crc..._MainActivity_n_1onKeyDown(
    ptr noundef %env, ptr noundef %klass,
    i32 noundef %键, ptr noundef %e)      ← 中文进了 IR
```

于是构建挂在：

```
error XA3006: Could not compile native assembly
[llc.EXE stderr] ... error: ... %键 ...
```

⇒ 修法：`<AndroidEnableMarshalMethods>false</AndroidEnableMarshalMethods>`

⚠ **为什么之前一直能构建**：那时被 Java 侧调用、且**带中文参数**的方法还没有
—— `OnBackPressed` 是**无参**的，`OnKeyDown` 带了 `键`/`e` 才撞上。

⚠ 报错里那行 LLVM IR **直接写着** `%键` ——
  我第一遍看日志时它就在那儿，只是被我当成噪音跳过了。

### ④ JDK / API 级别 / AOT

```
JDK  ：PATH 上是 25，.NET Android 拒绝 ⇒ 显式指 D:\AndroidToolchain\jdk21
API  ：net10.0-android 只认 API 36 ⇒ 装 platforms;android-36
AOT  ：必须全关，否则 MSB4236（MonoAOTCompiler 解析不出来）
```

### ⑤ ⚠ 别加"看起来无害的优化项"

我加过三个自认为安全的 MSBuild 设置
（`AndroidEnableAssemblyCompression` / `AndroidEnableProfiledAot` /
`PublishTrimmed`），结果应用一启动就崩：
`UnsatisfiedLinkError: No implementation found for …n_onCreate`。

删掉之后启动成功，**APK 还从 27.37 MB 降到 10.58 MB** ——
那些"优化"其实在**压制真正的构建流程**。

⚠ 而当时这台机器**没有设备可验**，那种错只会在真机上现形。
  ⇒ **能加不等于该加**；不确定的设置，先不加。

## 六、⚠⚠ 两个"构建会静默用过期东西"的坑（同类，都咬过我）

这一类 bug 的症状一模一样：**「我明明改了却没生效」**，
而人第一反应是"功能坏了"，不是"打包打的是旧的"。

### ① 素材指纹只比手写常量

```csharp
const string 素材版本 = "py312.7-chaq-1";   // 手写
if (已有 == 素材版本) { 跳过解压; }          // 常量不改就永不重解
```

注释里写着"版本标记用版本号 + **素材指纹**"，**但实现只比了版本号**。

⇒ 改成自动算：`python.zip 字节数 + APK versionCode`。
  不用哈希 —— 6 MB 的 SHA 要几百毫秒，而这段跑在**冷启动路径**上。

⚠ 这一条**本来就在 `docs/任务清单.md` 的待办里**
（"`_assets-ok` 标记只比版本号，内容变了不会重解"）。
我记下了却没修，直到它花掉一整轮排查时间。
**教训：已知的坑写成待办 ≠ 处理过了。**

### ② `python.zip` 过期，构建照样报成功

```
生成物 web/index.html   10:53:10   ← 新
app/python.zip          10:51:51   ← 旧
zip 里的 index.html 含「发到电脑」：**否**
```

`build_android.py` 只检查素材**在不在**，不管**新不新**。

⇒ 加了过期检查：网页比 `python.zip` 新就**拦下来并说清怎么修**。
⚠ 刻意**不做"自动重打"** —— 那会掩盖"我到底该跑哪一步"。

## 七之二、⚠⚠ 怎么**验**：两种入口，别只会一种

### ① 界面 / 交互 ⇒ CDP（`_build/_cdp.py`）

```powershell
python _build/_cdp.py --看                                  # 读页面状态
python _build/_cdp.py --点 "[data-做=判分]"                  # 点（不碰坐标）
python _build/_cdp.py "localStorage.getItem('hel-草稿')"      # 任意 JS
```

⚠ **它需要 `调试WebView = true`**（发布版是 false）⇒ 发布包上连不上，
  那是故意的。要再验界面：把它改回 true、重新构建。

⚠⚠ **它的不稳是实测过的**（不是网络问题）：
  WebView 的 devtools socket 会突然变成"**TCP 连得上、但一个字节都不回**"，
  而且 `adb forward` 的**失败信息被 `_cdp.py` 丢掉了**（`capture_output=True`
  只打印 stdout）⇒ 症状看起来像"socket 没出现"。
  实测对策（都写在那天的排查记录里）：
  · **每个实验**冷启动一次应用（`am force-stop` + `am start`）
  · **每次换一个本机端口**（不要固定 9222）
  · 连不上就 `adb kill-server` / `start-server` 再来

### ② Python / 判分 / 崩溃 ⇒ **Intent 实验台**（不需要 CDP，也不需要 WebView 调试）

```powershell
$act = "com.hybridengine.light/crc6491118639cd5d08e8.MainActivity"
adb shell am start -n $act --es hel fix2      # 修好的初始化路径
adb shell am start -n $act --es hel old       # 旧路径（复现那次崩溃）
adb shell am start -n $act --es hel bare      # 只调 Py_Initialize
adb shell am start -n $act --es hel 判         # 判分（错答案/对答案/跑代码/课程/题库）
adb shell am start -n $act --es hel dump      # 捞上一次的原生 stderr
adb shell am start -n $act --es hel maps      # /proc/self/maps
adb shell am start -n $act --es hel who --es 参 0x711b60eaf8   # 地址属于哪个 .so
```

⚠ **它为什么存在**：前 5 轮每换一个假设都要"改代码 → 构建 → 装 → 点"，
一轮几分钟，而且"上次到底怎么试的"只能靠注释记。
现在**每个假设是一个参数**，一次一个、冷启动一个进程，
`logcat` 里就是它自己的输出 —— 本条教训（一次只动一个变量）终于有了工具支撑。

⚠ **它不需要 `调试WebView`** ⇒ **发布包也能跑**，这是关掉 CDP 之后
  仍然能自证"Python 还在"的唯一入口。

⚠ 它也**不依赖 WebView/CDP**：所以 CDP 再翻车也不影响查 Python。
