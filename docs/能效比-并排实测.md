# 能效比：**同一份场景并排对照**（2026-10-14 · Round 25~26）

> 作者的目标：「在原来的性能基础上**提高能效比**，**尽量提升到原先的一倍**」。
>
> ⚠ 而在这之前，**两个后端从来没有用同一份场景并排量过** ——
> 我报过 `tkinter 4.855 ms`（分母：1000 个对象里 **250 个可见**），
> 队友报过 `0.11 ms`（分母：**1000 个全可见**）⇒ **两个数不能比**（我为此纠过一次口径）。
>
> 这一份是**并排**的数。复跑：`python _build/_cmp_two_backends.py`

---

## 一、⭐ 结果

同一份场景：**1000 个圆铺满视野** · 画布 800×450 · `size=100` ·
两边**裁剪规则相同**（都照 `render.py::Tk后端._在视野内` 的 `MARGIN×(宽/size)`，`MARGIN=10.0`）

| | ms/帧 | 真实画了多少 |
|---|---|---|
| **① Tk 后端** | **15.53** | 画布 item = **1000** |
| **② C++ 后端** | **2.08** | 写过的像素 = 52,677,216 · 呈现 81 帧 |
| **⇒ 倍数** | **7.5 倍** | |

⚠ **两次独立测量**（修正测量前提前/后）：`7.7` / `7.5` ⇒ **运行间波动，结论一致**。

**60 帧预算（16.67 ms）下能画的图元数**：

```
Tk   ≈ **1,073 个**      ← 刚好卡在 60 帧线上（这也解释了"为什么卡在这"）
C++  ≈ **8,020 个**
```

⇒ ⭐ **作者的"翻一倍" = 2000 个 ⇒ 实际 7.5 倍，远超目标。**

---

## 二、⚠⚠ 7.5 倍**不是**这条路的极限 —— 94% 被"接口粒度"吃掉

```
C++ 后端纯光栅化（队友 benchmark，1000 圆铺满）    **0.1107 ms**
C++ 后端接进引擎后的实测（本份）                  **2.0785 ms**
⇒ 多出来的 **1.97 ms（94.7%）是 Python→C++ 的逐图元 ctypes 开销**
```

⇒ **同一个病（队友在 `task-10` 量到的"粒度"），换了个地方发作**：

| | 当时（数值逻辑搬 C++） | 现在（渲染搬 C++） |
|---|---|---|
| 结果 | **+351%（净亏）** | **仍净赚 7.5 倍** |

⇒ 差别：**Tk 每个图元的原生代价（~15.5 µs）比 ctypes 往返（~2.0 µs）贵约 8 倍**，
  所以交了过路费还是赚。⚠ **但赚的没有本可以赚的多。**

### ⚠ 真上限（**推算，不是实测**）

```
若图元提交也能"一次调用干完一帧"：1000 圆 ≈ 0.11 ms + 极少量提交开销
⇒ 对 Tk 的 15.53 ms ⇒ 理论 **~140 倍**
而实测只有 **7.5 倍** ⇒ **~95% 的潜力被接口粒度吃掉**
```
⚠ 要做实需要改 ABI（C++ 侧持有整个场景）——**那是另一个设计，本轮没做。**

## 四、⚠⚠ 我自己的**两次"仪器故障"**（都要记，因为都很贵）

### 第一次（Round 25）：`子窗口可见()` 我以为是误报

我第一版对照台里 **`root.withdraw()` 了根窗** ⇒ 看到 `子窗口可见 = False`，
**一度把它写进文档当"待办"**，理由是"一条会误报的可见性判据比没有更糟"。

**真相**：`IsWindowVisible` 对**后代**会**一直查到根** ⇒ **根被 withdraw ⇒ 整棵子树都算不可见**。
⇒ **`子窗口可见()` 的实现是对的**（`return IsWindowVisible(hwnd) ? 1 : 0`），
  **错的是我的测量前提。**

⚠ 而这**正好是本仓反复记的那条**：
> **判据红了要先问"是它测的东西红，还是仪器坏了"。**

⇒ 本仓此前有过**假绿**（dll 静默退回）· 队友有过**假红**（`PostMessage` 投点击）·
  **这次是我的"假红"** —— **三种都出现了。**
  ⇒ ⭐ **规律：只要你在"测一个会静默降级/有前提的东西"，仪器就必须先被验。**

### 第二次（顺带查出的**真事实**）：**Tk 的 `winfo_id()` 不是顶层窗**

```
root.winfo_id()   HWND=22611854   GetAncestor(GA_ROOT)=**25364828**   ← **不相等**
Frame.winfo_id()  HWND=34343172   GetAncestor(GA_ROOT)=25364828
```

⇒ ⚠ **要挂子窗口就得挂顶层窗**（用 `GetAncestor(GA_ROOT)`）。
  ⇒ 而队长在 `task-12` 的提醒里写过"**先确认拿对了 HWND**" ——
    **现在有实据了**：它会**静默**给出一个后代窗，而一切看起来都正常。
