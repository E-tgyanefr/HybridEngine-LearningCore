# 跨平台（Windows / Linux / macOS）

> **一句话**：三个平台各有构建入口，而且**跨平台这件事现在有判据了**
> （`python _build/_check_platform.py`，任何平台都能跑、退出码 0/1）。
> ⚠ **但只有 Windows 是实测过的。** Linux 和 macOS 的构建脚本
> **一次都没在真机上运行过** —— 这台开发机没有 WSL 发行版、没有 Linux、没有 macOS。

---

## 0. 「实测」到底指什么（三级口径）

这张文档里每个状态都只用这三个词之一，**不许含糊**：

| 状态 | 含义 | 证据形态 |
|---|---|---|
| **实测** | 在**这台 Windows 机器**上真跑过 | 退出码 + 产物大小/文件数 |
| **半验** | 脚本的**某一段**真跑过（语法、闸门、只读检查），关键路径没跑 | 退出码 + 跑的是哪一段 |
| **未验** | 写了，但**一次都没执行过** | 无 —— 只有 `bash -n` 这一层 |

⚠ 特别地：**`bash -n` 通过 ≠ 能跑**。本轮就抓到一个反例：
`bash -n` 说语法没问题，但脚本里 `echo "...\`Info.plist\`..."` 的反引号
**在运行时会当命令替换执行**（`Info.plist: command not found`，报错信息被吃掉一半）。
⇒ 这类只能靠**真跑**发现。

## 1. 为什么 Linux / macOS 在这台机器上验不了（物理限制，不是没做）

| 限制 | 实测证据 |
|---|---|
| 本机是 Windows | `sys.platform == "win32"` |
| **没有 WSL 发行版** | `C:\Windows\system32\bash.exe` 是 WSL 的**启动器**；跑起来只打印"适用于 Linux 的 Windows 子系统没有已安装的发行版"。⚠ `shutil.which("bash")` **会命中它** —— 所以 `_check_platform.py` 里专门先找 Git Bash 再退回 `which`，并且真的跑一次 `--version` 才认 |
| **PyInstaller 交叉编译不了** | bootloader 是预编译的；本机 wheel 里只有 `Windows-64bit-intel/run.exe` |
| AppImage / .deb / .app 的工具是各平台原生的 | `appimagetool` · `dpkg-deb` · `iconutil/sips/codesign/hdiutil` —— Windows 上一个都没有 |
| x 位 | Windows 没有 Unix 的 `x` 位（`stat` 出来是 `0o666`），只能靠 `tar` 里**显式记 755** |

## 6. `.gitignore`：一个「规则写对了、但字节对不上」的实例

**这是本轮最值钱的发现**，形态和第 8 条教训（`relpath` 反斜杠 ⇒ `in` 永远 False）**一模一样**。

### 6.1 现象

`.gitignore` 是**混编码**文件：第 1~41 行 UTF-8、第 42~48 行 **GBK**。
更糟的是，损坏还把 **3 条规则行并进了注释行**（合并后整行以 `#` 开头 ⇒ 规则消失）。

### 6.2 实测证据（修之前）

```
$ git check-ignore -v --no-index -- x.log
（无输出，rc=1）                    ← 没被忽略
$ git check-ignore -v --no-index -- _build/dist/x
（无输出，rc=1）                    ← 没被忽略
$ git check-ignore -v --no-index -- csharp/demo3d/x.cs
（无输出，rc=1）                    ← 没被忽略
$ git check-ignore -v --no-index -- .学习进度.json
（无输出，rc=1）                    ← 没被忽略（规则是 GBK 字节，文件名是 UTF-8）
```

**阵亡的 4 条规则**（对比最后一个干净祖先 `144afadb`）：

| 规则 | 后果 |
|---|---|
| `csharp/demo3d/` | **专业版内容**（通过 csproj 链接 `hybridengine.dll`）可能进轻量版仓 |
| `*.log` | 运行期日志会进仓 |
| `_build/dist/` | **11.7 MB 打包产物**会进仓（`.gitignore` 自己的注释就在警告这件事） |
| `.学习进度.json` | 学员的本机进度会被提交 |

### 6.3 ⚠ 一个**工具会骗人**的坑

`git check-ignore` 在**命中取反规则（`!`）时也返回 0**。
所以**只看退出码会误判**。判据必须是二选一：

```
① git check-ignore -v 的输出里，匹配到的模式**以 `!` 开头** ⇒ 没被忽略
② 或者干脆用 git status --porcelain 实测（最权威）
```

（这是拿一个一次性仓库做对照实验测出来的，不是猜的。）

### 6.4 修法与判据

- 头部注释从**最后一个干净祖先** `144afadb` 取回（**是恢复，不是新写**）
- 尾部 GBK 块按 GBK 解码后**原样转 UTF-8**
- **写入前**先校验（环境坑第 6 条）：现有 16 条规则**逐条必须在结果里**
- 修复后 14 个路径的判据 **全部 OK**：

```
bin/x.dll obj/x.txt __pycache__/x.pyc answers/x.py cpp-answers/x.cpp
```

## 8. 怎么把这些「未验」变成「验了」

```sh
# Linux（真机或 WSL 发行版）
sh _build/build_linux_packages.sh          # 先看环境、看能打什么
sh _build/build_linux_packages.sh --go     # 真打
python3 _build/_check_platform.py          # 跨平台自检，退出码必须是 0
cd ../发布 && tar -xzf HybridEngine-light-v*-linux-*.tar.gz && ./HybridEngine-light 课程

# macOS
sh _build/build_macos_app.sh               # 只读检查
sh _build/build_macos_app.sh --go --dmg    # 真打
python3 _build/_check_platform.py
open ../发布/HybridEngine-light.app
```
