## 五、✅ 手机版 UI 重做（本轮重点）

### 5.0 产物与设计

```
引擎/发布/com.hybridengine.light-Signed.apk    11.87 MB
```

**手机优先**（作者：「一定要适应手机」）：

| 约束 | 怎么做的 |
|---|---|
| 拇指可达 | 主操作放**屏幕下半部**（底部大按钮），不放顶部 |
| 触控目标 ≥48px | `--碰:48px`；课程行**整行可点** |
| 安全区 | `env(safe-area-inset-*)` 让开刘海和手势条（`viewport-fit=cover` 是前提） |
| 动态视口 | `100dvh` 而不是 `vh`（地址栏收放会改视口高度） |
| 单列滚动 | 不做左右分栏 —— 手机上分栏等于两边都太窄 |
| 顶栏让位 | 滚动时收起，**往回滚立刻放出**（不然找不到返回键） |
| 性能 | 事件用**一个委托**（55 行列表逐个挂监听，低端机感觉得到） |
| 动画 | 全部 ≤240ms，且尊重 `prefers-reduced-motion` |

### 5.0.1 教学闭环（真机逐步验过）

```
① 课程正文       ✓ 完整渲染（等宽 + 缩进对齐）
② 要做的事       ✓ 「轮到你了」单列一块
③ 在手机上写     ✓ textarea + 边写边存（不等"保存"按钮）
④ 看参考答案     ✓ 带**确认门**：「抄一遍不如写错一遍学得多 —— 确定要看吗？」
⑤ 发到电脑       ✓ 原生分享面板（截图确认）
```

⚠ **确认门照搬桌面端的态度**（`learn_gui.py` 那句提醒）：
  **答案不是不让看，是别一上来就看** —— 直接给按钮的话，
  学员会先点答案再倒推，那样学到的最少。

### 5.0.1c ⚠ 两个"量了数据才发现"的设计错误

**① 按缩进猜"代码块"是错的**

我第一版按「缩进 ≥4 格 = 代码块」做等宽+底色。量完数据才知道：

```
缩进 ≥4 格的行里：像代码 7206 行 · **像散文 2940 行**
例：「    怎么跑一个 Python 程序，以及 print 和它的括号引号」
```

⇒ 改成**整篇等宽**，缩进自然对齐，不猜谁是代码。
  作者本来就是**在等宽环境（编辑器注释块）里排版这份文本的**，
  换比例字体反而会把他辛苦对齐的 ASCII 表格拆散。
  **真机截图确认：箭头图 ↑ 和「名字 = 「小明」」对得整整齐齐。**

**② 「停留够久才算读完」**

手机判不了分，所以"读过"是**唯一**的进度信号 ——
它至少该表示"真的看过一会儿"，而不是"手指划过"。
⇒ 进课程页后停留 **8 秒**才记读过（比最短的一课 3 分钟短得多，
  正常读一定会超过，狂滑一定不到）。

### 5.0.2 动画（**服务教学**，不是为了好看）

| 动画 | 教学意义 |
|---|---|
| **进度条**（列表页顶部，各线各一条） | 手机判不了分 ⇒「读过多少」是唯一的进度信号。可见的进度是坚持下来的关键 |
| **读完反馈**：号牌转一圈 + ✓ 弹入 | **只在刚读完那一课播一次** —— 每次都播会变噪音，噪音会让人不再注意它，反馈就白做了 |
| **底部按钮带进度** `下一课 · 12/55` | 随时知道"我在 55 课里的第几课"，比单独一个"下一课"有方向感 |
| 列表项淡入（≤240ms，逐项 12ms 延迟） | 有"内容在展开"的感觉，且不拖 |

⚠ 「检查中」那种**真实等待反馈**在手机版用不上 ——
  手机**不判分**（PEP 738），所以没有"等 1~3 秒"的场景。桌面上本来就有。

## 六、⚠⚠ 真机怎么验：**用 CDP，不要用 `input tap`**

**这是本项目在安卓侧最重要的经验。**

```
旧：adb shell input tap 540 825  + 截图 + 用眼睛看
      · 预览尺寸 838×1862 ≠ 屏幕 1080×2400，要乘 1.289
      · 页面一滚动，元素的 y 就变了，得重新截图重新量
      · 点了没反应时**分不清「没点中」还是「点中了但逻辑没跑」**
      ⇒ 我为它烧了好几轮，还误判过一次"功能坏了"

新：python _build/_cdp.py --看                 # 读页面状态
    python _build/_cdp.py --点 "[data-做=分享]"  # 点（不碰坐标）
    python _build/_cdp.py "任意 JS"
```

⚠ **前提**：`.NET Android` **没有** `WebViewDebuggingEnabled` 这个
  MSBuild 属性（全盘搜过，一次都没出现）—— 必须显式调
  `WebView.SetWebContentsDebuggingEnabled(true)`。
  我一开始以为"开了但 socket 没出现"就放弃了，**那个判断是错的**。

### CDP 直接抓出来的两个真 bug

```
① 桥拿不到 Activity
   Application.Context as Activity → **null**（前者是应用上下文，不是 Activity）
   而界面本身完全正常 ⇒ 只在运行期暴露，编译期一点提示都没有

② python.zip 过期，构建照样报成功
   生成物 web/index.html  10:53:10  ← 新
   app/python.zip         10:51:51  ← 旧
   ⇒ 打包用旧界面，而真机上看着像"功能坏了"
```

⚠ ②和「素材指纹只比手写常量」是**同一类 bug**：
  **构建会静默地使用过期的东西**。⇒ 已加过期检查（拦下来并说清怎么修）。

## 七、已做完的关键决定

| 决定 | 为什么 |
|---|---|
| **零第三方依赖** | 铁律。Python 只用标准库；C++ 引擎只用系统库 |
| **版本号第一位保持 `0`** | 作者要求。单一真值 = `hybridengine_light/__init__.py` 的 `__version__` |
| **GESP 官方 PDF 没读到** | 工具不支持 PDF。一到八级是从两个可读来源交叉核对的，文档里如实标注 |
| **Java / C# 不按 GESP 补** | GESP 只考 C++ 和 Python。那两门按"C++ 那批算法"补齐 |
| **安卓用 .NET Android 宿主，不用 Gradle** | 本机构建链是 .NET Android；Python 产物从 Maven Central 直接取裸 zip |
| **手机版 UI 用网页，不用 Tkinter** | Tkinter 在安卓上不存在（PEP 738 官方名单） |
| **手机版不走桌面引擎** | 作者：「手机要单独做一版」。而且这台设备上 `Py_Initialize()` 一调就原生崩（已实测排除五个候选） |
| **验证脚本不留、报告留** | 脚本是一次性脚手架。⚠ 但 `_cdp.py` **留** —— 它是"以后改安卓界面不再烧轮次"的基础设施，已在文件头写清 |
| **答案用「发到电脑」而不是剪贴板** | 剪贴板 API 上卡了三次；而分享对"手机→电脑"**还更合适**（系统面板里微信/QQ/邮件/蓝牙都能用） |
