## 二、⭐ 核心声明验证：**它真能做游戏**

用它的公开 API 拼了一个最小游戏并真跑：

```python
from hybridengine_light import pyengine as E
from hybridengine_light.pyengine import components as C

s = E.场景('t')
p = s.造('玩家', 50, 50); p.加(C.方块(宽=6, 高=6, 颜色='蓝'))
e = s.造('敌人', 20, 20); e.加(C.圆点(半径=3, 颜色='红'))
e.加(C.匀速移动(vx=0.5, vy=0.25))
b = E.录制后端()
g = E.游戏(场景=s, 宽=400, 高=300, 后端=b)
g.跑(帧数=60)
```

实测输出：

```
有圆 = [('圆', 20.008333333333333, 20.004166666666666, 3.0, '红')]
```

⭐ **x 从 20.0 → 20.0083** = `0.5 / 60` ⇒ **匀速移动真的在动**，
  场景 / 组件挂载 / 运动 / 游戏循环 **全部可用** ⇒ **"可模块化拼游戏"这条成立**。

## 三、⚠ 口径澄清：测试数 380 → 456 是**同步**，不是退步

`samplecore-pack` 交付时报"380 测试"，我自己重新生成后是 **456**。
差 76 = `test_neural`(32) + `test_果蝇`(17) + `test_engine_fingerprint`(27)。

⚠ **真因**：`make_samplecore.py` 就是**复制 LearningCore 的全部内容**（含 `tests/`）。
```
它交付时：LearningCore 是 380 测试 ⇒ SampleCore 380
现在：    LearningCore 是 456 测试 ⇒ SampleCore 456
```
⇒ **没有"SampleCore 该不该带神经模拟"的政策** —— **它跟着 LearningCore 走**。
  ⚠ 而这有个**后果要记**：**SampleCore 的判据数会随 LearningCore 变**，
    所以"SampleCore 380 全过"这个说法**只在某个时刻成立**。

## 四、✅ 干净度：生成器**确实会清** `__pycache__`

`samplecore-pack` 自己提过一个坑：**跑完测试 `.pyc` 会回来**。
按正确顺序实测：

```
生成前（我刚跑过测试）     .pyc = 11
跑 make_samplecore.py --go --force  → 输出「清扫：没有要清的（干净）」
生成后                     .pyc = 0   __pycache__ 目录 = 0
再跑一次门禁               **456 + 7 全过 · 退出码 0**
```
⇒ **发行物是干净的**；`.pyc` 只是"跑过测试"的痕迹，**再生成一次就没了**。

## 五、⚠ 我自己的三个误报（记下来，免得后人踩）

复核过程中我**连着猜错三次 API**：

| # | 我猜的 | 真实 |
|---|---|---|
| 1 | `录制后端.指令` 是全部记录 | 它是**本帧**的；**另一套是 `有圆()` / `有矩形()` / `有线()` / `有文字()`** |
| 2 | `匀速移动(速度=(30,15))` | `匀速移动(vx, vy, 边界=None)` |
| 3 | `匀速移动(每帧=(...))` | 同上 |
| 4 | `场景对象.位置` | `场景对象.世界位置` / `.变换` |

⇒ ⚠ **而这正好是本仓那条规矩的又一例**：
> **别猜 API —— 先 `inspect.signature` / `dir()` 打出来。**

⚠ 而且我一度因为 `指令 = 0 条` 写了"每帧有指令 = False"，
  **差点报成 bug** —— 其实是**我看错了记录通道**（`有圆()` 里明明有）。
  ⇒ 和队友那条"**判据红了要先问是它测的东西红、还是仪器坏了**"是**同一族**：
    **这次的"仪器"是我的 API 假设。**
