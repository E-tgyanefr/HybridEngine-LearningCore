## 七、⭐ 本会话学到的**工具性纪律**（比数字更值得留）

```
① ⭐⭐ **猜两次不对就该换工具** —— 用 `-D_GLIBCXX_ASSERTIONS` **一步**定位了两处越界
   （`u[n+i]` 与 `CgSolve` 契约违反），而"改一处看崩不崩"白费了两轮
② ⭐ **"可疑的巧合数字"往往是内存错误的症状**，不是数学现象
   （n=8 的 err 恰好等于一侧闭合的 4.9308e-02 —— 修后变成 3.02e-04）
③ ⭐ **判据要按性价比排序**：常数保持 → 守恒 → 特征值 → 对齐解析解
④ ⚠ **"实测阶"必须跨够宽的 h 区间** —— 区间太窄 ⇒ 两项混合 ⇒ 得到"看起来对"的阶
⑤ ⚠ **"行和 = 0"只能定总和** —— 抓得出"反射归错"，抓不出"结构错"
⑥ ⭐ **"必要条件达成" ≠ "充分条件达成"** —— 本会话栽过两次（守恒 / 每行方程）
⑦ ⭐ **"两个人写的一样"不是证据** · **"本机盘上有" ≠ "仓库里有"**
⑧ ⭐ **一条没有反面的判据 = "我加了个东西、它自己说自己行"**
```
