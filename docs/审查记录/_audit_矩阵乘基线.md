## 一、为什么量这个

目标：「**以及 ai 训练等大任务**」。
⚠ 而"大任务"的瓶颈在**张量的矩阵乘** —— 它是 MLP 的前向/反向里**唯一 O(N³)** 的算子。

⚠ 现状（我在 `src/ai/tensor.cpp:274` 读到的实现）：
```cpp
Tensor 矩阵乘(const Tensor& a, const Tensor& b) {
    ...
    for (int i = 0; i < M; ++i)               // ← 输出行
        for (int k = 0; k < K; ++k) {
            const 标量 aik = pa[i*K + k];
            if (aik == 0.0) continue;         // ← 稀疏跳过
            const 标量* brow = pb + k*N;
            标量* crow = c + i*N;
            for (int j = 0; j < N; ++j) crow[j] += aik * brow[j];   // ← 只写 crow
        }
}
```
⇒ ⭐ **行间完全独立**（每行只写自己的 `crow`，且 `k` 的累加次序在行内固定）
  ⇒ **并行化天然逐位安全** —— **不需要**"按块序求和"那类技巧（行之间没有归约）

## 三、⭐ 而我预期它**与光栅化器相反**（这次并行会赚）

| | 单次工作量的量级 | 一次并行派发的代价 | 结论 |
|---|---|---|---|
| **光栅化器**（r=9 的圆） | **~110 纳秒** | 微秒级 | ❌ **净亏**（实测 1.005x · 0 派发） |
| **矩阵乘**（N=512 的一行） | **~42 µs**（21.6773 ms ÷ 512 行） | 微秒级 | ✅ **应该赚**（派发占 ~2~5%） |

⇒ ⭐ **这是同一条规律的两个方向**：
  **并行的门槛不是"图元数/矩阵大小"，而是"单次派发的量级 ÷ 派发开销"** ——
  光栅化器那边这个比值是 **0.1**（亏），矩阵乘这边是 **~10**（赚）。

## 五、⚠ 没验到的（逐条）

1. **并行版的实际提速** —— **没做**（这一轮只交基线）
2. **不同 N 下的门槛**（N=64 / 256 / 512 / 1024）—— 只测了 512
3. **`-O3 -DNDEBUG` 与 CMake `release-ninja` 的实际标志是否一致** —— 我按 CMakePresets 读了
   （`CMAKE_CXX_FLAGS_RELEASE = -O3 -DNDEBUG`），但**没核 CMake 最终传给编译器的完整命令行**
4. **12.383 GFLOP/s 这个数本身好不好** —— 没有参照物（手写朴素 i-k-j 无分块、无 SIMD 提示）
   ⚠ 也就是说：**并行只解决"用几个核"，不解决"单核效率"** ——
   而单核还有很大空间（分块 / 向量化），**那是一条独立的优化**
