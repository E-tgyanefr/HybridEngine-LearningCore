## 五、本仓代码**怎么**进 APK（查到关键路径了）

`android/app/AssetInstaller.cs` 头部自己写了为什么必须解出来（**不是偷懒**）：

```
14| ⚠⚠ 为什么必须解出来，不能直接从 assets 用：
15|   ① assets 在 APK 里是**压缩**的，CPython 的 `import` 要 seek
17|   ② CPython 要往 `__pycache__` **写**字节码，assets 只读
18|   ③ 课程要生成答题文件
32| const string 标记名 = ".assets-ok";
35| const string 素材包 = "python.zip";
57|   · `python.zip` 的**字节数** —— 素材一变基本就会变（够用且零成本）
69| using var fd = 上下文.Assets!.OpenFd(素材包);
118| int 个 = 解zip(上下文, Path.Combine(临时, "python-stdlib"), ...
```

⇒ **解包在首次启动做一次**，而"要不要重解"靠 **`.assets-ok` 标记 + `python.zip` 的字节数**。

⚠⚠ **这是一条我要标红的判据**：
```
"素材一变基本就会变（够用且零成本）"
```
⇒ ⚠ **那是"字节数变了才重解"** ⇒ **如果本仓代码变了、但 `python.zip` 的字节数没变
  （或变了而标记没被清），手机上跑的还是旧代码。**
⇒ 而"**版本号标记只比版本号，内容变了不会重解**"是**它自己在注释里承认的坑**（L53）。
⇒ **真判据应该是"内容哈希"，不是"字节数"** —— ⚠ **这一条我没验，也没改。**
  ⇒ 但**它能解释一类最恶心的 bug**：本机改了代码、手机上看不到变化。
     ⚠ 而开发者会以为"我的改动没生效"⇒ 去查别的地方。

⚠ **我没验的**：
1. `.assets-ok` 现在存的是什么（版本号？字节数？两者？）
2. 本仓代码到底在**哪个文件**里进 APK（`python-app`？还是每次从别处拷）
3. **改一次源码 → 重装 APK → 手机上是否真的变了**（这条要真机，我没做）
