# 架构决定：新 C++ 窗口怎么和现有 tkinter GUI 共存（2026-10-14）

> 背景：作者批准「**允许轻量版有自己的窗口（不再嵌 tkinter）**」。
> 队友 `task-12` 已经证明**技术可行**（同口径 1000 个可见圆 **0.1107 ms/帧**，
> 而 tkinter 在 1000 个 item 时是 **16.18 ms** ⇒ 正好卡在 60 帧线上）。
>
> 但"新窗口怎么和学习内核**现在的** tkinter GUI 共存"是**架构决定**，不是技术问题。
> 这一份是我（Lead）的决定 + 依据 + 第一步实验。

---

## 一、量清的约束（不是猜的）

**① 后端协议只有 8 个方法**（`pyengine/render.py`）：

    清屏 / 画圆 / 画矩形 / 画线 / 画文字 / 呈现 / 关闭 / 还开着

⇒ 任何"能画这 5 种图元 + 呈现"的东西都是合法后端。**接口不是障碍。**

**② tkinter 独占主线程 + 自己的事件循环**（`learn_gui.py`）：

    156| self._容器 = tk.Frame(self, bg=背景)
    178| self.after(80, self._收任务)          ← 轮询
    373| self.after(120, self._后台载入编译型)   ← 轮询
    ⇒ 主线程是 Tk 的，**只能靠 `after()` 挤时间片**

**③ 现有 Tk 后端是"一帧一帧从主线程推"**：

    render.py 334| def 呈现(self): ...
    render.py 338|     self._root.update()

## 二、⭐ 决定：**同线程 + 子窗口（child window）**，不做独立进程

### 为什么不做独立进程

- `pyengine` 的意义是**学员在同一个进程里写代码、IDE 当场跑**（`sample_gui` 的"运行窗"）
  ⇒ 独立进程会**切断"代码 ↔ 画面"的直连**，而且**共享状态**（分数、场景）要跨进程同步
- 学习内核的 `examrun` / `check` 都是**进程内**判分 ⇒ 独立进程要重做那一层

### 为什么"同线程子窗口"可行

- Win32 里 **Tk 的 `update()` 本身就在抽 Windows 消息队列**，
  而创建在**同一线程**上的外部窗口，消息**会经由同一个队列**
  ⇒ 只要**每帧调一次 `泵消息()`**，外部窗口就能响应（含 WM_PAINT / 关闭 / 按键）
- 子窗口（`WS_CHILD`）挂在 Tk 的框架上 ⇒ **视觉上仍在 IDE 里**，
  不需要另开一个顶层窗口，**不需要用户切窗口**
  ⚠ 这正好满足作者那句"有自己的窗口"，而且**不破坏 IDE 的形态**

⚠⚠ **但这条有一个我没验的前提**：Tk 的窗口和我们的子窗口能否**真的共用一个消息泵**。
  ⇒ **这是第一步实验，不成的话整个方案要改。** 详见第四节。

## 三、⚠ 三个已知的坑（写在这里免得后人踩）

1. **`画文字` 需要字体光栅化** —— C++ 后端现在**没有文字**
   （队友报的"没验到的"第 4 条）。
   ⇒ 学习内核的 `标签` / `分数` 组件都要文字 ⇒ **不做文字就接不进去**。
   ⚠ `pyengine` 里还有 `render._界面字体()` 那套 —— 要么 C++ 侧自己光栅化，
     要么**文字仍走 Python**（混合，但那就不是"整帧 C++"了）。
2. **输入要自己接** —— 现在键盘是 tkinter `bind` 的（`render.py:371`）
   ⇒ 子窗口拿到焦点后，**键盘事件会走我们的窗口**，
     而 `pyengine.输入` 的 `_按下` set 是**唯一真源**（队友查证过：
     `render.py:356` 的 `按键表.add(k)` **绕过** `_按`）⇒ 要把两条路接回同一个 set。
3. **裁剪语义**：`Tk后端.允许裁剪=True`（画布上只留看得见的），
   而 `录制后端=False`。新的 C++ 后端**必须选一个并写清**，
   否则 `test_pyengine` 会因为"画布上 item 数"对不上而红。

## 四、第一步实验（**先验那个前提，别的都别做**）

```python
# 目标：证明"Tk 的 update() 能驱动一个外部创建的子窗口"
1. 在 Tk 主窗里拿 HWND（winfo_id()）
2. 用 CreateWindowEx(WS_CHILD, parent=那个 HWND) 建一个子窗口
3. 在 Tk 的 after() 循环里调 泵消息() + 每帧 StretchDIBits 一张位图
4. 判据：
   · 子窗口**可见**（截屏或 GetPixel）
   · **帧真的在变**（位图内容每帧不同 ⇒ 校验和变）
   · ⚠ **反向**：Tk 自己的控件（按钮/文字）**仍然正常响应**
     —— 这一条最容易翻车（消息被我们吃掉了）
```

⚠ **判据的写法要照本仓的规矩**：
  · 光"窗口出现了"不算 —— 要**证明帧在变**（校验和逐帧不同）
  · 光"帧在变"不算 —— 要**证明 Tk 控件还能用**（点一个按钮，看它响应）
  · ⚠ 而这正是本仓栽过的"**没跑到 vs 过了**"那一类 ⇒ **两条都要显式断言**

---

## 五、⚠ 这一步的风险等级：**高**

- 如果"共用消息泵"不成立 ⇒ 要退回**顶层窗口**（用户切窗口，IDE 形态变了）
  或**子进程**（IDE 形态不变，但 `pyengine` 的进程内语义破了）
- 两个退路**都比原方案差**，所以**先用一个半小时把第一步实验做完，再决定**

⚠ 而**在第一步实验通过之前，不许有人写"接进 pyengine"的代码** ——
  那是把地基没验的房子往上盖。
