# C++ 移植 · 行为契约

> **一句话**：C++ 版引擎的**可观察行为**必须与现 Python 版**逐位相同**。
> 这份文档说清「**哪些必须逐位相同**」「**哪些允许不同**」「**怎么证明**」。
>
> 比对基准：`_build/_engine_fingerprint.json`（**生成物，要提交**）
> 生成器：`_build/_engine_fingerprint.py` · 判据：`tests/test_engine_fingerprint.py`

```
指纹格式 v1 · 对应 Python 版 hybridengine_light v0.8.0
重新生成：python _build/_engine_fingerprint.py
```

⚠ **文件头那两个版本号是给未来的你留的**：
以后指纹对不上时，先看 `对应产品版本` ——
· 代码版本没变而指纹对不上 ⇒ **行为真的变了**（是 C++ 版错了，或 Python 版被改了）
· 代码版本变了 ⇒ **可能只是该重新生成指纹了**（那是进步，不是缺陷）
判据 `test_头里的版本号与代码一致` 就守着这一条。

## 1. 一句话口径

```
同一个脚本、同一串输入 ⇒
图元序列（类型 + 顺序 + 每个数值 + 颜色字符串）必须逐字节相同
```

⚠ 「数字看起来一样」**不是证明** —— 它盖得住末位差异，而**末位差异正是移植最常出的错**。
⇒ 本契约里所有浮点都写成 `float.hex()`（见第 2 节）。

---

## 2. 数值编码：`float.hex()`（**必须照抄**）

**每一个浮点数都编码成 `float.hex()`**，例如：

```
1.1          →  0x1.199999999999ap+1
100.0        →  0x1.9000000000000p+6
1/60         →  0x1.1111111111111p-6
-0.0         →  -0x0.0p+0          （⚠ 负零要保留，别规范化成 0）
```

为什么这样选：

| 理由 | 说明 |
|---|---|
| **精确** | `float.hex()` 逐位往返，十进制 `repr` 会把末位差异四舍五入掉 |
| **跨语言同格式** | **C++17 的 `std::hexfloat` 输出同一个格式** ⇒ 两边直接对字符串 |
| **看得见差异** | 末位差一位在 hex 里是**肉眼可见的一个字符**，在十进制里几乎是隐形的 |

特殊值：`nan` / `+inf` / `-inf` 直接写这三个词（Python 与 C++ 都能对上）。
非浮点：整数写十进制；布尔写 `真`/`假`；字符串原样。

---

## 3. ⚠⚠ 浮点累加顺序（**最容易翻车的一条**）

**同样的数学、不同的累加顺序 ⇒ 不同的末位。** 两个真实先例：

### 3.1 Python 3.12 的 `sum()` **不是**顺序累加

```python
sum([0.1] * 10)        # → 1.0                     ← Neumaier **补偿求和**
朴素循环                # → 0.99999999999999988898
```

⇒ Python 3.12 给 `sum()` 加了浮点补偿求和（gh-100425）。
**拿 `sum()` 当"顺序累加"用，跨语言必错。**
（这条是 `neural-light` 在神经模拟的对齐里实测踩到的：1000 步之后 DIGEST 全错。）

**C++ 侧要注意的是同一件事的另一面**：

```cpp
// C++ 的 std::accumulate / 手写循环是**朴素顺序累加** ⇒ 与 Python 的 sum() 不同
double acc = 0.0;
for (double x : xs) acc += x;
```

**结论**：Python 侧凡是要与 C++ 对齐的地方，**必须写成显式循环**
（或 `itertools.accumulate`，它是朴素累加），**不许用 `sum()`**。

### 3.2 现在的 `pyengine` 里有没有这个风险？

**读代码查过：核心路径上没有浮点归约。** 具体：

| 位置 | 写法 | 风险 |
|---|---|---|
| `向量.__add__/__sub__/__mul__` | 逐分量标量运算 | ✅ 无归约 |
| `变换.世界位置/局部转世界` | 沿父链**逐级**乘加（顺序固定） | ✅ 顺序由父链唯一确定 |
| `相机2D.世界转屏幕` | `(x-cx)*k + w/2` 纯算式 | ✅ 无归约 |
| `Tk后端._xy/_r/_在视野内` | 纯算式 | ✅ 无归约 |
| `游戏.跑()` | `累积 += 经过` | ⚠ 见第 5 节 —— 它依赖**墙钟**，本来就不能逐位比 |

**✅ 实测查过**：`scene.py` / `engine.py` / `render.py` / `components.py` 四个文件里
`sum(` 只出现 **1 次**，而且是 `sum(1 for _ in self.遍历())`（**数个数**，不是浮点归约）
⇒ 核心路径上**没有浮点归约**，"累加顺序"风险目前为零。
⚠ 但这条要**每次改动后重查** —— 它是"现在没有"，不是"永远不会有"。

⚠ 但**移植之后要小心**：C++ 侧如果为了性能把"沿父链逐级乘加"改成"先合成一个 4×4 矩阵再乘"，
**结果会差末位**。本契约要求：**保持与 Python 相同的运算顺序**（哪怕慢一点），
或者在 `-ffast-math` 这类会重排浮点的开关上**明确关掉**。

> ⚠ `-ffast-math` / `-Ofast` 允许编译器重排、融合浮点运算（FMA）
> ⇒ **与 Python 逐位相同这件事直接作废**。必须用 `-O2` 且不加 fast-math。

## 4. **必须逐位相同** ✅

| # | 项 | 说明 |
|---|---|---|
| 1 | **图元顺序** | 每帧：先 `清屏`，再按"根顺序 → 子对象递归"绘制；组件按**挂载顺序**，子对象按**加入顺序**（不是字典序） |
| 2 | **图元的类型与字段顺序** | `("圆", x, y, r, 色)` / `("矩形", x, y, w, h, 色)` / `("线", x1,y1,x2,y2, 色, 粗)` / `("文字", x, y, 内容, 色, 字号)` / `("清屏", 色)` |
| 3 | **每个数值的位模式** | 用 `float.hex()` 比 —— 末位不同就是不同 |
| 4 | **颜色字符串** | 中文色名原样传（`"红"`/`"蓝"`…）；**不许**在这一层翻译成 `#RRGGBB` |
| 5 | **对象遍历顺序** | `场景.遍历()` = 自己 + 后代，**按挂载顺序**；`场景.根` 是列表，顺序就是加入顺序 |
| 6 | **组件回调顺序** | `挂上时` →（每帧 `每帧` → 绘制时 `绘制`）→ `卸载时` |
| 7 | **控制流语义** | 例：`匀速移动` 的边界判定是 `<=` / `>=`（**不是** `<` / `>`）；`重力.跳()` 不在地上返回 `False`；`按键驱动` 方向已归一 |
| 8 | **渲染哈希** | sha256，**同算法同输入**（见第 6 节）—— 输入编码也要一样 |
| 9 | **两个后端的裁剪开关** | `录制后端.允许裁剪 = False`、`Tk后端.允许裁剪 = True`、`Tk后端.MARGIN = 10.0`、`游戏.步长 = 1/60` |
| 10 | **裁剪判定与坐标换算** | 屏幕坐标 `[-MARGIN×k, 宽+MARGIN×k]` 闭区间为真；**两轴必须同时在区间内** |
| 11 | **随机数** | 唯一随机源：`吃食物` 的食物重定位。见第 7 节 —— 这条最硬 |

## 5. **允许不同** ⚠（但每一条都要有理由）

| # | 项 | 为什么允许 | 但要满足什么 |
|---|---|---|---|
| 1 | **`游戏.跑()` 的帧间时序** | 它按**墙钟**补帧（`累积 = min(累积 + 经过, 步长*8)`）⇒ 快/慢机器上"第 N 帧更新了几次"本来就不同 | 逻辑**固定步长**必须相同；逐位比对一律用 `游戏.一步(dt)`，**不许用 `跑()`** |
| 2 | **超越函数的末位** | 两个语言的 libm 只保证 ~1 ULP，`cos/sin/hypot/pow/exp/sqrt` 都可能差最后一位 | 见第 5.1 节的**登记名单**；差的时候要能指出"这是登记过的" |
| 3 | **字体族名与字形** | `theme.界面字体()` 按 `sys.platform` 给候选表；Tk 会按系统回退 | 只影响**看起来**怎么样，不影响图元数值；`("文字", …)` 里的**内容字符串**仍必须相同 |
| 4 | **Tk 的 item id / canvas 内部状态** | Tk 自己分配 | 只比**数量**（`find_all()` 的长度） |
| 5 | **`_build/` 下的耗时类数字** | `ms/步` 之类随机器变 | 不进指纹 |
| 6 | **Python 版本 / 平台字符串** | 写在指纹 `头` 里 | **判据不比 `头`**（只比 `内容` + `统计`） |

### 5.1 超越函数登记名单（**差 1 ULP 时可以放过**）

生成器给每个场景打了 `含超越函数` 标记。当前**只有这 5 个**：

| 场景 | 用到的超越函数 | 在哪 |
|---|---|---|
| `组件_按键驱动` | `math.hypot` | `向量.长度()` —— 方向归一化 |
| `输入_按键语义` | `math.hypot` | 同上 |
| `组件_圆形碰撞` | `math.hypot` | `圆形碰撞.碰到` |
| `组件_跟随相机` | `pow(e, -dt/平滑)` | `相机2D.每帧` 的平滑追赶 |
| `确定性_吃食物重定位` | `math.hypot` | `吃食物.每帧` 的"碰到没碰到"判定 |

⚠ 其余 **25 个场景是纯算术 ⇒ 必须逐位相同，没有"1 ULP 容差"这一说**。

⚠ 还有一个**跨语言的坑**：CPython 的 `math.hypot` **不是** `sqrt(x*x+y*y)`，
它用带缩放的算法避免上溢。C++ 的 `std::hypot` 也带缩放，但**两者的最后一位不保证一致**。
⇒ 要么接受 1 ULP，要么在 C++ 侧**照抄 CPython 的算法**（那才能真正逐位相同）。

## 6. 哈希：**同算法、同输入**

### 6.1 算法

```
sha256(规范文本的 UTF-8 字节)
```

### 6.2 规范文本格式（**逐字节照抄**）

```
每帧一行头：      帧 <n>\n
该帧每个图元一行： <字段1>\t<字段2>\t…\t<字段k>\n
字段 = 该图元的每一项按第 2 节编码
```

即：

```python
文本 = ""
for f in 帧们:
    文本 += "帧 %d\n" % f["帧"]
    for 图元 in f["图元"]:
        文本 += "\t".join(编码(x) for x in 图元) + "\n"
哈希 = sha256(文本.encode("utf-8")).hexdigest()
```

⚠ 三个细节：**`\n` 是 LF 不是 CRLF**；**数字用十进制不带前导零**；**末尾没有多余空行**。
（生成器写文件时显式用 `newline="\n"`，就是为了平台无关。）

### 6.3 每个场景一个哈希

除了逐条比对，每个场景还有 `渲染哈希` —— 给 C++ 版**一眼看总量对不对**，
对不上再下钻到逐条。⚠ 两者必须**结论一致**（判据里有一条专测这个）。

## 7. ⚠⚠ 随机数：这条最硬

`pyengine` 核心**没有随机源**。唯一的随机调用在 `pyengine/games/snake.py` 的
`吃食物.每帧`：

```python
self.随机源.seed(self.吃到 * 7919)        # ← 每次吃到**重新播种**
self.食物.变换.位置 = 向量(
    (self.随机源.randrange(列数) - 列数 // 2) * 格,
    (self.随机源.randrange(列数) - 列数 // 2) * 格)
```

### 7.1 两个必须复现的行为（**都是实测确认的**）

| # | 行为 | 证据 |
|---|---|---|
| 1 | **同种子两遍 ⇒ 逐字节相同** | 指纹里 `确定性_贪吃蛇同种子两遍.同种子两次相同 = 真` |
| 2 | ⚠ **异种子也相同** —— 因为每次吃到都**重新播种**，构造时的 `种子` 对食物位置**无效** | 同上场景的 `⚠ 异种子也相同（设计如此，不是假绿） = 真` |

⚠⚠ **第 2 条不许"顺手修好"。** 它是一个**看起来像 bug 的设计**：
注释写着"不用全局 random，免得测试不可复现"。
C++ 版必须**照样复现** —— 否则指纹会对不上，而那不是指纹错了。

### 7.2 要逐位相同，C++ 侧必须实现**同款 RNG**

`random.Random(种子).randrange(25)` 在 CPython 里是：

```
MT19937（梅森旋转，CPython 的种子初始化 = init_by_array）
  → getrandbits(k)
  → _randbelow_with_getrandbits：**拒绝采样**（抽到 ≥ n 就重抽）
```

⇒ C++ 侧要么照抄这三层（**包括 `randrange` 的拒绝采样**，用 `%` 取模会得到不同的结果），
要么**放弃这一条的逐位相同**并在文档里明写。

**✅ 这个规格本身被验过**（不是照抄文档，是实测）：

```
用「MT19937 + getrandbits(k) + 拒绝采样(r>=n 就重抽)」复刻 CPython 的 randrange(25)：
  抽 2000 次 → **逐项相同** ✅
同一个种子改用 `getrandbits(k) % 25`：
  前 12 个 [13,23,0,1,1,0,9,2,11,4,6,8]，而 randrange 给 [13,23,0,9,11,6,8,18,13,5,11,3]
  ⇒ **不同** ⇒ 契约里必须写"拒绝采样"，写"% 取模"就错了
```

**实测输出已钉死**（`确定性_吃食物重定位`，连吃 3 次）：

| 吃到次数 | 食物新坐标（世界单位） | 世界坐标的 hex |
|---|---|---|
| 1 | (32, 12) | `0x1.0000000000000p+5` / `0x1.8000000000000p+3` |
| 2 | (-32, 20) | `-0x1.0000000000000p+5` / `0x1.4000000000000p+4` |
| 3 | (8, -32) | `0x1.0000000000000p+3` / `-0x1.0000000000000p+5` |

⚠ 这三个数是**实测**，不是算出来的。C++ 侧跑出别的值 ⇒ RNG 没对齐。
**✅ 而且它们能被上面的规格反推出来**：用复刻的 `randbelow` 算 `seed(吃到×7919)`
后两次 `randrange(25)`，得到的正是 (32,12) / (-32,20) / (8,-32) ——
⇒ 规格写全了，C++ 侧照着实现就能对上。

## 9. ⚠⚠ 指纹**没有**覆盖到的（照实列）

移植时这些地方**别以为有保护**：

1. **真实像素**。`Tk后端` 只钉了「提交多少 item」+「坐标换算」+「裁剪判定」。
   抗锯齿、线宽取整、圆角、z 序、重绘时机 —— **一个都没覆盖**。
2. **字体族与字形**。`_界面字体()` / `theme` 依赖平台，本来就会不同（见第 5 节）。
3. **输入事件绑定**（`Tk后端.装输入`，键盘/鼠标 → `输入` 状态）。指纹是**直接操纵**
   `输入._按/_放` 的，没有走真实事件。
4. **`游戏.跑()`** 的时序与帧率（墙钟）。
5. **`pyengine.games` 里的其它游戏** —— 只覆盖了贪吃蛇。
6. **异常与报错文案**（`explain.py` 的友好报错）—— 没有覆盖。
7. **`-O2` 之外的编译选项**：指纹是在 CPython 3.12.10 / win32 上生成的；
   换个 Python 小版本、换个平台，**超越函数那 5 个场景**就可能差 1 ULP。
   ⇒ 逐位相同的**先决条件**是：C++ 侧不许用 `-ffast-math`、不许让编译器重排浮点。
8. **性能**。这份指纹只管"对不对"，不管"快不快"。

## 10. 怎么用（给 `engine-docs` 的具体操作）

```powershell
cd 引擎\HybridEngine-LearningCore

# ① 生成 / 更新指纹（Python 侧；会开一次 Tk 窗口量 item 数）
python _build\_engine_fingerprint.py

# ② 只导 JSON 到 stdout（CI / 工具链用）
python _build\_engine_fingerprint.py --stdout

# ③ 无显示环境（跳过 Tk 那一段，指纹里会记「不可用」）
python _build\_engine_fingerprint.py --无Tk

# ④ 判据：重跑并与落盘逐条比
python -m unittest tests.test_engine_fingerprint -v
```

**C++ 侧的对法**（建议）：

1. 把 C++ 版跑出来的图元序列按第 2 节 / 第 6 节编码成**同样的规范文本**
2. sha256 与 `_engine_fingerprint.json` 里每个场景的 `渲染哈希` 比
3. 对不上 ⇒ 用 `比对()` 同样的思路**下钻到路径**（`内容.<场景>.帧[n].图元[m][k]`）
4. ⚠ 别只比"总数" —— 这个仓栽过的假绿就是"总数对了就放过"

⚠ 如果 C++ 版**有意**要做行为变更（比如修掉第 7.1 节第 2 条那个怪设计），
那要：**先改 Python 版 → 重新生成指纹 → 再让 C++ 版对**。
不许两边各改各的，那样指纹就成了没人维护的摆设。

## 11. 这份契约自身怎么被守着

判据 `tests/test_engine_fingerprint.py`（27 条）分三组：

| 组 | 守什么 |
