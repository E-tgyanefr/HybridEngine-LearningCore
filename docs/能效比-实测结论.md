# 轻量版能效比：实测结论（2026-10-14）

> 目标曾是「**在原来的性能基础上提高能效比，尽量提升到原先的一倍**」。
> 这份文档是**实测证据 + 诚实结论**：为什么那"一倍"在**当前渲染路线**上做不到，
> 以及要怎么做才有。
>
> ⚠ 本仓规矩：**数字不好看也要写。**

---

## 一、先看钱花在哪（1000 对象，1920×1080）

```
录制后端（纯逻辑 + 记账）       0.469 ms/帧
Tk后端（真画到 tkinter）        4.855 ms/帧
                                 ⇒ **绘制占 90.3%**
组件更新 0.2679 · 相机 0.0000 · 绘制(记账) 0.4333 ms
调用数：450 万次 / 300 帧 = **每帧 15000 次 Python 函数调用**
```

⚠ 而且那个 4.855 ms 的 Tk 数字**画布上只有 20 个 item**（裁剪把视野外的去掉了）
⇒ 它**不能**当渲染性能的代表。下面所有数都是**铺满视野、不被裁掉**量的。

---

## 二、每个图元的成本是**固定的**（300 个铺满视野）

| 画法 | ms/帧 | 每个 | 相对现状 |
|---|---|---|---|
| ① `create_oval`（现状） | 4.363 | 14.54 µs | 1.00x |
| ② `create_rectangle`（方块） | 3.353 | 11.18 µs | **1.30x** |
| ③ `create_line`（粗线，2 点） | 5.537 | 18.46 µs | 0.79x |
| ④ `create_line`（5 点闭合） | 6.394 | 21.31 µs | 0.68x |
| ⑤ `N×coords` 复用（不删不建） | 3.975 | — | 1.10x |

⇒ **每个图元 ~11~14 µs 是 Tk 呈现层的固定开销，跟"画什么"几乎无关。**
  ⇒ 换图元、复用 item、少删少建 —— **全是小钱**。

---

## 三、⭐ blit 路线：**在当前 Tk 上不成立**（这条记住，别再试）

想法：用 C++ 软件光栅化器画进内存，再"整帧贴上去"。
**实测被否**：

```
Tk 版本                                 8.6.15
PhotoImage 有 frombuffer                **False**      ← 要 Tk 8.7+
① 每帧 put() 整帧（800×450 十六进制）     **64.306 ms**  ← 慢到不可用
② 一帧 = delete + create_image + update   0.219 ms
```

⚠ `PhotoImage.put()` 要 Tcl 逐字符解析 288 万个字符 ⇒ **64 ms/帧**，
   比"老老实实画 300 个图元"（4.4 ms）**慢 15 倍**。
⚠ 而 `frombuffer`（快路径）**Tk 8.7+ 才有**，本机是 8.6.15 ——
   而本仓铁律是**零第三方依赖**，不能为了它换 Python/Tk。
⇒ **结论：blit 路线死在 Tk 版本上，不是死在 C++ 那一侧。**

---

## 四、那"一倍"从哪儿来？—— 两条路，都不是"优化 Python"

### 路 A：**少画**（裁剪）—— **已经做了，3.2x**

```
裁剪开（默认）   5.818 ms   画布 item =  342 / 世界 4000
裁剪关          18.448 ms   画布 item = 4000 / 世界 4000
```

⚠ 但基准里 1000 个对象**全在视野内** ⇒ 裁剪**无可裁** ⇒ 这是它的天花板。

### 路 B：**换渲染后端** —— `引擎后端`

`render.py:11` 本来就写着：

```
· `引擎后端` —— 有 `hybridengine.dll` 时改用它（**留接口**，见 `可用引擎后端`）
```

⚠ 而 `可用引擎后端()` **只有探测，没有实现**（`render.py:378`）。
⭐ **这才是那"一倍"（还不止）该来的地方** —— 用专业版的 C++ 光栅化器，
   实测专业版 1000 对象 1.237 ms vs 轻量版 4.855 ms。

---

## 五、诚实结论

| 问题 | 答案 |
|---|---|
| 能效比**翻一倍**做到了吗 | ❌ **没有** |
| 为什么 | 绘制占 90.3%，而它的成本是 **Tk 呈现层固定的 ~11~14 µs/图元** |
| 试过什么 | 换图元（方块省 30%，线更慢）· 复用 item（省 10%）· 少删少建（无感）· **blit（死在 Tk 8.6）** |
| 有效的 | **裁剪 3.2x**（真实大世界；已默认开） |
| 真正的路 | **`引擎后端`** —— 让 C++ 光栅化器接手渲染（接口已预留，未实现） |
| 能做到吗 | ✅ 能做到**远超一倍**（专业版同场景快 3.9x，且那是 Python 侧包的）；⚠ 但**与本仓"两个内核完全不共用"的原则需要作者裁决** |

⚠ **我没做 `引擎后端`** —— 因为它要作者先裁一件事：
  「轻量版把渲染委托给专业版」算不算违反「**两个不同的程序，完全不共用，各写一份**」？
  ⇒ 这**超出我的决定权**，如实停在这里。
