## 四、数据源 ↔ 产物一致性（生成式的四条线）


"我手改过产物"和"数据源本来就对"混为一谈。

**当前实际**：

```

四条线**全部一致** —— 数据源和产物没有分叉
```

（C++/Java/C# 会报"磁盘上多出来的课" —— 那些是**手写课**，本来就不归生成器管，
是正常的。它们只有 00/09~15 那几课是数据源生成的。）

### 4.1 ⚠ 这里踩过一个很深的坑，值得你知道

**C 线曾经被一个错误的生成器覆盖成编译不过的版本**：

```
python _gen_c16.py                              → c 41/41 ✓
python _gen_c16.py && python _gen_compiled.py c → c 39/41 ✗
```

`_gen_compiled.py` 的线表里**也有一条 `"c"`**，产物目录和 `_gen_c16.py`
一模一样 ⇒ 两个生成器抢同一批文件，**后跑的说了算**。
而它的共享 `打印行()` 会给 C 产出 `printf("%s\n", (…).ToString())` ——
**C 里没有 `.ToString()`**。

⇒ 报的是「编译没能通过」，**而学生的代码一个字都没错**。
⇒ 已把 `"c"` 从 `_gen_compiled.py` 摘掉，并给了一句能照着做的提示。

它们有个**共同点**：都不是"某处代码写错了"，而是
