# 神经模拟（轻量版 · LearningCore）

> **一句话**：轻量版（纯 Python · 零第三方依赖）能跑**人脑规模的群体 / mean-field 层**，
> 结果与专业版（C++）**逐位相同**；但**同口径下慢 23~111 倍** ——
> **不是"略慢"**。另外单独提供一条**果蝇规模的逐细胞**路径。
>
> 模块：`hybridengine_light/neural.py`（v0.1.0）· 示例：`examples/神经模拟_*.py`
> · 判据：`tests/test_neural.py`

---

## ⚠⚠ 0. 先说清"模拟的是哪一层"（不读这条，后面所有数字都会被误读）

**人脑 860 亿神经元 / 约 100 万亿突触，逐细胞做不到。** 这不是"慢"，是量级不够。
本仓实测（下面第 4 节有原始输出）：逐细胞路径 **0.000122 ms / 神经元 / 步**（3 次中位数）
⇒ 乘 8.6×10¹⁰ 个神经元，跑**一步**（0.1 ms 生物时间）要 **≈ 2.9 小时**
⇒ 模拟人脑 **1 秒**生物时间要 **≈ 3.3 年**。纯 Python 里这条路是死的。

⇒ 所以本模块走**两条明确分层的路**：

| | ① `群体网络` | ② `脉冲网络` |
|---|---|---|
| 层级 | **大规模群体 / mean-field 层** | **逐细胞层** |
| 规模 | 人脑级（代表 8.6×10¹⁰ 神经元） | 果蝇级（10 万神经元） |
| 状态 | **群体的平均放电率**（一个标量/群体） | **每个神经元的 LIF 膜电位** |
| 突触 | 群体间"有效耦合强度"矩阵 | 逐条显式突触、事件驱动投递 |
| 方法 | Wilson–Cowan / Amari / Wong–Wang / TVB 那一类 | 泄漏积分发放（LIF） |

### 实现了什么 / **没实现什么**

```
✅ 模拟了   群体平均放电率的动力学（率映射 + 群体间有向连接 + 兴奋/抑制符号 + 环路）
✅ 模拟了   （逐细胞那条线）单个 LIF 神经元的膜电位与逐突触事件投递
❌ 没模拟   单个神经元的膜电位 / 树突形态 / 离子通道   ← **人脑那条线没有这一层**
❌ 没模拟   逐突触的权重与可塑性（群体层只有"有效耦合强度"）
❌ 没模拟   空间结构（皮层柱/层、轴突传导延迟、几何）
❌ 没模拟   任何"意识 / 认知"层面的东西 —— 这是动力学模型，不是脑
```

⇒ **本报告任何地方都不写"模拟了人脑"。** 准确说法是：
「**用 mean-field 群体层，覆盖人脑规模的连接结构**」。

### ⚠ 两个数**必须分开写**（混起来就是数字造假）

| 口径 | 含义 | 怎么来的 |
|---|---|---|
| `NNZ_PER_STEP` | 每步真正做的乘加次数 | **CPU 真算的**（性能口径） |
| `REPRESENTED_NEURONS` / `REPRESENTED_SYNAPSES` | "代表了多少神经元/突触" | **算术换算**，一分算力都没花 |

1 个连接矩阵元代表「群体 j 全体 → 群体 i 全体」的总有效耦合，背后压着
p·N_i·N_j 条真实突触。**矩阵元 ≠ 突触。** 报告里两个数分开列。

## 1. 同口径：与专业版跑的是**同一个计算**（逐位证据）

⚠ 光说"我们口径一样"没有意义 —— 下面这张表是**硬证据**。

口径与专业版那条线（`neural-pro`）逐条对齐后钉死（`neural.py` 模块开头写全了）：

```
状态      每群体一个标量 r_i（Hz），初值 5.0（全同、不随机）
每步      I_i = I_ext_i + Σ_j W_ij·r_j  →  r_i ← f(I_i)          （同步更新）
非线性    f(I) = 0 (I≤0) : R_MAX·I/(I+I_SAT)                     R_MAX=100, I_SAT=20
外部输入  I_ext_i = I_EXT[type]·(1 + 0.5·((i%17)/8 − 1))         E:12 I:8
拓扑      每行恰好 k = k_local + k_long 个非零；local 是环上 i±d（kernel 1/d），
          long 每行独立 RNG 抽（kernel 1/half）；Dale 原则符号；
          行归一化 Σ|w| ≡ G = 3.0（输入尺度与 k 解耦）
RNG       s = splitmix64(seed·GOLDEN + i)；next(): s^=s<<13; s^=s>>7; s^=s<<17
```

### 三条"末位级"的规矩（都是实测踩出来的，凭直觉写必错）

| # | 规矩 | 不这么写的后果 |
|---|---|---|
| ① | **权重存 float32** | 专业版 CSR 里 `w` 是 4 字节 `float`；这边留 float64 ⇒ 末位必差 |
| ② | **累加起点是 `I_ext`，再按目标下标升序逐项加** | 顺序差一个 ⇒ 末位差 ⇒ 1000 步后 DIGEST 全错 |
| ③ | **绝对不能用 `sum()`** | ⚠ Python 3.12 的 `sum()` 对 float 走 **Neumaier 补偿求和**（实测 `sum([0.1]*10) == 1.0`，朴素循环给 `0.99999999999999988898`）⇒ 拿它当"顺序累加"用，1000 步后必错 |

（`itertools.accumulate` 是朴素累加、也能对上，但慢 ~20%：22 M vs 27 M nnz/s ⇒ 用显式循环。）

### 核对结果：4 个参照点 **全部逐位相同** ✅

参照点 = **专业版 C++ 实测输出**（不是我推算的，也不是文档口径）。`DIGEST` 是全 64 位
FNV-1a（最终状态 `double[]` 的原始小端字节），**不给任何容差**。

```
  P=8     k=6   steps=1      r̄=   28.16257945（参考    28.16257945 ✅）  DIGEST=0x0DFF8FAC4D340322 ✅
  P=8     k=6   steps=10     r̄=   25.94342077（参考    25.94342077 ✅）  DIGEST=0x533BA597805BA02A ✅
  P=100   k=30  steps=1      r̄=   36.75108304（参考    36.75108304 ✅）  DIGEST=0xDD2110086658BD53 ✅
  P=100   k=30  steps=1000   r̄=   10.60823279（参考    10.60823279 ✅）  DIGEST=0x83A8F7990742CA15 ✅
```

⚠ `P=8, steps=1` 那个**最值钱**：它只做一次 `W·r` + 一次非线性 ⇒ 对不上就是
**拓扑或权重**错，与积分无关。没有它，"对不上"只能靠猜。

**再往下跑整张网格，也全部逐位相同**（第 3 节表里的 DIGEST 一列）。
⇒ **"慢多少倍"比的是同一个计算**，这句话有逐位证据，不是自称。

## 2. 极限环：**快照放电率会骗人，只有时间平均是物理量**

⚠⚠ 这条最早是专业版那条线发现的，它直接影响怎么读下面所有"平均放电率"。

**专业版的实测**（P=10⁴、**k=100**）：`steps=19 → 0`，`steps=20 → 32.33`，
`steps=21 → 55.30` —— 单步快照**完全由"停在第几步"决定**。

### 本仓独立复核（不是照抄，是自己跑出来对上的）

**① k=100 那一档：确实是周期 4**，而且数值与专业版轨迹吻合：

```
P=1000  k=100  周期=4
   step=400   meanE=36.61574880  meanI=28.00130399  meanAll=32.30852640
   step=401   meanE=33.90624737  meanI=76.44363368  meanAll=55.17494052
   step=402   meanE= 0.00000000  meanI=49.01508598  meanAll=24.50754299
   step=403   meanE= 0.00000000  meanI= 0.00000000  meanAll= 0.00000000
   step=404   meanE=36.61574880  meanI=28.00130399  meanAll=32.30852640   ← 回到 step 400
P=10000 k=100  周期=4（同样复现）
```

（专业版那条线的轨迹是 `step3: 36.6157488 / 28.00130399 / 32.3085264` ——
 `36.61574880` 与 `32.30852640` 与本仓复现的**逐位相同**。）

**② ⚠ 但 k=30 那一档（也就是第 3 节的基准网格）**不是**周期 4** ——
12 步内找不到任何周期。这条必须说清，否则就是拿一个**不成立的性质**
去支撑"该报时间平均"。

**③ 不过结论照样成立**：k=30 时快照同样在剧烈跳（P=1000，连续 10 步）：

```
35.28 → 0.58 → 29.65 → 48.97 → 9.43 → 4.43 → 33.57 → 34.93 → 0.53 → 29.96
                          ↑ 相邻两步能差 10 倍以上
```

⇒ **两种参数下结论一样：单步快照不能当结论，必须报时间平均。**

`基准_群体()` 两个都给：`MEAN_RATE_*`（快照，用来和专业版对 DIGEST）
与 `TIMEAVG_*`（时间平均，**这才是物理量**）。判据里两只都钉着：
`test_周期4在k等于100那一档` + `test_k30那一档不是周期4`。

### 两边的时间平均**互相吻合**（各自独立跑出来的）

| P | 轻量版 `TIMEAVG_E` | 专业版 `TIMEAVG_E` | 轻量版 `TIMEAVG_I` | 专业版 `TIMEAVG_I` |
|---|---|---|---|---|
| 100 | 12.769293 | 12.769 | 31.023396 | 31.023 |
| 1000 | 13.921416 | 13.921 | 32.427793 | 32.428 |
| 10000 | 13.797913 | 13.798 | 32.269693 | 32.270 |

⚠ P=1000 / P=10000 的**快照** `MEAN_RATE_E` 是 **0.019 / 0.017 Hz**，看着像
"网络死了" —— 那是相位的假象。**时间平均才是 13.9 / 13.8 Hz。**

## 3. ⚠⚠ 核心结论：同口径下轻量版比专业版慢 **23 ~ 111 倍**（不是"略慢"）

**口径**（两边**逐字相同**）：

```
model = rate · k_local = 20 · k_long = 10 · dt = 0.1 ms · seed = 12345
计时 = **只包 step 循环**的墙上时间（建表/分配/输出都不计；不开窗、不渲染）
专业版 = neural_brain.exe --engine 0 --threads 1     ← 单线程，跨语言才公平
同一台机器（Windows · x86-64 · Python 3.12.10 / MinGW g++ 16.1.0 -O2）
每格取 3 次的中位数
```

| P | steps | nnz/步 | 轻量版 ms/步 | 专业版 ms/步 | **倍数** | 轻量版吞吐 | 专业版吞吐 |
|---|---|---|---|---|---|---|---|
| 100 | 2000 | 3,000 | **0.0993** | **0.004305** | **23.1×** | 30.21 M nnz/s | 696.9 M nnz/s |
| 1000 | 1000 | 30,000 | **1.1218** | **0.012800** | **87.6×** | 26.74 M nnz/s | 2343.8 M nnz/s |
| 10000 | 500 | 300,000 | **12.1876** | **0.109605** | **111.2×** | 24.62 M nnz/s | 2737.1 M nnz/s |

**三格的 DIGEST 两边逐位相同**（`0x4DD85107EB179CB5` / `0xD4C70028E2C071DD` /
`0x60433B534ED16C9B`）⇒ 倍数比的是**同一个计算**。

### ⚠ 作者的原话是「轻量版也可以，但是模拟速度略慢」

**实测不支持"略"这个字。** 差的是 **1~2 个数量级**（中位 ~88×），不是"略"。
按本仓的规矩：**数字不好看也照实写**，不为了迎合那句话把数字修饰掉。

**慢在哪**（可归因，不是笼统的"Python 慢"）：

| 因素 | 证据 |
|---|---|
| **解释器开销** — 每步每个群体一次 Python 级循环 | 轻量版吞吐 **~25~30 M nnz/s** 且**随 P 略降**（30.2 → 24.6）；专业版 **697 → 2737 M nnz/s**，随 P **升**（固定开销被摊薄） |
| **没有 SIMD / 没有多线程** | 专业版单线程已快 23~111×；它 24 线程时（P=2×10⁵, k=30）实测 **0.851 ms/步、7.05×10⁹ 耦合更新/秒** —— 比轻量版快 **~280×** |
| **数据布局** | 轻量版一次内积是 `array` 逐元素取值 + Python 乘法；专业版是连续 CSR + `(double)w[p]*src[col[p]]` 一条机器指令 |

⚠ 上面那条"24 线程 7.05×10⁹/秒"是**专业版那条线的实测**（不是我跑的），列在这里
只为说明"单线程 111× 是**下界**，不是专业版的全部实力"。

### 另一个角度：实时率

| 配置 | ms/步 | dt | 实时率 | 意思 |
|---|---|---|---|---|
| 轻量版 P=100 | 0.0993 | 0.1 ms | **~1.0×** | 刚好实时 |
| 轻量版 P=1000 | 1.1218 | 0.1 ms | ~0.09× | 比实时慢 11 倍 |
| 轻量版 P=10000 | 12.1876 | 0.1 ms | ~0.008× | 比实时慢 122 倍 |
| 专业版 P=1000 | 0.012800 | 0.1 ms | **~7.8×** | 比实时快 7.8 倍 |

⇒ 轻量版在 **P≈100**（几十个脑区那一档）还能实时；上到 P=1000/10000 就掉到
实时以下。**这就是"群体层能跑、但只到某个规模"那条线。**

## 4. 果蝇规模 · 逐细胞（10 万神经元）

⚠ 这条线**没有专业版对照** —— 专业版那条线做的是人脑**群体层**。果蝇逐细胞是
LearningCore 自己那条（"三条线能对上"里的第三条）。

**口径**：`dt=0.1 ms`、`τ_m=20 ms`、`τ_s=5 ms`、阈值 1.0、不应期 2 ms、
事件驱动突触投递、headless、只算不画。

本机实测（`examples/神经模拟_果蝇逐细胞.py`，原始输出见第 6 节）：

| 量 | 实测（3 次取中位数） |
|---|---|
| **神经元数** | **100,000**（逐细胞，每个一个 LIF 膜电位） |
| **显式突触数** | **1,000,000**（平均出度 10.0） |
| **ms/步** | **12.24 ms**（3 次样本 11.45 / 12.51 / 12.24） |
| ms/步/神经元 | **0.000122 ms** |
| 平均放电率 | **16.3824 Hz**（⚠ 3 次完全相同 —— 确定性，这就是同种子逐位相同） |
| 每步发放 / 突触事件 | 163.8 个 / 1638.2 次 |
| 神经元·步/秒 | 9.49×10⁶ |
| 建表耗时 | 250 ms（不计入 ms/步） |
| 模拟时长 | 500 步 × 0.1 ms = **50 ms 生物时间**，花 5.3 s 墙钟 ⇒ **0.95% 实时** |

⚠ **本机同时在跑别的任务**（多 agent 协作），所以单次 `ms/步` 有 ±10% 抖动
（实测样本 11.45 ~ 12.51）。上面取的是 3 次中位数；对比表（第 3 节）两边
各跑 3 次取中位数，条件相同。

### ⚠⚠ 三个必须照实说的近似（不许读成"模拟了果蝇全脑"）

1. **突触只显式表示 2%。** 果蝇真实约 **5×10⁷** 条（FlyWire 量级，平均出度 ~350），
   本实现默认 **1×10⁶** 条（出度 10）。纯 Python 里 5×10⁷ 条要 ~200 MB(索引)
   + ~400 MB(权重)，还要每步扫 —— 不现实。
   **缺掉的连通性用背景外部电流顶上**（真实脑里也确实有大量背景输入）。
   ⇒ 报告里「显式突触数 1×10⁶」与「果蝇真实 5×10⁷」**两个数分开写**。
2. **默认落在"强直驱动"区间**（外部电流 1.20、阈值 1.0）⇒ 平均放电率 ~16 Hz。
   **它不是一个自发活动网络**：每神经元只有 10 条突触（真实的 ~1/35），
   撑不起自发持续放电 —— 实测把驱动降到阈值以下，网络就静默。
3. **发放是"规则"的，不是不规则的。** 每个神经元一个固定的外部电流
   （"淬火无序"），所以它按自己的周期稳定发放。真实神经元发放不规则。
   ⚠ 为什么不用每步噪声：实测每步 10⁵ 次 `gauss()` 要多花 ~8 ms/步，
   而那是 **RNG 的开销、不是神经计算的开销** —— 混进 `ms/步` 就是脏数据。
   （另一条实测：噪声加在**突触电流**上会被 τ_s 低通掉，σ 从 0.5 调到 10
   平均放电率一直是 0 —— 所以要让噪声起作用得直接加在膜电位上。）

### 单独量"突触这一层"多快

`ms/步` 主要**不**花在突触上（真实脉冲网络里每步只有一小部分神经元发放）：

| 配置 | ms/步 |
|---|---|
| 10 万神经元 + 100 万突触（放电率 16.4 Hz） | 12.24 |
| 10 万神经元 + **0 突触**（纯 O(N) 向量更新） | 12.16 |
| **把每步逼成全体发放**（100 万次投递/步） | **91.30**（3 次中位数）⇒ **10.95 M 突触事件/秒** |

⇒ 突触投递本身只有 **~11 M 事件/秒**（纯 Python 逐条 `array` 索引）；
而常规活动下它只占 ms/步 的 **~3%** —— 瓶颈在 O(N) 的整数组更新。

### ⚠ 逐细胞 vs 群体层：把"人脑为什么做不到"算清

```
逐细胞 0.000122 ms/神经元/步
  × 8.6×10¹⁰ 个神经元        = 1.05×10⁷ ms ≈ **2.9 小时 / 步**（0.1 ms 生物时间）
  ⇒ 模拟人脑 1 秒生物时间     ≈ **3.3 年**
群体层（P=1000）1.12 ms/步，一步代表 8.6×10¹⁰ 个神经元 ⇒ 0.09× 实时
```

**同一句"人脑规模"，两条线差 10 个数量级** —— 这就是分层的原因，也是它的代价。

## 5. 与专业版的对比（总结成一张表）

| | 专业版（C++） | 轻量版（Python） |
|---|---|---|
| 层级 | 群体 / mean-field | 群体 / mean-field（**同一层**） |
| 计算是否逐位相同 | ✅ **是**（DIGEST 逐位相同，7 个点全中） | ✅ **是** |
| P=100 · ms/步 | 0.004305 | 0.0993（**23.1×**） |
| P=1000 · ms/步 | 0.012800 | 1.1218（**87.6×**） |
| P=10000 · ms/步 | 0.109605 | 12.1876（**111.2×**） |
| 耦合更新/秒（单线程） | 697 → 2737 M | 30.2 → 24.6 M |
| 多线程 | 有（24 线程实测 7.05×10⁹/秒） | **没有**（纯 stdlib，无并行） |
| SIMD | 有 | **没有** |
| 逐细胞果蝇路径 | 无（那条线不做） | ✅ 10 万神经元 / 100 万突触 / 12.24 ms/步 |
| 依赖 | 引擎 DLL | **零第三方依赖** |
| 能画出来 | 引擎窗口 | `pyengine` 轻量渲染（默认 headless） |

**一句话**：**同一个计算、同一个答案；速度差 1~2 个数量级，不是"略慢"。**


## 7. 判据（`tests/test_neural.py`，7 组 **32 条**，全绿）

## 9. 已知不足（⚠ 照实列，不藏）

1. **慢 23~111 倍**（同口径实测）。作者说"略慢"，**实测不支持**。
   纯 stdlib、无 SIMD、无线程是根因；要快只能用专业版。
2. **群体层不是"脑的还原"**：它把 8600 万个神经元压成一个标量，
   逐细胞那条线完全没做（也做不到）。任何"模拟了人脑"的说法都是错的。
3. **果蝇逐细胞的突触只显式表示 2%**（1e6 / 5e7），缺的用背景电流顶。4. **果蝇发放是规则的**（淬火异质驱动），不是不规则发放。
5. **P=10000 那一格 ms/步 是 11.8 ms**，比实时慢 122 倍 —— groups 再往上
   纯 Python 就跑不动了；本报告**没有外推**更大 P 的数字。
6. **`examples --大`（500 万突触）只做了冒烟测试**：建表 1.24 s（出度 50）、
   跑得动（50 步 10.27 ms/步）—— 但**没有**跑完整的 500 步基准，
   所以报告里没有 500 万突触那一档的数字。
7. **`--窗口`（Tk 真窗口）那条路没跑过** —— 它会在桌面上弹窗。
   无头那条（`录制后端`）是判据覆盖的，窗口那条只保证"代码路径存在"。
8. **`splitmix64` 的读法**曾是唯一歧义点（含不含内部 `+GOLDEN` 一步）。
   本实现按"含"写，4 个参照点全部对上 ⇒ 该读法已被**实测确认**。
9. **极限环是分档的**：k=100 是**周期 4**（本仓独立复现、数值与专业版吻合）；
   **k=30 那一档不是周期 4**（12 步内无周期）—— 但快照同样剧烈跳动。
   两档的结论一致：**任何单步快照的放电率都不能当结论用**。
   这不是 bug，是这套 canonical 参数的性质。
